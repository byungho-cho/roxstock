# Documentation

RoxStock의 기획, 설계, 개발 규칙 및 운영 문서를 관리합니다.

## 문서 관리 원칙

- Markdown(`.md`) 파일을 변경 이력을 추적하는 원본 문서로 관리합니다.
- PDF(`.pdf`) 파일은 GitHub 열람과 공유를 위한 배포본으로 관리합니다.
- DOCX(`.docx`) 파일은 필요할 때 별도로 제공하며 GitHub 저장소에는 저장하지 않습니다.
- 문서 내용이 변경되면 Markdown 원본을 먼저 수정하고 PDF를 다시 생성합니다.
- 확정된 과거 버전은 삭제하거나 덮어쓰지 않고 버전별로 보존합니다.

## 현재 기획 기준 (2026-10-06 · Figma v0.4 1차 확정)

사용자가 정리한 현재 Figma의 페이지명·번호를 기준으로 다음 문서를 사용합니다. A0000~A0003 공통 명세, C/T 4자리 화면번호, 더보기 C9900/T9900, MM.DD 페이지 날짜를 반영했습니다.

## 홈 목표가 도래 기능

- 현행 정본은 [기본설계서 v0.7의 20장](./매매일지%20설계%20v0.7.md#20-홈-목표가-도래-설계-2026-10-01-추가)입니다. 별도 목표가 도래 설계 v0.2 파일은 과거 참고 기록이며 중복 정본으로 사용하지 않습니다.

목표가 도래는 2026-10-01 확정 요구사항이며, 종목별 매도 목표가 비교 방식 대신 보유기간별 목표수익률 달성을 사용합니다. 기존 기획·설계의 관련 내용은 이 추가 명세를 함께 참조합니다. 디자인·개발·배포 완료 여부와는 별개입니다.

## v0.4 확정 이후 개발 인계 (2026-10-06)

- 종목 상세 이전·다음 스와이프, 세로 스크롤 우선 판정, 빈 상태 분류 변경 버튼 삭제, 거래내역0건 수동 분류 변경, 홈·종목목록 원형 새로고침 아이콘은 기존 기획·설계·UI 가이드의 10.06 항목에 기록했습니다. 별도 기능 설계 파일을 만들지 않습니다.
- 이 항목은 개발 요구사항이며 main 반영 완료로 보고하지 않습니다. 관련 구현·배포 상태는 개발현황에서 관리합니다.
- 개발은 기능·타입·빌드 검사 후 PR 병합·자동 배포 확인으로 종료하고 종합 QA는 사용자 요청 시 진행합니다.
