2026-10-18, main `03dceda5` 기준. 운영에서 동기화한 로컬 DB의 두 경고 그룹을 검토했다. 화면은 종목 단위로 묶어 8+5건으로 표시했으나 KCC 2016/2017을 펼치면 실제 기간·발생 기록은 14개다. 운영 DB 변경이나 배포는 이 작업에 포함하지 않았다.

## 공통 수집 경로

`getCfsThenOfs`에 해당 보고서를 전달한다. 자동 백필·현재 공시 수집, 수동 갱신의 기존/독립 작업, 수동 연간 경로가 같은 공개 원문 검증기를 사용한다. 일반 원본 보고서는 기존 JSON API 경로를 유지한다. 복수 결산 ANNUAL 및 내용 정정 ANNUAL만 공개 원문 검증 대상이다. 종목별 하드코딩은 없다.

공시 목록에서 기업·연도·정정 계열과 원본 존재를 확인한다. 공개 목차의 정적 숫자 좌표만 읽고 JavaScript를 실행하지 않는다. DART 공식 origin, 동일 접수번호, dart3/dart4만 허용하며 최대 목차 1개+본문 3개, 응답당 2MB로 제한한다. 기존 호출 간격·일일 예약 한도·수집 제외·실행 시간·금융 임대를 그대로 적용한다. 한도 소진 시 공개 원문 요청으로 우회하지 않는다.

표지 기간, 손익계산서 기간, 재무상태표 기준일이 일치해야 한다. 현재/비교 열은 colspan과 주석 열을 구분한다. 원 단위 재무상태표·손익계산서의 자산/부채/자본, 매출/영업이익/순이익 여섯 값을 확인하고 자산=부채+자본을 검증한다. `NULL`·대시를 0 또는 비교연도 값으로 바꾸지 않는다. 실제 0과 음수는 보존한다. 자본변동표·현금흐름표·후속 주석의 동명 행은 손익계산서 값으로 사용하지 않는다.

연결재무제표가 없다는 명시적 문구가 있을 때만 별도재무제표를 선택한다. 연결재무제표의 파싱 실패를 별도 전환 사유로 사용하지 않는다. 외화, 천원 단위, 미지원 양식, 원본 부재·철회·불명 정정은 검토를 유지한다. 파서가 확정한 보통 EPS·지배주주 항목만 추가하며, 부족한 주식수·종가·기타 항목을 추정하지 않는다.

원문 URL, 표지/재무본문 SHA-256, 실제 회계기간, 선택 정책은 `sourceValidation.publicDocument`에 저장한다. 검증한 기간은 기존 `FiscalDuration` 정책으로 전달한다. 보완 수집에서 이 출처를 다시 옛 JSON 원본으로 대체하지 않는다. 새 정정 접수번호로 바뀌면 기존 성공 지표를 섞어 쓰지 않고 재계산하며 이전 값은 `publicSourceCorrections`에 최대 4개 보존한다.

## 재개·리포트 정리

기존 DB 기간 재검토의 10건 페이지와 작업 CAS를 재사용해 복수 결산·내용 정정 보류도 검토한다. 충분한 대상 공시 목록이 있으면 PENDING으로 전환하고 실제 원문 검증은 기존 수집 루프에서 한다. 시도 횟수·기존 실행 이력을 보존한다. 검증 실패는 새로운 구체적 보류 사유를 남기므로 같은 옛 사유로 무한 재등록하지 않는다.

리포트 정리는 같은 종목·연도·기간·접수번호와 검증된 회계기간이 현재 저장 결과와 일치할 때만 수행한다. 실제 저장 없이 새 값이 생겼다는 이유만으로 정정 경고를 해결하지 않는다. 발생 이력은 삭제하지 않는다. 재수집되어 새 증거가 발생하면 기존 재발 정책을 따른다.

## 로컬 결과·제한

검증 환경: Windows / Node 24 / MariaDB. 실제 공개 공시 14기간에서 핵심 재무 6항목씩 총 84항목의 숫자와 등식을 검증해 로컬에 신규 저장했다. 14개 작업을 SUCCESS로 정리하고 경고 발생 기록 14개를 해결했다. 주식수와 과거 종가 등 별도 근거가 필요한 지표는 PARTIAL 상태로 보존한다. 공시 판정 해결은 모든 PER/PBR의 수집 완료를 뜻하지 않는다.

최종 수집기 단위·회귀 검사 204개, 격리 MariaDB 리포트 통합 검사 6개가 통과했다. 수집기 빌드와 백엔드 타입 검사도 통과했다. 실제 대조한 공개 본문의 최대 크기는 105,715자였다. 실제 운영 자동 루프와 운영 DB 반영은 미검증·미실행이다. DB 마이그레이션은 없다. 전체 로컬 백업과 대상 변경 전 JSON은 저장소 밖 비공개 폴더에 보관했다. 공개 원문 전문·DB 덤프·키·잠금 토큰은 커밋하지 않는다. 데이터 롤백은 해당 백업과 비교한 대상 기간만 복구하고, 코드 롤백은 이 브랜치 변경을 되돌린다.
