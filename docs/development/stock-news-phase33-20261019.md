# 33차 종목소식 — 1.1.19 (기능 도입 1.1.18)

32차 홈 카드(PR #271, 1.1.17)와 별개인 기능이다. Figma 파일 `FXEeCL5ivBCuAtbVuPwvio`의 목록 5005:54/5005:2231, 전체 목록 5040:56/5040:324, 요약 5044:237/5044:2를 대조한다. 지시문에 따라 태블릿 시안에 남은 우측 요약 패널은 제외하며 양쪽 모두 별도 요약 화면으로 이동한다. 예시 기사·수치·출처는 운영 DB에 넣지 않는다.

## 제공처와 접근 조건

- 한국경제 공식 RSS: <https://www.hankyung.com/feed>, 증권 `/feed/finance`, 경제 `/feed/economy`, IT `/feed/it`. 제목·링크·게시 시각을 읽는다. RSS에 내용 요약이 없을 때 선별된 기사에 한해 공개 HTML head(최대 64 KiB)의 `og:description`/`description`을 읽는다. 본문을 읽어 요약하지 않는다. 공개 메타데이터가 없으면 요약 없음이다.
- 한경 컨센서스: <https://consensus.hankyung.com/>의 공개 증권사 리포트 목록. 날짜·제목·작성 증권사·원문 PDF 링크와 목록에서 제공하는 공개 초록만 읽는다. PDF를 다운로드·저장·본문 분석하지 않는다. 목록 초록이 제목의 반복일 경우 요약으로 쓰지 않는다. 날짜만 공개된 리포트는 `publishedPrecision=DATE`이며 UI에 **시각 미상**을 표시한다. 자정 값은 날짜 정렬용이며 실제 게시 시각으로 표시하지 않는다. 원문 PDF의 무단 전재 금지 안내를 준수하여 원문 전체를 복사하지 않는다.
- DART 공개 회사별 RSS: <https://dart.fss.or.kr/api/companyRSS.xml?crpCd=00126380> 형태. RSS의 공시 대상 회사명을 검증한다. 제출자가 다른 회사인 항목을 현재 조회 회사에 무조건 연결하지 않는다. 최근 공시 RSS의 짧은 과거 범위는 기존 Open DART `list.json`의 회사·게시일 검증과 페이지 조회로 보완한다. 새 API 키를 만들지 않고 기존 키·일일 예산·공용 실행 lease·호출 간격·수동 요청 우선권을 재사용한다. 당일 020/예산 소진/기존 작업 잠금은 우회하거나 초기화하지 않는다.
- 네이버 금융은 `robots.txt`의 전체 자동 수집 금지 안내를 확인하여 제공처에서 제외했다.
- 공개 피드·목록은 유한한 과거 범위다. RSS가 직전 확인 지점까지 덮지 못하면 WINDOW_LIMIT, 리포트 페이지 상한은 REPORT_PAGE_BOUND, DART 예산·잠금·매핑 부족은 별도 사유로 기록한다. 누락 가능 구간을 정상 완료로 숨기지 않고 PARTIAL/FAILED로 표시하며 해당 제공처 watermark를 전진시키지 않는다.
- 신규 유료 API, 외부 생성형 요약, 새 비용·키는 추가하지 않았다. 로그인·결제·접근 제한을 우회하지 않는다. 공개 메타데이터에 무료 여부가 없으면 UNKNOWN을 저장한다. DART 공시는 FREE이며, 기사 `isAccessibleForFree`가 명시된 경우만 FREE/PAID를 반영한다.

실제 응답 확인일: 2026-10-19 KST. 피드 XML과 공개 리포트 HTML 응답을 확인했다. 원문 페이지/PDF의 기기별 접근 가능 여부는 제공처 정책에 따라 달라질 수 있다.

## 수집·선별·요약

활성 계좌들의 **매수 거래 이력 또는 관심(WATCHLIST)** 종목을 합친 중복 없는 집합을 사용한다. 실제 보유 종목은 매수 이력에 포함된다. 전량 매도 종목도 거래 이력이 있으면 대상이며, 수량이 없고 보유 분류만 등록된 종목·추천 종목은 관심/거래 조건 없이 포함하지 않는다. 모든 외부 수집 제외 종목 및 Z99 코드는 수집에서 제외한다. 종목 조회는 DB에서 200개씩 읽고, 조회 API는 10개씩 제공한다.

중요(2): 실적·전망 변경, 주요 공급계약·주요사항 공시, 합병·인수·증자·소각·배당 결정 등. 주요(1): 리포트 및 실적 분석·사업·산업·정책 변화 등. 단순 등락·홍보·이벤트와 관련성 없는 자료는 제외한다. 중요도는 투자 추천이나 호재/악재 판정이 아니다. 종목 코드 또는 검증한 종목명/별칭을 사용하여 연결하며 비슷한 회사명을 단순 부분 문자열로 연결하지 않는다.

기본 5개를 선별한다. 중요 자료가 5개보다 많으면 최대 10개까지 허용한다. 자료가 적으면 적게 저장한다. URL의 추적 인자·fragment 제거, 제공처 ID, 정규화 제목·관련 종목·KST 게시일 fingerprint로 중복을 제거한다. 이미 검토했으나 선별하지 않은 후보도 해시만 기록해 중첩 조회 때 과거 후보로 빈자리를 반복 채우지 않는다. 전체 목록 건수는 누적 선별 자료 중 현재 계좌에서 조회 가능한 건수다.

요약은 제공처 공개 근거를 정리한 추출식으로, 보통 200자 내외·최대 300 Unicode 문자다. 새로운 수치·전망을 만들지 않는다. 별도 한 줄 요약은 없다. 목록·상세 GET은 저장된 요약만 읽는다.

## 스케줄·장애·잠금

`collector/src/worker.ts`의 기존 일반 collector에 독립 60초 tick을 추가했다. 주가/스냅샷/수동 보완 타이머를 기다리거나 점유하지 않는다. `STOCK_NEWS_ENABLED=false`로만 새 기능을 중지할 수 있다.

최초 실행 시 DB에 실제 시작 KST 날짜를 저장하고 당일 00:00부터 실행 시점까지 수집한다. 완료 상태와 자료 발행을 같은 트랜잭션으로 커밋하여 재시작·재배포 때 최초 실행이 반복되지 않는다. 다음 날부터 KST 06:00 이후 당일 완료 여부를 확인하여 1회 실행한다. 중단·전체 실패 시 15분 간격, 날짜당 최대 3회 재시도한다. 다음 날에는 새 재시도 예산을 쓸 수 있다.

제공처별 직전 성공 watermark 뒤를 조회하면서 최대 72시간을 중첩하고 최초 활성화일 전으로는 내려가지 않는다. 공개 HTTP는 1초 이상 간격, 15초 타임아웃, 최대 2회 시도, 제공처 인스턴스당 180호출, 전체 실행 8분 상한이다. 리포트는 페이지당 80개·최대 8페이지다. Open DART는 기존 설정 간격·예산과 별도로 뉴스 실행당 100호출·회사당 5페이지 상한을 둔다. 전량 읽기나 무제한 재시도는 없다.

`stock-news` 전용 DB lease를 20초마다 갱신하며 발행 트랜잭션은 소유권·만료를 다시 확인한다. 만료된 소유자만 회수하고 이전 RUNNING 소식 실행은 중단 실패 이력으로 남긴다. DART 조회는 기존 financial lease를 추가 획득할 때만 수행하고 수동 요청이 도착하면 다음 호출 전에 양보한다.

일부 제공처 실패 시 정상 자료·기존 목록을 보존하고 제공처 오류와 실행 이력을 남긴다. 전체 실패는 최근 정상 수집 시각을 바꾸지 않는다. 정상 0건·최초 수집 전·수집 중·부분 실패·전체 실패·조회 실패·요약 없음을 구분한다.

## DB·조회 경계

추가 테이블만 적용한다: `stock_news_items`, `stock_news_securities`, `stock_news_seen`, `stock_news_state`, `stock_news_provider_state`. 기존 거래·재무·원화/외화 자료를 수정하거나 삭제하지 않는다. 원문 본문·리포트 PDF·키는 저장하지 않는다. 공개 자료는 전 계좌 공통 1건이며 관계 테이블만 종목 ID로 연결한다. 소식 외래키가 기존 빈 종목 삭제를 막지 않도록 종목 삭제 시 관계만 제거하며 소식 메타데이터는 유지한다.

인덱스는 중요도/게시 시각/ID, 유형/중요도/게시 시각/ID, 종목/소식 ID 및 URL hash/fingerprint/provider-ID 고유 인덱스다. 목록은 중요→주요, 게시 시각 내림차순, ID 내림차순이다.

`GET /api/accounts/:accountId/stock-news`와 `/:newsId`는 활성 계좌와 현재 계좌 대상 종목을 항상 검사한다. 다른 계좌 snapshot이나 해당 계좌와 관련 없는 상세 ID는 거부한다. snapshot에는 초기 최대 ID·계좌·필터·대상 집합 hash를 넣으며 새 삽입이 페이지 중간에 끼어들지 않는다. 페이지·상세 순번·이전/다음은 같은 snapshot 기준이다. 대상 집합이 바뀌거나 24시간이 지나면 새 목록 조회를 안내한다. 전체 자료를 내려받지 않고 DB count·커서 조건·limit 11로 처리한다. 기존 read-batch의 호출자 헤더별 캐시 격리를 재사용한다.

**인증 범위:** 현재 저장소는 개인 단일 사용자 설치이며 Account에 사용자 소유자/인증 주체가 없다(기존 accounts.ts에도 명시). 이번 기능은 기존 경계 안의 엄격한 계좌 분리다. 다중 사용자 인증·계좌 소유권 권한 검증을 새로 제공한 것으로 간주하면 안 된다. 다중 사용자 공개 서비스로 전환하기 전 인증/소유권 계층을 모든 API에 함께 적용해야 한다.

## 화면·원문·메뉴

필터 좌우 16px·간격 6px, 목록 카드 좌우 8px, 종목명/중요도 간격 8px, 12px 중요/주요 및 14px 유료 아이콘을 사용한다. 아이콘은 Figma 해당 레이어의 원본 SVG를 exportAsync로 추출해 재사용한다. 임시 Figma URL은 런타임에 사용하지 않는다. 전체·리포트·기사·공시 필터 후 건수, 최초 10개 및 다음 10개 더보기를 제공한다. 기존 항목과 스크롤은 유지하고 전체 자료를 일괄 요청하지 않는다.

상세는 양쪽 모두 별도 화면이며 같은 이동 함수로 버튼/좌우 스와이프를 처리한다. 좌측 가장자리 24px는 브라우저 뒤로가기에 남기고 세로 제스처·컨트롤 터치·다중 터치·중복 스와이프를 분리한다. 끝 방향은 비활성화한다. 필요 페이지를 기존 infinite query에 추가한 뒤 이동한다. 다음/이전은 replace navigation으로 쌓지 않아 뒤로가기 한 번으로 기존 필터·표시 개수·스크롤을 복원한다.

원문 링크는 웹 새 탭 `noopener noreferrer`, 앱은 같은 WebView 탐색을 가로채 Chrome ACTION_VIEW 우선·설치/사용 불가 시 기본 외부 브라우저로 연다. 새 권한·JavaScript bridge를 추가하지 않는다. 잘못된 URL은 화면 안내, 브라우저 자체 부재는 네이티브 Toast로 안내한다. 유료/로그인/출처의 접근 거부를 우회하지 않는다.

투자동향을 보존하며 메뉴를 홈·대시보드·종목목록·매매일지·예수금·자산분석·투자금·투자손익·가치분석·종목소식·재무제표·복리계획·투자동향·모니터링·설정·더보기로 통일했다. 이로써 종목소식은 홈 포함 10번째, 가치분석 바로 다음이다. 홈/더보기 고정과 중간 스크롤 구조는 유지한다.

## 운영 확인·배포·복구

앱 1.1.19, 네이티브 0.1.3(versionCode 4). PR 필수 검사·격리 MariaDB·두 화면 Playwright·Android 설치/Intent 검증을 통과한 뒤 병합한다. 기존 Production Deploy가 기존 DB 백업·gzip·체크섬 검증 후 추가 마이그레이션을 적용한다. backend→collector→frontend 배포를 사용한다.

일반 collector 시작 시 최초 실제 수집이 자동 실행된다. 배포의 `news_activation`은 같은 idempotent CLI를 실행하고 완료·저장 건수·제공처 사유·계좌별 저장 목록 API 응답·다음 06:00을 검증한다. 이미 실행 중이면 제한된 횟수만 기다린다. 상태가 끝나지 않으면 미완료로 기록하며 모니터링에서 원인을 확인하고 같은 명령을 다시 실행한다. 강제로 상태/예산/잠금을 초기화하지 않는다.

APK는 기존 영구 서명 키·동일 web-only 패키지로 빌드·설치 검증 후 기존 Caddy 다운로드 경로에 버전 파일을 추가한다. 공개 APK digest를 확인한 다음 latest.json을 교체하며 이전 APK/manifest를 남긴다. 키·덤프·APK 바이너리를 Git에 넣지 않는다.

복구는 새 collector를 중지하고 기존 이미지 복구 절차로 이전 backend/collector/frontend 이미지를 복원한다. 추가 테이블은 그대로 두어 이력을 보존하며 역마이그레이션·DB 덤프 복원은 하지 않는다. APK 문제 시 서버의 `.deploy/apk-news-<sha>/latest.json.previous`를 복원하여 기존 APK 링크로 돌린다. 새 APK 파일을 삭제할 필요는 없다. 최신 수집 건수·제공처 실패·예약 시각과 검증/미검증 결과는 PR 검사 및 최종 보고를 기준으로 한다.


### 배포 확인의 커밋 전달 보완

GitHub Actions는 SHA에 짧은 비밀값과 같은 문자열이 있으면 job output을 비밀정보로 오인해 제거할 수 있다. 전체 SHA를 job output으로 전달하지 않고 모든 checkout·하위 workflow·검증·APK 게시에 불변 `inputs.target_sha || github.sha`를 직접 사용한다. main 일치 검증은 유지한다. 공개 APK 버전이 소스보다 뒤처지면 네이티브 파일 변경이 없는 재배포도 미완료 APK 게시를 재시도한다. 동시 실행 시험은 어느 실행이 먼저 잠금을 획득하더라도 같은 제공처 구성을 사용하도록 보완했다. 앱 기능·스키마는 동일하며 검증·배포 보완 릴리스는 1.1.19다. 최초 수집 자료와 완료 상태는 보존하고 다시 최초 수집하지 않는다.
