# 재무제표 수동 갱신 대기·추적 (1.1.7)

2026-10-17 사례의 대기 원인은 미확정이다. 자동 작업 점유 또는 잔존 잠금으로 단정하지 않는다.

## 우선 처리와 재개

DART worker는 유휴 상태에서 5초 간격으로 수동 요청을 확인한다. 자동 실행 중에는 과거 수집의 보고서 작업 사이, 현행 수집의 종목·연도 작업 사이, 별도 자동 보완 수집기의 기간별 작업 사이에서 확인한다. 저장·collection scope가 끝난 뒤 자신의 실행 잠금을 반환하고 접수 순서(startedAt, id)로 수동 요청 **1건**을 처리한다. 같은 자동 루프의 다음 위치에서 잠금을 다시 획득하고 재개한다. 수동 요청 사이에 자동 작업 단위가 진행되므로 연속 요청이 자동 수집을 무기한 밀어내지 않는다.

잠금 재획득 실패 시 자동 사이클은 LOCK_LOST로 종료하고 기존 내구성 작업 상태를 유지한다. 다른 소유자의 잠금을 삭제하거나 강제로 실행하지 않는다. 프로세스 재시작 시 기존 계획·작업 기록으로 자동 수집을 재개하며, 수동 실행은 유효한 소유권이 남아 있으면 재실행하지 않는다. 이미 기록된 수동 기간별 결과는 재시도 시 보존한다.

API 일일 한도와 요청 간격은 유지한다. 전환 양쪽에 기존 minDelayMs를 적용한다. 기업 매핑 갱신·계획 작성·진행 중인 종목/연도 저장은 전환 불가 구간이다. 외부 DART 호출은 기존 20초 요청 제한을 유지하며, 전체 전환 대기에는 접수 후 30분 제한을 적용한다. 일정한 수초 이내 전환을 보장하지 않는다. 최근 활동 근거가 없으면 사유는 확인 중으로 표시한다.

## 시각과 상태

- startedAt: 기존 의미(접수 시각)를 유지한다. acceptedAt은 신규 명시 기록이며 과거 요청은 startedAt을 사용한다.
- executionStartedAt: 실제 실행 잠금을 얻고 시작한 시각. 과거 기록에서 역산하지 않는다.
- lastProgressAt: 서버 진행 저장 시각. finishedAt: 종료 시각.
- waitReason / waitReasonChangedAt / relatedRunId: 확인 중, 자동 수집, 선행 수동 요청, 실행 잠금 대기 및 관련 실행 ID.
- 자동/선행 요청 여부는 유효한 lease와 120초 이내 lock 활동, 실제 소유 식별자와 RUNNING 작업 일치로 판단한다. RUNNING 행만으로 판단하지 않는다.

재무제표·가치분석은 같은 UI를 사용한다. 대기 시간과 실행 시간을 구분하고, 대화창 재진입·앱 복귀 시 서버를 재조회한다. 조회 실패 시 진행 안내 대신 오류와 재조회 동작을 표시한다. 완료 시 결과·쿼리·버튼 상태를 함께 갱신한다.

재무제표 시각은 실제 filing.collectedAt을 사용한다. 보완 시각은 자료를 확인한 성공 작업 또는 값이 바뀐 부분 성공에만 별도 기록한다. 요청 종료 시각을 사용하지 않는다. 실패·자료 부족으로 값이 유지되면 시각을 새로 만들지 않으며 기존 기록이 없으면 미기록으로 표시한다. material-times API로 마지막 명시 기록을 다시 조회한다. 과거 보완자료 시각을 updatedAt으로 추정하지 않는다.

## 만료와 늦은 결과

수동 대기 30분, 실제 실행 10분, 개별 자료원 2분 제한을 유지한다. HTTP 조회와 독립적인 worker 15초 정리가 만료 요청을 종료한다. metadata snapshot과 RUNNING에 대한 조건부 갱신으로 진행 전환과의 경쟁을 방지한다. 만료 처리는 활성 잠금을 제거하지 않으며 소유자가 finally에서 반환하거나 기존 TTL이 자연 만료된다. 부분 결과는 보존한다. 완료된 작업은 RUNNING 조건부 갱신으로 재개되지 않는다. 비동기 작업 budget은 취소 신호와 쓰기 전 검사, 트랜잭션 반환 전 검사로 지연 응답을 차단한다.

## 장애 조사

1. 상태 API의 requestId, acceptedAt, executionStartedAt, lastProgressAt, finishedAt, 대기 변경 시각·relatedRunId를 확보한다.
2. DART collector 로그에서 manual_refresh_started / manual_refresh_task / manual_refresh_finished를 같은 요청 ID로 연결한다.
3. started 이벤트 ownerId(토큰 SHA-256 앞 16자리)로 collector_lock_attempt / failed / acquired / release를 연결한다. 로그의 expiresAt은 획득 시도 TTL이며 실제 연장은 collector_locks.locked_until/updated_at으로 확인한다. 토큰 원문을 보고서·화면에 복사하지 않는다.
4. 자동 실행의 metadata.ownerId와 유효 잠금 해시를 대조한다. 예전 실행처럼 소유 식별자가 없으면 자동 수집 점유로 추정하지 않는다.
5. API 조회 오류는 대기 원인으로 취급하지 않는다. 자료 시각과 요청 종료 시각을 별도로 확인한다.

## 검증

Mock provider/DB 단위 검증: FIFO 수동 처리 후 자동 루프 재개, 잠금 소유·활동 근거별 상태, 조회 없는 만료 정리, 오래된 만료 snapshot 경합, 늦은 자료원 쓰기 차단, 전체 실행 시간 제한, 부분 결과 보존. 기존 수집기·서버 회귀 테스트와 타입 검사도 실행한다.

커버 370×465 / 태블릿 725×396의 대기→조회 실패→재진입→완료·버튼 활성화 E2E를 CI에 포함한다. 로컬 브라우저 설치가 제한되면 그 사실과 CI 결과를 별도로 기록한다. 실 운영 데이터 초기화·대량 재수집은 수행하지 않는다. 동일 재현 환경에서 전후 시간을 측정하지 않았으므로 대기시간 개선 수치는 제시하지 않는다. 실제 DART 운영 한도·네트워크와 프로세스 강제 재시작 실험은 별도 검증 대상이다.
