# 8차 개선: DART 우선순위·기간별 가치지표·재무 화면 이동

## 기준과 운영 조사 (2026-10-07)

- 개발 기준: main `fcd2199` (1~7차 통합 문서 #115). 작업 브랜치 `codex/improvements-phase8-20261007`.
- 실제 운영 컨테이너 읽기 확인: 프론트 `sha-e1526ed`, 백엔드/수집기 `sha-3d2a324`. 서버 체크아웃 HEAD와 실행 이미지가 다르므로 실행 이미지를 기준으로 대조했다.
- 운영 DART 코드에도 올해를 먼저 순회하는 코드가 있지만, 기존 순서는 전체 종목 올해 → 종목별 과거였다. 8차는 모든 우선종목 올해 → 우선종목 연도 역순(2015까지) → 일반종목이다.
- 현대차(005380, security 240)의 운영 API 및 DB를 SELECT로 확인했다. 2024·2025 연결 재무자료는 저장됐으나 별도 valuation_metrics 값이 없다. 기존 saveFiling에는 지표 생성 연결이 없다.
- 현대차 2026 Q1/Q2는 SUCCESS, Q3/ANNUAL은 NO_FILING / NO_PERIODIC_FILING이다. 아직 없는 연간 자료를 실패 또는 0으로 처리하지 않는다.
- 운영 최근 실행 항목에서는 한 종목의 2016→2015 이력이 처리된 뒤 다른 종목의 2024년 자료가 처리되는 기존 종목별 과거 순서를 확인했다.

## 보존과 범위

활성 계좌의 매수 이력(전량 매도 포함), 수동 HOLDING, WATCHLIST의 합집합을 중복 제거한다. 추천 분류는 우선순위에서 제외한다. RECOMMENDED DB enum·읽기 필터·클라이언트 호환 타입은 기존 행을 읽기 위해 남긴다. 신규 분류 입력은 기존 manualClassification에서 HOLDING/WATCHLIST만 허용한다. 기존 추천 행의 전환·삭제는 없다. 이전 문서의 추천 우선수집 규칙은 이 문서로 대체한다.

신규 수집·보완은 2015~서울 기준 현재 연도만 수행한다. 2014년 이전의 저장 자료는 삭제하지 않으며 ROE 전기말 비교에 이미 존재하는 자료를 읽는 것은 허용한다. 기존 성공 재무 작업은 초기화하지 않는다. 올해 NO_FILING은 하루 뒤 재확인 가능하다. 공유 락·호출 제한·중단/재개를 재사용한다. 보조 종가 API 호출도 보수적으로 기존 일일 호출 예산에서 차감한다.

## 계산 기준

|항목|기준|
|---|---|
|저장 키|security + fiscalYear + periodType. 연간과 Q1/Q2/Q3를 구분하며 Q4 가치지표는 동일 연말의 연간 누적 기준을 재사용하고 기존 metricDate 테이블을 변경하지 않음|
|ROE|순이익 ÷ (전기 연말 자본 + 당기말 자본)/2 ×100. 연결은 당기 지배순익·당기 지배자본·전기 지배자본이 모두 있을 때 지배 기준. 부족하면 연결 전체 순익·전체 자본으로 일관되게 계산하고 TOTAL_SAME_DIVISION 명시. 별도와 연결 혼용 금지|
|분기 ROE/EPS|누적 실적 ×12/경과 개월(3/6/9), TTM 아님. 개별 분기 손익을 누적으로 오인하지 않음|
|EPS|공시의 기본 EPS 사용. 발행회사의 가중평균 보통주 수 기준. 분기는 누적 EPS가 있을 때만 연환산. 현재 주식수로 과거 EPS를 만들지 않음|
|BPS|연결은 소유주 자본, 별도는 전체 자본 ÷ 동일 공시의 유통 보통주 수. 우선주가 있으면 자본 배분 근거 부족으로 계산 보류|
|PER/PBR|재무기간 말일 또는 그 이전 7일 안의 가장 최근 비수정 종가 ÷ EPS/BPS. 분모 0 이하이면 계산 보류|
|주가·공시일|기간 말 가격과 나중에 공시된 실적을 결합한 **사후 기간 비교 지표**. 공시 당시 투자 가능 정보를 재현한 백테스트 값이 아님. 접수번호·공시일·재무기간 말일·실제 주가일 저장|
|RIM/W|전체 연결 ROE와 지배주주 BPS의 혼합 계산 금지. 기존 완전한 저장 지표 또는 일치하는 보완 기준만 사용|
|조회|기존 정상/수동 값 우선, null 항목만 기간별 보완값으로 채움. 정상 값 덮어쓰기 없음. 계산 근거 부족·실패·미공시·미수집·상장 전을 구분|

원천: [DART 전체 재무제표 공식 가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020) (2015년 이후, 당기 3개월/누적 구분), DART `stockTotqySttus.json` 동일 접수번호 주식수, [금융위원회 주식시세정보](https://www.data.go.kr/data/15094808/openapi.do) 일자별 종가. 후자의 별도 키 `DATA_GO_KR_STOCK_PRICE_KEY`가 없거나 해당 과거 날짜가 제공되지 않으면 현재가로 대체하지 않는다. 공급자 사용 조건과 키 권한은 운영 설정 단계에서 확인해야 한다.

## 현대차 로컬 보완 미리보기

운영 저장 자료를 읽어서 **로컬 계산만** 수행했다. 운영 API의 보완 후 값이 아니라 예상 결과다. 아래 값은 지배 항목이 부족하여 전체 연결 평균 자본 기준이다.

|기간|운영 ROE|로컬 예상 ROE|접수번호|재무 기준일|
|---|---|---|---|---|
|2024 연간|—|11.9143%|20250312001148|2024-12-31|
|2025 연간|—|8.3612%|20260318001394|2025-12-31|
|2026 Q1|—|7.9574% (누적 연환산)|20260515002418|2026-03-31|
|2026 Q2|—|8.3217% (누적 연환산)|20260814003521|2026-06-30|

EPS·BPS·PER·PBR은 기본 EPS/가중평균 보통주 근거, 지배자본/주식 종류별 배분, 과거 종가가 부족하여 미리보기에서도 —다. 기존 재무제표 전체를 재수집하지 않는다. 새 공시는 기본 EPS를 추가 정규화한다. 과거에 저장하지 않은 기본 EPS·지배 항목은 이 보완만으로 복구되지 않으며 추가 공시 근거가 필요하다.

## 저장 및 운영 실행 계획 (개발 당시 기록)

- 새 `period_valuations` 테이블만 추가하는 마이그레이션 파일을 제공한다. 기존 재무제표·거래·예수금·스냅샷·valuation_metrics를 변경하지 않는다.
- 지표 SUCCESS/PARTIAL/INSUFFICIENT/FAILED는 재무제표 작업 상태와 분리된다. 부가 원천 실패로 재무 성공을 지우지 않는다. 부족 자료는 일 단위, 오류는 시간 단위로 재시도한다.
- 기존 정상 보완값도 유지하며 누락만 채운다. 정정 공시에 따라 기존 정상값까지 재산정하는 기능은 이번 범위가 아니다.
- 승인 후 적용 순서: DB 백업 → 추가 테이블 마이그레이션 → 백엔드/수집기 및 프론트 배포 → 현대차 미리보기 → 우선종목 올해 보완 → 과거 역순 보완 → API 대조. 이번 작업에서는 어느 단계도 운영에 실행하지 않았다.
- 보완 도구(backend 디렉터리): `npx tsx src/scripts/supplement-valuations.ts --security=240`은 기본 읽기 전용 미리보기. 승인 후 `--apply`를 추가하면 공유 DART 락 하에서 저장 재무자료로 계산 가능한 값만 저장한다. security 생략 시 우선종목 먼저, 연도 역순으로 전체 저장 자료를 확인한다. 이 도구는 외부 공시 전체를 다시 수집하지 않는다.
- 부족한 동일 공시 주식수와 과거 종가는 수집기의 별도 보완 경로가 확보한다. 기본 EPS·지배 항목 자체가 저장돼 있지 않으면 근거 부족을 보고한다.
- 적용 전 새 테이블이 필요하므로 기존 DB를 대상으로 새 API 서버를 먼저 배포하면 안 된다. 운영 SQL 적용은 별도 승인 후 수행한다. GitHub Backend Check의 격리된 MariaDB에서는 마이그레이션 검사를 통과했다.
