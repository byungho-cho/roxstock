## 판정 계약

- 마지막 실행 결과는 시간이 지나도 유지한다. 별도 scheduleState에 KST dueAt/nextAt/허용 시간/장시간 기준/사유를 반환한다. 설정의 실제 종목 마스터 시각·주가 시각·복수 스냅샷 시각을 사용한다.
- 회차 시작 허용 10분(스케줄 tick 및 짧은 지연 허용), 장시간 기준 마스터30분 / 스냅샷10분 / 전체 주가120분. 경계까지 허용하고 초과 시 지연. 주가 정상 약42분 진행 근거와 기존 최소2시간 lease를 기준으로 120분을 사용하고 실제 작업에도 같은 제한을 적용한다. 운영 장기 관측으로 재평가할 여지는 남긴다.
- 일일 스케줄은 기존처럼 휴일에도 예정된다. 정상 stale/제외를 실패·지연으로 바꾸지 않는다. 실시간·DART는 기존 장 구간/비활성/호출 예산 정책을 유지한다.
- 동일 실행의 대상 집계와 시각을 연결한다. 잠금 충돌 요청은 본 실행 선택에서 제외하고 별도 요청 ID·사유로 표시한다. 최근 성공 시각은 별도 과거 성공 정보이며 현재 대상 집계는 resultScope.runId를 따른다.
- 사용자 설정/Z99라는 확인 가능한 원문만 EXCLUDED. IDENTITY_CHANGED/INACTIVE/LOCK_CONFLICT/UNKNOWN은 정상 제외가 아니다. STALE/NO_DATA/NOT_APPLICABLE은 별도 원래 상태를 유지한다. 제외를 success에 합산하지 않는다.
- 성공+정상 제외 또는 전체 정상 제외는 새 주가 실행을 SUCCESS로 저장한다. 과거 완료 실행은 기록 건수가 원본 집계와 일치하고 실패/원천 부족/기타 건너뜀이 없는 경우만 서버에서 동일 판정을 제공하며 originalStatus를 같이 보존한다. 실행 목록의 결과 필터는 보존된 원본 상태를 기준으로 한다. 이력 삭제·소급 DB 변경은 없다.

잠금 충돌은 예정 회차 완료로 기록하지 않고 5분 간격으로 재확인한다. 실제 전체 원천 실패의 1회 재시도 정책은 유지한다.

## 종료·잠금 복구

주가 작업 중 소유권을 확인하고 lease를 갱신한다. 원천 응답 후에도 다시 확인해 소유권 상실 응답을 저장하지 않는다. 다른 소유자 잠금 해제는 금지한다. SIGTERM 시 주가에 종료 요청을 전달하고 tick·보완 작업 종료를 기다린 뒤 DB 연결을 닫는다. 운영 compose의 collector 종료 유예는60초로 늘린다. Docker 강제 종료/OS kill은 여전히 가능하다.

다음 주가 lease 획득에서 기존 행을 FOR UPDATE 잠근다. 유효 lease는 탈취하지 않는다. 만료 lease의 원래 owner가 확인된 RUNNING 실행만 FAILED/COLLECTOR_LEASE_EXPIRED로 종료한다. 원본 상태·종료 없음·원본 집계·기존 metadata와 복구 시각/사유를 보존하며 실제 대상 집계를 반영한다. 이미 종료된 실행을 늦은 finishRun이 덮지 않는다. 소유자가 없거나 입증할 수 없는 과거 실행은 자동 보정하지 않으며 별도 확인 대상이다.

새 스키마 마이그레이션은 없다. 복구 코드는 아직 운영에 적용되지 않았다. 5409의 원본 상태·잠금은 이번 작업에서 변경하지 않았다. 배포 승인 이후 실제 복구와 후속 예정 회차는 별도 운영 검증이 필요하다.
