# 수집 오류 리포트

운영 백엔드가 1분마다 수집 작업·실패 항목·실시간 오류·가치지표 보완 누락을 DB에서 확인한다. 스캔 시각과 발생 식별자를 영구 저장해 재시작 후 미처리 기록을 이어서 읽으며 겹치는 조회로 같은 발생 횟수가 증가하지 않는다. 가치지표 갱신 중 데이터 변경은 시각/종목/연도/분기 순서로 이동해 누락을 줄인다. 최초 활성화는 최근 5분부터 기록하며 과거 전체 오류를 소급 생성하지 않는다.

같은 기능·코드·지표는 한 리포트로 묶는다. 최초/최근 발생, 반복 횟수, 종목·결산 연도·분기·작업 ID를 저장한다. 원천 URL, 인증키, 토큰, 응답 본문, 스택은 저장하지 않고 허용된 오류 코드와 정해진 설명만 사용한다. 적자 음수 배수, 0 분모 계산 제외, 미공시·대상 아님은 일반 수집 오류로 집계하지 않는다. 자료 부족은 경고, 요청·저장 실패는 오류로 기록한다.

수집 모니터링 목록 맨 아래에서 미해결/검토 중/해결/전체 및 한국 날짜로 조회한다. 20개씩 더보기, 상세에는 최근 발생 50개와 검토 메모가 나온다. 해결 후 새로운 발생이 있으면 다시 신규로 열린다. 해결한 리포트만 삭제할 수 있으며 삭제 시 발생 문맥도 제거하되 중복 방지용 해시와 시각은 남겨 과거 로그 때문에 다시 생기지 않게 한다. 새 오류는 별도 생성한다. 재무·거래·수집 원본은 삭제하지 않는다.

보고서는 일반 운영 DB 백업에 포함된다. 테이블 3개와 스캔 인덱스만 추가하며 기존 자료 초기화는 없다. 자동 수정이나 외부 알림 전송은 하지 않는다. 검토 후 필요한 개발 작업을 별도로 진행한다.

검증: 분리된 MariaDB에서 동시 중복 발생 4개를 1건으로 집계, 리플레이, 검토/메모/해결, 재발 열기, 해결 전 삭제 차단, 해결 후 삭제·과거 재생 차단·새 발생 재생성, 민감 원문 제외 및 날짜/상태 입력 검증. 모바일 목록/상세/검토/해결/삭제 UI 검증.
