기준: Figma 2735:2, 2806:3, 3093:2, 3106:2; 기본설계서 v0.7 24장 및 PR #69.

- 홈/종목 추가 본문 바깥 여백 16px, 펼침 홈 열 간격 8px, 본문만 스크롤·끝 여백 80px. 다른 페이지의 전체 시각 리팩터링은 별도 범위다.
- 커버 홈 목록은 최대 5행에 맞춰 높이가 줄어들고 펼침은 290px을 유지한다. 목표가 도래의 Lot별 기간·수익률 판정과 갱신 중 기존 데이터 유지를 그대로 사용한다.
- 홈 +는 보유종목 추가 전체 화면으로 이동한다. 검색/직접 입력은 전체 화면, 추가 확인은 화면 중앙 팝업이다. 뒤로가기 시 홈 스크롤을 복원한다.
- 검색 API의 계좌별 제외는 실제 관심/보유 상태를 기준으로 결과와 총건수에 함께 적용한다. 검색은 전체 시장이며 결과 개수를 6건으로 제한하지 않는다. 펼침 결과는 2열이다.
- 직접 입력은 종목명→종목코드→상장연도의 Enter 이동, IME 보호·입력 검증·실패 상태 유지·중복 요청 방지를 사용한다. 상장연도는 실행 시 올해로 시작하며 API/DB에 실제 저장한다. 기존 종목의 nullable 상장연도는 임의로 채우지 않는다.
- 관심/보유 등록과 변경의 거래 이력 제한은 폐기한다. 거래 이력+잔여수량 0은 거래, 잔여수량 양수는 보유로 자동 판정한다. 거래 없는 수동 보유는 0수량으로 보유 분류를 유지하며 매수/예수금/자산을 생성하지 않는다.
- 목록 탭과 추가 선택지에서 추천을 제거하지만 기존 RECOMMENDED 저장값·메모·거래 기록은 보존한다. 일괄 데이터 이관은 별도 개발 작업이다.
- 하단 메뉴 아이콘은 Figma의 원본 18×18 SVG를 내보내 사용한다. 원본 노드: 3107:26/31/36/41/46. 커버는 세로형, 펼침 홈/종목 추가는 가로형이다.

검증 경로: backend/tests/account-classification.integration.ts는 격리 MariaDB의 실제 Fastify/Prisma API와 기존 데이터 보존을 검사한다. frontend/tests/targets/home-v04.spec.ts와 account-classification.spec.ts는 네 크기의 배치·스크롤·상태·키보드·저장 동작을 격리 API로 확인하며 Figma 대조용 화면을 저장한다. 연결 Lot 거래 검사와 TypeScript/빌드도 유지한다.

Figma 예시 데이터는 운영 데이터나 실제 API 저장 검증을 대신하지 않는다. 종합 QA 미실시. 종목목록 전체 시각 교정 및 추천 데이터 이관은 후속 범위다.
