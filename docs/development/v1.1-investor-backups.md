# V1.1.0 투자동향·DB 백업 시험 구현

기준일 2026-10-16. 작업 브랜치 `codex/v1.1-investor-trends-backups`. 운영 기준은 V1.0.45 / `5316e99ee21d9089cbd9d9cd94f1a1fb4d688147`이며 `v1.0` 태그는 이 커밋을 유지한다. V1.1.0은 개발 버전이다. 이 문서는 운영 앱 배포 완료를 의미하지 않는다.

## 확정 범위와 보류

사용자 후속 지시에 따라 최근 3년 보충은 보류하고 **2026-10-16 이후 자료만** 수집한다. 기존 키와 공개 웹 응답으로 시험 구현하며 기존 수집기와 소스·이미지·컨테이너를 분리한다. 공급자의 제공 범위와 이용 조건이 전부 확인된 정식 공급 경로는 아니다. 인증 우회·차단 회피는 구현하지 않는다.

화면 3100은 [커버](https://www.figma.com/design/HFguP6QYb6xnO9FRsjYlc2?node-id=3883-107), [태블릿](https://www.figma.com/design/HFguP6QYb6xnO9FRsjYlc2?node-id=3888-687), [백업](https://www.figma.com/design/HFguP6QYb6xnO9FRsjYlc2?node-id=3910-76)을 기준으로 한다. Figma는 수정하지 않았고 예시 숫자·날짜는 앱 데이터로 사용하지 않았다.

실제 조회 출처: [삼성전자 종목 응답](https://m.stock.naver.com/front-api/stock/domestic/trend?code=005930), [코스피](https://m.stock.naver.com/api/index/KOSPI/trend), [코스닥](https://m.stock.naver.com/api/index/KOSDAQ/trend), [KRX API 목록](https://openapi.krx.co.kr/contents/OPP/INFO/service/OPPINFO004.cmd), [DART 소개](https://opendart.fss.or.kr/intro/main.do).

시험 시 종목 응답 최신일은 10월 15일이어서 시작일 이전 자료를 저장하지 않았다. 시장은 10월 16일 원문을 받았지만 단위 미검증으로 금액·수량에 노출하지 않았다. 금액을 수량×종가로 추정하지 않는다. 상시 저장·재표시 이용 조건, 호출 허용량, 최종 자료 시각, 시장/종목 거래소 범위의 일치 여부는 추가 확인 대상이다.

## 수집·저장

- `investor-crawler/`의 독립 Dockerfile, `infra/docker/compose.investor-crawler.yml`, 수동 전용 이미지 워크플로를 사용한다. 기존 `collector/`의 이미지·실행부를 변경하지 않는다.
- 모든 계좌의 거래 이력·관심 등록 합집합을 종목코드로 중복 제거한다. 전량 매도 종목도 포함한다. 수집 시 비활성·전체 제외·Z99 자동 제외를 준수한다. 계좌별 화면 분류는 보유 → 관심 → 거래 순이다.
- 최근 3일 재조회는 시작일 이상으로 제한하며, 3년 보충을 뜻하지 않는다. 시험 스케줄은 KST 18·21시, 요청 간 2초·동시 요청 1개다. 이는 공급자 확정 제공 시각으로 검증된 일정이 아니다.
- 별도 `investor-trends` 잠금과 소유권 검증·하트비트를 사용한다. 중단 실행은 다음 유효 소유권 확보 후 실패로 남기며, 다른 실행의 잠금을 강제 해제하지 않는다.
- 새 `investor_flow_daily` 테이블만 추가한다. 일자·대상·주체·출처·거래소 범위가 같은 자료는 upsert한다. Decimal(32,4), 실제 0과 null, 원문과 단위·확정 상태·수집 시각을 보존한다. KRX 수량 3항목 누락·순매수 불일치 응답은 기존 값을 덮어쓰지 않는다.
- 기능 범위가 불완전하면 실행을 PARTIAL로 남긴다. 시장 원문 확보를 금액 수집 성공으로 집계하지 않는다.

## API·화면

`GET /api/accounts/:accountId/investor-targets`, `GET /api/investor-trends`. 화면 진입은 저장 DB만 조회한다. 계좌·종목·날짜·기간·단위가 쿼리 키에 포함되고 요청 취소 신호를 전달한다. 재조회는 같은 조건의 캐시를 유지하며 다른 대상의 값을 임시 표시하지 않는다.

누적은 달력일·선택일 종료 기준이다. 확보한 구간 직전 0에서 출발하고 누락 영업일 이후 합계를 알 수 없으면 선을 끊는다. 주말의 무자료일은 생략한다. 현재 별도 거래소 휴장일 달력이 없어 평일 휴장과 미수집을 자동 구분하지 못한다. 따라서 휴장일에서 보수적으로 부분 자료가 될 수 있다. 3년 버튼은 조회 범위 선택일 뿐 3년 자료 보유를 의미하지 않으며 실제 확보 범위·보류를 안내한다.

커버 1열·태블릿 2열, 고정 헤더/하단 메뉴와 본문 단일 스크롤, 8px 간격을 사용한다. 예수금 → 투자동향 → 자산분석 메뉴, 더보기 마지막 설정·모니터링 동등 크기, 설정 DB 백업 메뉴를 추가한다. 수량만 가능한 종목은 거래량 선택으로 확인하며 기본 거래대금은 `—`와 미제공 사유를 표시한다. 기관 세부 주체는 공급자가 없어 임의로 생성하지 않는다.

## 백업 정책

확정 운영안: **매월 1일 04:30 KST**, `/opt/roxstock/backups/managed` 영구 디렉터리, 자동 삭제 없음, 공간 부족 시 생성 차단·오류 기록, 서버 복구 후 현재 월 1회 보충·실제 생성일 표시. 월간 고유성은 삭제 이력까지 보존해 중복 실행을 막는다.

백업 전용 scrypt 관리자 비밀번호 해시·8시간 서버 세션·동일 출처/CSRF 검증을 적용한다. 공개 계좌 API의 권한과 분리한다. SQL·인증정보·백업 파일은 Git이나 정적 경로에 넣지 않는다. 컨테이너에는 mariadb-client를 설치하며 수동 `.sql`, 자동 `.sql.gz`를 스트리밍 생성한다. 임시 파일→덤프 완료·gzip 무결성·SHA-256·동기화→완료 이름 전환 순서다. 실행 중 파일은 다운로드·삭제할 수 없다.

목록 12개 cursor, 완료 파일 스트리밍 다운로드, ID 기반 경로·일반 파일 검증, 생성/다운로드/삭제 감사 기록을 구현한다. 최신 완료 자동 백업만 `삭제 확인`을 정확히 입력해야 하며 서버가 삭제 직전 재검증한다. 수동·이전 자동은 일반 확인을 사용한다. 앱에는 복원 버튼이 없다.

운영 활성화 전 관리자 해시·0700 영구 디렉터리 권한을 준비해야 한다. 기본 `BACKUP_ENABLED=false`, `BACKUP_AUTO_ENABLED=false`로 기존 운영에 즉시 월간 덤프를 시작하지 않는다. 로컬은 백업 관리만 활성화하고 자동 스케줄은 비활성으로 시험했다.
