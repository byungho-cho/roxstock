# 튜닝 1차: 홈·종목목록

## 변경
- `GET /api/pages/home`, `GET /api/pages/stocks`: 계좌 선택/기본계좌와 화면 데이터를 한 요청에 반환. 기존 개별 API는 유지.
- 홈: 대시보드, 한 달 자산추이, 목표가, 최근 매수 5건. 거래/보유정보 한 번 조회, 오늘 차트 값은 대시보드와 공유. 부가 영역 실패는 null로 구분하고 해당 응답은 캐시에 보존하지 않는다.
- 종목목록: 기본정보, 보유수량, Lot 기준 거래요약 통합. 보유조회 결과를 분류/실현손익에 재사용.
- 프로세스별 최대 64개/10초 응답 캐시. 동시 동일 요청 병합, 실패 제거, 무효화 중 계산된 과거 결과가 캐시를 다시 채우지 못하도록 보호.
- API 쓰기 응답 후 캐시 무효화. 실시간 시세 수신 시 무효화. 별도 수집기의 직접 DB 쓰기는 최대 10초 TTL로 반영. 서버 재시작/캐시 미적중 첫 요청은 DB 조회가 필요하다. Redis/시작 전 워밍은 이번 변경에 포함하지 않음.
- HTTP 응답은 private/no-store. 계좌 선택과 KST 날짜를 캐시 키에 포함.
- 클라이언트 홈/종목목록 및 계좌 제목이 같은 통합 query를 공유. 다른 화면 API 유지. 쓰기 완료 이벤트로 통합 query 무효화.
- 최근 매수 더보기: 응답 전 기존 query 유지. 성공 시 기존 ID/순서 유지하고 새 항목만 추가. 기존 행 memo. 추가 스켈레톤 없음, 요청 중 버튼 중복 실행 방지, 실패 재시도, 계좌 전환 후 늦은 결과 반영 방지.

## 검증
- 프론트 production 빌드 통과.
- 백엔드 빌드 및 관련 21개 테스트 통과 (기존 계좌/현재 예수금/목표가/시세/차트/매수 Lot + 신규 캐시·통합 API).
- 브라우저 테스트는 커버 370×465, 태블릿 725×396, 단일 요청/탭 이동/더보기 DOM 유지/중복 방지/실패 재시도/계좌 전환을 검증한다.
- 로컬 Chromium 실행은 환경의 socket 권한 제한으로 시작 실패. 기능 assertion 실행 전 실패이며 CI의 Tuning 01 Check 결과로 별도 검증해야 한다.
- 실기기 최초 표시 1초, 운영 DB 쿼리 실행계획 및 배포 후 cold/warm 실측은 아직 미검증. 모의 데이터 테스트 시간을 운영 성능으로 해석하지 않는다.

## 반영 순서
백엔드 → 프론트. 프론트는 새 endpoint가 필요하므로 역순 배포 금지. DB migration 없음.
운영에서는 기본/선택/비활성 계좌, 매매·입출금 후 갱신, 시세 수신, 더보기 실패/계좌 전환을 확인한다.
`X-Page-Cache` HIT/MISS/COALESCED와 `Server-Timing`을 함께 기록하고, cold/warm 및 실제 화면 표시시간을 구분한다.
문제 시 프론트를 이전 커밋으로 되돌릴 수 있다. 기존 개별 API는 그대로 제공한다.
