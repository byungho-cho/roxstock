## 화면·상태·정렬

- 종목명 → 코드 → 실제 기준연도 → 정보 아이콘. 컨센서스 연도 노랑, 전년 결산 파랑. 연도 색상은 아이콘 상태와 독립적이다.
- 하단 기준/누락 안내행은 상태 툴팁으로 이동한다. 원천·자본·순이익·주식 종류/기준일/단위·누락·RIM 제한·가격 기준일·캐시 생성 시각을 유지한다.
- 정보 아이콘은 클릭·Enter/Space로 열고 재클릭·바깥 클릭·Esc로 닫는다. 상세 진입과 전파를 분리하고 viewport 8px 여백을 둔다.
- ERROR(빨강): 실제 FAILED 작업/제공처 오류. 오류가 누락보다 우선한다.
- PARTIAL(노랑): 요구 필드가 미수집·미제공·계산 근거 부족. 이들 사유를 수집 실패로 바꾸지 않는다.
- COMPLETE(녹색): 필요한 표시/계산 값이 유효하고 실제 수집 오류가 없다. EPS/BPS 비양수에 따른 PER/PBR 해당 없음은 실패나 누락으로 취급하지 않는다.
- 최초 W 내림차순, 선택 헤더 노랑 및 순번/방향 표시. 선택 순서로 다중 정렬, 방향 변경은 순위를 유지하고 해제 시 재번호화한다. 클릭 순환(내림→오름→해제)과 별도 × 버튼을 제공한다. Shift는 필요 없다.
- 서버가 Decimal 원본으로 전체 결과를 정렬한다. 결측은 양방향에서 마지막, 동률은 종목코드/id로 안정 정렬한다. 클라이언트는 표시 개수만 줄이며 서버 순서와 상세 이웃 이동을 공유한다.

## 캐시 설계

기존 가치 목록의 60초 재무 join 캐시는 조회마다 주가 조회·전체 재계산을 수행했다. 이를 DB에 저장하는 연도별 완성 projection과 작은 프로세스 메모리 캐시로 대체한다.

- `analysis_read_cache`: 연도별 목록 snapshot을 하나의 JSON 레코드로 게시한다. revision UUID의 compare-and-swap으로 늦은 생성이 새 세대를 덮지 못하게 한다.
- `analysis_revisions`: 재무/지표/주식수/수집 상태/종목 변경의 DB 트리거가 원본 변경과 같은 트랜잭션에서 전체 및 종목별 revision을 올린다. 롤백은 revision도 롤백한다. 여러 프로세스와 수동 SQL 변경도 감지한다.
- MariaDB 반복 읽기 트랜잭션은 callback의 첫 snapshot 전에 revision 행을 잠근다. 기존 수집의 명시적/자동 트랜잭션에 동일 순서를 적용하여 동시 원본 변경의 1020 충돌을 막는다. 트리거는 선행 생성한 전체 revision을 UPDATE하고 종목 revision을 갱신한다.
- 저녁 전체 가격 수집 및 해당 재시도 종료 후 저장 자료로 미리 생성한다. 장중 보유 시세 worker는 이 경로를 호출하지 않는다.
- 재무 변경은 즉시 revision으로 무효화하고 다음 조회가 변경 종목만 다시 계산하여 새 완성본을 게시한다. 이때 직전 저녁 가격 snapshot은 보존한다. 가격 변경과 재무 갱신을 혼동하지 않는다.
- 일부 가격 수집 실패는 마지막 유효 가격·가격 기준일과 ERROR 사유를 함께 보존한다. 생성/게시 실패는 이전 정상 snapshot을 유지하고 조회의 STALE 상태와 재시도를 제공한다.
- 프로세스 재시작은 영구 snapshot으로 복구한다. 캐시가 없으면 기존 저장 자료 조회로 동작하며 검색/시장 조건을 적용한다. 화면 조회는 외부 수집을 호출하지 않는다.
- 검색·시장·멀티 정렬은 같은 전체 snapshot 위에 적용한다. `priceUpdatedAt`, `metricBasis.year`, `cache.generatedAt`, `cache.priceCacheGeneratedAt`를 구분한다.
- 재무제표 상세는 종목 재무 revision과 요청 기간으로 기존 `PageCache`를 사용한다. 현재 시세 변경만으로 순수 재무 상세를 다시 생성하지 않는다.
- 마이그레이션은 캐시/변경 감지용 테이블·트리거 추가이며 원본 금융 자료의 값을 수정하지 않는다.

## 검증과 성능

프론트·백엔드 TypeScript 및 빌드/압축을 검사한다. 원천/선택·0·음수·부분 누락·상태 우선순위·Decimal 멀티 정렬·캐시 실패·동시 변경 검사는 백엔드 테스트에 포함한다.

`Value Financial Cache` CI에서 실제 MariaDB 트리거/롤백·변경 종목 갱신·재시작·다른 프로세스의 가격 세대·재무 상세 변경을 검사한다. 동일 50종목 검증 자료, 연도/검색/W 조건, 단일 요청 5회로 이전 조회 구조의 재무 캐시 MISS/HIT와 새 FALLBACK/HIT를 구분한다. `performance.json`에 각 응답시간·중앙값·최소/최대·DB SQL 횟수·캐시 상태를 기록한다. 이전 구조는 같은 선택 함수로 재현하며 운영 변경 후 측정과 혼동하지 않는다. 화면 표시 시간과 별개이다.

운영 변경 전 읽기 전용 측정은 각 API 5회다. Server-Timing의 app 중앙값은 가치분석 15.85ms(9.20~1,154.14ms), 재무자료 25.64ms(11.71~105.54ms)였다. 캐시 적중·DB 횟수는 이전 API에 노출되지 않아 미측정이다. 클라이언트/중계 지연이 포함된 전체 시간은 별도 JSON에 기록했으며 서버 시간으로 간주하지 않는다.

화면 검사는 370×465, 725×396, 430×932, 1024×768에서 연도/아이콘/툴팁 경계·정렬·검색·상세 이웃·늦은 응답을 검증하고 전후 캡처를 artifact로 첨부한다.
