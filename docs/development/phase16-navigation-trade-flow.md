# 16차: 팝업·종목 추가·거래 제세금·계좌 전환

기준일 2026-10-09. 이 문서는 같은 기능에 대한 이전 메뉴·홈 제목·종목 검색 명세를 대체한다. Figma v0.5 노드 3751:2, 3755:2, 3757:837, 3757:1118, 3757:1975, 3757:2259를 대조했다.

## 최종 동작

- 하단은 홈 / 스크롤 메뉴 / 더보기이며 높이 44px. 중앙 순서는 종목목록, 매매일지, 예수금, 자산분석, 투자금, 투자손익, 가치분석, 재무제표, 복리계획, 모니터링, 설정이다. 커버 중앙은 5.5개, 태블릿 항목은 52px 고정이다. 좌우 고정 버튼과 1px 구분선을 유지한다. 메뉴 SVG는 Figma 제공 18px 원본을 사용한다.
- 홈 제목은 현재 계좌와 전환 표시다. 계좌 팝업은 계좌명(번호) 한 줄, 현재 계좌는 우측 굵은 녹색 ‘사용 중’으로 표시한다. 기존 공통 계좌 선택 저장소와 계좌별 쿼리 키를 사용한다.
- 로컬 상태 팝업은 `usePopupHistory`/`HistoryDialog`로 같은 URL에 팝업 전용 이력을 추가한다. Back은 해당 이력만 소비하고 Router의 페이지 이동을 막는다. X/저장 등 상태 종료도 이력을 소비한다. 가치지표 상세 연결은 이력 소비를 기다린 후 이동한다.
- 적용: 홈 계좌 선택, 가치지표, 현재가, 종목 분류, 재무제표 갱신, 달력 연도/매매일지 월 선택, 예수금 기간·태블릿 입력. URL로 열리는 거래 입력·복리 폼·차트 상세·계좌 초기화는 기존 라우팅 이력을 재사용한다. 확인창·알림창은 제외한다.

## 종목 검색과 등록

로컬 DEV의 069500은 기존 ID 2592, `isActive=false`, 해당 조회 계좌에는 미등록이었다. 검색의 활성 필터와 직접 추가의 전체 종목 중복 검사가 서로 다른 결과를 만들었다. 운영 데이터를 이 작업 중 임의로 활성화하지 않는다.

종목 추가는 `includeInactive=true`로 검색하며 등록 종목을 제외하지 않는다. 서버는 기존 초성 매칭 함수를 사용하며 이름/코드 검색과 함께 작동한다. 현재 계좌의 분류·매수 이력만 결과에 적용하므로 다른 계좌 등록 때문에 추가가 막히지 않는다. IME 조합 동안 검색 제출을 억제한다.

직접 추가도 코드로 기존 종목을 확인하여 기존 ID의 등록 확인으로 전환한다. 비활성 결과는 비활성임을 명시하고 사용자가 활성화·등록을 확인했을 때만 `reactivate:true`를 전달한다. 서버는 등록/분류 변경과 활성화를 같은 트랜잭션에서 수행한다. 실패하면 활성화도 롤백한다. 거래 이력이 있는 종목의 기존 분류 변경 제한은 유지한다. 종목 마스터 수집 정책은 변경하지 않는다.

## 거래 후 제세금

신규 매수/매도 성공 응답의 `cashTransactionId`로만 연결한다. 거래 수정에는 새 확인창을 띄우지 않는다. 취소하면 저장된 거래를 유지하고 원래 흐름으로 돌아간다. 확인하면 계좌 ID와 연결 ID로 예수금 편집 화면을 열고 제세금에 포커스한다.

신규 GET `/api/accounts/:accountId/cash-transactions/:id`는 활성 계좌와 해당 계좌 소속 내역을 검증한다. 다른 계좌 ID/누락 내역은 404다. 최신 내역 조회로 대체하지 않는다. 조회 오류는 재시도를 제공한다. 제세금 저장은 기존 PATCH를 사용하며 신규 거래·예수금을 만들지 않는다. `invalidatePortfolio`로 관련 조회를 갱신한다. 원본 거래·과거 스냅샷·후속 예수금 보정 정책은 변경하지 않는다.
