# 관리자 DB 백업 범위

2026-10-29 로컬 구현. 운영 배포 전이며 DB 스키마 변경은 없다.

## 생성 및 호환성

- 수동 **전체 백업**과 **사용자 데이터 백업**은 모두 압축 SQL(`.sql.gz`)이다. 압축 스트림 검증과 SHA-256 기록 후에만 완료·다운로드를 허용한다.
- 전체 백업은 모든 테이블·루틴·이벤트·트리거를 포함한다. 월별 자동 백업도 기존처럼 전체 압축 백업이다.
- 기존 수동 `.sql`은 변환·삭제하지 않는다. 목록·다운로드·삭제를 그대로 지원하고, 파일 확장자에 맞는 응답 형식을 사용한다. 범위가 없는 과거 메타데이터는 전체 백업으로 해석한다.
- 전체와 사용자 백업은 같은 서버 잠금을 사용한다. 화면에서도 요청 중 양쪽 버튼을 잠그며, 중복 실행을 방지한다. 기존 관리자 인증·Origin·CSRF·최신 자동 백업 삭제 확인을 유지한다.

## 사용자 데이터

`backend/src/domain/backup-scope.ts`의 명시적 29개 테이블만 내보낸다. 사용자 인증·설정·보안 상태, 계좌, 매수 Lot·분할매도·요청 이력, 예수금·배당, 관심종목, 복리계획, 자산 스냅샷·투자 집계, 알림 설정·기기·발송 이력, 뉴스 스크랩과 사용자 열람 감사 기록을 포함한다. 현재 로그인한 한 사람만이 아닌 **전체 사용자** 자료다.

종목 마스터·시세·투자동향·재무제표·가치지표·컨센서스·뉴스 원문·수집 작업·공용 재무 편집 감사 기록은 제외한다. 사용자 백업에서 루틴·이벤트·트리거를 내보내지 않는다. 클라이언트가 임의의 테이블을 지정할 수 없다.

## 복원 기준

사용자 백업은 독립적인 전체 시스템 복구본이 아니다. 같은 스키마와 동일 식별자의 `securities`, `stock_news_items` 공용 자료가 이미 있는 별도 대상에 복원한다. 공용 자료 없이 외래키 검사만 끄고 서비스에 투입하면 안 된다. 구조·공용 자료까지 복구해야 하면 전체 백업을 사용한다.

실제 복원 전 최신 대상 DB와 해당 범위의 기존 자료를 추가 백업하고 쓰기·자동 작업을 멈춘다. 먼저 격리된 DB에서 압축 및 체크섬, 테이블 범위, 행 수, Lot·분할매도와 기타 참조 관계를 확인한다. 복원으로 계정·세션·기기 상태도 되돌아갈 수 있으므로 운영 전 인증 및 알림 연결 상태를 확인한다. 관리자 백업 화면에 자동 복원 기능을 추가한 것은 아니다.

## 로컬 검증

- 백업 범위·요청 검증·압축·기존 비압축 파일·잠금·관리자 인증 관련 11개 테스트.
- 휴대폰 370×465·태블릿 725×396에서 두 버튼 순서/동일 폭, 요청 범위, 중복 요청 차단, 실패 시 목록 보존 4개 브라우저 테스트.
- 운영을 복제한 로컬 DB로 실제 생성: 전체 76테이블 약 76MiB, 사용자 29테이블 약 151KiB. 개인정보와 원본 SQL은 비공개 위치에만 보존한다.
- 사용자 백업을 임시 DB에 복원하고 29테이블 건수 및 외래키 27개를 대조했다. 공용 의존성은 종목과 뉴스 식별자이며 원천 재무·가치·시세 자료는 사용자 덤프에 없음을 확인했다. 검증용 DB는 제거했다.
- 타입 검사·프런트 빌드 통과. 이 검증으로 운영 백업을 생성하거나 운영 DB를 변경하지 않았다.
