# 복리계획·종목목록 빈 프레임 표시 · 2026-10-15

## 적용
예수금·투자금·투자손익의 후속 로컬 작업이다. 아직 병합·운영 배포하지 않았다.

종목목록은 최초 코드 다운로드부터 검색·분류 탭·정렬·카드/표 제목을 표시한다. 종목명·금액·건수·표 데이터 행은 응답 전 비워두며 기존 카드/행 높이는 유지한다. 스켈레톤과 공통 회전 표시는 제거한다. 실제0·정상 빈 결과·조회 실패는 응답 완료 후 기존 기준으로 구분한다. 검색·초성·정렬·즐겨찾기·상세 연결과 계좌별 메모리는 유지한다. 같은 조건 재조회 시 기존 데이터를 표시하고 다른 계좌 값이 섞이지 않도록 기존 query 키를 유지한다.

복리계획은 계좌와 계획 기본 데이터 도착 전에도 현재 자산·목표·진행률 카드 틀을 먼저 표시한다. 목표 상세의 초기 차트는 축과 범례만 표시하며 임의 수치·연도·계획명·건수를 만들지 않는다. 기본 계획 조회 뒤 현재 자산을 별도로 계산하는 순서는 유지한다. 기본 자료가 도착한 부분부터 표시하고, 계산 대기 중 현재 자산·진행률·차이 금액·미수집 연도 금액은 빈 상태로 유지한다. 기본값/계산식/과거 스냅샷/계좌 분리/정기 재조회 정책은 변경하지 않는다. 입력 코드 대기도 빈 영역을 사용한다. 오류·재시도는 프레임 내부에서 접근할 수 있다.

## 검증
프론트 타입 검사·생산 빌드 통과. 신규6건을 포함한 계획/목표/종목 기존 기능45건과 기존 종목목록 로딩 회귀6건이 통과했다. 커버 전용 종목 상세 열 검사는 기존 정책에 따라1건 제외했다. 최종 프레임 핵심6건 재실행도 통과했다. 커버370×465·태블릿725×396과 일부 기존 목표 검사의 자체 화면 크기를 사용했다.

코드 및 계좌 응답 지연, 부분 자산 응답, 스켈레톤/회전 표시0, 응답 전0원·0건/빈 결과 오표시 방지, 코드 다운로드 중 검색/탭 유지, 카드 높이 유지, 조회 실패·재시도, 계획 편집·목표·연간 금액·강조·계좌 분리·기존 금액 계산을 확인했다. 실제 DEV에서도 두 화면의 최초 코드 다운로드 및 API 반영 전후 스켈레톤0·회전표시0을 확인했다. 실제 데이터 확인은 읽기만 수행했다.

구 회귀 검사 중 현재 메뉴에 없는 모니터링 버튼 기대와 별도 이전 연도 펼침 기대를 기존 main의 설정 메뉴·이미 조회된 거래 연도 확인으로 현행화했다. 앱 내 메뉴/거래 조회 동작은 변경하지 않았다. 기존 compound-goal 검사는 자체적으로370·725 화면을 전환하거나370을 전제로 하므로 태블릿 프로젝트의 단순 중복 실행은 제외하고 원래 실행 조건을 유지했다. 별도 신규/compound-v04 검사는 커버·태블릿에서 실행했다.

캡처는 모의 API 기준(docs/qa/assets/compound-stocks-empty). 운영 화면과 실기기 모바일 검증은 미수행이다.

최초 종목목록 태블릿 표의 부모 높이와 요약 여백을 실제 페이지와 통일했다. 코드 다운로드→계좌/API 대기 전환 전후 커버 카드/태블릿 표의 bounding box 동일을2건 재검증했다. 최신 빌드 통과.
