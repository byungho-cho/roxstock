## 자산분석 계산과 데이터 계약

기간은 실제 선택 범위 안에서 첫/마지막 일별 계좌 스냅샷이다. 표시는 실제 snapshotDate, 원장 집계 구간은 해당 값이 기록된 `first.updatedAt < cashTransaction.createdAt <= last.updatedAt`이다. 입출금과 세부 손익에 동일한 구간을 사용한다. 기존 기간 투자손익=(종료자산−시작자산)−순입출금 규칙 유지.

평가손익은 기간말 포지션 평가손익−기간초 포지션 평가손익. 위치 스냅샷 시장가 합계가 계좌 스냅샷 주식액과 일치해야 유효하다. 실현손익은 구간 원장에 연결된 매도 원본의 `(매도가−원본 매수가)×매도량`이며 수수료 제외 값이다. 배당은 연결 배당의 세전액, 비용은 매수·매도 저장 수수료/세금 및 배당 세전−세후를 합산한다. 원본 연결 누락은 계산 불가(null)이며 0으로 만들지 않는다.

세부 합계와 기간 투자손익의 차이 `reconciliationDifference`를 보고한다. 잔액 직접 교정, 과거 거래 수정/삭제, 불완전한 위치 이력 등이 영향을 줄 수 있다. 차이를 특정 원인으로 단정하거나 합계를 강제로 맞추지 않는다. 정상 빈 결과, 로딩, 오류·재시도, null 계산 불가를 분리한다.

복리계획은 선택 계좌의 활성 계획 중 displayOrder/id 첫 계획, 보이는 목표 중 기본 목표 우선이다. 현재 계좌 총자산을 계획 기초 자산으로 바꾸지 않는다. `계획 기준 자산`은 저장 initialAssetValue, 올해 목표는 계획 시작 연도부터 연복리 후 연말 annualContributionAmount를 납입하는 기준이다. 계획/목표가 없거나 계획 기간 밖이면 없음/계산 불가로 표시한다.

## 검사 범위

새 기능 브라우저 검사는 cover 370 한 프로젝트만 수행한다. 기존 CI의 자동 기능 검사는 그대로 두며, 별도의 전체 회귀/다중 뷰포트 시각 QA를 추가하지 않는다. API 실데이터 연동은 disposable MariaDB의 Fastify/Prisma 통합 검사에서 스냅샷·원장·계획 조인, 기초 제외, 누락·단일 스냅샷을 확인한다. 기능 검사, TypeScript, 빌드는 분리한다.

별도 디자인 교정본 링크는 이번 요청에 제공되지 않았다. Figma v0.4 기존 FINAL과 사용자가 명시한 교정값(헤더 왼쪽0, 추이 높이1.5배, 날짜 중앙/화살표)을 적용했다.
