## 집계 계약과 남은 확인

- 기존 `/accounts/:id/trades`는 매도 수량 × (매도가 − 연결된 매수 건의 매수가)로 실현 매매손익을 계산한다. 수수료·세금 및 미실현 평가손익은 포함하지 않는다. 거래 수정·삭제 시 현재 거래 기록을 다시 집계하며 과거 스냅샷을 수정하지 않는 기존 규칙을 유지한다.
- 매도분 원가 = API 매도금액 − API 실현손익. 연도별 투자금 및 모든 손익률의 분모는 해당 집계 범위의 매도분 원가 합계다. 매수총액은 별도 표시하며 미매도 원가를 실현손익률 분모에 혼합하지 않는다. 원가가 0 이하 또는 미수집이면 수익률은 `—`다.
- 배당은 현금 거래의 연결 배당 `netAmount`(세후)만 사용한다. grossAmount, 현금잔액, 입출금, 평가손익을 합산하지 않는다.
- 누적 투자손익·연도별 목록·종목별 목록·연도별 상세 합계 = 실현 매매손익 + 세후 배당. 동일 불변 조회 결과에서 집계해 누적값 = 연도 합계 = 종목 합계가 성립한다. 상세에서 매매손익과 배당 및 배당포함 합계를 분리한다. 수익률은 합계 금액/합계 원가로 계산하며 개별 수익률을 더하지 않는다.
- Figma 예시 누적 184,600,000원과 연도별 합계 275,700,000원의 차이는 운영 산식으로 복제하지 않는다. **기획 확인 사항:** 실현손익 화면과 자산분석의 평가손익 범위 차이, 누적·목록의 배당 포함 정책, 연도별 투자금의 매도 원가 정의, 수수료·세금 제외 정책. 이번 구현은 위의 일관된 계약을 적용하며 디자인 확정이 계산 정책 승인 또는 실기기 검증을 의미하지 않는다.
- Decimal(19,4) 수량×단가 결과의 8자리 소수까지 BigInt로 유지한다. 원 표시만 반올림하고 손실에는 ASCII 음수 부호를 표시한다.

## 조회와 화면

거래 API 전체 결과와 DIVIDEND 현금 내역을 100건씩 끝까지 읽는다. 조회 제한 13건을 두지 않는다. 페이지 건수 변경·중복 및 재검증 중 거래 변경은 오류로 처리한다. 계좌별 AbortSignal/Query 캐시를 사용하고 목록·상세 선택은 동일 결과에서 파생한다. 갱신 중 및 실패 시 마지막 성공 내용을 보존하고 실패 안내·재시도를 제공한다. 새 계좌에 이전 계좌 결과를 placeholder로 넘기지 않는다.

연도별·종목별 탭, 손실 포함 전체 종목 목록 및 실제 건수, 커버 상세 이동/뒤로가기 목록 위치 복원, 2010~현재 연도 순환, 종목 이전·다음 순환을 구현한다. 종목별 목록에는 연도 선택·스와이프가 없다. 태블릿 좌우 독립 스크롤/선택 동기화 및 우측 빈 상태 카드만 표시하는 규칙을 적용한다.
