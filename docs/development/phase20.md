# 20차 구현

- `DelayedSkeleton`이 MUI 크기·sx·표시 공간을 보존하고 표시만 200ms 늦춘다. 타이머는 unmount 시 취소한다. API/렌더링/콘텐츠 표시 시간은 변경하지 않는다. 모든 기존 스켈레톤 사용처가 이 공통 컴포넌트를 사용한다. 코드 Suspense 역시 동일 기준을 사용한다.
- `MorePage`, `SettingsPage`만 정적 import. 더보기의 가벼운 `SettingsOverview`를 `MoreScreens`에서 분리해 계좌 편집·제세금·수집 상세가 초기 메뉴에 끌려오지 않도록 한다. 상세 Suspense는 패널 내부에 남는다.
- 매수 폼의 기존 `allBuyLots(accountId, securityId)` 조회를 재사용하며 `remainingOnly=false` 및 AbortSignal을 전달한다. 서버는 accountId/securityId로 필터링한다. `latestBuy`는 일시와 정확한 BIGINT ID로 직전 기록을 선택하며 API 반환 배열을 변형하지 않는다.
- 계좌·유형·종목·거래 변경 시 폼 key가 바뀌어 입력/초기화 플래그를 격리한다. 입력 변경·포인터·키보드 조작 후에는 늦은 자동 입력과 포커스를 실행하지 않는다. 수정에는 초기값·포커스 규칙을 적용하지 않는다.
- 태블릿 팝업의 배경 종목 탭 동기화는 실제 화면 경로와 배경 경로가 같을 때만 실행한다. 팝업을 배경 탭 URL로 덮어 닫지 않게 한다.
- 가치분석의 성공 데이터 보존은 동일 계좌에 한정한다. 계좌가 바뀌면 이전 계좌의 retained list/detail을 사용할 수 없다.
- DB 스키마·백엔드·계산식·자동 수집 스케줄 변경 없음. PR 필수 검사 후 자동 병합하고 기존 운영 배포 경로 사용. 운영 배포 완료 대기는 기존 사용자 지시에 따라 별도 상태로 보고한다.

검사: `npm run typecheck:frontend`, `npm run build:frontend`, `node --import tsx --test frontend/tests/unit/phase20.test.ts`, `npm exec --workspace frontend -- playwright test --config playwright.phase20.config.ts`.

홈 후속: DashboardPage가 기존 history query 데이터를 직접 읽고, 신규 API 없이 차트의 summary 의존을 제거한다. HomeListCard stable 옵션은 홈의 290px/5행 공간만 고정한다. AssetSummaryCards loading 옵션은 홈만 활성화한다. 상세 페이지의 기본 옵션과 계산 로직은 유지한다. 지역 재시도는 해당 query의 refetch를 사용한다.

## 후속: 화면별 부분 로딩 확대 (2026-10-11)

기준 main `458e17de3d1b41df6336518c1bbf66fb0ffb9b2c` (#189). 열린 20차 구현 PR은 없었으며 #188·#189의 입력·홈 개선을 보존한다. 아래 기준이 이전의 '홈만 활성화 / 다른 화면 확대 보류'를 대체한다.

- 매매일지: 계좌 확인 전에도 302px 달력/42셀(6주×44px), 월 이동·오늘·선택 날짜·거래현황을 렌더한다. 거래 칩/금액/건수만 지연 표시한다. 매수/매도 구분과 실제 거래의 3열·다중행 형태를 유지한 목록 로딩을 사용한다. 조회 전 날짜 접근성 이름에 0건을 확정하지 않는다.
- 계좌 관리: `AccountManagement`를 가벼운 별도 모듈로 분리한다. 계좌 추가·고정 안내는 즉시 표시하고 추가 버튼은 목록 위에 고정한다. 카드 내부 두 줄(제목/편집, 갱신/금액)에 맞춘 61px 기본 행을 사용한다. 계좌 편집/삭제/초기화 코드의 동적 로딩은 유지한다. 캐시가 있는 조회 실패에서도 기존 계좌 카드를 유지한다.
- 종목목록: 계좌 대기에도 제목·추가·탭·검색·정렬을 렌더한다. 조회 전 총 0개/합계 0원을 표시하지 않는다. 커버는 기존 유형별 139/112/148px 카드 내부 필드, 태블릿은 실제 28px 행의 컬럼별 표시기를 사용한다. 조회 실패 후에는 확정 빈 목록/시세 정상 배지를 표시하지 않는다.
- 자산분석: 총자산·비율·구성·기간 성과 값만 대기 표시한다. 성과의 11개 고정 레이블과 구분선을 유지한다. 차트 224px/성과 영역 270px를 유지하며 지역 오류/재시도는 배치를 늘리지 않는다. 계좌 조회 실패도 고정 카드 구조를 보존한다. 같은 조회의 캐시를 유지하고 새 계좌/기간은 해당 query key의 데이터만 사용한다.
- 평가자산: 이미 있던 공통 요약 카드의 `loading` 옵션을 재사용하고 성과의 고정 레이블·자산구성 틀을 표시한다. 3행 보유 목록은 공통 행 표시기의 `rowCount=3`을 사용한다. 홈의 기본 5행과 조회 순서는 그대로다.
- 예수금: 변경내역의 60px 단일 박스를 기존 4컬럼/24px 행의 로딩으로 교체한다. 잔액 정책·편집·수집·원본 데이터는 변경하지 않는다.
- 코드 대기: `PriorityRouteShell`은 매매일지/자산분석/종목목록의 가벼운 구조·컨트롤을 표시한다. 종목 탭·검색·정렬·로딩 행을 실제 페이지와 공유하고 페이지 메모리를 보존한다. 화면 모듈의 lazy 로딩과 코드 오류 재시도는 유지한다. 다른 경로의 범용 큰 박스는 작은 지연 아이콘으로 교체한다.
- 모든 표시기는 기존 `DelayedSkeleton`의 200ms 규칙을 재사용한다. API 응답/콘텐츠 표시를 늦추거나 최소 대기 시간을 추가하지 않는다. 신규 API·조회 주기·캐시 무효화·계산식·DB/수집 변경 없음.

검증/전후 캡처: [화면별 QA](../qa/phase20-screens.md). 변경된 계좌 모듈 경계에 맞춰 기존 '설정 편집 코드 지연' 검사도 갱신한다. 명세상 일반 입력의 포커스/히스토리 동작은 그대로 유지한다. 이번 요청은 운영 배포 완료를 확인해 보고하는 범위다.

종목 검색·정렬은 첫 계좌가 확인되기 전에 입력한 조건을 해당 history entry의 최초 계좌에 한 번만 이어받는다 (`usePageMemory`의 opt-in `adoptInitialAccount`). 이후 다른 계좌는 자체 저장 조건을 사용한다. 표시 데이터 query key/요청 취소/캐시는 변경하지 않는다. 코드 대기 및 계좌 대기를 동시에 보류하는 회귀 검사로 이 전환을 검증한다.

코드/계좌 전환 경계에서 열린 정렬 메뉴도 같은 페이지 메모리를 사용한다. 입력 이벤트는 컴포넌트가 교체되기 전에 동기 저장하며, 이미 첫 계좌로 전환된 경우 그 최초 소유자에게만 전달한다. 이 opt-in 경로의 UI 메모리 알림은 API 캐시·계좌 데이터와 분리되어 추가 조회를 발생시키지 않는다.

자산분석 기간 선택에도 최초 계좌 조건 인계를 적용한다. 계좌 조회 대기 중 선택한 기간이 첫 계좌 도착으로 초기화되지 않으며 계좌별 저장 조건은 분리한다.
