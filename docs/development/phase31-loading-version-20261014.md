# 31차 로딩·조회와 버전 · V 1.0.31

기준 main `4b850e5fd4080afa01fd98dd903c728f1a3a827f` (PR #220 포함). 작업 [PR #221](https://github.com/byungho-cho/roxstock/pull/221). 30차 및 가치·재무자료 선택/계산/서버 캐시를 수정하지 않는다.

## 구현

- 매매일지 달력 42칸·날짜·공휴일·선택은 거래 응답과 독립적으로 표시한다. 날짜별 스켈레톤만 제거하며 손익/거래 상세의 대기는 유지한다.
- 월의 첫날~마지막날을 먼저 조회한다. 월 데이터 반영 후 50ms 타이머로 paint 기회를 양보한 뒤 해당 연도 1.1~12.31을 조회한다. 월 요청은 fetch high, 연도는 low이며 묶음 조회를 우회하여 Lot 요청이 월 표시를 막지 않는다. 브라우저 priority는 힌트이고, 실제 순서는 월 성공 후 연도 enabled로 보장한다.
- 계좌/월과 계좌/연도의 Query 키는 `journalTrades` prefix를 공유한다. 유효한 연도 캐시에서 새 월을 즉시 구성한다. 같은 연도 observer는 진행 중 요청을 공유한다. 월/계좌 변경 시 연도 요청을 취소하고 새 월에 우선권을 준다. AbortSignal과 서로 다른 키가 늦은 응답 혼입을 막는다.
- 거래 등록/수정/삭제·계좌 초기화는 기존 invalidatePortfolio를 재사용하여 월/연도 모두 stale로 만든다. 무효화된 연도는 새 월의 initialData로 사용하지 않는다. 미수신 월은 빈 결과/0원으로 확정하지 않는다. 월 밖 인접 날짜는 미수신으로 표시하고 선택 시 해당 월을 조회한다.
- 메모리 Query 캐시 유지 30분. 로컬 영구 저장은 조건부 요구이므로 추가하지 않는다. 재진입 및 연도 캐시 월 이동의 추가 거래 요청 0건을 CI에서 검증한다. 앱 종료 후 재시작은 API 조회한다.
- 자산분석 추이 224px, 투자금 추이 188px, 자산구성 막대의 고정 영역은 작은 상태 문구로 대기한다. 기존 카드/제목/기간 버튼과 나머지 스켈레톤을 보존한다. 같은 Query의 재조회는 기존 차트를 유지하고 다른 계좌/기간은 그 조건의 Query만 표시한다.

## 버전·배포

단일 원본 `backend/src/release.json`. 프론트는 빌드 fallback으로 같은 파일을 읽고, 메뉴 진입/포커스/60초마다 `GET /api/version`을 no-store로 확인한다. 서버 응답도 Cache-Control:no-store. 따라서 백엔드만 배포해도 기존 프론트에 새 버전이 전달된다. 메뉴 헤더 action 위치에 11px 회색·우측 정렬로 표시하고 44px 헤더는 유지한다. 프론트 Docker 빌드에도 공통 JSON을 복사한다.

새 코드 배포는 작업 브랜치에서 `npm run release:bump`를 한 번 실행한다. 이번 초기 도입은 1.0.31이며 다음은 1.0.32이다. 여러 변경의 일괄 배포는 한 번, 같은 SHA/버전 재시도와 문서만 변경한 경우는 증가시키지 않는다. PR Validation은 기준 main의 버전과 코드 변경 범위를 비교하여 정확한 1 증가를 검사한다. 백엔드 단독 변경도 검사 대상이다.

main 직접 push 없이 필수 CI → PR 병합 → 기존 PR Auto Merge의 Production Deploy dispatch 경로를 사용한다. 배포 완료/운영 확인은 생략한다. 네이티브·내장 자산 변경이 없어 APK 재빌드는 필요 없다.
