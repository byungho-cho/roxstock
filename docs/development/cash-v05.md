# 예수금 v0.5 · 2026.10.08

최신 main `19e9f47`에서 구현을 대조했다. Figma `HFguP6QYb6xnO9FRsjYlc2`의 커버 158:2, 태블릿 740:4와 최신 명세 3674:2 / 3674:331 및 각 FINAL 목록·매수·매도 수정 프레임을 확인했다. v0.4의 동일 항목과 충돌할 때 이 문서를 우선한다.

## 화면과 금액 입력

- 변경내역은 구분 / 날짜·시간(KST) / 제세금 / 잔액(세후) 네 열이다. 제목과 숫자의 오른쪽 기준선을 공유하며 모든 유형의 과거 내역을 선택·편집할 수 있다.
- 삭제는 조회 기간과 무관한 `cash-overview.recentTransactions[0]`로 판정한다. 계좌 전체 `createdAt DESC, id DESC`의 최신 1건만 활성화하며 실패 상태에서는 활성화하지 않는다. API는 동일 조건을 Serializable 트랜잭션 안에서 재검증한다. 기존 공통 빨간 삭제 버튼과 비활성 상태를 재사용한다.
- 매수·매도 수정의 세전예수금은 최초 저장된 세후 잔액 `balanceAfter` + 제세금 `feeTaxAmount`로 시작하며 직접 수정할 수 있다. 세전을 바꾸면 세후·제세금을 빈 문자열로 초기화한다. 세후 또는 제세금 입력 이벤트에서만 상대 항목을 계산한다. 순환 effect를 사용하지 않으며 Decimal 문자열 연산으로 소수 오차를 방지한다.
- 변경한 잔액은 **선택한 내역에 명시적으로 입력한 세후 잔액**만 저장한다. 연결된 BuyTrade / SellTrade / Lot, 계좌 현재 잔액 및 다른 내역·스냅샷은 수정하지 않는다. 일반 입출금·배당 수정에서도 저장된 잔액을 자동 보정하지 않는다. 삭제 역시 계좌/과거 잔액을 재계산하지 않는다. 최초 입출금·배당 등록의 기존 계좌 반영 규칙은 유지한다.
- 커버의 일반 입력 화면과 태블릿 중앙 팝업을 유지한다. Small 입력을 재사용하며 취소 / 저장과 삭제를 제공한다. 긴 팝업 본문은 스크롤되고 하단 동작 버튼은 유지한다.

## 조회 API

- PATCH `/cash-transactions/:id`: 모든 유형 수정. `feeTaxAmount`는 선택적인 부호 있는 Decimal 문자열이고 `balanceAfter`는 0 이상 Decimal 문자열이다. 기존 음수 제세금도 그대로 편집·저장할 수 있으며 세후가 세전보다 큰 경우 계산된 음수 제세금을 임의로 0으로 보정하지 않는다. 생략한 잔액은 유지한다. `cashBalanceAdjusted:false`를 반환한다.
- DELETE `/cash-transactions/:id`: 계좌 전체 최신 1건만 허용한다. 구버전의 현재 잔액 역산 보정은 제거했으며 `cashBalanceAdjusted:false`를 반환한다.
- GET `/accounts/:id/cash-overview`: 기존 월·연 요약 및 전체 계좌 최신 내역을 유지한다. `currentYearTax:{year,amount}`는 **현재 KST 연도 1월 1일~조회 시점**을 집계하므로 목록의 선택 월·연과 독립적이다. 배당은 저장된 gross/net 차액을 사용해 구버전의 `feeTaxAmount=0` 내역도 포함하고 중복 합산하지 않는다. 최초 배당 등록과 편집은 feeTaxAmount에도 차액을 저장한다. 운영 데이터 백필이나 스키마 변경은 없다.
- 현재예수금 카드의 올해 제세금과 계좌 기준은 동일 10px / 15px 줄 높이로 나란히 표시한다. 올해 제세금 전체는 공통 파란색이다. 계좌 전환·등록·수정·삭제 때 기존 portfolio 캐시 무효화로 갱신한다. 조회 실패는 0원으로 대체하지 않는다.
- 추이는 기존 `/accounts/:id/asset-history?from&to`의 저장된 일별 `cashBalance`를 공통 `SnapshotChart`에 연결한다. X·Y 금액축·가이드·터치 드래그·마우스 툴팁을 재사용한다. 상세보기는 없다. 누락 잔액과 날짜 공백은 선을 끊고 0으로 채우지 않는다. 고립된 유효 스냅샷도 점으로 표시한다. 빈 결과 / 잔액 미수집 / 조회 실패를 구분한다. 거래별 즉시 추이가 아닌 저장된 일별 스냅샷 기준이다.

## 검증

- 프론트 TypeScript / 빌드, 백엔드 TypeScript / 빌드 및 전체 백엔드 테스트.
- `playwright.cash-v05.config.ts`: 기존 예수금 회귀 + v0.5 검사, 커버 370×465 / 태블릿 725×396 / 데스크톱 1280×800. 과거 5개 유형 편집, 기간 밖 최신 내역 삭제 제한, 금액 초기화·상호 계산·저장 payload, 제세금 갱신·계좌 전환, 차트 축·누락·터치 툴팁·빈/오류 상태, 스크롤·입력 포커스·Enter·등록·최신 삭제·팝업을 검사한다.
- 백엔드 route 검사는 실제 Fastify 요청 경로를 사용하며 저장소 대역으로 모든 유형의 수정·삭제 및 현재/과거 잔액과 원본 거래 미변경, 기간 없는 최신 정렬 조건, 입력 검증과 올해 집계의 계좌·KST 경계를 확인한다.
- Figma의 숫자는 구현에 고정하지 않는다. API 모드에서 목 데이터로 fallback하지 않는다. 배포 후 실제 서버의 읽기 API·화면과 배포 커밋을 별도로 확인한다. 서버 데이터의 쓰기 시나리오는 테스트 대역 검증과 구분하며 실기기 QA는 포함하지 않는다.

기존 메인 로딩바의 QueryCache 구독이 render 중 상태 변경을 알리던 경고도 구독 알림을 microtask에 모아 해소했다. 금액 계산 상태에는 effect를 추가하지 않았다.
