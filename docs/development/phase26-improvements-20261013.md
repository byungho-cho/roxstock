## 항목별 구현

1. 예수금: 수정 내역 로딩/폼 준비 후 세후예수금을 한 번 포커스하고 전체 선택. 거래 수정은 해당 세후 입력, 기타 내역 수정은 별도 세후 필드를 사용한다. refetch·재렌더링·팝업 전환 onEntered가 이미 선택한 입력을 다시 뺏지 않도록 entry guard를 둔다. 새 입출금/배당 입력의 기존 필드·Enter/한글 조합/중복 저장 정책은 유지한다.
2. 보유 요약: 평균단가 주식수·평가손익률을 64px 가운데 열에 가운데 정렬하고 거래 요약과 동일 grid 축으로 맞춘다. 보유 평가손익률은 현재 보유 매입금액으로 계산하고 0/불명확 분모는 —. 좌 항목명·우 금액은 유지한다.
3. 평가금액은 보유 평가손익 부호, 매도총액은 Lot 연결 매매손익 부호로 색상 판단. 총 매수금과 총 매도금의 단순 차이는 사용하지 않는다. 이익 적색·손실 청색·0 흰색 유지.
4. 종목 연도별 손익: 기존 버그는 summary가 account 전체 years를 렌더하고 상세 링크에 종목 조건이 없었던 것. `GET /accounts/:id/investment-profit?securityId=...`가 기존 계좌/버전/원본 집계를 재사용하되 응답 events를 해당 종목으로 제한하고 scope를 반환한다. 계좌 snapshot 투자금은 종목 투자금으로 둔갑시키지 않고 scope 응답 capital은 비운다. 프런트 응답 scope 검증 및 계좌·연도·종목별 cache key, 원본 무효화·취소 신호를 유지한다. 연도 목록/상세는 매수 Lot 연결 실현손익과 연결된 배당만 사용한다. 종목 연간 상세는 기존 종목 손익 분모인 매수총액을 명시하여 표시하고, 계좌 전체 투자금은 섞지 않는다.
5. 홈: 보유→최근 매수→목표가 도래 순서. 태블릿도 대응 영역을 교체. 커버 목표0건 확정 빈 상태만290→98px(33.8%), 제목/0건/안내/갱신 표시 유지. 정상 활성·판정불가0건만 축소하며, 시세 기준일이 없는 실제0건은 API 계산시각을 갱신시각으로 사용한다. 로딩·오류는 빈 결과로 표시하지 않는다. 유효한 기존0건을 background refetch 때 유지한다. 내용 있을 때 커버 높이는 자연스럽게 늘며 태블릿290px 유지.
6. 홈 및 종목목록 보유 진입에 `detailTab=summary`를 명시하여 과거 탭 기억보다 우선. 요약 카드 py8px.
7. 재무제표: 제목 한 줄+정보 아이콘 클릭형 Popover, 기존 전체 설명 유지하고 단위 백만원은 우측에 별도 표시. 터치/클릭/키보드, 밖 클릭·Esc·viewport 경계 처리. 기존 전역 자료 안내도 유지한다.
8. 가치분석: 목록은 연간 공시만 읽어 반기 공시에 연결된 보통주 수를 누락했다. 표시 주식수 조회에는 중간 공시를 포함하되 연간 지표/총액 선택은 그대로 연간·추정 기준만 사용한다. 상세에도 검증된 동일 기준 RIM 총액/근거·미제공 이유를 추가한다. 기간별 원천이 검증된 OPEN_DART 경로는 기존 엄격한 기간·접수·연결/별도·귀속·분모/BPS 대조를 유지한다. 같은 제공처의 2026E 지배주주자본과 연간 ROE는 원천값/연도/CFS/소유주 귀속이 일치할 때만 총액 계산을 허용한다. 총액에 불필요한 주식수 때문에 총액까지 차단하던 제한을 분리하되, 미검증 수정 분모를 추론하거나 표시 주식수로 대체하지 않는다. RIM 자체에 필요한 근거가 불충분하면 총액도 null. 계산은 local Decimal60 정밀도, 0·음수·소수 원 보존. 기존 적정주가 계산 함수/가격은 변경하지 않는다. 2025 총자본은 기준일·출처가 있는 참고 결산 카드로 분리하고, 실제 2026E RIM 카드에는 검증된 지배주주자본과 같은 연간 ROE를 함께 표시한다.
9. W0.7~1.0: 목록/상세 모두 구분선 다음4px, 라벨 전체 공통 노란색, 4개 동일 너비·기존 가격 유지.

## SK하이닉스 근거

운영 저장 데이터의 조회 API를 읽었으며 운영 DB에 직접 접속하거나 값/출처를 수정하지 않았다. [근거 JSON](evidence/phase26-sk-source-20261013.json)에 실제 응답에서 필요한 값·기간·원천을 기록했다. source→DB 연결은 API가 제공하는 저장 provenance·collectedAt로 대조했으며 제공처 원문 재수집과 직접 DB dump는 하지 않았다.

- 2026E EPS351,909.16원·BPS526,869.36원·ROE102.88%, NAVER_FNGUIDE_ANNUAL의 연간 추정·CFS·지배주주 기준. 기존 W0.8 가격5,525,805.84768원.
- 표시 가능한 별도 보통주 공시: 2026-06-30 반기, 접수20260814003509, 발행712,702,365 / 자기1,626,865 / 유통711,075,500주, 저장2026-10-09. 상세는 이미 이 값을 표시했지만 목록의 ANNUAL 필터가 이 공시를 누락했다.
- 재무제표 저장2026E 지배주주자본373,868,000,000,000원, 자본총계375,006,843,000,000원. 총액은 지배주주자본만 쓰고 총자본/이전2025 자본120,666,751,000,000원으로 대체하지 않는다.
- 동일 원천 저장값·기간·귀속 검증 후 초과이익 =373,868,000,000,000×(1.0288−0.08)=354,725,958,400,000원; 주주가치 =373,868,000,000,000+354,725,958,400,000×0.8÷0.08=3,921,127,584,000,000원. 실제 원천 입력의 unit/domain 회귀로 검증하며 코딩에 상수로 박지 않는다.
- 수정 기말 BPS 분모는 저장되어 있지 않아 주당 환산/기존 W0.8 대조는 null+구체적 이유. 반기 유통711,075,500주로 나누면 BPS525,778.204986…로 저장526,869.36과 다르므로 그 분모를 사용하지 않는다. 자본÷BPS로 주식수를 역산해 검증했다고 주장하지 않는다. 기존 가격/과거 자료 그대로 유지한다.
