# 23차 개발 기록

## 변경

`collection-policy.ts`는 Z99/전체/기능별 제외를 공통 판정한다. 코드와 `collectionRevision`을 요청 전에 캡처하며 설정 변경 후 재활성화해도 이전 요청의 버전은 유효해지지 않는다. 실제 외부 요청 전후 확인과 DB 행 잠금 안의 저장 확인을 함께 적용한다. 수집 재시도 대상의 SQL 조건도 제외 설정을 따른다. 계좌 스냅샷은 이 외부 수집 판정으로 중단하지 않는다.

`collection-client.ts`는 수집 중 DB 쓰기에 현재 코드 근거를 기록하고 잠금 안에서 코드·제외 버전을 확인한다. 코드가 바뀐 기존 수집 값은 현재 코드 조회에 혼입되지 않는다. 코드 정정 시 `security_code_history`에 이전 자료 사본을 보존한다. 코드 정정 전의 DART 작업 큐·진행 상태도 사본에 보존하고, 변경 후 큐는 새 코드의 미처리 상태로 초기화한다. 과거 실행/실패 이력 행은 변경하지 않는다. 코드 변경 또는 제외 저장 시 처리 중인 큐를 대기 상태로 돌려 이전 요청이 새 상태를 덮어쓰지 못하게 한다. 즉시 외부 수집 작업을 실행하지 않는다. 기존 자료의 내부 종목 ID, 종목코드 근거, 거래·관심 연결을 소급 변경하지 않는다. 종목 삭제는 참조 검사 후 비활성화만 수행한다.

`security-management.ts`는 마스터 커서 조회(50+1 lookahead), 일반 정보 수정, 등록 출처가 MANUAL인 코드 정정, 전체/기능별 제외, 참조 보호 삭제를 제공한다. DB 전역 종목코드 유일성으로 동시에 같은 코드를 저장하는 경우도 차단한다.

모니터링 집계는 최근 실행 대상 행 집계로 통일하며 `resultScope.runId`를 제공한다. 실시간 수집은 실제 사이클 대상 결과를 실행·대상 이력에 기록해 성공 목록도 조회할 수 있다. 상태 판정, 주기, 스케줄, 기존 DART 진행률은 유지한다. 상세 페이지 조건에 실행 ID가 포함되고 커서는 이 조건에 종속된다. 공통 공개 오류 설명은 URL·키·인증 헤더·SQL/스택 원문을 숨긴다.

프런트는 성공/실패 집계 이동, 실패 행의 제외/재활성화와 오류 요약, 설정 아래 종목 관리, 공통 종목명/코드 표시·검색 경계, 전체 APK 링크를 연결한다. 제외 설정은 서버 응답 후 화면에 반영하며 실패·취소 시 기존 상태를 유지한다.

## 데이터 보존·마이그레이션

마이그레이션 `20261012120000_phase23_security_management`는 출처·제외·버전과 코드 근거, 보존 사본 테이블을 추가한다. 기존 출처는 UNKNOWN으로 유지한다. 기존 자료의 현재 연결 코드만 `collection_symbol`에 기록하며 원본 수치·기간·영수증·연결/별도 기준은 바꾸지 않는다. 중복 코드가 있으면 유일성 인덱스 생성이 실패하게 하여 임의 병합·삭제를 막는다.

운영 읽기 사전 점검: 종목 마스터 2,657개, 정규화 중복 그룹 0개, 6자리 규칙 위반 0개. 운영 원본을 수정하지 않았다. 배포 스크립트의 서버 내부 사전 DB 백업(.sql.gz, 제한 권한, gzip 검사, SHA256)을 유지한다. 복구는 배포 전 DB 백업 및 이전 이미지 태그를 사용한다. 실패한 DDL은 임의 재실행하거나 기존 출처를 바꾸지 않고 실제 적용 상태를 확인해야 한다.

## 검증·배포 상태

별도 브랜치 `codex/phase23-management-20261012`. 로컬 타입/빌드·관련 단위 검사를 수행하며 실제 MariaDB 및 브라우저 검증은 CI에서 실행한다. PR·검증 SHA·배포 결과는 확정 후 이 문서와 QA 문서에 기록한다. Android 실기기·WebView는 현재 환경에서 확인할 수 없어 완료로 기록하지 않는다.
