# 15차 검증 계획 · 계좌 관리·삭제·예수금 비율

기준: [15차 통합 명세](../handoff/20261009-phase15-accounts-cash-ratio.md). 날짜2026-10-09. 요구 목록과 아래 실행 결과를 구분한다.

## 확인된 범위

- Figma 커버·태블릿에서 카드 선택 강조, 초기화/삭제 버튼 상태, 중앙 삭제 확인 팝업, 구간별 색상 예시를 시각 확인했다.
- 홈·평가자산의 주식평가액·예수금 금액/비율을23.8% 구간(주식 빨강·예수금 파랑)에 맞춰 확인했다.
- 최초 기획 문서 단계에서는 서비스/API/DB 미실행. 아래 구현 검증으로 갱신.

## 구현 후 확인 목록

| 영역 | 사례 | 기대 결과 |
|---|---|---|
| 카드 | 선택/사용중 전환, 긴 계좌명 | 노란 테두리2px·제목, 사용중 흰색, 레이아웃 흔들림 없음 |
| 편집 | 비선택 계좌 편집/초기화/삭제 | 클릭한 accountId에만 작용 |
| 입력 | 계좌명·증권사·계좌번호 빈값 | 필수 표시와 저장 차단 일치 |
| 정규화 | 공백·탭·하이픈만 입력, 중복 번호, 자기 계좌 수정 | 빈값 차단·중복 거부·자기 제외 |
| 기존 데이터 | NOT NULL 이행 전 기존 값 및 계좌 연결 | 검증 근거 기록, ID/연결 보존 |
| 버튼 | 데이터 있음/없음/초기화 직후/조회실패 | 초기화 또는 삭제 표시, 실패를 빈 계좌로 오판하지 않음 |
| 초기화 | 이름 불일치·일치·중복클릭·실패 | 기존 확인절차, 원자 처리, 대상 외 보존 |
| 삭제 팝업 | 클릭·취소·확인 | 중앙 DIM, 취소/빨간 삭제, 이름 재입력 없음 |
| 삭제 API | 연결 데이터 있음 | 서버에서 거부 (사용자 추가 결정: 로그인/소유권은 후속 2차) |
| 동시 변경 | 삭제 검증 후 거래/예수금 추가, 중복삭제 | 데이터 유실 없이 차단 또는 일관된 원자 결과 |
| 삭제 후 | 비선택·사용중·기본·마지막 계좌 | 계좌 전환/기본 참조/계좌없음 안내 및 캐시 정상 |
| 삭제 실패 | 서버 오류 | 계좌·선택 상태 유지, 오류/재시도 |
| 구간 | 19.99%,20%,29.99%,30% | 각각 주식/현금 파랑/빨강, 빨강/파랑, 빨강/파랑, 녹색/노랑 |
| 반올림 | 19.999%,29.999% | 표시 반올림 전 값으로 아래 구간 판정 |
| 누락 | 분모0·시세없음·계산불가 | 중립색·비율 —, 확인 금액 보존 |
| 계좌 구분 | 계좌별 상이한 비율·빠른 전환·갱신 | 다른 계좌 색상 혼입 없음 |
| 화면 일치 | 홈·평가자산·자산분석·현재예수금·계좌 | 막대/금액/비율 같은 공통 판정 |
| 회귀 | 월증감·손익·종목별 비중·선택 테두리 | 기존 의미별 색상 유지 |
| 반응형 | 370×465,725×396,큰 화면 | 카드·버튼·팝업·스크롤 잘림 없음 |

실제 쓰기 검증은 테스트 계좌 또는 격리 DB에서 수행한다. 요청 없는 운영 초기화/삭제를 검증 수단으로 사용하지 않는다.

## 실행 범위 구분

운영에서는 계좌번호 결측 건수만 읽기 전용 확인(3계좌, 결측0). 운영 초기화·삭제 미실행. 브라우저는 실제 프론트+모의 API, DB검사는 실제 격리 MariaDB. 실물 접이식 기기·장시간 운영 동시 접근은 미검증. 인증/권한 검사는 단독 사용 사용자 지시로 이번 범위에서 제외.
