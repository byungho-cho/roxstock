# 20차 후속: 홈 부분 로딩

## 적용 범위
홈 커버 370×465·태블릿 725×396에 한정한다. 다른 화면 확대는 홈 확인 후 별도 결정한다. 공유 카드의 신규 loading/stable 옵션은 기본 false이며 홈만 사용한다. 목표가 도래 전체 상세 화면의 기존 표시와 조회 정책은 유지한다.

## 표시·데이터 기준
- 평가자산(76px), 주식평가액/예수금(68px) 틀·레이블은 즉시 표시하고 금액·수익률·월 증감만 작은 스켈레톤을 표시한다.
- 차트 제목·배경을 먼저 표시하며 기존 차트 영역 87px/171px를 모든 상태에서 유지한다. 스켈레톤·빈 결과·오류도 이 공간 안에 표시한다.
- 보유종목·목표가 도래·최근 매수 카드 제목은 즉시 표시한다. 기본 5행을 수용하는 카드 290px를 유지하고 목록 내부만 5개 2줄 행 스켈레톤을 사용한다. 최근 매수의 기존 더보기 확장은 추가 행에 맞춰 높이를 늘린다.
- 건수·기간·시각은 응답 전 값으로 표시하지 않는다. 지표 없음과 실제 0은 구분한다. 200ms 표시 지연은 표시기만 지연하며 데이터 표시의 최소 대기시간은 없다.
- 자산추이는 기존 별도 API 응답을 직접 사용하므로 대시보드 지연/실패와 독립적으로 표시한다. 추가 API는 없다.
- 기존 주요 조회 종료 후 paint → 최근 매수 후속 호출 순서를 유지한다. 오류도 종료 상태로 처리한다. 최근 매수 후속 호출 전에도 카드 틀을 표시한다.
- 동일 key 재조회는 React Query의 기존 data를 유지한다. 계좌별 key·AbortSignal·placeholder 없음 정책과 계산/시세/수집 스케줄은 유지한다.
- 초기 오류는 해당 공간에서 재시도를 제공한다. 기존 값이 있는 오류는 값과 고정 공간을 유지하고 해당 영역에 재시도를 표시한다.

## 검증
모의 API Chromium 커버·태블릿 검사: 계좌 조회 대기, 대시보드 지연과 차트 선표시, 부분 실패·재시도, 실제 0·빈 결과, 기존 계좌 갱신 중 새 계좌 전환/늦은 응답, 빠른 응답, 대시보드/목표 실패 후 최근 매수, 계좌 조회 실패. 카드/차트 높이·아래 카드 상대 위치는 로딩·정상·빈·오류·재시도 간 동일하다. 버튼 클릭에 따른 브라우저 자동 스크롤은 배치 이동과 구분한다.

API 요청은 기존 accounts/dashboard/asset-history/target-arrivals/recent-buys를 사용한다. 초기 StrictMode 취소·재시작은 요청 계수에서 구분하며 새로운 endpoint/중복 query를 추가하지 않는다. 유효 캐시 재진입에는 추가 호출이 없음을 검사한다.

전후 캡처는 모의 API accounts 응답을 같은 조건으로 보류했다. before는 main 838df2c, after는 이번 구현이다. 실제 운영/실기기 캡처가 아니다.
