## 환경별 증거

- TypeScript: frontend/backend 통과. 프론트 production 빌드와 백엔드 빌드 통과. 기존 Vite 청크 크기 경고는 유지된다.
- 기존 백엔드 회귀: 153/153 통과.
- 실제 MariaDB: 로컬 `roxstock_phase16_test`에서 초성·코드 검색, 계좌별 분류, 비활성 포함 조회/명시적 활성화 등록, 정확한 cashTransactionId 조회, 다른 계좌 조회 404, 거래 재요청 중복 방지 통과.
- DEV 읽기 확인: KODEX 200 ID 2592는 비활성 상태. 화면 검색은 해당 상태를 명시하며 사용자가 확인한 등록에서만 재활성화한다. 이 검증으로 DEV/운영의 해당 종목을 변경하지 않았다.
- 브라우저 모의 API 12/12 통과: 370×465와 725×396에서 팝업 Back/X 반복, 검색 상태 유지, 하단 고정 영역·5.5개/52px 폭, 계좌 선택/연속 전환 중 늦은 응답 차단, KODEX 기존 ID 분류 변경, 매수/매도 직후 정확한 예수금 연결·제세금 포커스·기존 내역 PATCH 검증.
- Figma와 캡처 대조: 메뉴 18px SVG, 44px 높이, 계좌 제목 16px, 계좌 팝업 최대340px/내부20px, 행40px, 사용 중 녹색·굵게 표시.

## 확대 회귀 결과

관련 기존 브라우저 검사 확대 실행에서 96건 통과, 4건은 원래 화면별 skip. 오래된 자산/더보기/설정 검사에는 현재 main과 불일치하는 제목 위치, 메뉴 순서·버튼 및 초기화 위치 기대가 남아 있다. 새 메뉴 관련 기대값만 16차에 맞췄으며 과거 화면 전체를 이전 디자인으로 되돌리지 않았다. 새 팝업 검사의 중복 선택자 오류는 하단 메뉴 범위로 한정해 수정 후 통과했다.

## 미검증/배포

- CI 재실행 기록: 배당 입력 메모 검사가 최초 1회 실패했으나 로컬 동일 검사 5회 및 CI 예수금·매매일지·복리계획 72건 재실행은 통과했다. 투자손익 재시도 검사는 이전 요청의 늦은 응답을 잡는 테스트 경쟁 조건을 발견해 모의 응답에 시나리오 표식을 추가했다. 실제 API·계산 로직은 변경하지 않았다.

- 실제 Android/iOS 시스템 Back과 실기기 키보드 IME는 미검증. Chromium 터치 뷰포트와 브라우저 history로 검증한다.
- 운영 거래 등록·예수금 수정·계좌 데이터 변경은 실행하지 않는다. 모든 쓰기 검증은 격리 DB 또는 모의 API다.
- 운영 반영 커밋과 자동 배포 결과는 PR/Actions에서 확인하여 완료 보고한다. DB 스키마 변경은 없다.
