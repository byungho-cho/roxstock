## 운영 확인

[Production Deploy](https://github.com/byungho-cho/roxstock/actions/runs/38048939839)는 반영 커밋 `4668722e6765d91b05633c3c9dca9b3c75bf038d`로 성공했고 2026-10-10 20:45:02 KST에 종료했다. 백엔드·모든 수집기·프론트·프록시 healthy 및 외부 API 확인이 통과했다. Docker 발행 로그와 배포 후 새 운영 브라우저 DOM의 `/assets/index-DSdxbSqA.js`가 일치한다.

운영 브라우저 1363×936에서 실제 자료로 다음을 확인했다. 개인 계좌 값·운영 캡처는 공개 저장소에 첨부하지 않는다.

- 자산분석의 현재 계좌 기본 복리 요약 → 해당 계획/목표 상세 이동, 기간 표기, 최종 목표 흰색·올해 목표 배경/노란 기준선, 돌아온 뒤 기존 1년 조회 조건 유지. 운영의 비영(非零) 스크롤 복원은 추가 확인하지 않았으며 CI에서 확인했다.
- 복리 차트 선택: 사각 테두리 없음, 노란 단일 세로선/선택점, 축소 툴팁. 툴팁 내부 클릭 유지 및 바깥 뒤로가기의 첫 클릭 실행. 자산추이 선택 후 바깥 하단 메뉴 첫 클릭의 이동/선택 해제.
- 예수금 목록의 MM/DD, 동일36px 날짜 열·24px 행·tabular-nums 및 열/행 겹침 없음.
- 매매일지 상단 날짜 선택으로 상세 날짜/집계/숨은 날짜 입력 동기화. 평일 흰색·토요일 파랑, 10/03 개천절은 토요일이어도 빨강 우선. 상세 날짜 제목의 네이티브 picker 호출을 시도했으나 클라우드 브라우저에서 OS 팝업 표시/팝업 날짜 확정은 직접 확인하지 못했다. 해당 이벤트·선택 동기화는 CI에서 검증했다.
- 가치분석에서 삼성전자 검색 Enter 확정 및 입력 포커스 해제, 현재 저장 자료의 갱신 방식 선택창 문구/3버튼 표시, 취소 후 기존 갱신 폼과 상세로 복귀. 운영에서 새 수집을 실행하거나 장애를 주입하지 않았다. 서버 작업의 장애/종료/보존 검증은 실제 MariaDB 통합 검사 결과를 따른다.

최종 CI 캡처42장(모의 자료)과 배포 후 운영 캡처4장(실제 자료)을 분리해 제공한다. 커버/태블릿/큰 화면은 CI 크기 검증이며 실제 운영 캡처는 위 브라우저 크기다.

배포 전 기존 DART 컨테이너의 최근24시간·최대500줄을 allowlist 필터로 확인했다. 반환된9건은 run3088, 2026-10-10 20:20:38 KST, FINANCIALS 단계의 `DART_CORP_CODE_NOT_MAPPED`(DartApiError/PARSING)였다. 이 범위에서 확인한 실패 원인은 DART 기업코드 미연결이며, DART 서비스 장애·무응답은 운영 로그로 입증하지 못했다. 원본 요청/키/스택을 출력하거나 문서에 보관하지 않았다. [백엔드 배포 로그](https://github.com/byungho-cho/roxstock/actions/runs/38048939839/job/114204633989)의 안전 진단 단계가 근거다.

실기기 모바일 키보드 표시/닫힘·네이티브 날짜 캘린더의 실제 팝업 표시/확정·물리 터치 감도는 미검증이다. 운영 장애 주입/새 수집 실행 및 운영의 모든 기간·항목 전수 검사는 하지 않았다. 운영 데이터에 테스트 계좌·가짜 종목을 만들지 않았고, 자동 수집의 실행 주기/대상 정책·계산식·DB 스키마는 변경하지 않았다.
