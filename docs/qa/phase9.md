# 9차 재무제표·가치지표 개선 검증

## 변경

- 보유 Lot 날짜를 14px·흰색·700으로 표시하고 보유요약에 현재 계좌·종목의 재무제표 링크를 추가했다.
- 연간 차트는 종료연도까지 3년을 표시한다. 2015~2018 선택은 2016~2018로 정규화한다. 이전 시작연도 URL을 종료연도로 변환하고 종목 이동 시 조건을 유지한다.
- 유동비율은 재무지표 표·차트·범례에서 제외하고 저장 값은 유지한다.
- 재무제표와 가치분석이 기간·보고서 선택 및 저장 데이터 조회/수동 갱신 팝업을 공유한다. 저장 조회는 GET만 사용한다. 수동 갱신은 현재 종목의 지정 기간만 처리한다.
- 서버의 기존 작업 잠금과 RUNNING 요청 검사를 재사용하며, 브라우저 재진입 시 요청 ID로 상태를 복구한다. 팝업을 닫아도 진행 상태를 추적하고 완료 시 호출 화면을 재조회한다.
- 기존 보충 로직을 공유한다. 구버전 재무제표의 누락 원천 계정을 같은 공시번호·연결/별도 기준으로 보충하며, 기존 정상 값은 유지한다. 보존된 지표의 출처는 지표별 provenance에 유지한다.

## 가치지표 기준 및 실제 내부 DB 결과

내부 DB는 저장소의 백업을 복원한 테스트 DB다. 운영 DB 결과와 구분해야 한다. 기존 8차 마이그레이션을 적용했으며 9차의 새 스키마 변경은 없다.

2024·2025년 연간 재무제표 1,104건을 기존 보충 함수로 계산·저장했다. 외부 수집은 실행하지 않았다.

| 연도 | 저장 재무제표 | ROE 계산 | PER 계산 | PBR 계산 |
| --- | ---: | ---: | ---: | ---: |
| 2024 | 558 | 527 | 0 | 0 |
| 2025 | 546 | 522 | 0 | 0 |

미산출 사유: 1,104건에 공시 EPS/가중평균 보통주 근거가 부족하고, 동일 공시의 주식 수 또는 소유주 자본 자료가 부족하다. 기간 말 과거 종가는 모두 미확보다. 55건은 동일 연결/별도 전기말·당기말 자본 또는 순이익이 부족해 ROE도 계산할 수 없다.

예: 현대차(내부 ID 240)의 ROE는 2024년 11.9143%, 2025년 8.3612%이며 실제 내부 API의 `endYear=2025` 조회가 2023·2024·2025를 반환하고 해당 값을 표시하는 것을 확인했다.

현재 주가를 과거 종가로 대신 사용하지 않는다. 가격은 금융위원회 공공데이터 주식시세 API의 재무기간 말 이전 7일 내 마지막 거래일 비수정 종가를 사용한다. 공시 EPS 또는 동일 공시 보통주 근거로 EPS를 계산하고, 소유주 귀속 자본과 대응 주식 수로 BPS를 계산한다. ROE는 같은 연결/별도 기준의 평균 자본을 사용하며 전체 순이익·전체 자본을 사용하는 경우 그 기준을 표시한다. 다른 사이트의 기록된 PER/PBR을 혼용하면 주가일·귀속 기준·연환산 기준이 달라질 수 있어 확인 없이 저장하지 않는다.

현재 환경에는 `DART_API_KEY`와 `DATA_GO_KR_STOCK_PRICE_KEY`가 등록되지 않아 외부 원천 자료의 실제 보충 검증은 미완료다. 다른 채팅에서 키 저장 위치를 확인하지 못했다. 키가 있는 운영 환경의 실제 수집 결과를 이 내부 계산 결과로 주장하지 않는다.

## 검증

- 프론트 TypeScript 검사·빌드와 백엔드 TypeScript 검사 통과. 백엔드 단위 테스트 113개 통과.
- 8차·9차·가치분석 회귀 34개를 두 크기에서 검증했다. 수정된 기존 테스트 4개는 재실행해 모두 통과했다.
- Playwright API 모드의 370×465 및 725×396: 종료연도 경계, 기존 URL, 종목 이동·분기 선택 유지, 저장 조회와 수집 분리, 기간 역전, 요청 범위, 재진입 시 중복 방지, 실패 후 활성화, Lot 스타일과 링크.
- API 테스트 fixture는 검증용 응답이며 서비스 API 모드에 목 데이터 fallback을 추가하지 않았다.
- `popup-*`·`lot-date` 캡처는 API fixture 테스트다. `internal-financials`·`internal-value` 캡처는 실제 내부 DB API를 사용한 현대차 화면이다. 두 크기에서 가로 넘침을 확인했다.

## 배포

저장소의 auto-merge와 필수 PR Gate를 확인했다. main 병합 시 기존 Production Deploy가 같은 병합 SHA로 백엔드, 프론트를 순서대로 배포한다. 기존 환경변수·DB·백업 절차를 사용한다. PR·병합 SHA·배포 실행과 운영 버전은 실제 완료 결과로 보고한다.
