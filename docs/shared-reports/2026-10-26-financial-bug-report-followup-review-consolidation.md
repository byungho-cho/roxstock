## 중단 시 AssertionError와 재개

최초 반영 시도는 116개 사건 모두 `PRESERVED_CHANGED_REVIEW`였고, 사건 쓰기 0회였다. 조사 이후 상위 그룹에 새 사건이 추가되어 **occurrences와 lastSeenAt**이 달라진 것이 원인이다. 사건 자체 116행은 그대로였다. 이후 확인식 `all(status == APPLIED)`가 실패했다. 실행 완료 기록 COMPLETE를 실제 전 행 반영 성공으로 해석할 수 없으며, 조건을 제거하거나 동시 변경을 무시하지 않았다.

중단 전 그룹 15·18·26만 REVIEWING으로 반영됐고, 그룹 37은 변경 감지로 보존됐다. 재개 시 3개 그룹의 전체 현재 행이 변경 후 사본과 정확히 일치함을 먼저 확인했다. 같은 그룹을 중복 변경하지 않았다.

재개는 현재 사건·그룹과 원 실행 항목을 다시 추출하고, 원 실행 식별 해시·종목·실행·보고서 코드·기존 기간의 충돌 여부를 재검증했다. 같은 원천·기간의 최신 작업·공시·지표를 읽어 새 계획을 만든 뒤 사본을 비공개 저장하고 SHA-256을 확인했다. 이 과정과 변경을 하나의 연속 실행으로 수행하여 긴 조사와 반영 사이의 간격을 줄였다. 기존의 그룹 전체 행 비교, 사건 전체 행 비교, 원 실행 항목 비교와 행 잠금은 유지했다.

새 계획의 기간 보완 151회는 **기존 보류 116회 + 이후 확인 35회**이며, 151회 모두 APPLIED와 변경 후 사본을 확인했다. 실행기는 반영 수·계획 수·행별 결과를 별도로 검증하며, 보존·보류 결과가 하나라도 있으면 성공으로 처리하지 않고 재대조 필요로 종료한다. 그룹 27·37·43을 추가 전환했고, 먼저 반영한 그룹 3개와 합쳐 실제 변경은 6개다.

## 통합 표시와 개발 인계

원본 사건을 이동·삭제하거나 새 합성 원인으로 덮어쓰지 않았다. 그룹의 기존 code·feature·severity·summary·검토 메모·발생 시각·발생 횟수와 사건키·실행·종목·지표를 보존하고 state만 REVIEWING으로 바꿨다. ‘검토한 미해결 항목’은 기존 `review-pending` 가상 카드로, 원인별 28개 실제 그룹을 계속 열람할 수 있다. 그룹 37을 포함해 두 기존 카드의 미해결 사건 전체가 최종 가상 카드와 정확히 일치했다.

현재 미해결만 검토 상태로 통합했다. 기존 리포터는 새로운 발생 시각의 사건이 들어오면 해당 그룹을 OPEN으로 되돌린다. 이 동작을 수정하거나 이후 신규 사건을 자동으로 계속 REVIEWING으로 보내는 작업은 만들지 않았다. 따라서 이 기준점 이후 새 사건이 발생하면 별도 신규 오류 카드가 다시 나타날 수 있다.

## 백업·동시 변경·선별 복구

서비스 전체 DB 백업은 서버 비공개 경로 `/root/roxstock-investigations/bug-report-followup-private-20261026/database.sql.gz`에 보존했다. MariaDB `--single-transaction --quick --routines --events --triggers --hex-blob --databases roxstock` 덤프이며 시스템 DB는 포함하지 않는다. 압축 82,998,484 bytes, 전체 해제 1,125,638,466 bytes, SHA-256 `c5b0ee017ec6a6138171f045d7036ed89a25de07548c8bca87c23baff5466d05`다. 압축 전체 CRC 읽기·덤프 머리말과 완료 꼬리말·체크섬을 검증했다. **격리 DB 복원 검증은 미실시**다.

같은 비공개 디렉터리에 최초·재개 사본, 계획, 미반영 116회 기록, 성공 151회/6개 그룹 변경 전·후 사본, 해시 manifest, 최종 검증 결과와 선택 복구 스크립트를 보존했다. 컨테이너 /tmp의 재개 근거도 영구 비공개 경로로 복사했다. 파일을 공개 저장소에 추가하지 않는다.

쓰기에는 기존 리포터와 동일한 그룹 행 잠금과 사건 행 잠금을 사용했다. 사건에 updatedAt이 없어 전체 현재 행을 사본과 비교했고, 그룹의 전체 행 및 원 실행 항목도 다시 비교했다. 동시 변경된 행은 최초 116회처럼 건너뛰어 원본을 보존한 뒤 재대조한다. 정상 수집의 금융 실행권을 해제하거나 탈취하지 않았고, 재무·가치 저장이나 외부 조회를 수행하지 않아 수집기 실행권으로 작업을 끼워 넣지 않았다.

복구는 전체 DB 덮어쓰기가 아니다. 기본 읽기 전용인 `selective-rollback-bundle.mjs`는 현재 전체 행이 이번 변경 후 사본과 일치하는 경우만 복구 후보로 잡는다. 사건은 이번에 바꾼 fiscalYear·periodType만, 그룹은 state만 원래 값으로 돌리도록 준비했다. 이후 변경이 있으면 보존한다. 실제 복구는 실행하지 않았으며, 읽기 전용 계획에서 **151개 사건 + 6개 그룹 = 157개**가 모두 사본과 일치하는 후보임을 검증했다.
