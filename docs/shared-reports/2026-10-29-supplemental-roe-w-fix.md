# v1.2.43 동일 공시 보충 계정을 이용한 ROE·W 보완

## 원인 및 수정
한싹(430690)의 연간 연결 원본에는 지배주주 자본 직접 계정이 없지만, 같은 공시의 총자본-비지배지분에서 검증한 자본이 보충 계정에 저장되어 있었다. 정기 계산은 보충 계정을 읽지만 선별 재계산 도구가 원본 직접 계정만 읽어 W 미충족이 유지됐다.

공통 closingParentRoe에 보충 계정 입력을 추가했다. 직접 계정 우선순위를 유지하며 공시번호·연결·KRW·보고기간·원 단위 일치를 검증한다. 파생 자본은 같은 공시의 총자본과 비지배지분 차감식, 원본 총자본 금액까지 대조한다. 불명확·불일치 근거는 거부한다. 선별 도구는 `--only-w-unblocked`에서 실제 W 미충족 -> 충족으로 바뀌고 RIM 원천 자본·주식수·BPS 대조까지 통과하는 대상만 저장한다. 수동 ROE·다른 지표 보호, lease·CAS·원천 변경 확인과 비공개 전후 사본을 유지한다.

## 검증 및 계획
- 공통 계산/기간/W 회귀 42개 통과. 한싹의 손실/파생 자본 재현, 원본 무변경, 통화/공시/기간/차감식 불일치 거부 및 직접 값 우선 검증.
- 관련 공유·백엔드·수집기 타입 검사 통과.
- 운영 읽기 전용 전수 계획 2회 일치: 초기 256종목 중 RIM 자본·주식수·BPS 재대조에서 1종목 보류. 최종 255종목 (코스피 199, 코스닥 56), 주의 66 / 별도 주의 불필요 189. 한싹 ROE -7.9048 -> -8.1717, W 충족 전환 확인.
- BPS 등 다른 조건으로 W가 여전히 막히는 경우 62종목은 제외했다. 기존 보완 완료 1,437종목은 재저장하지 않는다. 제외·수동·기간·출처 미확인 자료는 보존한다.
- 외부 API 호출, 과거 보완 대기열/스케줄 재개, 목록 상태 초기화 없이 저장된 근거만 이용한다.

## 운영 실행 및 복구
최신 전체 DB 백업과 읽기 전용 계획 재확인 후, 승인된 255종목 JSON allowlist와 비공개 output-dir를 사용해 배포된 collector/dist/scripts/reprocess-closing-parent-roe.js를 `--production --only-w-unblocked`로 계획 실행한다. 검증 후 `--apply`를 명시한다. 반영 후 ROE·W 충족·다른 지표 보존·중복 방지·revision 갱신을 확인한다.

전후 사본과 체크포인트를 서버 비공개 위치에 보존한다. 복구는 이후 변경 여부를 먼저 확인하고 해당 ROE 및 관련 근거/주의 메타데이터만 선별 복구한다. 전체 DB를 과거 상태로 덮어쓰지 않는다. 코드 복구는 이전 backend/collector 이미지로 수행한다. 프런트 및 APK는 변경하지 않는다.

실제 운영 반영 수와 배포/검증 결과는 완료 후 추가한다.
