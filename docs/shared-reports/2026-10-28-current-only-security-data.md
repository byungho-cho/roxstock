# 신규 공시 수집 범위 전환 · 종목 관리 분리

신규 수집기는 첫 조회를 올해 1월부터 시작했고, 조회 완료 후의 2일 중첩에도 시작 경계가 없었다. 최초 조회를 실행 당일 KST로 바꾸고, 지속 커서의 `coverageFrom`보다 이전 공시는 발견·중간 종료 복구·처리 대상·후속 정정 연결 대기열에서 제외한다. 발표일 기준이므로 시작일 이후 발표된 과거 회계기간 정정은 대상이다. 새로 과거 누락 기간을 순회하지 않는다.

운영 전환 경계는 사용자 요청에 따라 **2026-10-28 KST 00:00 포함**이다. DART 조회는 날짜 단위이며 활성화 순간의 시각 단위 경계는 아니다. 중복 접수번호를 제거하고 날짜 중첩은 이 경계 이후로 제한한다. 서버 재시작이나 연도 변경에도 경계를 유지한다.

종목 관리는 수집 실행·조회 범위와 독립적으로 현재 저장된 재무자료 및 가치지표를 읽는다. 수집기 커서로 과거 공시 여부를 추정하지 않으며, 근거 없는 공시 대기 대신 `공시 여부 확인 필요`로 표시한다. 상세 미수집 재무 항목 이름을 표시하고 화면 조회로 수집을 시작하지 않는다. 관리자 권한·편집 보호와 기존 값은 유지한다.

## 전환 절차

1. 전용 신규 수집기 중지 및 자동 재시작 방지 확인. 기존 과거 보완 타이머는 비활성 상태 유지.
2. 운영 DB의 일관된 전체 백업과 비공개 복제 검증.
3. 승인된 collector 이미지에서 같은 네트워크·비공개 환경을 사용해 도구를 실행한다. 도구는 이미지에 임의 설치하지 않고 해당 커밋의 `scripts/security-data-current-cutover.mjs`를 `/app/scripts`에 읽기 전용 마운트한다.
4. 기본 dry-run: `node scripts/security-data-current-cutover.mjs --from=20261028`.
5. 적용: `node scripts/security-data-current-cutover.mjs --from=20261028 --apply --directory=/private/new-empty-evidence-directory`.
6. 공통 금융 lease 아래 시작일 이전 `PENDING/RETRY/PROCESSING`만 `SKIPPED`로 전환한다. 접수번호·발표일·시도 횟수·이전 상태와 결과는 보존한다. 완료·실패·보류 이력과 재무 원본·지표·개인 자료는 변경하지 않는다. 커서만 시작일로 이동한다.
7. 수정 이미지 배포 후 전용 수집기를 재개하고 실제 커서·과거 대기열 0건·새 실행 범위를 확인한다.

## 복구

수집기를 먼저 정지한다. 코드 문제는 이전 이미지로 복구하되, 예전 코드가 2일 중첩으로 경계 이전 공시를 다시 넣을 수 있으므로 자동 재개하지 않는다. 데이터 복구가 필요한 경우 `before.json`의 커서·대기열과 현재 행을 대조해 이 전환이 바꾼 상태만 선택 복구한다. 이후 새로 처리된 행이나 전체 운영 DB를 덮어쓰지 않는다. 백업 및 원본 근거는 비공개 보관하며 저장소에 게시하지 않는다.

## 검증

- 수집기·백엔드 타입 검사와 전체 서비스 빌드 통과.
- 시작 경계·날짜 중첩·연도 경계·범위 밖 공시 필터 단위 검증 통과.
- 격리 DB에서 시작일 당일 커서, 과거 대기·재시도·중간 종료 항목 미실행, 접수번호 중복 방지, 페이지 트랜잭션 복구, 재시도 상한 검증 통과.
- 종목 관리 OFF/ON 동일 누락 현황, 조회로 대기열 생성 없음, 기존 권한·수기 편집·감사 이력 통합 검증 통과.
- 운영 전환 및 실행 결과는 적용 완료 후 별도 기록한다. 메뉴 정사각형 및 모니터링 순서 변경은 별도 보존한 작업으로 이번 수집 수정에 포함하지 않는다.
