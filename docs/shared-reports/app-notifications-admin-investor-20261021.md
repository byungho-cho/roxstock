## 동작과 보존

사용자 알림 기본값은 각각 OFF이다. 별도 preferences 테이블에 설정/활성 세대를 저장하며 OFF→ON에 뉴스 최대 ID와 기준 시각을 새로 설정한다. 최초 목표가 스캔과 재활성 첫 스캔은 기존 보유 Lot을 기준 상태로 저장하고 발송하지 않는다. 기존 목표가 Decimal 판정 함수를 사용한다. 계속 충족하면 재발생하지 않는다. 유효한 관측에서 미충족 24시간 연속 유지(관측 간격 5분 이하) 후 다시 충족하고 이전 발생 후 24시간이 지난 경우에만 재알림한다. 관측 누락/가격 없음은 미충족으로 추정하지 않고 재알림을 보수적으로 억제한다. 기존 Lot의 초기 시세 미확인도 기준 행을 만들어 일괄 알림을 막는다.

뉴스는 원래 item ID와 최초 저장 당시 종목 연결 스냅샷, 사용자별 보유·관심·거래 계좌 범위를 교차 검증한다. 여러 종목·계좌에 연결돼도 사용자/item 사건은 하나다. 수정·관계 추가는 신규 사건을 생성하지 않는다. 기준 시각 이전에 발행된 과거 소식의 뒤늦은 수집도 알리지 않는다.

60초 주기 백엔드 worker가 사용자 20명/뉴스 100건/목표가 Lot 100건씩 페이지로 읽는다. 사건·기기별 발송 기록, 활성 세대, 시도 횟수, 다음 시각, 오류 분류는 DB에 남는다. 설정과 발송은 같은 사용자 preference 행 잠금으로 직렬화하며, 실제 전달 직전에 ON·세대·기기 소유권·연결 값·유효 세션을 재검증한다. 오류는 최대 5회, 지수 지연(최대 5분), 사건 수명 10분 내 재시도한다. 만료 FCM 토큰은 제거한다. 푸시 발송 성공은 FCM 접수이며 사용자 열람/OS 표시 완료를 뜻하지 않는다.

외부 FCM과 DB는 단일 원자 트랜잭션을 제공하지 않는다. 응답 유실 후 재시도는 같은 eventId를 사용하고 Android가 표시 전 ID를 영속 저장해 중복 표시를 막는다. 표시 직전 프로세스가 죽으면 알림이 누락될 수 있으며 중복 대신 보수적 누락을 선택했다. 장애·장시간 OFF·만료 사건을 나중에 대량 발송하지 않는다.

## Android와 외부 설정

기존 Android는 증권사 알림 접근 서비스만 지원했다. 이를 유지하며 별도 FirebaseMessagingService/POST_NOTIFICATIONS 경로를 notifications flavor에 추가했다. webOnly flavor에는 FCM/알림 접근 서비스를 넣지 않는다. 서버는 data-only 메시지로 개인정보 없이 TARGET/NEWS·eventId·기기 binding·만료 시각만 전송한다. Android는 현재 binding·종류별 로컬 설정·OS 권한·만료·중복 ID를 검증한 뒤 일반 문구를 표시한다. 로그아웃은 로컬 연결·설정을 먼저 지우고 서버 세션을 폐기한다. 비동기 등록이 나중에 돌아와 이전 binding을 복구하지 못하게 로컬 revision도 검증한다. 토큰 변경 후 다음 앱 활성 시 인증된 API로 재등록한다.

알림 클릭은 UUID만 받으며 임의 URL을 실행하지 않는다. 서버가 사건 소유권을 검증해 TARGET은 홈, NEWS는 종목소식 목록을 반환한다. 종료 상태의 실행도 같은 경로를 사용하고 로그인 화면에서도 pushEvent를 유지한다. 다른 계정의 사건은 404다. 사건에는 실제 대상 계좌 ID를 비공개 DB 문맥으로 보존한다. 클릭 시 서버가 현재 소유권·활성 상태를 재검증하며, 기존 계좌 선택 저장 경로로 해당 계좌를 선택하고 홈/소식 캐시를 새로 조회한다. 비선택 계좌의 사건을 클릭해도 기존 선택 계좌의 다른 자료로 대체하지 않는다. 계좌가 사라졌거나 권한이 없으면 오류를 안내한다. Android 강제 종료(force-stop), 절전/네트워크/Google Play 서비스 제약은 FCM의 수신을 지연하거나 막을 수 있다.

필요 설정(원문 비밀값은 저장소/공개 로그에 기록하지 않는다):

1. Firebase 프로젝트에 실제 패키지 `com.roxstock.app.debug`를 Android 앱으로 등록한다. 현재 서명된 배포는 기존 시험 APK 채널을 유지한다. `com.roxstock.app.webonly.debug`와 다른 앱이다.
2. GitHub Actions Variables: `ROXSTOCK_FCM_APP_ID`, `ROXSTOCK_FCM_PROJECT_ID`, `ROXSTOCK_FCM_SENDER_ID`. Secret: `ROXSTOCK_FCM_API_KEY`. 이 네 값으로 FirebaseOptions를 구성한다. 값이 없으면 APK는 FCM 미설정으로 표시하고 기기 등록을 하지 않는다. 클라이언트 API 키는 서버 서비스 계정 키와 구분한다.
3. 프로젝트의 Cloud Messaging API v1을 활성화하고 최소 발송 권한의 서비스 계정을 준비한다. 서버의 기존 읽기 전용 runtime 디렉터리 안에 서비스 계정 JSON의 소유 UID를 컨테이너 node 사용자와 맞춰 0600으로 보관하고 상위 디렉터리의 접근 권한도 확인한다. `backend/.env.auth`에 `FCM_SERVICE_ACCOUNT_FILE=/run/roxstock/fcm-service-account.json` 경로만 설정하고 백엔드를 재생성한다. collector에는 설정/키를 전달하지 않는다. 키 내용은 git·PR·채팅·공개 로그에 게시하지 않는다.
4. 같은 프로젝트 설정으로 APK를 다시 빌드·서명·배포한다. 설정 화면의 알림 지원 APK 링크로 다운로드하고 ‘출처를 알 수 없는 앱 설치’를 필요한 설치 앱에만 허용해 설치한다. 설정 → 알림 설정에서 항목을 켜면 Android 13+ 런타임 권한을 요청한다. 거부 시 시스템 알림 설정 버튼으로 안내한다. 기존 증권사 ‘알림 접근’ 권한과 다른 권한이다.
5. 실제 기기에서 실행 중/백그라운드/종료 수신 및 클릭·로그인 복귀·계정 전환을 검증해야 외부 푸시 운영 준비 완료로 판단한다. 에뮬레이터 로컬 표시 테스트와 실제 FCM 전달을 혼동하지 않는다.

공식 참고: [FCM Android 수신](https://firebase.google.com/docs/cloud-messaging/android/receive), [HTTP v1 발송](https://firebase.google.com/docs/cloud-messaging/send/v1-api).

## 관리자 및 투자동향

일반 설정에서 DB 백업·시세 수집·종목소식 수집 설정·종목 관리를 제거하고 별도 관리자 화면으로 옮겼다. 버전은 실배포 API 값을 표시하며 ADMIN만 클릭 가능하다. 모니터링은 기존 메뉴/하단 위치를 유지하고 일반 사용자에게 숨긴다. 관리자 URL과 API는 서버 세션에서 현재 role을 읽어 차단한다. 역할·계정 변경 시 클라이언트 캐시/페이지 기억을 정리한다.

사용자 목록은 가입 시각/id 내림차순 keyset 30개, 연결 계좌는 id 순서 100개씩 조회한다. 목록·상세는 같은 createdAt과 한국시간을 사용한다. 응답은 ID·이메일·인증/비밀번호 변경 필요 상태·가입 시각·증권사·마스킹 계좌번호·기본 여부만 제공한다. 사용자 수정/삭제·자산/보유/거래·비밀번호/토큰 조회는 추가하지 않았다. 관리자 조회 감사는 actor/subject ID·동작·시각만 기록한다.

종목 상세 매수 왼쪽에 투자동향 보조 버튼을 추가했다. 현재 symbol을 URL에 전달하고 기존 목록·차트 조회를 사용한다. 전달 종목이 목록에 없으면 다른 종목으로 대체하지 않는다. 기존 목록 이동/페이지 기억 경로를 통해 뒤로가기의 종목·탭·스크롤을 유지한다. 매수 및 이전/다음 이동은 유지한다.
