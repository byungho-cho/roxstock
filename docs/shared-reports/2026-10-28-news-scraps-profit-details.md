## 변경 동작

- stock_news_scraps의 사용자/소식 복합 기본키와 사용자 소유권 검사로 중복·타 사용자 접근을 차단합니다. 공개 소식 원본은 공유하며 개인 스크랩만 분리합니다. 멱등 저장·해제, 재로그인 유지, 선택 상태 동기화, 실패 복원, 스크랩 순서의 이전/다음 탐색과 뒤로가기 복원을 지원합니다.
- 종목 전용 연도 화면은 기존 서버 손익 계산기를 이용한 전체 기간 통계를 한 번에 조회합니다. 실제 매수·매도·배당 연도만 최신순으로 표시합니다. 선택 연도에 처음 위치하고 기존 전체 종목 연도 메뉴는 유지합니다. 수익률은 기존 원금 분모로 다시 계산하며 비율을 합산하지 않습니다.
- 거래별 상세는 계좌·종목·연도·월 조건을 서버에서 적용합니다. 매매 실현손익과 배당을 날짜/구분/고유 ID로 안정 정렬합니다. 50건 단위 커서, revision 스냅샷, 조건 해시로 변경 중 혼합을 차단합니다. 월 합계와 전체 건수는 전체 조건의 서버 계산값입니다. 조회 원본 전체를 프런트로 내려보내지 않습니다.

- 한 거래 한 줄, 고정 날짜/구분/금액 열과 종목명 공간 유지, 월 그룹 병합, 16px 년월/합계, 하단 80px 여백을 적용했습니다.

## 마이그레이션과 운영 절차

`20261028180000_news_scraps_report_window`는 새 테이블 두 개와 리포팅 시작점만 추가합니다. 기존 재무·거래·수기·오류 원본을 갱신하거나 삭제하지 않습니다. 기존 세션·권한도 유지합니다.

1. 운영 DB 추가 백업, gzip 검사와 비공개 사본 SHA-256 일치 확인.
2. 기존 재무·지표·수기·매수·분할매도·예수금/배당·오류 원본의 행별 해시 기준 확보.
3. PR 필수 검사 통과 후 병합하고 기존 자동 배포 경로로 백엔드·필요 수집기·프런트 순서 반영.
4. 실제 운영 인증으로 스크랩 저장/해제·조회, 사용자 분리, 전체 기간 통계와 월별 합계, 신규 리포트 시작점 및 과거 작업 중단 상태 확인.
5. 기존 행 해시를 대조하고 임시 검증 세션은 폐기. 개인 금액·쿠키·토큰은 공유 보고서에 게시하지 않음.

## 복구

새 테이블은 유지한 채 이전 정상 서비스 이미지로 복구할 수 있습니다. 스크랩과 리포팅 시작점은 지우지 않습니다. 원본을 수정하지 않는 추가 마이그레이션이므로 전체 DB 복원은 일반 코드 복구에 필요하지 않습니다. DB 복구가 불가피하면 검증한 백업을 별도 DB에 복원하고 운영 이후 쓰기를 보존한 선별 복구를 수행합니다. 인증/소유권 검사 없는 과거 이미지로 복구하지 않습니다. 리포팅 표시 시작점 조정도 이력 삭제 대신 별도 검토로 수행합니다.

### 남은 범위와 복구 참고

요청 기능의 코드·DB 마이그레이션·병합·운영 웹/API 확인을 완료했습니다. Android 실기기 시스템 뒤로가기 등 네이티브 환경을 새로 검증한 것은 아니며, 기존 APK는 변경하지 않았습니다. 이번 확인은 실제 운영 웹을 휴대폰·태블릿 크기로 사용한 결과입니다. 새로운 운영 오류의 원인 보완은 별도 사건으로 유지하며, 목록 초기화를 반복해 숨기지 않습니다.

코드 복구 시 이전 인증·소유권 검사가 있는 정상 이미지를 사용하고 새 스크랩/리포팅 테이블은 보존합니다. 이전 서버 이미지가 리포팅 시작점을 지원하지 않으면 보관 목록이 다시 보일 수 있으므로 화면 정책을 포함한 후속 수정이 필요합니다. 자료 삭제로 이를 우회하지 않습니다. 검증용 로컬 복원 DB는 운영과 연결되지 않으며 재현 근거로 비공개 보관합니다.
