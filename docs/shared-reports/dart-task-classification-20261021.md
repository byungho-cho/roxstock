# DART 작업 분류·집계 보완 — v1.2.2

기준: main `f31662ece9c1c68d7853f2dd620e222be94cf89b` (v1.2.1), 조사 PR [#287](https://github.com/byungho-cho/roxstock/pull/287), 조사 브랜치 `085da991fe205cf75c0d56849b8b2cdb7c8554e5`.

조사 PR과 댓글을 재확인했으며 공개된 후속 처리 결과는 없었다. 조사 보고서는 운영 변경·재수집 0회라고 명시한다. 따라서 과거 조사 수치를 현재 운영 실측으로 표현하지 않으며, 대상 상태·매핑·정상 저장 자료를 보정 시점에 다시 확인한다. PR #287 자체는 문서 초안으로 유지한다.

## 코드 변경

기존 상태·자료·시도 횟수·접수번호를 유지하는 확장 마이그레이션이다. 상태 enum에 `NOT_DUE`, `DATA_UNAVAILABLE`, `EXCLUDED`만 추가했다. 검토 보류는 기존 `FAILED / REVIEW_REQUIRED`를 유지한다. 알 수 없는 `NOT_APPLICABLE`과 원응답 증거가 없는 기존 `ROWS_NOT_PUBLISHED`는 화면/API에서 보류로 분류한다. 성공은 저장 완료 작업만이다.

공통 `dart-task-status.ts`가 집계와 상태별 조회 조건을 정의한다. 명시적인 정책 제외만 기본 조회에서 제거하고, 완료 분자·전체 분모·상태별 분포에서도 제거한다. NULL 사유의 과거 대상 아님은 제외로 간주하지 않는다. 전체 계획에서 미도래를 뺀 현재 처리 대상이 진행률 분모다. 처리 완료율과 실제 자료 저장 성공률을 별도로 표시한다. 0건은 수집 대상 없음, 전부 미도래면 전부 미도래이며 100%를 만들지 않는다. 전체·우선종목 상세 집계는 같은 RepeatableRead 트랜잭션에서 계산한다.

`CALENDAR_REPORT_YEAR`와 확인된 결산월을 사용한다. 3S 반기는 2026-09-30, 3분기는 2026-12-31이다. 결산월 근거가 없거나 모호하면 보류한다. 일반 제출기간은 확정 마감일이 아닌 미도래의 하한 근거로만 사용한다. 연장·특례·휴일 조정을 확인하지 못한 경우 최종 기한을 생성하지 않는다. 하한 이후 공시가 없으면 기한 검토 보류로 남기되 매일 재조회한다. 목록에서 실제 보고서를 먼저 찾으며, 조기 제출 자료를 기한 때문에 건너뛰지 않는다.

판정 근거·기준일은 diagnostics, 재확인 일정은 nextAttemptAt에 저장한다. `(status,next_attempt_at,id)` 인덱스로 도래 작업 최대 100개만 읽어 재가동한다. CURRENT 단계 이후에도 재가동한다. 기존 financial lease와 조건부 UPDATE가 중복 작업을 막으며 새 프로세스에서도 DB 일정으로 이어진다. 정기 재확인 간격은 24시간이며 기간 중 매일 조기 제출도 확인한다.

회사번호 미매핑으로 끝난 과거 NOT_APPLICABLE만 현재 매핑·회사번호·종목코드·수집 허용 설정을 검증해 PENDING으로 돌린다. 기존 사유·시도 횟수·접수번호·diagnostics를 지우지 않으며 `dart_task_decisions`에 전후 스냅샷을 트랜잭션으로 남긴다. 정책/사용자 제외와 이미 처리된 작업은 건드리지 않는다. 3S 연도 이동이나 검증 우회는 없다.

CFS/OFS 응답은 코드·행 수·요청 회사/기간·연결/별도·확인 시각·응답 접수번호를 구분해 보존한다. 013과 000 빈 행, 제한·인증·통신 오류가 구별된다. API 오류를 미공시로 바꾸지 않는다. 보고서는 있으나 재무 행이 없는 새 작업은 자료 미제공 근거와 원문 보완 필요를 기록하고 완료에서 제외한다. 삼성증권·기업은행·KB금융의 연간 원문은 기존 검증 파서를 시도하되 금융업 계정과목 대응이 검증되지 않으면 저장하지 않는다. 지원하지 않는 분기/레이아웃은 이유와 함께 보류한다. 금융업 전체를 제외하지 않는다.

상태별 상세는 기본 우선종목/전체 범위, 종목·연도·보고서·사유·확인/다음 확인 시각을 제공한다. 제외 조회는 기본 집계 밖에 있다. 기존 collection 경로의 관리자 제한과 scoped Prisma의 개인 계좌 범위를 유지하며 원본 diagnostics나 개인 계좌/거래 자료를 API에 추가하지 않는다.

## 운영 보정과 복구

`collector/dist/scripts/reconcile-dart-task-status.js plan /absolute/private/plan.json`은 조사 164개 조합과 현재 DB를 대조한다. 정상 저장 자료, 변경된 상태, 수집 제외 설정, 불일치 매핑은 변경하지 않는다. 원보고서 캐시가 만료되거나 실제 후보가 발견되면 미도래를 강제하지 않고 목록 재확인으로 대기 전환한다.

- 더본코리아만: 2015–2023 연간 9개 + 2020–2024 Q1/Q2/Q3 15개. 2024 연간과 기존 성공 자료는 유지한다. 사유 `PRE_LISTING_POLICY_EXCLUDED / 상장 전 수집 제외`이며 공시 부존재 판정이 아니다.
- 조사 70개: 최신 캐시와 결산월 근거가 일치하면 미도래, 만료·변경 시 목록 재확인.
- 미매핑 13개: 아직 같은 상태인 경우만 정확한 매핑을 재검증해 대기 전환.
- 금융 57개: 과거 API 원응답 근거 부족을 보류로 표시하며 일괄 운영 재수집하지 않는다. 웹서버 담당의 추가 결과·실제 작업 ID 대조가 필요하다.

운영 스크립트 `scripts/reconcile-dart-status-production.sh`는 컴포넌트 SHA를 확인하고 계획을 서버 비공개 디렉터리에 0600으로 복사한 뒤에만 apply한다. 대상 작업의 전후 상태는 DB 감사 테이블에도 남긴다. 기존 financial lease가 사용 중이면 제한된 횟수만 재시도한다. 적용은 ID·수정 시각·이전 스냅샷으로 조건부 변경하므로 재실행/동시 실행/웹서버 선처리를 건너뛴다. 공개 로그에는 집계와 변경/건너뜀 건수만 출력한다.

복구는 보존한 plan.json을 같은 이미지의 `reconcile-dart-task-status.js restore /absolute/private/plan.json`으로 실행한다. 적용 직후 감사 스냅샷과 현재 상태가 일치하는 작업만 복구한다. 이후 성공·재처리·추가 변경된 작업이나 정상 재무자료가 존재하는 작업은 덮어쓰지 않는다. 새로운 데이터가 있는 경우 자동 원복 대신 개별 검토한다. DB 스키마는 이전 상태를 모두 보존하는 확장이므로 무리한 enum 축소/테이블 삭제를 하지 않는다.

## 검증과 현재 실행 상태

로컬 공통 모듈 105개, collector 232개 테스트 통과. 프론트엔드·백엔드·collector 타입 검사 통과. 추가한 실DB 테스트는 도래 일정·동시 조건부 갱신·매핑 복구·정책 제외 유지·감사 이력·SQL/공통 집계 일치와 사용자별 우선목록 격리를 검증한다. 370×465, 725×396 Playwright 테스트는 혼합/0건/전부 미도래 및 상세 목록을 검증한다.

현재 환경에는 MariaDB/Chromium 실행 환경이 없다. Chromium 다운로드도 실패했으므로 실DB·브라우저 검증은 CI 결과 확인 전 미검증이다. 코드 PR·병합·운영 배포·보정·실재수집 결과는 실행 후 별도로 갱신한다. 준비된 배포 후 보정 job은 v1.2.2에만 적용된다.

초기 조사 상태가 전혀 바뀌지 않았고 70개가 미도래로 확인될 때의 검산 예시: 전체 계획 1,131 = 기존 1,155 - 정책 제외 24, 현재 처리 대상 1,061 = 1,131 - 미도래 70, 저장 성공 990. 이는 운영 변경 후 실측값이 아니다. 미매핑 복구 후 수집 결과와 웹서버 선처리에 따라 달라진다. 미해결 금융 57개 및 별도 접수번호 불일치 1개를 성공으로 치환하지 않는다.
