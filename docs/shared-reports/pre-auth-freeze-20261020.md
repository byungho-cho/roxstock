## 서버 담당 실행 지시

1. Git 원격 태그 생성
- 위 main 전체 SHA를 대상으로 annotated tag freeze/pre-auth-20261020-v1.1.26을 만들고 원격에 push한다.
- 동일 이름이 존재하면 대상과 주석을 확인한다. 기존 태그를 강제로 덮어쓰지 않는다.
- 태그 주석에 실제 DB 백업 시각·비공개 백업 식별자·체크섬 및 각 서비스 이미지 기준을 연결한다. 키·DB 내용은 넣지 않는다.
- 원격 refs/tags 및 peeled commit SHA로 등록을 검증한다.
- 태그 push로 배포 workflow가 실행되는지 먼저 확인하고 의도하지 않은 배포를 발생시키지 않는다.

2. 현재 운영 DB 일관 백업
- 기존 검증된 백업 절차와 비공개 자격증명을 사용한다.
- 트랜잭션 일관성을 보장하고 비트랜잭션 테이블·DDL·실행 중 수집 쓰기의 영향을 확인한다.
- 필요하면 짧은 유지보수 구간에서 신규 쓰기와 수집 시작을 통제하고 실행 중 작업을 안전하게 정리한다. 잠금을 강제로 삭제하거나 데이터·작업 기록을 초기화하지 않는다.
- 스키마·데이터·필요 루틴·트리거·이벤트·마이그레이션 상태를 복구 가능하게 보존한다.
- 덤프를 공개 Git이나 웹 정적 경로에 올리지 않는다.
- 기존 비공개 /opt/roxstock/backups/managed 또는 검증된 보안 백업 경로에 권한을 제한해 보존한다.
- 시각(KST/UTC)·DB 버전·파일 크기·SHA-256·테이블별 건수를 기록하고 gzip 무결성을 검사한다.
- 기존 백업을 덮어쓰지 않는다.
- 환경설정·메일/수집 인증키는 DB 덤프와 별도로 안전하게 보존하되 Git·채팅에 노출하지 않는다.

3. 격리 복원 검증
- 운영 DB에 덤프를 넣지 않고 외부 수집·메일 발송이 비활성화된 격리 DB에 복원한다.
- DATABASE/USE 목적지가 운영을 가리키지 않도록 검증한다.
- 증권계좌·매수 Lot·분할매도·예수금·배당·스냅샷·관심종목·뉴스·수집 설정·마이그레이션 건수와 주요 합계를 대조한다.
- 운영 계좌·금액은 공개 보고서에 기재하지 않는다.
- 백업 시점과 검증 시점의 차이를 명시한다.

4. 롤백 계획
- 코드만 복구 가능한 경우 각 서비스의 기록된 이미지 digest로 복귀한다.
- 계정화 스키마 변경은 가능한 추가 방식으로 설계하고 기존 소유 데이터는 보존한다.
- DB 전체 복원은 최후 수단이다. 백업 이후 거래·수집 자료가 사라질 수 있으므로 복원 직전 추가 백업과 후속 데이터 보존·재적용 계획을 마련한다.
- 로그인 보호가 이미 배포된 뒤에는 롤백으로 무인증 자산 API를 다시 공개하지 않도록 접근 차단/유지보수 경계를 보존한다.
- 실제 운영 복원은 장애 상황에서 영향 범위 확인 후 진행하며 이번 작업에서는 격리 복원만 수행한다.
