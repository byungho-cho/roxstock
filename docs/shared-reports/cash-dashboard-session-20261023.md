# 제세금·자산구성·홈 보유종목·세션 유지 개선

기준: main `7db57a0c7981967e76ce09faebc72713d34acba2` (PR #311), 작업 브랜치 `fix/cash-dashboard-session-20261023`. 열린 PR들은 문서 작업이며 이번 변경에 섞지 않았다. 웹/API 1.2.13 → **1.2.14**. 비용 확인 체크, 중복 방지, 시스템 알림, 가치지표 링크, 투자동향 기본 기간 및 34차 소식 UI를 유지한다.

## 변경 구조

- KRW 예수금 BUY/SELL: 최근 3건 가중 비용률은 60자리 중간 정밀도로 유지하고 최종 비용에 한 번만 ceil. API 생성/명시적 편집 저장도 같은 원 단위 기준. 편집 중 입력은 보존하며 소수 비용은 적용액을 안내하고 blur 시 정규화한다. 적용 결과와 PATCH에는 정수 비용·이에 맞춘 잔액을 사용한다. 과거 소수 내역 열기는 초안만 만들며 저장 전 DB 쓰기 없음. 동일 저장 재시도 시 같은 금액을 대입하여 중복 차감하지 않는다. 현행 계좌 예수금에는 통화 필드가 없고 KRW 전용이다. 재무제표 외화, 배당, 단가·수량·거래금액 정밀도는 변경하지 않는다.
- 자산구성 범례: 공통 버튼 스타일의 비율/금액 전환. React 지역 상태로 조회·갱신과 독립. 실제 보유 평가액을 기존 top7/기타 집합에 전달하여 기타 금액도 합산. 표시만 만원 반올림하며 소액은 `1만원 미만`. 도넛·순서·색·비중·중앙총액은 유지한다.
- 홈: HoldingRow의 가운데에 손익률/손익금액, 오른쪽에 수량×평균가/평가액. 해당 행만 제한된 열과 줄바꿈을 적용하며 최근 매수·목표가 도래에는 적용하지 않는다.

## 자동 로그인 분석과 수정

소스로 확인한 경로:
1. AuthGate의 모든 예외 catch가 QueryClient·사용자·native 알림 소유자를 해제했다. 네트워크/5xx/잘못된 응답만으로도 로그인 화면으로 돌아갈 수 있었다.
2. 이전 토큰 유예 종료 요청이 같은 세션 행 전체를 철회했다. 정상 최신 쿠키를 가진 다른 요청도 이후 거부됐다. 기존 실DB 테스트도 이 동작을 기대하고 있었다.
3. 매 갱신 토큰 교체 후 Set-Cookie 응답이 역순 도착하면 오래된 토큰을 덮어쓸 가능성이 있었다. 실기기 이번 발생과의 인과관계는 미확정이다.

수정: 인증 확인의 15초 제한, 알려진 서버 401 세션 코드와 일시 오류 구분, 2/5/15초 최대 3회 자동 재시도 및 수동/online/복귀 재확인. 검증된 기존 사용자의 일시 오류에는 캐시·계좌·알림 연결을 유지하고 연결 안내를 표시한다. 최초 미확인 또는 다른 탭의 사용자 전환 신호에는 개인 화면을 차단한다. 응답 순번으로 오래된 사용자 응답을 무시한다. 인증 쿠키를 쓰는 요청은 동일 출처 Web Locks로 탭 간 직렬화하여 이전 사용자 갱신 응답이 새 로그인 쿠키를 덮어쓰지 않게 한다. 미지원 단일 WebView는 문서 내 Promise 순서를 유지한다. Web Locks 미지원 다중 탭 환경의 탭 간 순서는 보장하지 못하며 검증 범위에서 구분한다. 권한 부족 403은 세션 종료 근거가 아니다. 인증 완료 뒤 사용자/역할 변경에만 기존 개인 캐시를 비우고 scope를 바꾼다.

서버는 유효한 현재 토큰을 유지하며 활동 확인 `/me` 및 `/refresh`에서 자동 로그인 90일/일반 12시간을 연장한다. 갱신마다 토큰을 교체하지 않아 동시 탭·역순 갱신 응답에 같은 쿠키가 설정된다. 새 로그인마다 독립 난수 토큰을 발급하고 모든 요청에서 DB 만료·철회·인증 상태를 검증한다. 비밀번호 변경·초기화·로그아웃은 기존 DB 철회를 유지한다. 배포 전 은퇴 토큰은 기존 유예까지만 허용하며 유예 종료 시 해당 요청을 거부하되 정상 현재 세션을 철회하지 않는다. 자동 로그인과 세션 쿠키 구분, HttpOnly/Secure/SameSite/CSRF·소유권 검증은 유지한다. 클라이언트에 비밀번호를 저장하지 않는다.

`AUTH_COOKIE_MISSING/INVALID`, `AUTH_SESSION_UNKNOWN/EXPIRED/REVOKED`, `AUTH_USER_DISABLED`, `AUTH_TOKEN_MISMATCH/RETIRED`, `AUTH_TEMPORARY_EXPIRED` 코드와 비식별 분류 로그를 추가했다. 클라이언트는 NETWORK_UNAVAILABLE/TIMEOUT/RESPONSE_INVALID를 구분한다. 비밀번호·토큰·쿠키 원문을 출력하지 않는다. 운영 진단은 최근 최대 10,000줄/7일의 집계만 출력하며 개인 세션과 실기기 사건을 연결하지 않는다. 과거 로그에 원인 코드가 없거나 컨테이너 교체로 소실된 내용은 추정하지 않는다.

## DB·배포·롤백

스키마/마이그레이션/운영 데이터 일괄 수정 없음. 과거 비용·잔액·스냅샷을 재작성하지 않는다. 실제 사용자 명시 저장 행과 활동 세션 만료 갱신만 쓰기 대상이다. 기존 배포 전 DB 백업 절차 유지. 변경 서비스는 backend/frontend이며 collector와 네이티브는 변경하지 않는다. Android AuthCookies는 새 프로세스에서 세션 전용 쿠키만 제거하고 영속 쿠키는 보존하므로 수정하지 않았다. APK 재게시 없음(기존 패키지·서명·버전 유지).

롤백은 이전 backend/frontend 이미지로 서비스별 복구하고 DB를 유지한다. 새 스키마가 없으므로 이전 이미지와 호환된다. 이전 버전의 일반 catch 로그아웃·갱신 토큰 경쟁이 재발할 수 있다. 비용 일괄 역수정·세션 전체 삭제·과거 스냅샷 복원은 하지 않는다.
