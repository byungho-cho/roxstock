# v1.2.17 · DART 호출 예산과 검토 결과 선별 반영

## 변경

- DART 현행 수집의 기본 일일 예산을 3,000회에서 10,000회로 변경한다. 운영 환경의 명시적 설정도 별도로 갱신한다. 실제 사용량은 초기화하지 않는다.
- 내부 예산을 올린 경우 이전 `DAILY_CALL_LIMIT` 기록만으로 재개를 막지 않는다. 현재 사용량과 실제 DART `020` 제한은 계속 검사한다.
- 현재 2단계와 과거 1단계 결과를 구분하고, 전환 이후에는 2단계 카드를 먼저 표시한다. 호출 한도 대기도 별도로 표시한다.
- 종목소식 및 과거 요약 수집 오류는 오류 리포트에 기록하지 않는다. 원 수집 실행·항목 이력과 모니터링은 유지한다.
- 보유종목 이름·매수금액 흰색 표시, 최근 매수·목표가 도래 열 정렬, 거래 보유기간 앞 간격 16px를 적용한다.

## 데이터 적용 범위

2026-10-23 로컬 검토에서 재무자료 128개 기간을 재계산했지만 추가 보완값은 없었다. 재무 값이나 개인 데이터는 이관하지 않는다. DB 스키마 변경도 없다.

2026-10-24 운영 읽기 전용 사전 대조에서 사건 식별 충돌과 누락은 없었다. 검토 대상 중 17개 그룹은 통합 가능하며, 새 사건이 추가된 5개 그룹은 상태를 유지한다. 종목소식 오류 그룹 5개는 제외 대상이다. 숫자는 실제 반영 직전 재대조하며 운영의 신규 사건·기존 해결 상태를 우선한다.

운영 DB 전체 덮어쓰기를 금지한다. 동일 사건 키·원 실행·종목·기간·그룹 지문을 대조하고 하나의 직렬화 트랜잭션으로 검토 상태와 종목소식 리포트만 변경한다. 수집 실행 원본, 인증·사용자·계좌·거래·예수금·배당·스냅샷은 변경하지 않는다.

## 검증

- 오류 리포트 제외·내부 한도 재개·실제 한도 유지·설정 검사: 9개 통과.
- 프론트·백엔드·수집기 TypeScript 검사 통과, 웹 production 빌드 통과.
- DART 진행 단계·미도래 분모·호출 한도 화면: 370×465 및 725×396에서 8개 통과.
- 병합은 해당 PR의 모든 필수 CI 통과 후 진행한다. 운영 적용 및 로컬 최신화 결과는 별도 비공개 실행 기록으로 보존한다.

## 적용·복구 순서

1. 운영 전체 DB를 `/opt/roxstock/backups/roxstock-v0.2-<UTC>`에 백업하고 gzip·SHA-256을 검사한다. 비공개 복제와 격리 복원 검증을 보존한다.
2. 코드 배포를 완료하고 운영 비공개 설정의 `DART_DAILY_CALL_LIMIT=10000`을 반영한다. API 호출 이력은 유지한다.
3. 실제 적용 직전 사건을 다시 비교한다. 변경 전 리포트·사건 행을 같은 비공개 백업 디렉터리에 보관한다. 새 사건이 있는 그룹과 이미 해결된 상태는 덮어쓰지 않는다.
4. 선택한 오류 리포트 상태만 통합하고, 종목소식 오류 리포트만 제거한다. 수집 원본과 개인 데이터는 보존한다.
5. 로컬 DB를 먼저 백업한 뒤 최신 운영 스냅샷으로 개발 DB만 복원한다. 테이블별 건수를 대조하고 로컬 서비스를 실행한다.

코드 복구는 기존 배포 워크플로와 이전 정상 이미지로 진행하며 인증·소유권 검사를 유지한다. 예산은 백업한 운영 설정의 해당 키만 복원한다. 오류 리포트 복구는 비공개 행 원본을 현재 상태와 비교해 누락된 키만 복원하고, 이후 신규 사건·해결 상태는 보존한다. 전체 DB 복원은 이번 변경의 기본 복구 방법이 아니다. 종목소식 리포트 제외 코드를 되돌리면 이후 재기록될 수 있다.

비밀 설정, 원천 응답, 개인 자산 원본, DB 덤프와 행 원본은 Git에 포함하지 않는다.
