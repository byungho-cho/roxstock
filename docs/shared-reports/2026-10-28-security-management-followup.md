## 운영 검증·복구 절차

1. PR의 필수 검사를 모두 통과한 SHA를 main에 병합하고 기존 운영 배포 워크플로로 배포한다. DB 마이그레이션은 없다. 과거 수집 재개나 기존 대기열 초기화는 수행하지 않는다.
2. 운영 버전과 각 서비스 이미지 SHA, 신규 수집기의 오늘 이후 범위 및 과거 대기0 상태를 확인한다.
3. prepare-security-data-browser.mjs로 5분 임시 관리자/일반 사용자 세션을 만들며 쿠키는 비공개 파일로만 전달한다.
4. SECURITY_DATA_UI_FIXTURE_ACTION=prepare로 security-data-ui-fixture.mjs를 운영 백엔드 안에서 실행한다. 별도의 비활성 임시 종목만 생성하고 /tmp 마커로 대상 식별자를 보관한다. 기존 종목·계좌·자산·재무자료를 변경하지 않는다.
5. SECURITY_DATA_BROWSER_SESSIONS 및 SECURITY_DATA_UI_FIXTURE에 비공개 파일 경로를 지정해 verify-security-data-browser.mjs를 실행한다. 두 크기에서 실제 조회·선조회·더보기·관리자 권한과 임시 종목의 최초 기준·EPS/PBR 저장·재조회를 확인한다.
6. 성공/실패와 관계없이 SECURITY_DATA_UI_FIXTURE_ACTION=cleanup으로 임시 종목·그 종목의 감사/지표/종목 revision만 삭제한다. 비활성 여부·고유 심볼·이름을 모두 대조하고 기존 종목의 값이나 전역 revision을 되돌리지 않는다. cleanup-security-data-browser.mjs로 이번 임시 세션도 폐기한다.
7. 배포 복구는 이전 서비스 이미지로 component rollback을 수행한다. 새 basis 데이터는 기존 JSON 필드에 저장돼 호환되며, 실제 종목 값 삭제/DB 전체 복원은 필요 없다. 검증 중단 시 임시 fixture cleanup부터 수행한다.

PR·최종 배포 실행 및 운영 검증 결과는 PR 완료 댓글과 최종 보고로 연결한다. 개인정보·인증정보·원본 운영 응답은 공유하지 않는다.
