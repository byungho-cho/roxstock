# 비용 확인·통합 알림·종목 연결 개선

기준: 2026-10-23 KST. main `9bd4343ccdf4d9c30dabcb485bd451586f5bd98f` (웹 1.2.12 / APK 0.1.8)에서 별도 브랜치로 개발. 열린 PR은 Firebase/DART/백업 조사 문서이며 해당 작업은 변경하지 않는다.

## 변경

- 매수·매도 예수금 편집에서 양수 비용(자동 추정 포함)은 기본 확인 체크. 빈 값·0은 해제. 거래마다 사용자 체크 선택을 초기화하며, 사용자가 해제한 뒤 양수를 수정해도 다시 체크하지 않는다. 재렌더·늦은 응답·다른 거래의 추정 캐시가 입력이나 체크 선택을 덮지 않는다.
- 실제 비용 미확인 기본 안내 제거. 추정 근거/조회 오류만 안내. 왼쪽 정렬한 네이티브 체크박스 label 행 전체를 클릭 가능하게 사용하며 단일 change 이벤트로 토글한다. 키보드 Space 유지.
- 저장 버튼을 눌러야 기존 PATCH 호출. 체크 저장 시 CONFIRMED, 해제 시 ESTIMATED/UNKNOWN. 과거 DB 일괄 변경 없음. 기존 최근 최대 3건 CONFIRMED 가중 비용 추정과 사용자·계좌·매매·시장·상품 필터를 유지한다. 예수금은 기존 차액 정산을 재사용한다.
- 알림 무시 버튼은 카드 전체 높이 중앙, 40×22 → 50×28, 글씨 10px 유지. 본문과 독립된 버튼으로 이벤트 전파 차단.
- Android 거래 알림은 기존 SQLite 트랜잭션이 신규 저장한 경우에만 로컬 시스템 알림을 생성한다. receipts 원본 중복 이력은 유지한다. 표시 실패는 내부 저장에 영향 없음. 등록 완료·무시 시 해당 시스템 알림만 취소하며 OS 알림 삭제는 DB를 변경하지 않는다.
- 거래 채널은 HIGH. 앱 전경에서도 동일하게 생성하며 OS 권한·채널·사용자 거래 설정 확인. 거래 알림 접근(카카오 읽기)과 시스템 알림 표시 권한은 별도로 표시/설정한다. 강제 중지·알림 접근 차단·OS/OEM 제한 시 수신을 보장하지 않는다.
- 클릭 목적은 통합 목록뿐이며 거래 생성/완료 없음. 네이티브에 검증한 owner/원본 ID를 보관하고 웹 목록 준비 후 ack한다. 초기 인증/로그인 중 목적을 보존하되 다른 사용자 로그인·로그아웃 시 이전 사용자 클릭/알림을 정리한다. 현재 사용자 ID와 네이티브 소유자 불일치 시 목록 조회 차단.
- 기존 로고의 외곽+R 경로를 단색 흰색/투명 배경 24dp 상태바 vector로 재사용. 거래·소식·목표 자체 생성과 Firebase 기본 smallIcon 모두 통일.
- 종목 상세 요약의 가치지표 링크는 기존 `/stocks/:id/value` 화면을 재사용한다. DB 종목 ID가 선택을 고정하고 해당 종목의 코드로 기존 데이터를 조회한다. source summary를 복귀 대상으로 명시하여 목록으로 건너뛰지 않는다.
- 누적 순매수 차트 기본값만 1y로 변경. 당일 표의 기존 30일 요청·종료일 처리 유지. 사용자 period URL은 종목 이동/갱신에 유지한다.

## 버전·데이터·복구

예정 웹 1.2.13 / APK 0.1.9 (versionCode 10). 기존 `com.roxstock.app.debug` 패키지와 승인된 서명 인증서 유지. 비밀키/FCM 서버 자격증명/개인 알림 원문은 포함하지 않는다. 기존 배포 CI의 보안 설정과 APK 검증/게시 절차를 재사용한다.

추가 점검에서 기존 API는 CONFIRMED 음수만 차단하고 UNKNOWN/ESTIMATED 음수는 허용하는 경로가 확인됐다. 매수·매도 비용은 모든 상태에서 음수 저장을 차단하도록 화면/API를 보완하고 상태별 거부 및 비용·잔액 불변 통합 검증을 추가한다. 기존 저장 자료는 변경하지 않는다. 기존 단위 테스트 중 음수 비용 저장을 허용하던 기대값은 상태별 거부·기존 값 보존·명시적 양수 수정 검증으로 대체했다.

DB 스키마·운영 거래 데이터 보정 없음. 시스템 알림 채널과 클릭 대기 preference만 추가. 원본 inbox/receipts 삭제나 재수집 없음. 복구 시 직전 웹 이미지와 게시 APK 메타데이터/파일을 복구하며 DB를 되돌리지 않는다. Android는 versionCode 하향 덮어쓰기가 불가하므로 문제가 있으면 동일 서명의 높은 versionCode로 수정 릴리스한다. 앱 삭제로 복구하지 않는다(로컬 원본 손실 위험).
