## 1. 일반 기업의 기간 선택 오류 수정

확인된 대상은 다음 9개 작업입니다.

- 에이텀(355690): 2025년 1분기·반기·3분기
- 프레스티지바이오로직(334970): 2022년 1분기·반기·3분기
- 위더스제약(330350): 2021년 1분기·반기·3분기

현재는 인접 연도의 결산월 변경 때문에 정상적인 대상 연도의 자료까지 CLOSING_MONTH_CHANGED로 차단됩니다.

- 대상 연도에 유효한 결산 이력과 실제 보고기간을 기준으로 공시를 선택합니다.
- 인접 연도의 다른 결산월이 있다는 이유만으로 대상 연도를 일괄 차단하지 않습니다.
- 종목별 하드코딩이 아니라 같은 조건에 적용되는 공통 로직으로 수정합니다.
- 실제 복수 결산·단기 결산·전환 연도와 근거 부족은 계속 보류합니다.
- 대상 밖 연도의 진단 후보를 확정된 대상 자료처럼 취급하지 않습니다.
- 기업·보고기간·접수번호·정정 관계·통화 검증은 유지합니다.
- 기간 선택 통과를 수집 성공으로 간주하지 않고 후속 원본 검증을 수행합니다.

보존된 공시 목록을 fixture로 사용해 9건과 보류 유지 사례를 함께 검증합니다.

## 2. 리츠·ETF·ETN·상장 파생상품 등의 분류

작업명은 ‘파생상품 수집 기능 보완’으로 관리하되, 리츠·ETF·ETN을 모두 파생상품으로 분류하지 않습니다.

- 기존 종목 마스터의 신뢰할 수 있는 분류 정보를 우선 사용합니다.
- 리츠·ETF·ETN 등 실제 유형을 각각 유지합니다.
- 종목명 문자열만으로 확정하거나 미확인 종목을 일괄 제외하지 않습니다.
- 분류 정보가 부족한 경우 기존 수집 경로에서 확보 가능한 근거를 확인하고 미확인 상태를 구분합니다.
- 일반 기업의 결산월 변경·정정 공시 보류를 상품 유형 보류와 혼동하지 않습니다.

## 3. 자동 재무 수집·보완 보류

- 리츠의 현재 재무 수집 보류는 유지합니다.
- 다른 비일반 상품은 재무·가치자료가 미지원 또는 구조상 수집 불가로 확인된 경우 이후 자동 수집·보완을 보류합니다.
- DART 자동 수집과 가치지표 자동 보완의 후보 선정 양쪽에 동일한 정책을 적용합니다.
- 보류 대상을 매 주기 호출하거나 재시도 큐에 반복 등록하지 않습니다.
- 기존 DB 작업 상태·제외 정책을 재사용하고 부족한 필드만 최소한으로 추가합니다.
- 보류 사유·근거·적용 시각을 추적할 수 있도록 합니다.
- 기존 저장 자료는 삭제하지 않으며 정상 자료는 계속 조회할 수 있어야 합니다.
- 주가·투자동향 수집은 별도 정책으로 유지합니다.
- 통신 실패·호출 한도·인증·DB 오류는 상품 미지원과 구분합니다.
- 보류를 성공·자료 없음으로 바꾸거나 검증을 우회하지 않습니다.

리츠 반복 결산, 단기 결산 및 한 해 여러 결산을 저장하는 신규 모델은 이번 범위에서 개발하지 않습니다.

## 4. 재무제표·가치분석 목록 구분

커버 카드와 태블릿 목록에 공통 적용합니다.

- 일반 종목과 구분되는 은은한 황갈색 배경을 적용합니다.
- 종목명 옆에 ‘리츠’, ‘ETF’, ‘ETN’ 등 실제 유형을 표시합니다.
- 노란색 주의 아이콘과 ‘지표 참고 주의’ 표시를 제공합니다.
- 아이콘 클릭 시 상품 유형과 실제 보류 사유에 맞는 툴팁을 표시합니다.
- 상승 적색·하락 청색 등 기존 수치 색상과 선택·포커스 가독성을 유지합니다.
- 색상만으로 구분하지 않고 유형·텍스트를 함께 제공합니다.

공통 안내:
‘일반 기업과 분석 기준이 달라 지표 해석에 주의가 필요합니다.’

리츠 보류 안내 예시:
‘일반 기업과 결산 구조가 달라 일부 재무자료 수집과 가치지표 계산을 보류하고 있습니다.’

거래소 공식 지정으로 오해할 수 있는 ‘투자주의’ 단독 표시는 사용하지 않습니다. 상품 자체의 위험 판정이 아니라 자료·지표 해석 안내임을 명확히 합니다.

## 5. DART 세부 보류 사유 전달

- DB에 저장된 validationResult를 목록·상세 API와 화면까지 전달합니다.
- 기존 API와의 호환성을 유지하고 필요한 진단 필드만 제공합니다.
- DART_SOURCE_REVIEW를 일반 통신 실패 문구로만 표시하지 않습니다.
- 다음 사유를 이해 가능한 문구로 구분합니다.

| 코드 | 문구 |
| --- | --- |
| CLOSING_MONTH_CHANGED | 결산월·회계기간 확인 필요 |
| MULTIPLE_ANNUAL_PERIODS | 같은 해 복수 결산기간 확인 필요 |
| CLOSING_MONTH_UNAVAILABLE | 결산월 판단 근거 부족 |
| CONTENT_CORRECTION_REQUIRES_ORIGINAL_VALIDATION | 내용 정정과 원본 자료 대조 필요 |
| CORRECTION_RELATION_UNVERIFIED | 원본·정정 공시 연결 근거 부족 |

- 요청 대상 기간과 검토용 후보 기간을 구분합니다.
- 과거 기록에 진단값이 없으면 추정하지 않고 상세 사유 미기록으로 표시합니다.
- 실제 API·DB 오류와 자료 부족·검토 보류를 구분합니다.
- 이번 수정만으로 기존 이력 전체를 성공 처리하거나 삭제하지 않습니다.

## 6. 휴장일 전체 주가 수집 개선

- 기존 거래일·휴일 판단 로직을 우선 재사용합니다.
- 주말·확인된 휴장일에는 당일 전체 종목 주가 수집을 시작하지 않습니다.
- 비거래일의 전 거래일 가격을 당일 가격으로 저장하지 않습니다.
- 과거 누락 거래일 보충과 당일 정기 수집을 구분합니다.
- 재시작 후 같은 비거래일 작업이 반복 실행되지 않도록 합니다.
- 거래일 판단 근거가 없거나 공급자 오류가 발생한 상태를 정상 휴장으로 처리하지 않습니다.
- 기존 정상 거래일 수집·재시도·스냅샷 동작을 보존합니다.
- 투자동향 수집 등 다른 일정에 정책을 무분별하게 확대하지 않습니다.

## 7. 기존 보류 자료 처리 범위

조사 기준 208건은 다음과 같습니다.

- 코드 수정 필요 9건
- 검토 보류 타당 189건
- 근거 자료 부족 10건

189건 전체가 리츠인 것은 아닙니다.

- 확인된 9건은 수정 후 현재 상태를 재검증하고 필요한 작업만 안전하게 재시도 대상으로 전환합니다.
- 실제 재시도는 기존 큐·호출 한도·우선순위·중복 방지 정책을 따릅니다.
- 208건 일괄 초기화·대량 재수집은 하지 않습니다.
- 정상 보류·근거 부족·상품 유형 보류는 각각 유지합니다.
- 재시도 결과와 과거 발생·검토 이력을 보존합니다.
