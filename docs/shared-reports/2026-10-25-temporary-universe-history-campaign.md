# 1단계 전체 종목 과거 자료 임시 보완

## 목적과 범위

2026-10-25 운영에서 시작하는 일시적 보완 작업이다. 2단계 현행 수집과 우선종목은 보류한다. 완료 후에도 2단계는 자동 재개하지 않는다. 차기 주기 실행 정책은 별도 설계한다.

최초 운영 조회의 보완 대상은 14,043기간 / 1,155종목이었다. 2015년 이후 연간 및 2020년 이후 분기 중 미보완 기간만 고정 계획에 담는다. 성공·미도래·명시적 수집 제외 자료는 건드리지 않는다. 우선종목은 계획 수립 시 및 각 기간 처리 전에 다시 제외한다. 계좌·거래·예수금·알림 설정은 쓰지 않는다.

## 실행 방식

- 서버 systemd 일회 배치와 timer를 사용한다. 이전 배치 **종료 후 5분**에 다음 배치를 시작하므로 실행이 겹치지 않는다. PC를 켜 둘 필요가 없다.
- 배치는 최대 60기간, 4분을 기준으로 작업 사이에서 종료한다. 진행 중 HTTP는 20초 제한이다. 위치·재시도 횟수·결과·변경 전 작업 상태를 비공개 파일에 저장한다. 프로세스가 중단되면 마지막 체크포인트부터 재개한다.
- 종목별 연간/분기 재무비율·재무상태표·손익계산서를 KIS로 묶어 조회하고 24시간 비공개 캐시로 재사용한다. KIS 호출 사이 최소 2.1초를 두며 기존 비공개 공유 토큰 캐시를 사용한다. 다른 수집기의 계정 공용 한도를 별도 증설하지 않는다.
- DART 공시 식별·보고기간·통화·연결/별도·정정 관계 검증은 기존 검증기를 재사용한다. DART 조회는 기존 DB 공용 10,000회 예산을 예약하고 소진 시 작업 위치를 유지한다.
- KIS는 억원 단위 반올림 자료이며 접수번호와 연결/별도 식별을 제공하지 않는다. 다섯 핵심 금액을 원 단위 DART 자료와 대조한다. 차이가 나면 KIS 값을 섞지 않고, 독립 검증된 DART 원본만 차선으로 사용한다. 검증 근거 없는 KIS 값만으로 빈 기간을 성공 처리하지 않는다.
- 기존 재무 원본이나 기간 지표가 있는 기간은 보존하고 별도 검토 대상으로 남긴다. 이 캠페인은 신규 검증 원본 저장과 미보완 작업 상태 정리에 한정한다.
- 자료 미제공과 조회/기간/정정 검증 실패를 구분한다. 공급자 통신 오류는 재시도하고, 인증·호출 한도·실행권 상실은 해당 배치를 멈춘다. 실패를 자료 미제공이나 성공으로 바꾸지 않는다.
- 고정 계획을 모두 점검하면 timer를 종료한다. 실패·보존 대상은 결과 목록에 남으며, 자동으로 성공 또는 수집 제외 처리하지 않는다. 완료는 ‘검토 계획 처리 완료’이며 전 기간 성공을 뜻하지 않는다.

## 운영 구성과 확인

설치 위치는 `/opt/roxstock/.deploy/kis-history-campaign/`이다. `state/`는 사용자·외부에 공개하지 않는다. 서비스는 `roxstock-kis-history.service`, 예약은 `roxstock-kis-history.timer`이다. 기존 검증된 collector 이미지에 이번 실행 스크립트 및 기존 KIS 읽기 전용 공급자만 읽기 전용으로 연결한다. 서버의 기존 비공개 설정을 사용하며 Git에 구성값을 저장하지 않는다.

기존 DART 자동 컨테이너는 공용 financial lease가 비는 시점에 보류했다. 재시작 정책을 임시 `no`로 보존하여 재부팅으로 2단계가 재개되지 않게 한다. 새 임시 서비스는 기존 financial lease/heartbeat 및 수집 제외 검사를 사용한다. 원래 `backfillCompletedAt`과 2단계 이력은 유지하며, 현재 표시 단계만 BACKFILL로 설정한다. 별도 배포가 기존 DART 컨테이너를 다시 시작하면 임시 wrapper는 중복 실행하지 않고 중단한다.

실행 상태는 systemd 상태, 비공개 `state/state.json`의 cursor/total/totals/lastStop, `results.jsonl` 및 기존 DART 실행 이력으로 확인한다. 웹/APK 릴리스 버전은 변경하지 않는다.

## 검증

외부 HTTP/DB를 사용하지 않는 테스트 8개 통과:

- 원 단위 정확 변환, 잘못된 수치 거부
- 정확한 기간·분기 누적값 대조, 중복 행 거부
- 다섯 핵심 금액 누락·차이 검증
- 한도·인증·실행권 오류 중단
- 실제 실행 경로의 저장·완료·체크포인트
- 우선종목 및 기존 재무 자료 쓰기 차단
- 미제공을 성공 처리하지 않음
- 한도 소진 시 작업 위치와 자료 상태 보존

기존 DART 기간·원문·저장·출처 검증 테스트 60개도 통과했다. 첫 운영 배치는 2026-10-25 08:20 KST에 정상 종료했으며, 39기간 처리 중 6기간 신규 저장·9기간 실패·24기간 미제공 또는 보존 결과를 남겼다. 신규 원본 6개의 접수번호·기간 근거 및 우선종목 쓰기 차단을 운영에서 확인했다. 우선종목 기존 성공 1,061기간은 그대로 유지됐다. 이 수치는 첫 배치 시점이며 이후 실행에 따라 바뀐다. 다음 배치는 종료 후 5분 예약된다.

운영 최초 구동에서 Docker env-file과 Compose 간 따옴표 처리 차이를 확인하여 dotenv 방식으로 정규화했다. 동일 조건을 실행 경로 테스트에 포함했다. 개인 원본 및 비공개 설정은 이 보고서에 포함하지 않는다.

## 보류와 복구

1. `systemctl stop roxstock-kis-history.timer` 후 캠페인 `state/STOP`을 만들면 신규 배치가 시작하지 않는다. 실행 중 배치는 다음 요청 경계에서 멈춘다. 필요 시 `docker stop --timeout 90 roxstock-kis-history-batch`로 정상 종료한다.
2. 운영 시작 전 `/opt/roxstock/backups/roxstock-v0.2-20261024T231305Z/`에 일관된 전체 DB 백업·gzip 무결성·SHA-256·이미지 기록을 보관했다. 이번 새 백업의 별도 DB 전체 복원 검증은 수행하지 않았다. 기존 백업을 삭제하지 않았다.
3. 수정 상태는 task 결정 이력 및 `state/preimages.jsonl`, 신규 원본은 캠페인 sourceValidation 및 실행 이력을 기준으로 선별 대조한다. 전체 DB를 덮어쓰면 운영 신규 자료가 사라지므로 기본 복구로 사용하지 않는다. 선별 복구도 공용 financial lease 아래에서 현재 상태와 변경 후 상태가 일치하는 항목만 되돌린다.
4. 원본·지표·계좌를 일괄 삭제하지 않는다. 원래 단계 상태는 `state/state.json`의 priorDartState에 보존한다. 2단계 복구는 별도 설계/사용자 지시 후 원래 컨테이너 재시작 정책과 단계 표시를 복구하여 진행한다. 이 작업 완료만으로 재개하지 않는다.
