# 네이버 뉴스 검색 API 개발 준비

기준: main 44ab19fc2b4e8e949b569d957eefcbe13cbd7cbd, 작업 브랜치 codex/naver-news-api-20261021.

## 설정

기존 KRX 자격 증명을 사용하는 서버 비공개 환경 파일에 다음 항목을 함께 둔다.
로컬의 기존 파일에 빈 입력란을 추가했으며 값은 기록하거나 커밋하지 않았다.
운영의 공유 환경 파일은 `backend/.env.production`이며 이번 작업에서는 수정하지 않았다.

```dotenv
NAVER_NEWS_ENABLED=false
NAVER_NEWS_CLIENT_ID=
NAVER_NEWS_CLIENT_SECRET=
```

네이버 클라우드 NAVER API HUB에서 Application(RoxStock)을 등록하고 뉴스 API를 선택한다.
Client ID와 Client Secret을 비공개 파일에 입력하고 활성화 값을 true로 변경한다.
해당 파일을 읽는 수집기 프로세스를 재시작해야 적용된다. 프런트엔드 환경 변수에는 넣지 않는다.
로컬 수집기를 실행할 때도 기존 KRX와 동일한 환경 파일 로더를 사용한다.

공식 문서: https://guide.ncloud-docs.com/docs/apihub-migration

## 동작

- 기존 한경 RSS·리포트·DART 제공처를 유지하고 NAVER_NEWS를 추가한다. 기본 비활성 상태에서는 호출도 모니터링 오류도 생성하지 않는다.
- 고정된 HTTPS 검색 엔드포인트에만 인증 헤더를 전송한다. 리다이렉트를 허용하지 않고 응답 1MB·요청 15초·실행당 180회로 제한한다. 오류 응답 본문이나 자격 증명은 기록하지 않는다.
- 종목명으로 최신순 검색하고 제목의 실제 종목 연관성을 재검사한다. 기존 중요도·중복 제거·하루 게시 상한·사용자별 뉴스 노출 정책을 유지한다.
- API description을 요약으로 한 번 사용한다. 요약이 없어도 제목 후보를 보존하며 기사 본문 조회나 요약 보완 재시도를 하지 않는다. 게시 대기 후보도 받은 요약을 보존한다.
- 네이버 기사 링크의 정확한 호스트와 기사 경로를 검증하고 이전/현재 URL을 같은 기사 주소로 정규화한다. 기존 공시·리포트·본문 수집 HTTP 호스트 제한을 확대하지 않는다.
- 검색 결과는 종목당 최대 10페이지를 조회한다. 날짜 범위를 덮지 못했거나 요청 상한에 도달한 경우 전체 이력 확인 성공으로 기록하지 않는다.
- API 조회 실패는 기존 제공처 재시도 정책의 대상이 될 수 있으나 요약 실패로는 재시도하지 않는다.

## 검증

- 수집기·프런트엔드 타입 검사 통과.
- 네이버 신규 테스트 6건 및 기존 뉴스 정책·수집·요약 테스트 15건 통과.
- 수집기 전체 240건 중 239건 통과. KIS 기존 테스트 1건은 제한 환경의 임시 캐시 쓰기 실패였으며 정상 권한으로 해당 파일 3건을 재검증해 모두 통과했다.
- 로컬 웹 HTTP 200, 서버 health 및 DB health HTTP 200, 비로그인 auth/me HTTP 401 확인.
- 운영 DB의 2026-10-21 19:04 KST 스냅샷으로 로컬 복원 완료. 복원 전 로컬 백업, 압축·체크섬 검증 및 마이그레이션 상태 확인. 개인 데이터 원본은 보고서에 포함하지 않는다.

## 남은 확인 / 복구

19:17 KST 사용자가 저장한 로컬 설정으로 단발 수집 실행(로컬 run 16060): 대상 37종목,
첫 API 요청에서 인증 거절되어 신규 저장 0건. 추가 진단 응답은 HTTP 401 / 공개 오류 코드 024였다.
단발 테스트가 반복되지 않도록 해당 실행의 로컬 재시도 예약을 해제했다.
설정 파일에는 두 자격 증명이 존재하나 자동 활성화 값은 false이며 변경하지 않았다.
이후 API HUB 주소(`/search/v1/news`)와 X-NCP-APIGW 인증 헤더로 수정했다. 같은 설정으로 최근 24시간, 37종목, 107회 요청 결과 인증 정상·후보 95건·요약 95건을 확인했다. DB 저장은 하지 않았고 자동 활성화 값 false를 유지했다. 검색 창 범위 제한 및 미지원 기사 링크 안내가 남아 있다. 앞선 401을 키 오류로 단정할 수 없으며 이전 호출 방식의 불일치를 수정했다. 운영 수집·저장 흐름 검증은 후속 단계다.
지원 대상 기사 URL은 기존 한경 호스트 및 검증된 네이버 기사 경로다. 네이버 기사 링크가 없는 다른 언론사 결과는 제외하고 지원 대기 안내를 남긴다. 실제 결과로 추가 언론사 필요성을 확인해야 한다.
이번 작업은 로컬 개발이며 PR 생성·운영 배포·운영 DB 변경은 수행하지 않았다.

중단하려면 NAVER_NEWS_ENABLED=false로 바꾸고 수집기를 재시작한다.
DB 구조 변경이 없으므로 스키마 복구는 필요 없다. 코드 복구 시 기존 main으로 되돌린다.

## 보유종목 우선 및 실제 저장 테스트

현재 보유 여부는 활성 계좌의 매수 Lot에서 매도 수량을 차감한 잔량으로 판단한다. 조회 순서와 최종 선별 모두 현재 보유종목을 우선한다. 네이버 후보는 중요도 2 이상으로 제한하고 특징주·기념행사 등은 제외한다. 관련 테스트 10건 통과.

로컬 run 16061에서 후보 7건을 수집했으나 기존 하루 10건 상한으로 자동 신규 저장은 0건이었다. 사용자가 요청한 단발 실제 저장 테스트로만 상한 예외를 적용해 공개 기사 2건(카카오 주주환원, 대한항공 합병 비용)을 직접 검토해 저장했다. 주가 반응·기념행사 및 같은 사건의 반복 보도는 제외했다. 저장된 2건 모두 요약·종목 연결을 검증했고 요약 재시도는 0건이다. 기존 소식은 삭제하지 않았다. 자동 활성화 false와 운영 DB를 유지했다. 공유 제공처 일일 상한은 여전히 10건이며 운영 배포 전 선별 정책과 상한을 확정해야 한다.

## 최종 수집 및 표시 정책 변경

이전 일일 10건 정책은 폐기했다. 전체 제공처를 합쳐 실행 1회당 최대 5건, 일일 저장 한도 없음이다. 중복 제외와 보유종목 우선, 중요 뉴스 선별을 유지한다. 네이버가 활성화되고 후보를 반환하면 기사 RSS는 생략하며, 네이버 실패 또는 후보 없음일 때 RSS를 차선으로 사용한다. 공시·리포트 전용 제공처는 유지한다. 자동 활성화 값 false는 사용자 설정대로 유지한다.

목록은 수집 시각 내림차순으로 정렬하며 한국 날짜별 헤더 왼쪽에 날짜, 오른쪽에 해당 계좌·필터·스냅샷 전체 수집 건수를 표시한다. 날짜만 제공된 소식은 시각 미상 문구 없이 날짜만 표시한다. 네이버 원문 링크도 허용된 기사 경로만 연다.

검증: 관련 단위 테스트 11건, 커버·태블릿 화면 자동 테스트 2건, 수집기·백엔드·프런트엔드 타입 검사 통과. 실제 로컬 DB 읽기 검증으로 날짜별 합계와 목록 전체 건수 일치, 페이지 중복 없음, 수집 날짜 순서 및 상세 이동 일치를 확인했다. 운영 배포는 수행하지 않았다.

## 전체/보유 전환 및 자동 수집 활성화

상단 최근 확인 시각을 제거하고 현재 표시 건수/전체 건수를 이동했다. 유형 탭 오른쪽에 전체/보유 전환을 제공한다. 보유 필터는 서버에서 해당 계좌의 매수 수량에서 분할매도 수량을 차감한 잔량 > 0인 종목으로 조회하며, 페이지·전체 건수·상세 이동·스냅샷을 같은 범위로 묶는다. 보유 화면에는 날짜바를 표시하지 않는다. 유형 전환 시 보유 선택을 유지한다.

사용자 요청에 따라 기존 KRX 비공개 설정 파일의 NAVER_NEWS_ENABLED를 true로 변경하고 로컬 뉴스 전용 프로세스를 실행했다. 기존 DB 주기를 따르며 운영 서버에는 적용하지 않았다. 로컬 프로세스는 비공개 news-auto-dev.mjs로 구동하며 중단/설정 변경 시 해당 뉴스 전용 Node 프로세스만 종료 후 재실행한다.

기사 조회는 네이버가 우선이다. 최근 72시간 내 새 주요 기사 중 기존 저장 건과 후보 중복을 제외한 유효 후보가 5건 이상이면 한경 RSS 기사 조회를 생략한다. 부족/실패 시에만 차선 조회한다. 동일 중요도에서는 네이버 기사를 우선하되 현재 보유종목 우선순위는 유지한다. 공시와 리포트는 전용 제공처를 계속 사용한다.

검증: 관련 단위 테스트 13건, 커버/태블릿 UI 테스트 4건, 실제 로컬 활성 계좌 6개에 대한 보유 건수·스냅샷 분리·상세 이동 검사 통과. 백엔드·프런트엔드·수집기 타입 검사 통과. 공유 빌드 파일 복사 단계는 실행 중 Prisma 파일 잠금으로 한 번 실패했으나, 소스 컴파일과 수집기 타입 검사를 독립 실행해 통과했고 최신 모듈로 뉴스 프로세스를 재시작했다.

## v1.2.4 병합·운영 배포 기준

최종 확정 정책: 실행 1회당 기사 최대 5건, 리포트 최대 5건, 공시 건수 제한 없음. 일일 누적 한도는 없다. 기존 관련성·중복 제외 및 유효기간 검증은 유지한다. 기사와 리포트가 각각 5건, 공시 18건인 혼합 입력이 총 28건 선별되는 테스트를 추가했다. 초기 단일 회당 5건 설명은 이 유형별 정책으로 대체한다.

최종 검사: 전체 수집기 243건 통과, 정책·네이버 관련 14건 통과, 커버/태블릿 화면 12건 및 모든 구성 요소 타입 검사 통과. 운영 네이버 연결값은 서버 비공개 환경 파일에만 주입했으며 기존 설정은 서버 내 제한된 백업으로 보존했다. DB 스키마 변경은 없다. 배포 워크플로가 서버 내 최신 DB 백업과 무결성 확인을 수행한다. 복구 시 NAVER_NEWS_ENABLED=false로 비활성화하고 직전 배포 이미지로 되돌린다. 개인 DB를 Git에 포함하지 않는다.

CI 추가 확인: 기존 통합 테스트가 1주 미만 잔량을 비보유로 가정해 실패했다. 양의 잔량을 보유로 처리하는 정책에 맞춰 소수점 잔량 보유 및 전량 매도 후 보유 0건을 검증하도록 수정했다. 별도 로컬 테스트 DB에서 실제 수집·페이지·스냅샷·계좌 분리 통합 검사 통과. 다른 기존 phase27 UI의 검색 디바운스 대기 테스트 실패는 새 CI에서 재확인한다.
