## 검증 및 실제 확인 범위

[최종 PR Validation](https://github.com/byungho-cho/roxstock/actions/runs/39524846162)과 배포 검증 모두 통과했다. 공통 106개, collector 234개 테스트와 타입 검사·빌드, 실제 MariaDB의 일정 재가동·동시 복구·중복 보정·복구 dry-run·사용자 격리·제외 유지 검증을 수행했다. 재시작 시 사용할 일정과 단계 재개 플래그는 작업/감사 기록과 같은 트랜잭션에 저장한다.

Playwright는 370×465와 725×396에서 혼합 상태·0건·전부 미도래·상태 상세 및 기존 화면 회귀를 통과했다. 이는 CI의 테스트 데이터 화면이며 실제 운영 로그인 화면 캡처가 아니다.

운영 보정 job `118988677908`에서 배포된 백엔드 API 핸들러를 실제 DB와 연결하고 기존 관리자 인증 범위로 호출하여 전체·우선 집계, 8개 상태별 상세 합계, 별도 제외 상세를 DB 공통 집계와 대조했다. 실제 외부 익명 HTTP 요청은 401, 버전 조회는 200이었다. 새 로그인 세션을 생성하거나 타인의 인증정보를 사용하지 않았다. authenticatedBrowserChecked=false이며 운영 로그인 브라우저의 시각 확인은 수행하지 않았다. 사용자 간 접근 차단은 CI의 scoped Prisma/API 테스트로 검증했다.

## 백업·복구

마이그레이션 전 전체 SQL 백업과 보정 직전의 별도 전체 SQL 백업을 서버 `/opt/roxstock/backups/roxstock-v0.2-<실제 UTC 시각>/`에 보존했다. 보정 job은 gzip 무결성·SHA-256 검증, 대상 계획 0600 보존 및 체크섬 확인 후에만 변경했다. 원본 SQL·계획·비공개 로그·인증키·개인 자료는 저장소에 게시하지 않는다.

보정 직후 restore dry-run 결과 restored=0 / restorable=151 / skipped=0이었다. 실제 운영 복구는 실행하지 않았다. 동일 이미지에서 비공개 계획을 인자로 `reconcile-dart-task-status.js restore /absolute/private/plan.json`을 실행하면 감사 스냅샷과 현재 상태가 일치하는 대상만 복구한다. 이후 저장 자료·상태 변경이 생긴 작업은 덮어쓰지 않으므로 개별 검토한다. 중복 apply는 이전 스냅샷·수정 시각 CAS 및 financial lease로 방지한다.
