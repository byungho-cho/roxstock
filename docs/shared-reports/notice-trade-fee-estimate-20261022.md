## 원인과 범위
알림 거래는 공통 거래 폼을 별도 로컬 팝업으로 감싸고 있었다. 수동 등록과 동일한 `/trade` 라우트로 이동하도록 변경했다. 태블릿은 기존 수동 등록 라우트의 반응형 다이얼로그를 그대로 재사용한다. 알림 전용 매수·매도 폼/팝업은 제거하고 연결 매수 선택과 배당의 기존 흐름은 유지했다. 중복 저장이 실제 발생했다고 단정하지 않는다. 기존 requestId 원자적 중복 방지와 저장 후 제출 잠금은 보존했다.

원문에 날짜가 있으면 유효한 명시 날짜를 사용한다. 날짜 필드가 없을 때만 저장된 receivedAt의 Asia/Seoul 날짜를 사용하며 잘못된 명시 날짜를 임의 보정하지 않는다. 알림 계좌·사용자 범위를 확인하고 전달하며, 서버의 소유권·잔여수량 검증은 그대로 유지한다. 알림 경유만 포커스/전체 선택을 생략하고 태블릿 공통 모달의 자동 포커스도 차단한다. 수동 등록의 포커스 동작은 유지한다.

저장 성공 후에만 Android 알림을 처리하고 목록을 갱신한다. 실패·취소 시 미처리 유지. 저장 후 ‘예수금을 입력하시겠습니까?’ 확인을 유지한다. 확인 시 거래 라우트를 연결 cash 라우트로 replace하여 거래 폼이 남지 않는다. 예수금 취소/재입력은 기존 cash 행 PATCH이며 매수·매도 POST를 다시 실행하지 않는다.

## 비용 확인과 산식
cash_transactions에 fee_tax_status (UNKNOWN/ESTIMATED/CONFIRMED), fee_tax_basis_count 및 조회 인덱스를 추가한다. 기존 금액·잔액·연결 ID는 변경하지 않으며 기존 이력은 UNKNOWN으로 보존한다. 과거 nonzero 비용도 실제 확인의 근거가 없으면 자동 확정하거나 추정 기준으로 사용하지 않는다. 이로 인해 최초에는 기준 이력이 없어 수동 입력이 필요할 수 있다. 기존 nonzero 값은 추정으로 덮어쓰지 않는다.

인증된 계좌의 해당 cash 행을 확인한 뒤 같은 매수/매도, 시장, 상품 유형, 이전 거래일 및 이전 등록 이력 중 CONFIRMED만 조회한다. OTHER 분류는 추측하지 않는다. 실제 비용 0원은 CONFIRMED이면 포함하고 UNKNOWN 0원은 제외한다. 연결이 없는/삭제된 거래, 금액 0 이하, 수량×단가와 원장 금액 불일치, 음수 또는 거래금액을 초과하는 비용, 미확인 추정은 제외한다. 최근 유효 3건을 25행 단위 조회로 선택하므로 전체 이력을 메모리에 올리지 않는다.

비용 합계 ÷ 거래금액 합계의 가중 비율을 이번 수량×단가에 적용한다. Decimal 고정밀 계산 후 기존 원장 DECIMAL(19,4)의 4자리 half-up 규칙을 사용하며 법정 세율로 표시하지 않는다. 기준 0건이면 추정을 반환하지 않는다.

화면에 추정 금액과 ‘최근 매수/매도 N건 기준’을 표시한다. 사용자 수정 가능. ‘실제 금액으로 확인’ 체크를 명시적으로 선택하고 저장해야 CONFIRMED로 바뀐다. 저장만 하면 ESTIMATED/UNKNOWN을 유지하고 다음 기준에서 제외한다. 값 수정 시 확인을 해제하며 늦은 조회/재렌더링이 사용자의 입력을 덮어쓰지 않는다. 기존 확정값은 보존한다.

## 예수금 계산
거래 저장 시 거래금액은 기존 원장에 한 번 반영된다. 비용 입력은 해당 행의 세전 잔액(기존 세후 잔액 + 기존 비용)을 기준으로 새 비용만 차감한다. 이 방식은 매수/매도 모두 기존 거래 전 잔액 ± 거래금액 − 비용과 같다. 거래금액을 다시 반영하지 않으며 최신 행일 때만 기존 syncCurrentCash 경로로 계좌 현재 잔액을 갱신한다. 이전 행은 이후 잔액이나 스냅샷을 재작성하지 않는다. 실제 잔액 직접 입력과 기존 세전/세후 필드도 유지한다.
