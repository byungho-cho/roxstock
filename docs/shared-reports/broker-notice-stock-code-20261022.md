# 카카오 거래 알림 종목 코드 식별 수정 (2026-10-22 KST)

기준 main: af5fe6ffd8608d88926823a0d99fde0faf1b9377 (1.2.9). 별도 브랜치 fix/broker-notice-stock-code-20261022. 패치 1.2.10 준비.

## 재현과 원인 구분
미래에셋 원문의 종목명 기아(A000270)를 기존 파서에 전달하면 name='기아(A000270)', symbol=undefined였다. 기존 연결 조건은 코드가 없으면 종목명을 정확히 비교하므로 앱의 name='기아', symbol='000270'과 일치하지 않았다. 수정 전 파서 회귀 테스트에서 이 차이를 재현했다. 이 오류는 클라이언트 종목 선택 단계에서 매수 POST 이전에 발생한다.

앞선 수동 매수 오류는 인증 소유권 wrapper가 commit 전 신규 매수 Lot을 트랜잭션 밖 연결로 조회해 POST /api/buy-trades에서 404 NOT_FOUND가 발생한 서버 문제였다. 해당 수정은 1.2.9에 실제 적용돼 있고 이번 브랜치에서도 유지한다. 두 오류는 다른 원인·단계이며, 종목 코드 파싱 수정으로 서버 트랜잭션 검증을 우회하지 않는다.

## 변경
- 종목명 끝의 코드 괄호에서 국내 숫자 코드 형식 A + 6자리 또는 6자리 자체를 확인한 경우에만 이름과 코드를 분리한다. 예: 기아(A000270) → 기아 / 000270, 현대차(A005380) → 현대차 / 005380.
- 코드는 문자열로 다뤄 선행 0을 보존한다. 별도 종목코드 필드도 같은 정규화를 사용한다.
- 정확한 정규화 코드가 있으면 코드로 우선 조회한다. 코드가 없는 경우에만 유일한 동일 이름을 허용한다. 유사도/부분 이름 검색은 사용하지 않는다.
- 명시된 코드가 잘못됐거나 괄호 코드와 별도 코드가 충돌하면 연결하지 않는다. 일치 대상이 없거나 여러 개여도 임의 선택하지 않는다.
- 매수·매도·배당은 동일 파싱/종목 연결 함수를 사용한다.
- 알림 가격/수량/배당금과 매도 연결 선택 요약에 천 단위 구분자를 적용한다. 108400 → 108,400원. 숫자 문자열/소수 정밀도를 보존하며 실제 폼/API 값은 108400으로 유지한다.

## 기존 미처리 알림
Android SQLite는 raw 원문과 원본 ID/상태를 보관하고 조회 시 웹 공통 파서가 매번 해석한다. 따라서 재수신·DB 보정 없이 저장된 raw를 수정된 파서로 처리한다. 원문·원본 ID·owner·완료/무시 상태·중복 fingerprint는 변경하지 않는다. 새 APK/SQLite migration/서버 거래 원문 동기화는 필요하지 않다. 새 웹을 로드한 뒤 같은 미처리 알림으로 이어서 등록한다.

## 검증
- 파싱/식별/표시 순수 테스트 7건 통과: 기아 A000270, 현대차 A005380, 선행 0, 정확한 코드 우선, 없는 코드, 잘못된 형식, 코드 충돌, 이름만 있는 알림, 중복 이름, 유사 이름 거부, 매수/매도/배당 공통 경로, 소수 보존 및 천 단위 표시.
- 커버 370×465 / 태블릿 725×396 Playwright 통합 알림 24건 통과. 모의 Android 원문 보관함의 오래된 기아 알림을 취소·reload 후 같은 ID로 열어 자동 입력과 저장 요청, 성공 후 처리 확인. 식별 불가 알림은 API 호출 없이 보관함에 남음.
- 저장 요청: 기존 등록 종목 ID에 quantity='10', unitPrice='108400', 동일 원본 requestId. 화면 입력값은 108,400으로 표시됨.
- 운영과 분리된 MariaDB에서 기존 실제 인증 거래 테스트에 같은 10주/108400원 입력을 대입해 201·원장 금액 1084000·중복 1회 저장 확인. 기존 수동 매수·추가 매수·평균단가·예수금·소유권 및 전체 롤백 검증도 통과했다. synthetic 계좌/종목 fixture이며 운영 개인 거래를 생성하지 않았다.
- frontend TypeScript 및 production build 통과. 기존 번들 크기 안내 외 실패 없음. 순수 테스트를 기존 필수 통합 알림 CI 단계에 추가했다.

## 배포 및 미검증
이 보고서 최초 작성 시점에는 CI·병합·실제 배포 전이다. CI 통과 후 main 병합과 웹 배포를 진행하고 실제 공개 웹 bundle 및 /api/version 1.2.10을 확인한다. 네이티브 변경이 없어 APK는 0.1.8 유지한다. 실제 휴대전화의 원문 재수신·로컬 SQLite 클릭은 미검증이다. 운영 개인 계좌에 테스트 거래를 임의 생성하지 않으며 실제 기기 재시도 확인은 별도로 남긴다.

운영 DB 변경·알림 재수집·강제 상태 초기화·자료 삭제는 하지 않는다. 문제 시 기존 배포 이력의 이전 frontend 이미지로 복귀하고 원문/상태를 유지한다.
