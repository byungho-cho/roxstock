# 34차 저장 안내·종목소식 UI와 공개 근거 요약 보완

기준: main `b77b428043ca93c1909baec6e8b0b7958240c182` / 1.1.19 → **1.1.20**. 32차 홈·33차 소식 구현을 보존하고 별도 브랜치에서 변경했습니다. 기존 조사 초안 PR과 다른 작업 트리는 변경하지 않았습니다.

## 화면·저장

- 목표가 조건 저장 후 새 버전의 목표가 목록을 실제 조회하고 홈 캐시에 반영한 경우에만 공통 토스트 `저장했습니다. 홈 목록을 갱신했습니다.` 표시. 고정 토스트 큐를 공유해 저장 버튼의 위치와 레이아웃은 유지합니다. 저장 또는 후속 조회 실패에는 성공 토스트 없음.
- 목록/요약 헤더 장식 뉴스 아이콘 삭제. 상세 뒤로가기·수집 갱신 시각·순번 유지. 더보기 소식 아이콘은 기본색 마스크, 하단 선택 메뉴 노란색 유지.
- 부분/전체 수집 실패는 필터·건수 옆 공통 ClickInfo 느낌표 툴팁으로 안내. 모바일 클릭, 키보드 Enter/Escape 지원. 정상 상태는 생략.
- 페이지에 포함된 관련 종목에 대해 현재 계좌 매수 수량에서 해당 Lot의 매도 수량을 뺀 합계를 DB에서 계산합니다. 1주 이상인 경우 목록과 상세 테두리·종목명을 노란색으로 표시합니다. 관심 등록/거래 이력/타 계좌 보유만으로 강조하지 않습니다. 거래·계좌 변경의 기존 stockNews/stockNewsDetail 캐시 무효화를 재사용합니다.
- 상세는 남은 가용 높이를 flex로 채웁니다. 상단 고정 헤더, 고정 이전/다음, 카드 메타 정보와 본문 스크롤을 분리하고 하단 여백 8px와 safe-area를 반영합니다. 요약 없음/로딩/조회 오류에도 같은 카드 틀을 유지합니다. 기존 스와이프 방향·경계·세로 판별을 유지합니다.

## AI 없는 수집·요약

외부 생성형 AI, API 키, 비용, 신규 PDF/OCR 패키지를 추가하지 않습니다. 유효한 기존 요약은 덮어쓰지 않습니다. 우선순위는 공개 제공처 소개/요약 → 공개 본문 문장 → `요약 정보 없음`입니다. 문장을 약 200자에서 우선 끝내고 최대 300 Unicode 문자로 제한하며 숫자·단위 토큰 중간을 자르지 않습니다. 제목 반복/광고/메뉴/기자/면책 문구를 걸러냅니다. 요약 조회 API는 원문 수집을 실행하지 않습니다.

| 제공처 | 구현 | 제한 |
| --- | --- | --- |
| 한국경제 기사/RSS | 피드 요약 보존, 공개 메타 description 우선, 알려진 article-body 컨테이너의 문장 추출 | 유료·로그인 자료는 head 공개 소개문만 사용. 응답 1MB, 소개 64KiB. robots 금지 /api 등 호출 안 함 |

## 영속 큐·실패·운영

`stock_news_items`에 summary_status/attempts/checked_at/next_retry_at/source/reason 6개 열과 `(summary_status, summary_next_retry_at, id)` 인덱스를 추가합니다. 마이그레이션 `20261019190000_stock_news_summary`는 기존 행/금액/소식/계좌/수집 이력을 삭제하지 않습니다. 기존 요약이 있는 행은 READY로만 표기합니다.

- 조회 시점이 아닌 collector에서 DB 조건으로 미요약 PENDING 또는 재시각 도래 RETRY **최대 5건**을 처리합니다. 기존 뉴스 공용 lease와 쓰기 시 소유권 검증을 사용합니다. 90초 작업 한도, HTTP 15초·최대 2회, DART API 기존 20초 한도. 외부 요청은 배치 대상과 공급처별 제한에 묶입니다.
- READY, NO_DATA(근거 없음), BLOCKED(403/차단), UNSUPPORTED와 RETRY(통신/일일 예산 등)를 구분합니다. 종결 상태 재조회 없음. 일시 실패는 1시간 뒤(기존 DART 예산 소진은 다음 KST 06:00) 재시도, 항목별 최대 3회. 재배포/중단은 같은 DB 상태에서 이어갑니다.
- daemon의 기존 독립 소식 점검(60초)에서 수집 뒤 요약 배치를 실행합니다. CLI: `docker exec roxstock-collector node collector/dist/worker.js news-summary`. `stock-news-summary` 작업/항목 이력은 공통 수집 모니터링에서 조회합니다. 원문 전체/ZIP/PDF는 DB나 저장소에 저장하지 않습니다.
- 기존 최초 수집 1회와 다음날 06:00 수집 일정, 주가/DART 호출 예산·작업 우선권은 유지합니다. 배포 검증 작업은 멱등 news/news-summary와 저장 API를 확인하고 상태별 집계만 로그에 남깁니다.

## 배포·롤백

기존 운영 DB 백업(gzip+checksum, 서버 내부 보관)을 유지한 뒤 추가 마이그레이션과 backend/collector/frontend 이미지를 배포합니다. 네이티브·패키지 변경은 없어 APK 재배포 대상이 아닙니다.

이전 1.1.19 backend/collector/frontend 이미지로 되돌릴 수 있으며 추가 열·인덱스를 남겨 구버전의 읽기/저장 호환성을 유지합니다. 새 큐 배치는 구버전 collector에서 실행되지 않습니다. 새 요약과 처리 이력을 삭제하지 마세요. DB 백업 복원은 이후 거래까지 되돌릴 수 있으므로 일반 롤백으로 사용하지 않습니다. 키·DB 덤프·원문 파일은 저장소에 올리지 않습니다.
