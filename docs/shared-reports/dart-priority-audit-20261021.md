## 화면·API·DB의 정확한 집계 조건

### 우선종목 선정

실행 코드 `shared/src/collection/job-repository.ts`의 `prioritySecurityIds()`는 활성 계좌의 STOCK 종목 가운데 HOLDING·WATCHLIST 등록 또는 매수 이력이 있는 종목의 합집합을 선정한다. 전량 매도된 매수 이력도 후보에 포함한다. 정렬 우선순위에는 보유·관심 구분 및 설정 우선순위가 사용되지만 보고서에는 개인별 구분·순위·수량·거래·계좌 식별자를 싣지 않았다. RECOMMENDED만 등록된 종목은 이 목록으로 선정되지 않는다.

실제 화면의 API는 인증 컨텍스트에 따라 개인 데이터 범위를 제한한다. 조사 초기 전역 후보는 37개였으며 최종 수집 적격 조건을 적용하면 35개였다. 별도로 인증 범위별 후보를 서버 내부에서 대조하여, 기준 화면의 35개 범위와 조사 집합의 동일성을 확인했다. 따라서 전역 합집합을 아무 인증 화면에나 적용하는 방식으로 일반화하면 안 된다. 범위별 사용자 식별자는 추출·게시하지 않았다.

API가 우선후보에 추가하는 조건은 다음과 같다.

1. `securityType = STOCK`, DART 매핑 행 존재.
2. 종목 유형이 REIT·ETF·ETN이 아님, Z99 접두사 아님.
3. `collectionExcluded = false`이고 `excludedFeatures`에 `dart-financial-statements`가 없음 또는 SQL NULL.
4. `isActive = true`는 이 우선종목 집계 조건에 **없다**. 따라서 비활성 우선종목도 포함될 수 있다.

최종 35개는 아래 종목별 표의 전체 집합이다. 현재 종목코드 = DART `stockCode` = `collectionSymbol` 일치 **35/35**, 서로 다른 회사번호 **35개**, 매핑 없음 **0개**다. 표시명 현대차/현대자동차, KT/케이티, KT&G/케이티앤지는 명칭 차이이고 종목코드가 일치한다. 회사번호가 있는 종목만 화면 범위로 들어오므로 이 결과로 전체 마스터의 매핑 누락이 없다고 결론낼 수는 없다. 외부 회사번호 원본을 새로 내려받아 대조하지는 않았다.

### 작업 기간·상태

`dartTaskScope(now)` = 요청 연도 2015–2026 AND (사업보고서 OR 요청 연도 ≥ 2020) AND 위 수집 적격 종목 조건이다. 여기에 최종 35개 `securityId IN (...)`를 적용한다. API의 날짜·상태·시장·종목 필터는 실행 이력 조회에 적용되며 우선종목 과거 작업 누적 집계에는 추가되지 않는다. 이번 조회에는 해당 필터를 넣지 않았다.

사업보고서 12개 연도(2015–2026) + 분기·반기 7개 연도 × 3종(2020–2026) = 종목당 33건, **35 × 33 = 1,155건**이다. 보고서 코드: 11013=1분기, 11012=반기, 11014=3분기, 11011=사업보고서. 요청 `fiscalYear` 필드가 화면의 연도다. 특히 3월 결산 3S의 분기는 일반적인 12월 결산사와 같은 월로 해석하면 안 된다. 현재 캐시의 `CALENDAR_REPORT_YEAR` 선택 정책과 실제 제목의 기간을 사용했다.

화면 `CollectionProgress`는 `NO_FILING + NOT_APPLICABLE`을 ‘미공시·대상 아님’으로 묶는다. 검토 보류는 `FAILED AND errorCode=REVIEW_REQUIRED`를 별도로 세어 실패 수에서 분리한다. 현재 API의 전체 범위 검토 보류는 289건이지만 이 보고서 범위의 `priority.reviewRequired`는 **1건**이다. 둘을 혼합하지 않았다.

## 사유의 타당성 검증

### 정상적인 미공시 — 70건

34개 12월 결산사 각각의 2026 사업보고서·3분기보고서 **68건**과 3월 결산 3S의 2026 반기·3분기 **2건**이다. 35개 기업의 유효한 2026 캐시 모두 v2 선택 정책을 사용하며 해당 보고서 후보가 없다. 각 사의 결산월은 저장된 사업보고서 제목과 캐시 `selection.annualPeriods`·`fiscalYearEndMonth`로 대조했다.

- 34개사의 사업보고서: 대상기간 2026-12-31, 아직 기간 미종료 **34건**.
- 34개사의 3분기보고서: 대상기간 2026-09-30, 조사일은 21일 뒤로 일반적인 45일 제출기간 이전 **34건**.
- 3S 반기: 3월 결산이므로 대상기간은 2026-09-30, 제출기간 이전 **1건**.
- 3S 3분기: 대상기간 2026-12-31, 기간 미종료 **1건**. 현재 2026-03 사업보고서 및 2026-06 1분기 공시는 캐시에 존재한다.

금융감독원 [DART 보고서정보](https://dart.fss.or.kr/introduction/content2.do) 및 [기업공시 길라잡이](https://dart.fss.or.kr/info/main.do?menu=210)의 공식 검색 결과는 사업보고서 90일, 분·반기보고서 45일의 일반 제출기간을 안내한다. 원문 직접 열기는 502로 실패하여 공식 페이지의 검색 색인에 있는 안내를 근거로 삼았다. 개별 회사의 연장·특례·최종 휴일 조정일을 확정한 것은 아니다. 여기서는 일반 제출기간조차 지나지 않았거나 대상기간이 끝나지 않았다는 점만 사용했다. 이 **70건은 조사 시각의 정상적 미공시라는 판단**이며 조기 제출 가능성까지 배제하거나 영구적 부존재를 확정하는 판단이 아니다.

현대홈쇼핑은 현재 DB `isActive=false`이나 수집 대상인 STOCK으로 매핑되어 있고 위 2026 캐시 근거가 동일하게 적용된다. 비활성 사유로 제외한 작업은 없다. 비활성 등록 자체의 정확성은 이번 근거만으로 확정하지 않았다.

현재 수집 코드는 네트워크 오류·타임아웃·유효하지 않은 JSON·013 외 API 오류를 예외로 전파하고 FAILED/검토 경로로 처리한다. `NO_FILING`은 목록 후보 없음 또는 CFS/OFS 재무 행 없음 분기에서만 저장된다. 따라서 현재 실행 코드에서 통신 오류를 곧바로 미공시로 처리하는 경로는 발견하지 못했다. 그러나 과거 판정 시의 원응답이 없으므로 **164건 전부에 대해 실제 통신 오류가 없었다고 확정할 수는 없다**.

현재 공시 조회기간은 요청연도 전년 1월 1일–조회 당일 KST, `pblntf_ty=A`, `last_reprt_at=N`, 100건씩 전체 페이지 순회다. 보고서 제목의 기간과 회사번호를 검증하고 정정 후보를 정렬한다. 캐시는 회사번호·요청연도별로 24시간 유효하며 최신 선택 정책 v2와 `CALENDAR_REPORT_YEAR`가 맞아야 재사용한다. 과거 캐시가 단순 빈 목록이거나 구버전 후보인 경우 실제 공시를 놓쳤는지 단독 판단할 수 없다. 만료된 과거 NO_FILING/NOT_APPLICABLE 작업이 다시 선택되지 않는 점도 수정 시 검토해야 한다.

## 보존·검증·한계

- 원 DB와 기존 로그는 운영 서버에 그대로 유지했다. 필요한 DB 행·공시 후보·실행 로그의 원형 추출과 실행 코드 사본은 Git 작업 트리 밖 서버 비공개 조사 디렉터리에 보존했다. 공개 저장소에는 원본 DB·로그·스크립트·자격증명·사용자/계좌 식별자·개인 보유수량·거래·자산 데이터가 없다.
- 관련 작업의 DB 실행 항목 **788개**를 읽었고, 164건 및 별도 보류 1건 모두 최소 1개 이상의 관련 이력이 확인되었다. 실행 항목의 `diagnostics`는 이 조회 범위에서 전부 NULL이다. 현재 DART 컨테이너의 해당 기간 stdout/stderr 조회 결과는 0바이트로, 이 결과가 과거 실패가 없었다는 뜻은 아니다. 실제 근거는 DB 작업·실행 항목·공시 캐시·저장 공시다.
- 저장 공시는 개인 데이터 없이 접수번호·기간·판본 메타데이터만 조회했다. 164개 대상 조합에 현재 비철회 저장 공시가 없는지 대조했으며, 회사별 다른 기간의 저장 공시는 회사 연결·결산월 근거로만 사용했다. 재무 금액은 보고서에 싣지 않았다.
- 생성 시 검증: 상세 164행, 종목·연도·보고서 조합 중복 0, 상태 합계 151+13=164, 검증 합계 70+13+81=164, 전체 990+164+1=1155, ROWS 57개 선택번호–캐시 일치, 정상 70건 유효 캐시·대상후보 없음, 매핑 35개 종목코드 일치, API 핸들러 수치와 DB 일치.
- 2026 과거 종료 판정의 정확한 법적 제출기한이나 개별 특례는 확정하지 않았다. 현재 저장 근거만으로 금융회사 API 미제공 이유·더본코리아 설립 전 여부·13건의 과거 매핑 소실 원인은 미확인이다.
- **상태 초기화·재수집·데이터 수정·재시작·배포를 수행하지 않았다.** 변경물은 이 보고서와 비식별 상세 목록 문서뿐이다.
