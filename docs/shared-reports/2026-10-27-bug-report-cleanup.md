# 운영 오류 리포트 점검·정리

## 요청과 범위

사용자 요청: 보완 가능한 원인은 처리하고, 현재 미해결은 한 검토 항목으로 통합하며 해결된 리포트는 백업 후 삭제한다. 재무 원본·기존 보완값·개인 자산은 삭제 대상이 아니다. 삭제 후 과거 실행 로그가 재생돼 같은 리포트가 다시 생기지 않도록 발생 해시는 유지한다.

첫 읽기 전용 점검: 리포트 36그룹, 연결 발생 이력 9,460건. 미해결에는 과거 수집 실패와 원천 검증 보류, 기간 문맥이 누락된 항목이 함께 있었다. 아래는 초기 시점 수치이며 실행 후 수치는 별도 기록한다.

## 확인한 프로그램 문제와 수정

1. 원본 작업의 메시지가 정확히 `REVIEW_REQUIRED`이고 구체 오류 코드가 없을 때 이를 일반 `COLLECTION_FAILED` 오류로 표시했다. `SOURCE_REVIEW_REQUIRED` 경고로 구분하며 여전히 **미해결 검토**로 유지한다. 명시된 DB/통신 오류는 우선하고 경고로 낮추지 않는다.
2. 예전 repository는 대상 문맥을 `종목:task.fiscalYear:task.reportCode`로 기록했으나, 복원기는 ANNUAL/Q1/Q2/Q3 문자열만 읽었다. 실제 발생 hash·작업 ID·종목 ID·시각이 일치하는 경우에만 11011/11013/11012/11014를 ANNUAL/Q1/Q2/Q3로 복원한다. 기존 task 연도를 유지하며 결산월이나 실제 재무기간 종료일을 추정하지 않는다. 초기 사본에서 1,312건의 누락된 기간 문맥을 복원할 수 있었다.
3. 값이 이미 채워진 `KRX_ROLLOUT_NOT_VALIDATED` 등 일부 지표 오류는 자동 재검증 목록에 없었다. 재무 지표 5개 필드에 속한 오류를 동일 종목·기간의 최신 저장 상태로 확인한다. 0뿐 아니라 음수 분모의 PER/PBR 정상 미적용도 구분한다. 더 오래된 자료나 종목코드 변경 후 근거가 불명확한 이력은 해결 처리하지 않는다. 트랜잭션 안에서 최신 자료 시각을 다시 확인한다.

기존 공통 계산기·재무 저장·권한 경로는 변경하지 않았다. 실제 재무 데이터 보완을 의미하지 않는 분류 변경은 저장 성과로 계산하지 않는다.

## 검증과 운영 절차

- 백엔드 전체 157개 검사 중 156개 통과, 기존 DB 조건부 1개 skip. 타입 검사·빌드 통과. 구체 DB 오류 우선, 명확한 과거 report code 복원, 새 저장값으로 해결, 비양수 정상 미적용, 오래된 자료/종목코드 변경 보호 포함.
- 변경 전 최신 전체 운영 DB 백업의 gzip 검사·별도 비공개 복제 SHA-256 일치를 확인했다. 초기 사본, 작업 문맥 및 실행 전후 리포트·발생 기록은 Git 밖의 비공개 위치에 보관한다.
- 복원된 기간과 실제 저장된 재무·시세 근거를 대조해 해결 여부를 판정한다. 자료 미확보·원문 검증 보류는 성공으로 바꾸지 않는다.
- 미해결 그룹은 `REVIEWING`으로 전환해 기존 `REVIEW_PENDING_SUMMARY` 한 카드로 보여 준다. 원래 코드·발생 시각·종목·기간·작업 ID와 메모는 보존한다. 전체 발생 이력을 한 가짜 원인으로 덮어쓰지 않는다.
- 해결 상태이며 활성 사건이 없는 리포트만 삭제한다. 삭제된 리포트의 발생 문맥은 기존 삭제 정책에 맞춰 제거하되 중복 방지용 해시·관측 시각은 유지한다. 다른 미해결 그룹의 사건을 삭제하지 않는다.
- 실행 후 기본 목록 한 카드·신규 0·해결 0, 미해결 문맥 보존과 삭제 후 중복 재생 방지를 확인한다. 이후 실제 새 사건은 기존 정책대로 신규 표시될 수 있다.

DB migration·Android 변경 없음. 표시 버전은 1.2.29다.

## 복구 기준

최신 전체 DB 백업·gzip 검사·비공개 별도 복제의 SHA-256 일치와 정리 직전 리포트/발생 사본을 보관했다. 삭제·재분류 전후 사본, 실제 해결 판정 결과, API 검증 및 이력 보존 대조 결과도 Git 밖에 보관했다.

복구가 필요하면 전체 운영 DB를 과거 시점으로 덮어쓰지 않는다. 사전 사본과 정리 후 상태를 대조해 이번 작업의 리포트와 발생 행만 선별 복원한다. 이후 신규 사건이나 검토 변경이 있으면 자동 덮어쓰지 않고 충돌 대상을 분리한다. 재무·개인 자산 테이블은 복구 대상이 아니다. 코드 복구는 기존 백엔드 이미지로 전환하되 인증과 관리자 접근 통제를 유지한다.
