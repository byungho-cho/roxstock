# 종목 관리 W 집계·손익 표시·선별 재처리

## 변경 범위

웹 표시 버전 1.2.41. 최신 main `168a4e09`에서 별도 브랜치로 작업했습니다. Android 네이티브·APK와 DB 스키마는 변경하지 않습니다.

- 종목 관리 종합/가치 탭: 직전 연도 결산과 당해 연도 추정을 분리하고 같은 관리 대상 분모를 사용합니다. 기존 공통 W 계산기를 재사용하며 파랑은 W 계산 가능, 파랑 내부 노랑은 그중 가치지표 부족입니다. 다른 연도/분기 자료로 대체하지 않습니다. 재무 탭의 분기 현황은 유지합니다.
- 제목·기준일자 글꼴을 통일하고 기준일자·하단 설명은 본문 응답이 준비된 후 표시합니다. 50개 표시/50개 선조회, 조건 분리, 직접 상세 재진입을 보존합니다.
- 투자손익: 종목별 손익률, 가운데 비율 우측 기준선, 투자금 기준일 인라인 표시, 정렬 아이콘을 적용했습니다. 연도/거래 월 카드의 구분선·매매/배당 열·색상과 비율을 조정했습니다.
- 매매 비율은 연결된 매도 수량의 매수원가 기준입니다. 배당 비율은 해당 종목·연도 매수총액 기준이며 툴팁에 명시합니다. 배당 권리 기준일 보유원가 또는 시장 배당수익률을 구현한 것은 아닙니다. 원가가 없거나 0이면 비율은 미산정입니다.
- 거래 API는 원가 계산 근거만 추가합니다. 원래 손익·배당액·월/전체 합계·소유권 검사·페이지 정렬은 유지합니다. 이전 응답 캐시와 새 계산 근거 응답은 구분합니다.
- 네이버 연간 파서는 검증된 DART 결산월을 사용합니다. 12월만 찾던 조건을 보완하되 다른 결산월을 빌려 쓰지 않습니다. 선택적 보조 표 미제공은 자료 부족으로 구분하고 통신·인증·검증 오류를 무시하지 않습니다.

## 로컬 두 건 선별 재처리

공시 `20261028000469`(씨엑스아이), `20261028000493`(GRT)만 기존 lease·잠금·API 예산과 저장 경로로 재처리했습니다. 새 공시 발견이나 과거 대기열 초기화를 실행하지 않습니다. 기존 시도 횟수를 보존해 3회에서 4회가 됐고 새 실행 이력을 추가했습니다.

결과: 대상 2, 성공 0, 실패 0, 부분 완료 2. 재무 원천 저장을 확인했습니다. 두 종목 모두 EPS·BPS·ROE는 존재하지만 원천 통화가 CNY이므로 PER/PBR은 `CURRENCY_CONVERSION_REQUIRED`로 남았습니다. 환율 근거 없이 KRW 주가와 섞어 계산하지 않았습니다. `NAVER_ANNUAL_TABLE_MISSING` 예외는 재현되지 않았습니다. 조회 커서와 지정하지 않은 모든 공시 대기열 행의 해시가 변경되지 않았음을 확인했습니다. 기존 오류·실행 이력은 삭제하지 않습니다.

## 검증

- 공통 계산/정책 138건, 수정 관련 수집기 16건, 실제 인증/DB 통합 2건, 휴대폰·태블릿 UI 18건 통과.
- 추가 선별 재처리 DB 통합 1건 통과: 명시 목록 외 행과 조회 커서 불변, 시도 횟수 보존, 자동 발견 없음 확인.
- shared/backend/collector/frontend 빌드 통과. 실제 로컬 데이터 두 화면 크기에서 두 연간 카드·분기 4개 카드·100개 표시·상세 재로드·안내 표시 확인.
- CI에 연간 집계 API, 선별 재처리, 두 화면 크기 UI 검증을 연결했습니다.

## 실행·복구

기본 읽기 전용 계획:

```sh
node collector/dist/security-data-reprocess.js --receipts 20261028000469,20261028000493
```

실제 반영은 `--apply --backup-dir /비공개/백업/경로`를 추가합니다. 현재 확인 범위 안의 최대 20개 고유 접수번호만 허용하고 변경 전후 두 종목의 기간 지표·공시·선별 공시 상태를 비공개 위치에 보관합니다. 과거 조회 범위/스케줄을 재개하지 않습니다. 새로 완료된 건은 건너뜁니다. 부족한 건을 재검토할 때만 다시 지정합니다.

코드 복구는 이전 인증/소유권 검사가 있는 1.2.40 이미지로 수행합니다. 이번 작업에 DB 마이그레이션은 없습니다. 데이터 복구가 필요하면 비공개 사본과 현재 행을 먼저 대조해 두 접수번호·기간에 한정합니다. 기존 실행/오류 이력을 삭제하거나 DB 전체를 덮어쓰지 않습니다. 로컬 사본을 운영 DB로 이관하지 않으며 운영 선별 실행은 운영 최신 원천을 재확인합니다.
