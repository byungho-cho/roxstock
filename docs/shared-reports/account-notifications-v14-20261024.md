# 계좌별 알림 설정과 최고 목표 통합 · 2026-10-24

기준 main `89c3ce277b9795a869d3faca33d326ccaad01834`에서 별도 브랜치로 작업했다. 웹 버전은 **1.2.18**, Android는 **0.1.10 / versionCode 11**이다. 거래·수익 계산과 DART 수집기를 변경하지 않는다.

## 적용 내용

- 계좌 전체 AND 매수·매도·배당·소식·목표 종류별 설정을 서버에 저장한다. 새 계좌는 OFF, 기존 사용자 설정은 각 소유 계좌로 이관한다. 전체 OFF는 하위 선택값을 보존한다.
- 설정은 필드별 PATCH를 순차 처리한다. 실패한 변경만 복원하고 뒤에 대기한 사용자 선택을 재적용한다. 서버 정책 revision으로 늦게 도착한 네이티브 설정 응답이 최신 값을 덮어쓰지 않게 한다.
- 목록·플로팅 배지·계좌 건수는 실제 표시 항목에서 계산한다. 메인 계좌 우선, 나머지는 기존 displayOrder 순서다. 공통 카드의 무시 버튼은 둘째 줄 우측에 둔다.
- 목표는 기존 정밀 Lot 판정을 그대로 호출해 실제 충족한 최고 비율을 선택한다. 사용자·계좌·종목·KST 날짜별 최고 기준을 별도 테이블에 보존하고, 설정/수집/발송을 같은 사용자 행 잠금으로 직렬화한다. 낮은 기준 재진입·무시·재시작·동시 실행은 중복을 만들지 않는다. 다음 날의 새 항목은 전일 미확인 항목을 대체한다.
- 소식은 잔여 보유 Lot이 있는 허용 계좌별로 표시하되 사용자·기사·기기당 시스템 발송은 한 번 생성한다. OFF 중 소식 및 최초 목표 기준은 시스템 알림으로 소급 발송하지 않는다. 기존 미확인 목록의 복원은 발송과 분리한다.
- Android 카카오 원문은 기기 안에만 보관한다. 모호한 계좌번호를 현재 계좌로 대체하지 않는다. OFF 중 보존한 항목은 ON 때 표시할 수 있지만 시스템 재발송하지 않는다. 서버에 원문이나 카카오 등록 대기 목록을 추가하지 않는다.
- 네이티브 시스템 발송 직전 서버 인증·소유권·현재 계좌 설정을 확인한다. FCM은 해당 이벤트가 아직 미확인인지도 확인한다. 네트워크/인증 확인 실패 시 시스템 표시를 생략하고 원본 대기 항목은 보존한다. FCM 도착 순서가 뒤집혀도 낮은 목표가 높은 목표를 덮지 않도록 기기에도 최고 기준을 보관한다.
- 다른 계좌의 거래 알림에서 계좌 전환 중 종목 조회가 중단되던 기존 문제도 수정했다. 기존 등록 폼·매수 연결·취소/실패 유지·성공 후 제거 동작을 재사용한다. 새 소식 이벤트는 해당 기사 상세로 이동한다.

## 데이터 보존과 복구

개발 DB는 변경 전에 비공개 gzip 백업과 압축 무결성을 확인했다. 운영 적용은 기존 자동 배포의 사전 백업·checksum·마이그레이션/health 절차를 따른다. 운영 DB를 로컬 데이터로 덮어쓰지 않는다. 신규 테이블 2개와 알림 메타데이터만 추가하며 계좌·Lot·분할매도·예수금·배당·스냅샷 값은 변경하지 않는다.

기존 목표 이벤트는 삭제하지 않는다. 기존 identity에서 종목/비율/날짜를 이관하고, 중복 미확인 표현만 dismissed로 표시하며 관련 대기 발송을 취소한다. 실제 최고 이력은 별도 테이블에 남긴다.

복구는 같은 스키마의 후속 수정 배포를 우선한다. 구버전 코드로 되돌려야 한다면 먼저 알림 worker를 중단하고, 기존 사용자 전체 설정의 trade/news/target 플래그를 OFF로 묶어 계좌별 OFF 우회를 막고 대기 delivery를 취소한다. 추가 스키마를 자동 DROP하거나 운영 전체 DB를 복원하지 않는다. 필요한 알림 행만 변경 전 비공개 백업과 대조해 복원한다. 개인 API의 인증 보호를 유지한다.

APK는 예전 파일로 링크를 되돌려도 이미 설치한 versionCode 11을 자동 다운그레이드할 수 없다. 같은 패키지·기존 서명으로 versionCode 12 이상인 수정 APK를 배포한다. 개인 앱 데이터를 삭제하는 복구를 자동 실행하지 않는다.
