배포 대상: 웹 1.2.35 + 정상 제외 전용 문구 보정 1.2.36 + 조회 경합 보정 1.2.37 / Android 변경 없음. 기준 main e031ebac (1.2.34).

## 변경

- 집계 정책 SECURITY_DATA_20261028_V2. 종목 관리는 종목·보고기간의 저장 자료 충족 현황이다. 재무 6개 누적/기말 항목과 가치 EPS/BPS/ROE/PER/PBR 5개 항목으로 판단하며 상세 26항목과 구분한다.
- 숫자만 존재해서는 충족하지 않는다. 같은 기간·연결/별도·통화·보통주 근거를 확인한다. 검증된 비양수 EPS/BPS의 PER/PBR 미적용은 별도 근거로 인정한다. 외화의 환산 필요를 임의 미적용으로 인정하지 않는다.
- 미확인 적격성·공시 여부·누락은 분모에 유지한다. 기존 종목 수집 정책과 근거가 있는 기간별 제외·미도래 결정만 별도 집계한다. 단순 NOT_APPLICABLE 상태만으로 제외하지 않는다. 전부 미적용인 그룹은 적용 대상 아님으로 구분한다. 종합은 두 그룹 모두 적용 가능하고 충족해야 한다.
- 카드/목록은 동일 평가 함수와 필터를 사용한다. 버전·집계 시각·기준일·필수 항목·사유·스냅샷 ID를 반환한다. 제외 근거는 기존 DB에 보존하고 카드 응답은 사유/기간/정책 버전별 건수와 근거 출처 표본으로 압축한다.
- 50개 표시/다음 50개 선조회는 유지한다. 후속 페이지는 최초 스냅샷을 전달하며 변경 시 409로 첫 페이지부터 재조회한다. 숨겨진 선조회 행은 표시 건수에 포함하지 않는다.
- 수집 모니터링은 현재 실행의 고유 접수번호 발견 수와 실제 작업 수를 분리한다. 작업 키는 접수번호·종목 ID·공시상 보고기간·처리 연결정책으로 구성한다. 현 실행기는 CFS 우선/OFS 대체를 한 작업으로 수행한다. CFS/OFS 조회 호출을 각각 새 작업으로 세지 않는다. 실제 복수 작업은 서로 다른 작업 키로 집계하며 재시도는 중복 대상이 아니다.
- 작업 상태는 대기/처리 중/성공/부분 완료/실패/정상 제외의 상호 배타적 6개다. 성공률은 성공/(성공+부분 완료+실패), 분모 0이면 null과 사유다. 미해결 상세는 부분 완료와 이중 합산하지 않는다.
- 정상 빈 조회, 모두 중복, 조회 실패/범위 불완전, 실행 없음 등을 구분한다. SKIPPED만으로 결과를 추정하지 않는다. 기존 메타데이터가 근거를 제공하지 못하는 과거 실행은 확인 필요로 표시하며 이력을 바꾸지 않는다.
- 조회 완료/확인 지점/실행 종료/실제 자료 저장 성공은 독립 시각이다. 저장 없는 조회로 과거 저장 시각을 갱신하지 않는다. 새 실행 이력은 서버가 계산한 작업 결과를 표시한다.
- 최초 기준이 없는 상세 진입에서만 연결/별도 팝업을 자동 표시한다. 수기 편집은 KRW만 지원한다. 같은 종목·기간의 기존 수집/수기 기준은 재사용하며 값만으로 기준을 추정하지 않는다. 취소 시 저장하지 않는다. 외화/충돌은 조회만 허용한다.
- 실제 회계 시작/종료일을 알 수 없는 최초 수기 기준은 정확한 종목·보고기간 키의 MANUAL_PERIOD로 저장한다. 12월 결산 날짜를 만들어 넣지 않는다. 추후 실제 공시와 기준이 충돌하면 기존 수기 값은 보존하고 검토하도록 차단한다. 기존 ACTUAL 기준 및 원본 공시는 유지한다.

## 운영 브라우저 검증에서 확인한 조회 경합 보정 1.2.37

운영에서 각 분기를 순차 조회하면 약 6.6~9.0초였으나, 네 분기 병렬 집계가 공통 쓰기 revision 잠금을 잡으면서 마지막 조회가 31.1초에 P2028(30초 트랜잭션 만료)로 실패했다. 제한 시간을 올리거나 오류를 무시하지 않고 읽기 경로를 분리한다.

- 종목/공시의 findMany만 노출하는 변경 불가 조회 전용 capability를 제공한다. 계좌 등 개인 모델, 수정 delegate 및 원시 SQL은 제공하지 않는다.
- DB RepeatableRead 스냅샷으로 일관성을 유지하고 기존 collection-symbol 원천 namespace 보호를 재사용한다. 일반 쓰기 transaction·financial lease·수기 보호·revision 잠금은 변경하지 않는다.
- 동시에 실행 중인 같은 분기 조회만 합치며 영속 캐시는 만들지 않는다. 동시에 수행하는 분기 DB 조회는 최대 2개로 제한한다. 필터별 상태/분모는 같은 전체 평가에서 산출한다.
- 분리 DB에서 실제 쓰기 revision 잠금을 보유한 동안에도 네 분기 API가 정상 응답함을 검증했다. 조회 capability의 수정 호출은 실패하고 원본 값은 변하지 않는다. 종목코드가 다른 원천 행의 차단, 6개 동시 API 요청의 같은 스냅샷도 확인했다.
- 로컬 운영 복제본의 6개 동시 조회(4분기·3필터, 논리 조회 24개)는 약 2.3초에 완료됐으며 스냅샷이 일치했다. 이는 로컬 수치이며 운영 재검증 결과는 PR 완료 댓글에 기록한다.
- 공통 테스트 135개, 수집기 279개, 백엔드/수집기 분리 DB 통합 테스트 재통과. 웹 코드는 1.2.36 그대로이며 backend·shared 조회 경로만 보완한다.

운영 검증에 사용한 비활성 임시 종목과 5분 세션은 실패한 첫 검증에서도 정리했다. 실제 종목 값이나 과거 대기열을 초기화하지 않았다. 최종 운영 브라우저 검증은 1.2.37 적용 후 다시 진행한다.

## 반복 조회 안정화 1.2.38

1.2.37은 첫 운영 브라우저·API 검증을 통과했으나 수기 저장 후 반복 조회에서 500이 재현됐다. 따라서 첫 통과를 최종 완료로 간주하지 않는다. 기존 기록으로는 반복 오류의 정확한 Prisma 원인을 알 수 없어, 메시지·SQL·매개변수를 제외한 제한된 오류 코드/분류만 기록한다.

- 집계의 MVCC 읽기는 API 쓰기·캐시 재구성과 분리된 최대 2연결 풀을 사용한다. 기존 쓰기/lease/namespace 보호는 유지한다. 제한 시간을 늘리지 않는다.

- 격리 DB에서 API의 두 연결을 쓰기 잠금과 느린 조회로 모두 점유해도 네 분기 집계가 2초 제한 내 완료됨을 확인했다. 같은 테스트에서 기준 재사용·수기 저장·감사·원천 보호도 확인했다.
- 공통 135개, 수집기 279개, 백엔드 157개(1개 별도 환경 검사 생략), 격리 DB 통합 2개 통과. 백엔드·수집기 타입 검사/빌드 통과.
- 운영 검증 스크립트는 자동 설정 팝업이 열린 동안 배경 제목의 접근성이 숨겨지는 정상 동작을 반영하고, 모니터링 자료가 실제 표시된 뒤 화면을 검증하도록 강화했다.

## 현재 모니터링의 과거 통계 읽기 분리 1.2.39

1.2.38의 실제 운영 브라우저 4개 조합과 API 12개 분기·필터 검증은 통과했다. 6개 동시 집계는 약 19.5초에 같은 스냅샷으로 응답했다. 그러나 서버 안에서만 오류를 분류한 결과 `/collection/monitoring/dart-financial-statements` 상세의 P2028 만료 1건을 확인했다. 화면 재시도 성공만으로 완료 처리하지 않는다.

현재 상세 API에 남아 있던 과거 backfill 전체/우선종목 통계 조회가 금융 쓰기 revision 잠금을 획득하고 있었다. 이 경로는 현재 증분 수집 화면에서 사용하지 않는 옛 통계 읽기이며 과거 수집 실행은 아니다. 현재 상세는 동일한 `securityProcessingStatus` 응답을 사용하고 과거 통계 그룹 조회를 수행하지 않도록 수정했다. 과거 원본·실행 이력·명시적 이력 조회 API는 보존한다.

- 실제 금융 revision 쓰기 잠금을 잡은 상태에서도 현재 모니터링 상세가 2초 내 정상 응답하고 다른 상태 API와 같은 작업 건수를 반환하는 통합 테스트를 추가했다.
- 운영 검증은 화면 도달뿐 아니라 묶음 조회 내부의 모니터링 500도 검출하도록 강화했다. 자동 재시도로 가려진 오류도 실패로 처리한다.
- 스키마·원본·수기 값·수집 일정·확인 시작점 변경은 없다. 최종 반복 검증과 자료 보존 비교는 후속 PR 댓글에 기록한다.
