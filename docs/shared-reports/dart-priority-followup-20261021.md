**수정 대상 13건은 13건 성공**, 미공시 0건, 보류 0건, 실패 0건이다. 기존 미확인 81건의 추가 검증 결과는 **정상 57건·수정 필요 0건·추가 확인 24건**이다. 미도래 후보 70건은 상태를 그대로 보존했다. 정확한 회사별 법적 기한은 별도 근거가 부족해 **미확인**으로 기록하고, 일반 제출기간을 이용한 재확인 제안일을 정리했다.

### 금융회사 57건

삼성증권·기업은행·KB금융 각각 19건이다. 기존 로그·캐시를 먼저 확인하고 회사별 공시 목록을 최초 요청연도 전년 1월 1일부터 조사일까지 전체 페이지로 새로 읽었다. 같은 원목록을 연도별로 다시 정규화하여 중복 목록 요청을 줄였다. 보고서가 있는 각 대상에 **CFS·OFS를 각각 조회**하고 HTTP 상태·DART 상태·응답 행 수를 분리 기록했다.

현재 검증으로 정상 분류한 항목은 정기보고서가 실제로 존재하고 **HTTP 200 / DART 013 / CFS 0행·OFS 0행**을 직접 확인한 건이다. 이는 ‘공시 자체 없음’이 아니라 **현재 전체 재무제표 API에서 미제공**이라는 의미다. 과거 모든 시점에 통신 오류가 없었다는 증명은 아니지만 이번 재현에서는 정상 HTTP 응답의 명시적 013을 확인했으므로 통신 실패를 자료 없음으로 바꾼 결과와 구분된다. 다른 연도 자료는 요청하거나 저장하지 않았다.

금융감독원 [XBRL 확대 관련 안내](https://dart.fss.or.kr/dsaa003/selectBodoMain.ax?seqno=25349)와 [시범가동 안내](https://dart.fss.or.kr/dsaa003/selectBodoMain.ax?seqno=25689)의 공식 검색 색인은 금융회사 본문 공시 확대와 2023년 3분기 도입 배경을 안내한다. 안내 원문 직접 열기는 502로 실패했다. 이 배경은 2015–2023 상반기에 집중된 관측을 설명할 수 있지만 회사별 원인 확정에는 사용하지 않았다. 정상 분류의 직접 근거는 **이번 각 대상의 CFS/OFS 실제 응답**이다.

### 더본코리아 과거 24건

2015–2023 사업보고서 9건, 2020–2024 분·반기 15건이다. 새 정기공시 전체 목록에서 각 기간을 대조했으며 회사 기본정보와 공시 유형을 제한하지 않은 목록도 추가 확인했다. 회사의 설립 시점·비정기 감사보고서 존재와 사업/분기/반기보고서 존재를 구분했다. **상장 전이라는 사유만으로 부존재나 제출의무 없음을 확정하지 않았다.**

DART 회사 기본정보의 설립일 `est_dt`는 **19940112**, 결산월 `acc_mt`는 **12**다. 해당 값으로 설립 전 기간인지 대조했다. 설립일이 요청기간보다 이르다는 사실만으로 정기보고서 제출의무가 있었다고 확정하지는 않았다.

유형을 제한하지 않은 신규 목록 **63건** 가운데 감사보고서 표제 공시는 **20건**이다. 정기보고서 API에 대상이 없더라도 다른 공시 원문에 재무정보가 있을 수 있음을 확인했다. 과거 정기보고서 제출의무의 발생 시점과 대체 원문의 대상기간·회계범위까지 확정할 근거가 부족한 항목은 계속 추가 확인으로 남겼다.

## 개발 담당 전달 요구사항

1. **미도래를 별도 상태·표시·API 집계로 분리:** 근거 있는 결산월·보고기간·제출기한을 함께 보존한다. 미확정 기한은 미확인으로 표시하고 SUCCESS나 영구 자료 없음으로 치환하지 않는다. 기존 NO_FILING·상품 제외·API 미제공·검토 보류와 각각 분리한다.
2. **기한 도래 후 자동 재확인:** 일반 법칙·회사별 특례·휴일 보정을 적용한 기한 근거 및 다음 확인일을 저장한다. 미도래 판정 작업도 도래 후 큐에 다시 들어가도록 하되 공유 lease·호출 예산·자동 실행 시간표를 유지한다. 이미 제출됐으면 회사·기간·접수번호 검증 후 정상 수집하고 중복 실행은 방지한다.
3. **매핑 복구 시 과거 제외 재평가:** `NOT_APPLICABLE AND DART_CORP_CODE_NOT_MAPPED`에 한해서 회복된 정확한 매핑·동일 코드 namespace·STOCK·수집 허용 여부를 확인한다. ID·이전 상태/사유/갱신 시각을 CAS로 비교하고, 기존 성공 작업·상품 제외·사용자 제외·다른 사유의 보류는 건드리지 않는다. 원인·이전 진단·재처리 이력은 삭제하지 않는다.
4. **회사번호 누락과 상품 대상 제외의 분리:** 일반 기업의 일시적 미매핑을 영구적 상품 NOT_APPLICABLE로 종료하지 않는다. 재시도/검토 대상 여부와 복구 조건을 명확히 한다.
5. **3월 결산 등 비12월 결산 테스트:** 3S의 요청연도 Q1=6월·반기=9월·Q3=12월을 실제 제목/응답 접수번호로 검증한다. 요청연도를 일괄 ±1 이동하거나 다른 연도 자료를 대신 저장하지 않는다.
6. **첨부정정 체인과 실재무 원본 번호 구분:** selectedReceiptNo와 실제 저장 receiptNo를 별도 보존한다. 동일 회사·기간의 검증된 첨부정정 관계만 허용하고 내용 정정·철회·모호한 원본은 계속 보류한다. 현재 13건의 검증 결과를 회귀 사례로 사용한다.
7. **진단 보존:** CFS/OFS 각각의 HTTP/DART 상태·행 수·요청연도·보고서 코드·선택/응답 접수번호·조회시각을 비식별 필드로 보존한다. 013, 000 빈 목록, 통신/인증/제한 오류를 다른 원인으로 구분하고 이전 사유를 덮어써 없애지 않는다.
8. **화면 범위 검증:** 인증 범위의 우선종목 집합과 수집 적격/요청기간 필터를 공통으로 사용한다. 전체 범위 검토 보류와 우선종목 검토 보류를 혼합하지 않는다. 이번 전후 기준 35개·1,155개·성공 1,003·미공시 151·대상 아님 0·보류 1을 회귀 기준으로 삼는다.
