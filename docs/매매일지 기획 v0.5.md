# 1. 서비스 개요

RoxStock은 매수 건별 보유수량과 매도 손익, 현재 실제 예수금, 주식 평가액, 배당, 가치투자 지표와 장기 복리목표를 한곳에서 관리하는 개인용 주식 매매일지다.

초기 버전은 증권사의 모든 정산 규칙을 재현하지 않는다. 사용자가 현재 얼마를 보유하고 있고, 얼마를 더 투자할 수 있으며, 각 투자 판단이 어떤 결과를 만들었는지를 단순하고 명확하게 보여주는 데 집중한다.

# 2. 제품 원칙

- 한 번의 매수를 하나의 독립된 매수 Lot으로 관리한다.
- 매도는 사용자가 선택한 단일 매수 Lot에만 연결한다.
- 여러 매수 Lot을 한 번의 매도로 묶는 기능은 제공하지 않는다.
- 한 매수 Lot은 여러 번 나누어 매도할 수 있다.
- 예수금은 현재 증권계좌에서 확인되는 실제 현금 잔액을 기준으로 한다.
- 신규 거래는 등록 순간에만 예수금에 반영하고, 이후 거래 수정·삭제는 예수금을 자동으로 되돌리지 않는다.
- 현재가는 자동 수집하되 수집이 불가능하면 사용자가 직접 수정할 수 있다.
- 개인용 초기 버전에 필요한 기능부터 구현하고, 복잡한 기능은 실제 필요가 확인될 때 추가한다.
- 모든 화면에서 주가와 손익의 상승 금액은 밝은 적색, 하락 금액은 밝은 청색, 보합은 흰색으로 표시한다.
- 색상만으로 상태를 구분하지 않고 부호와 수익률을 함께 표시한다.

# 4. 핵심 사용자 흐름

## 4.1 최초 설정

1. 계좌와 증권사명을 등록한다.
2. 현재 증권계좌에서 확인한 실제 예수금을 입력한다.
3. 기존 매수 건을 종목·매수일시·수량·매수단가로 등록한다.
4. 종목을 관심·보유·추천 중 하나의 목록에 등록한다.
5. 최신 시세와 가치투자 정보를 확인한다.

## 4.2 매수와 매도

1. 매수 등록 시 매수금액과 수수료·세금을 예수금에서 차감한다.
2. 매도할 매수 건을 선택한다.
3. 선택한 매수 건의 잔여수량 범위에서 매도수량과 단가를 입력한다.
4. 매도 등록 시 매도금액에서 수수료·세금을 제외한 금액을 예수금에 더한다.
5. 실현손익은 선택한 매수 건의 매수단가를 기준으로 계산한다.
6. 거래 수정·삭제 후 실제 예수금과 차이가 생기면 사용자가 현재 예수금을 직접 수정한다.

## 4.3 배당과 입출금

- 배당은 세전 배당금과 세후 실수령액을 함께 기록한다.
- 배당 최초 등록 시 세후 실수령액만 예수금에 더한다.
- 연도별 실수령 배당금은 세후 배당금 합계로 계산한다.
- 입금과 출금은 투자손익과 구분되는 외부 현금흐름으로 관리한다.

# 5. 자산과 손익

```text
매수 Lot 잔여수량 = 매수수량 - 연결된 매도수량 합계
실현손익 = 매도수량 × (매도단가 - 연결된 매수단가)
Lot 평가금액 = 잔여수량 × 현재가
Lot 평가손익 = 잔여수량 × (현재가 - 매수단가)
주식 평가금액 = 모든 보유 Lot 평가금액의 합
총 평가자산 = 주식 평가금액 + 현재 예수금
현금 비중 = 현재 예수금 ÷ 총 평가자산 × 100
```

거래비용은 기본 실현손익에 자동 반영하지 않고 별도 참고값으로 보여줄 수 있다. 월별·연도별 수수료와 세금은 예수금 변동 내역의 비용 합계로 계산한다.

# 6. 종목 목록과 모바일 UX

종목목록은 선택 계좌 기준 **보유종목 → 관심종목 → 추천종목 → 거래종목** 4개 탭을 사용한다.

| 탭 | 표시 기준 | 분류 이동 |
|---|---|---|
| 보유종목 | 실제 잔여수량이 있는 종목 또는 사용자가 보유로 분류한 거래 전 종목; 자산 집계는 잔여수량>0만 | 관심·추천에서 진입 가능. 거래 이력이 있으면 관심·추천으로 이동 불가 |
| 관심종목 | 거래 자동 상태가 아닌 관심 분류 | 추천↔관심 자유, 보유로 이동 가능 |
| 추천종목 | 거래 자동 상태가 아닌 추천 분류 | 관심↔추천 자유, 보유로 이동 가능 |
| 거래종목 | 과거 거래 이력이 있고 종목 전체 잔여수량=0 | 자동 판정, 사용자 직접 분류 불가 |

- 동일 계좌에서 종목을 탭에 중복 표시하지 않는다. 매수 시 보유로, 전량 매도 시 거래종목으로 이동한다.
- 거래종목에서 상세보기는 기존 종목 상세의 거래내역 탭으로 진입한다. 재매수·매도 수정/삭제는 허용한다.
- 거래종목은 현재 보유수·평가금액에서 제외하고 과거 실현손익·매매일지 기록은 유지한다.
- 탭 클릭·양방향 스와이프 순환을 지원하며 입력폼·차트·버튼·OS 제스처와 충돌을 방지한다.
- 분류 제한·매도 삭제 수량 복원·예수금 표시의 세부 기준은 아래 2026-10-02 확정 항목 및 기본설계서 22장을 따른다.

# 7. 시세와 스냅샷

- 종목별 최신 가격 한 건만 저장한다.
- 가격 제공처의 기준시각인 `price_as_of`는 사용하지 않는다.
- 자동 또는 수기 가격 갱신 시각은 `price_updated_at`으로 관리한다.
- 자동 수집 실패 시 마지막 정상 가격을 유지한다.
- 사용자가 현재가와 전일 종가를 직접 수정할 수 있다.
- 다음 자동 수집이 성공하면 수기 가격을 최신 수집 가격으로 갱신한다.
- 계좌 스냅샷의 현재 설계 기본값은 한국 시간 23시 1회 UPSERT이며 장중 주기 갱신은 선택 확장이다. 세부 운영은 기본설계서·수집기 설계를 따른다.
- `is_final`은 사용하지 않는다.
- 종목별 일별 스냅샷은 설계에 포함하되 선택 구현으로 둔다.

# 8. 가치투자와 복리목표

| 영역 | 핵심 정보 |
|---|---|
| 재무제표 | 매출, 영업이익, 순이익, 자산, 부채, 자본, 영업현금흐름, 설비투자 |
| 가치평가 | EPS, BPS, PER, PBR, ROE, 주당배당금, 배당수익률, 시가총액 |
| 배당 | 세전 배당금, 세후 실수령액, 종목·월·연도별 합계 |
| 복리목표 | 기간명, 시작자산, 목표수익률, 매년 추가 투자금, 목표 성장곡선 |

한 계좌에 여러 복리계획을 등록하고 각 계획 아래 복수의 목표를 둔다(계획 1 : 목표 N). 1차·2차·3차처럼 기간이 다른 차수는 계획, 같은 기간의 10%·20%·30% 시나리오는 하위 목표다. 비교 화면에는 보통 3개 목표를 우선 표시하지만 저장 개수에는 제한을 두지 않는다. 계획별 목표 자산과 실제 자산·손익·달성 여부를 요약 조회하는 요구사항은 추가·수정·삭제 화면과 별도로 검수한다.

```text
1년 차 목표자산
= (시작 자산 + 연간 추가 투자금) × (1 + 목표수익률)

2년 차 이후 목표자산
= (직전 연도 목표자산 + 연간 추가 투자금) × (1 + 목표수익률)
```

## 9.2 하단 메뉴

기존 하단 메뉴의 배치·순서를 유지하며 더보기의 순서에 맞춰 재배열하지 않는다. 커버 기본 순서는 종목목록 → 매매일지 → 홈 → 자산분석 → 더보기다. 태블릿의 기존 5개·9개 시안 차이는 별도 교정 항목이며 이번 번호 정리로 새로운 개수를 확정하지 않는다.

## 9.4 번호와 페이지 이름

| 페이지 | 역할 |
|---|---|
| A0000. 정보구조 | 전체 메뉴와 화면 관계 |
| A0001. 화면흐름도 | 메인·상세·등록·팝업 이동 |
| A0002. 입력폼 표준 | 공통 입력·달력·선택·버튼 표준 |
| A0003. 디자인 가이드 명세 | 화면번호·레이아웃·스크롤·공통 표현 기준 |

- `A`는 공통 기획·명세 페이지, `C`는 커버, `T`는 펼침·태블릿을 뜻한다.
- 같은 기능은 커버·태블릿에서 같은 숫자를 쓴다. 예: `C1000 / T1000`.
- 대메뉴는 1000부터 2100까지 100 단위로 배정한다. 하위 화면은 해당 대메뉴 번호에 1부터 더한다.
- 공유 기능은 대표 기능 아래 번호를 한 번만 배정한다. 진입 메뉴마다 페이지나 번호를 복제하지 않는다.
- 평가자산은 홈 하위 `C1001 / T1001`이다. 예수금은 대메뉴 `C1400 / T1400`이며 홈 카드와 더보기에서 같은 화면으로 진입한다.
- 거래등록·수정은 종목 상세와 매매일지에서 공통 호출한다. 커버 4개 거래 화면과 명세의 Figma 위치는 `C1100`이며 기존 `C1101` 페이지는 삭제됐다. 태블릿 위치는 현재 디자인을 별도 확인한다.
- 더보기는 공통 탐색 화면인 `C9900 / T9900`이다. 더보기 화면 자체는 12개 대메뉴 항목에 포함하지 않는다.
- 페이지명은 `C1000. 홈 · v0.2 · 09.28` 형식이다. 날짜는 해당 수정일의 `MM.DD`이며 연도를 생략한다. 날짜가 없는 `v0.0` 페이지에 임의의 완료일을 추가하지 않는다.
- 업무 데이터의 거래일자·재무 사업연도와 문서 이력의 기준일은 실제 연도를 유지한다. 페이지명 날짜 규칙과 혼동하지 않는다.
- 하단 메뉴의 기존 배치·순서는 유지한다. 더보기 순서와 강제로 맞추지 않는다.
- 페이지 버전과 프레임의 `WORK/FINAL`은 별개다. `v0.2` 페이지라고 모든 프레임이나 실제 개발·배포가 완료된 것으로 판단하지 않는다.

원본 페이지 링크와 구 번호 대응은 [화면번호·메뉴 명세 v0.1](./RoxStock%20화면번호%C2%B7메뉴%20명세%20v0.1.md)을 따른다.

## 9.5 공통 화면 기준

카드 라운드 8px, 헤더·하단 메뉴 44px 고정, 본문 스크롤, 약 40% 스크롤 이후 최상단 이동 버튼, 최하단 80px 안전 여백을 적용한다. 커버 370×465와 펼침 725×396 CSS px 및 더 넓은 화면에서 검증한다. 이전·다음 기간 스와이프는 인접 데이터 선조회와 기존 화면 유지로 깜빡임을 방지한다.

## 2026-10-01 목표가 도래 정의 교체

이 기능은 종목별 매도 목표가 비교가 아니라 **선택 계좌 매수 Lot의 보유기간별 목표수익률 달성**이다. 기본 독립 조건은 7일/5%, 30일/10%, 90일/15%, 180일/20%, 365일/30%이며 각 조건은 기간 AND 수익률, 조건 간 OR다. 매수 당일0일, KST 달력일, 잔여수량>0, 개별 Lot 단가 기준이며 평균단가를 사용하지 않는다. 경계 포함·반올림 이전 판정·대표 최단 기간·중복 Lot 제거를 적용한다.

2100 설정은 계좌별 조건 추가·수정·삭제(최대5개)를 저장한다. 명시적 빈 조건은 비활성이다. 홈은 전체 도달 Lot 수를 표시하고 최대5건을 요약한다. C1003/T1003 전체 목록에서 모든 결과를 볼 수 있다. 최근 매수 카드 요구는 유지한다. 홈 본문 단일 스크롤·최하단80px·공통헤더/하단44px을 적용한다.

계산·검증·API·이동·오류·설정 계약은 [목표가 도래 설계 v0.2](./RoxStock%20목표가%20도래%20설계%20v0.2.md)를 개발 정본으로 사용한다. 이전 방식과 충돌하는 정의는 본 명세를 우선한다. 과거 버전 문서는 작성 당시 기록으로 보존한다.


## 2026-10-02 예수금 대메뉴 승격·번호 현행화

예수금은 기존 1002에서 1400으로 이동한다. 투자금1500·투자손익1600·가치분석1700·재무제표1800·복리계획1900·모니터링2000·설정2100을 사용한다. 홈1000·평가자산1001·목표가 도래 전체1003·종목목록1100·공유 거래등록1101·매매일지1200·자산분석1300·더보기9900은 유지한다. 하단 메뉴 순서는 유지한다. 번호 변경은 기능 구현·QA·배포 완료를 뜻하지 않는다. 앱 내부 route/API는 별도 개발 계약이며 이번 문서 작업에서 변경하지 않는다.


## 2026-10-02 종목목록4개 탭·분류 제한·매도 복원 확정

- 탭 순서: 보유종목→관심종목→추천종목→거래종목. 클릭·양방향 순환을 지원한다.
- 관심↔추천 및 관심·추천→보유는 허용한다. 보유→관심·추천은 해당 계좌의 매수·거래 이력이 있으면 차단한다.
- 거래종목은 거래 이력 있음+현재 잔여수량0인 자동 상태다. 직접 분류 변경은 불가하지만 매도 수정·삭제와 새 매수는 가능하다. 재매수/매도 삭제로 수량이 생기면 보유로 복귀한다.
- 부분매도 Lot은 잔여수량으로 유지하고 전량 매도 Lot만 보유현황에서 제외한다. 거래종목은 현재 자산 합계에서 제외하고 과거 기록은 보존한다.
- 거래내역 카드의 수정·삭제는 해당 매도1건에만 연결한다. 매도 삭제는 연결 매수를 보존하고 삭제한 수량만큼 잔여수량을 복원한다. 확인창에 복원 수량과 예수금 자동 변경 없음 안내를 표시한다.
- 등록은 기존 “거래 후 예수금” 예상값을 사용한다. 수정은 “현재 예수금”과 자동 변경 없음 안내를 사용하며 수정·삭제 시 예수금/과거 스냅샷을 변경하지 않는다.
- 거래종목 상세보기는 기존 종목 상세의 거래내역 탭으로 직접 진입한다. 제목 가치지표 팝업·하트·현재가 수정·상세보기의 클릭 영역을 분리한다. 탭별 검색·정렬은 유효한 데이터 기준으로 명세한다.
- 분류와 자동 상태는 계좌별로 판정하고 한 종목을 같은 계좌의 여러 탭에 중복 표시하지 않는다. 거래 전 수동 보유 분류는 자산을 생성하지 않으며 잔여수량>0만 보유 자산 집계에 포함한다.
- 커버 거래 등록/수정4개 화면·거래일자 명세는 C1100으로 이동했으며 C1101 페이지는 삭제됐다. T1101은 별도 디자인 확인 대상으로 유지한다.
- A0003 v0.3 입력규칙, 카드8px·헤더/하단44px·본문 좌우8px/상단0·최하단80px를 적용한다.
- 디자인에는 전체 매도 목록·부분매도·복원 확인·분류 이동 차단·빈 상태를 추가하고, 손실 부호·등락률·현재가 평가 계산 및 거래일/보유일·금액 천단위 표기를 정합하게 교정한다.

업무 정본은 [기본설계서22장](./매매일지%20설계%20v0.7.md#22-종목목록-4개-탭분류-제한매도-복원-확정-2026-10-02)을 따른다. 이전 3개 탭과 전량 매도 후 관심 이동 규칙은 대체된다. 설계 확정이며 Figma/개발/QA 완료를 뜻하지 않는다.
