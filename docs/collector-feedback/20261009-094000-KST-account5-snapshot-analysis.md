## 영향과 조치 제안

계좌5의 10-08 스냅샷을 저장하지 않았고, 다른 두 계좌는 성공했다. 기존 10-07 스냅샷은 남아 있다. 이번 오류 경로는 외부 DART API를 호출하지 않으므로 DART 점검과 별개다.

미확정 현금을 임의로 0원 처리하면 자산 값이 잘못될 수 있다. 실제 계좌 잔액을 확인하고 정상적인 현금 잔액 입력/초기화 흐름으로 원장을 만들어야 한다. 이후 실행은 현금 검증을 통과할 수 있지만 10-08 과거 값을 현재 잔액으로 재작성해서는 안 된다. 과거 일자 복원은 당시 잔액·보유 현황·가격 확인 후 별도 지시가 필요하다.

코드 개선은 현금 누락과 가격 누락을 별도 오류 이유로 표현하고, 원장 없는 계좌 생성 시 잔액 확인 필요 상태를 안내하는 것이다. 실제 수정은 별도 브랜치·PR로 분리한다. 검증은 현금 null/명시적 0/원장 존재/주가 누락을 각각 구분하고 기존 스냅샷 보존을 확인한다.

당시 원장이 삭제됐다가 현재0건인지까지 감사 이력으로 확인하지는 않았다. 다만 당시 CURRENT_CASH_MISSING 분기는 원장 조회 결과가 null이었다는 직접 코드 근거이고 현재 DB 상태도 일치한다. 기존 10-07 스냅샷이 어떤 코드·입력으로 만들어졌는지는 미확인이다. 실제 잔액·계좌번호는 조회·기록하지 않았다.
