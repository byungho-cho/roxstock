# 주식 매매일지 DB 스키마

**버전:** v0.2  
**상태:** Prisma 모델 작성 전 검토 초안  
**기준일:** 2026년 9월 16일

# 1. 공통 기준

- DBMS는 MariaDB, ORM은 Prisma를 사용한다.
- PK는 `BIGINT UNSIGNED`를 사용한다.
- 수량은 `DECIMAL(18,6)`, 단가·금액은 `DECIMAL(19,4)`, 비율은 `DECIMAL(9,4)`를 기본으로 한다.
- 재무제표와 시가총액은 `DECIMAL(24,0)`을 사용한다.
- 모든 주요 테이블에 `created_at`, `updated_at`을 유지한다.
- 업무 데이터 FK의 삭제 기본값은 `ON DELETE RESTRICT`다.
- 저장 테이블은 13개이며 `daily_position_snapshots`는 선택 구현이다.

# 16. 서비스 검증 규칙

- `quantity`, 가격과 금액은 허용 범위를 API에서 검사한다.
- 매도 등록은 DB 트랜잭션 안에서 매수 Lot의 잔여수량을 다시 확인한다.
- 신규 매수·매도·입출금·배당과 예수금 반영은 각각 하나의 트랜잭션으로 처리한다.
- 매수 삭제 시 연결 매도 삭제 후 매수를 삭제한다.
- 비용 수정 시 변경 전후 차액만 현재 예수금에 반영한다.
- 현재가 수집 실패 시 기존 가격을 유지한다.
- 스냅샷 작업은 UNIQUE 조건과 UPSERT로 멱등성을 보장한다.
- 과거 거래 수정·삭제는 과거 스냅샷을 변경하지 않는다.

# 17. 다음 검토사항

- Prisma에서 MariaDB `UNSIGNED BIGINT`와 Decimal 매핑 방식
- 날짜·시간 저장 기준과 한국 시간 변환 규칙
- 비용 수정과 `balance_after`의 표시 의미
- 휴장일 스냅샷 생성 여부
- `daily_position_snapshots` 실제 구현 여부
