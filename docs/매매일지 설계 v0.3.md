# 주식 매매일지 실시간 수집 및 자산관리 기본설계서

**버전:** v0.3  
**부제:** 13개 저장 테이블과 모바일 순환형 UX 기준

| 항목 | 내용 |
|---|---|
| 문서 목적 | 현재까지 확정된 업무 규칙과 데이터 책임을 구현 전 기준으로 고정한다 |
| 대상 시스템 | React·Vite·TypeScript, Node.js·Fastify·TypeScript, Prisma·MariaDB |
| 작성 기준일 | 2026년 9월 16일 |
| 연계 문서 | 매매일지 기획 v0.3, 매매일지 스키마 v0.2 |
| 문서 상태 | DB 스키마 v0.2, 계산 시뮬레이션 및 핵심 메뉴 명명 규칙 반영 |

# 1. 설계 결론

- 매수와 매도는 `buy_trades`, `sell_trades`로 분리한다.
- 한 매수는 하나의 독립된 Lot이며 여러 매도를 가질 수 있다.
- 한 매도는 반드시 하나의 매수 Lot만 참조한다.
- 여러 매수 Lot을 한 번에 매도하는 기능은 제공하지 않는다.
- 보유현황은 조회 시 계산하며 `positions` 테이블을 저장하지 않는다.
- 예수금은 `accounts.cash_balance`에 현재 실제 금액을 유지한다.
- 모든 예수금 변동과 수수료·세금은 `cash_transactions`에 기록한다.
- 배당은 세전·세후 금액을 모두 저장하고 최초 등록 시 세후 금액만 예수금에 반영한다.
- 현재가와 일별 스냅샷, 가치투자 정보, 여러 복리목표를 함께 관리한다.

# 4. 매수·매도 설계

## 4.1 매수

`buy_trades` 한 행이 매수 Lot 한 건이다. 매수 등록 시 `quantity × unit_price`와 예수금 내역의 `fee_tax_amount`를 현재 예수금에서 차감한다.

## 4.2 매도

`sell_trades.buy_trade_id`는 반드시 한 `buy_trades.id`를 참조한다. 잔여수량보다 많은 매도는 허용하지 않는다.

```text
잔여수량 = 매수수량 - 연결된 매도수량 합계
실현손익 = 매도수량 × (매도단가 - 연결된 매수단가)
```

실현손익, 잔여수량, 총거래금액은 저장하지 않고 조회 시 계산한다.

## 4.3 매수 삭제

- 연결된 매도가 없으면 매수 한 건을 삭제한다.
- 연결된 매도가 있으면 연결 매도 건수를 포함한 확인창을 표시한다.
- 확인한 경우 서비스가 연결된 매도를 먼저 삭제하고 매수를 삭제한다.
- 삭제는 하나의 DB 트랜잭션으로 처리한다.
- DB FK는 `ON DELETE RESTRICT`로 유지한다.
- 일괄삭제 UI와 소프트 삭제는 제공하지 않는다.
- 거래 삭제로 예수금과 과거 스냅샷을 자동 변경하지 않는다.

# 5. 예수금과 거래비용

## 5.1 현재 예수금

`accounts.cash_balance`는 현재 증권계좌에서 확인한 실제 예수금이다. 사용자는 이 값을 직접 수정할 수 있으며 보정 이력은 저장하지 않는다.

## 5.2 예수금 변동

`cash_transactions.transaction_type`은 다음 값을 사용한다.

```text
BUY, SELL, DEPOSIT, WITHDRAWAL, DIVIDEND
```

| 유형 | 현재 예수금 계산 |
|---|---|
| BUY | 이전 예수금 - 매수금액 - 수수료·세금 |
| SELL | 이전 예수금 + 매도금액 - 수수료·세금 |
| DEPOSIT | 이전 예수금 + 입금액 |
| WITHDRAWAL | 이전 예수금 - 출금액 |
| DIVIDEND | 이전 예수금 + 세후 배당금 |

수수료와 세금은 `fee_tax_amount` 하나로 통합한다. 매수·매도·배당 테이블과 예수금 내역 사이에는 FK를 두지 않는다.

일반 거래 수정·삭제는 예수금을 자동 변경하지 않는다. 거래비용을 나중에 수기로 입력하거나 수정할 때는 비용 차액만 현재 예수금에 반영하는 예외 규칙을 적용한다. 실제 잔액과 차이가 있으면 사용자가 현재 예수금을 직접 수정한다.

```text
월별 비용 = 해당 월 fee_tax_amount 합계
연도별 비용 = 해당 연도 fee_tax_amount 합계
```

# 6. 배당

`dividends`에는 `gross_amount`와 `net_amount`를 함께 저장한다.

```text
배당소득세 = gross_amount - net_amount
연도별 실수령 배당금 = 해당 연도 net_amount 합계
```

배당 최초 등록과 예수금 증가는 하나의 DB 트랜잭션으로 처리한다. 이후 배당 수정·삭제는 예수금을 자동 변경하지 않는다.

# 7. 종목 목록

`watchlist_items.list_type`은 `WATCHLIST`, `HOLDING`, `RECOMMENDED` 중 하나다. `security_id`에 UNIQUE를 적용하여 한 종목이 여러 탭에 중복되지 않게 한다.

- 매수 후 잔여수량이 생기면 `HOLDING`으로 변경한다.
- 전량 매도하면 `WATCHLIST`로 변경한다.
- 목록을 한 번 조회하고 프런트엔드에서 `list_type`으로 필터링한다.

# 8. 현재가

`market_prices`는 종목별 한 행만 유지한다.

| 컬럼 | 역할 |
|---|---|
| `security_id` | PK이자 종목 FK |
| `current_price` | 최근 정상 또는 수기 입력 가격 |
| `previous_close_price` | 전일 종가, 선택값 |
| `price_updated_at` | 자동 또는 수기 가격 갱신 시각 |
| `created_at`, `updated_at` | 생성·수정 시각 |

- `price_as_of`, 수집상태, 오래된 가격 여부 컬럼은 두지 않는다.
- 자동 수집 실패 시 기존 정상 가격을 유지한다.
- 화면에서 현재가와 전일 종가를 수기로 수정할 수 있다.
- 다음 자동 수집 성공 시 수기 가격을 덮어쓴다.

# 9. 스냅샷

## 9.1 계좌 스냅샷

`daily_account_snapshots`는 `cash_balance`, `stock_value`, `total_asset_value`를 저장한다. `account_id + snapshot_date`를 UNIQUE로 둔다.

## 9.2 종목 스냅샷

`daily_position_snapshots`는 종목별 `quantity`, `purchase_amount`, `market_price`, `market_value`, `unrealized_profit_loss`를 저장한다. `account_id + security_id + snapshot_date`를 UNIQUE로 둔다.

종목별 스냅샷은 ERD에 유지하되 선택 구현으로 분류한다.

## 9.3 실행 규칙

- 같은 날짜의 행을 약 1시간마다 UPSERT한다.
- 한국 시간 23시 실행을 당일 마지막 예정 갱신으로 사용한다.
- `is_final`은 두지 않는다.
- 시세가 없으면 잘못된 0원 스냅샷을 만들지 않는다.
- 거래나 예수금 변경으로 과거 날짜 스냅샷을 수정하지 않는다.

# 10. 가치투자 데이터

## 10.1 재무제표

연간과 분기별로 매출액, 영업이익, 순이익, 자산, 부채, 자본, 영업현금흐름과 설비투자를 저장한다. 금액 단위는 원으로 통일한다.

## 10.2 가치평가

기준일별 EPS, BPS, PER, PBR, ROE, 주당배당금, 배당수익률과 시가총액을 저장한다. 미수집 값은 NULL을 허용한다.

# 11. 복리목표

한 계좌에 여러 목표를 허용한다. 기간별 목표와 같은 기간의 복수 수익률 비교를 모두 지원한다.

핵심 컬럼은 `period_name`, `goal_name`, `start_date`, `end_date`, `initial_asset_value`, `annual_target_rate`, `annual_contribution_amount`, `is_visible`, `display_order`다.

연간 추가 투자금은 첫해부터 기초 자산에 더한 후 목표수익률을 적용한다.

```text
첫해 목표자산
= (initial_asset_value + annual_contribution_amount)
  × (1 + annual_target_rate)

다음 해 목표자산
= (직전 목표자산 + annual_contribution_amount)
  × (1 + annual_target_rate)
```

비교 화면에는 일반적으로 3개 목표를 표시하지만 DB 저장 개수에는 제한을 두지 않는다.

# 12. 반응형 내비게이션과 모바일 UX

## 12.1 핵심 메뉴 명칭

핵심 메뉴명은 가능한 한 4글자로 통일한다. `더보기`는 의미 명확성을 우선한 3글자 예외다. 반응형 구간이 변경되어도 메뉴명과 기능 범위는 바꾸지 않는다.

| 순서 | 메뉴명 | 책임 |
|---:|---|---|
| 1 | 종목목록 | 관심·보유·추천종목과 매수 Lot 조회 |
| 2 | 매매일지 | 거래 이력·실현손익·필터·수정·삭제 |
| 3 | 홈 | 대시보드 진입, 자산·손익·배당·추이 요약 |
| 4 | 자산분석 | 예수금·배당·가치투자·복리목표 분석 |
| 5 | 더보기 | 계좌·현재가·수집 상태·앱 설정 |

`홈`은 2글자, `더보기`는 3글자지만 익숙하고 의미가 명확하므로 명명 원칙의 예외로 둔다. 화면 내부 제목은 `대시보드`를 사용한다. `거래등록`은 목적지 메뉴가 아니라 실행 액션으로 분리하고, Fold 커버에서는 대시보드 헤더 최우측의 `+` 아이콘으로 제공한다.

| 화면 그룹 | 내비게이션과 거래등록 표현 |
|---|---|
| 모바일 | 중앙 `홈`을 포함한 5개 하단 내비게이션 + 대시보드 헤더 우측 `+` 거래등록 아이콘 |
| 펼침·태블릿 | 동일 메뉴의 축약형 사이드 내비게이션 + 별도 거래등록 액션 |
| PC | 동일 메뉴의 좌측 사이드 내비게이션 + 상단 또는 콘텐츠 영역 거래등록 버튼 |

### 공통 스크롤 최상단 동작

- 세로 스크롤이 있는 모든 화면에 적용한다.
- `scrollY >= viewportHeight × 0.4`일 때 버튼을 표시하고 그보다 위에서는 숨긴다.
- 모바일 버튼은 44 × 44px 이상의 원형 버튼으로 만들고, 하단 내비게이션 위 우측에 독립적으로 배치한다.
- 버튼을 누르면 페이지 최상단으로 부드럽게 이동한다.
- 사용자가 모션 감소 설정을 사용하면 즉시 이동한다.
- 콘텐츠와 하단 내비게이션을 가리지 않아야 한다.

## 12.2 모바일 상호작용

- 모바일 우선으로 설계한다.
- 동일 레벨의 탭·카드·기간 화면은 좌우 스와이프를 지원한다.
- 마지막 다음에 첫 화면, 첫 화면 이전에 마지막 화면이 이어지는 무한 순환을 지원한다.
- 탭 클릭과 스와이프 선택 상태를 동기화한다.
- 화면별 세로 스크롤 위치를 유지한다.
- 입력폼, 버튼, 차트 조작 영역은 스와이프 시작 대상에서 제외하거나 방향·거리 임계값을 적용한다.
- 상세·등록·수정 화면은 OS 뒤로가기 제스처와 충돌하지 않도록 필요한 화면에만 적용한다.

## 12.3 주가·손익 색상 규칙

한국 주식 서비스의 관습을 기준으로 모든 화면에 동일하게 적용한다.

| 상태 | 다크 테마 색상 | 표시 규칙 |
|---|---|---|
| 상승 | 밝은 적색 · `red/400` | `+` 부호와 수익률을 함께 표시 |
| 하락 | 밝은 청색 · `blue/400` | `-` 부호와 수익률을 함께 표시 |
| 보합 | 흰색 · `neutral/50` | `0` 또는 `0.0%`를 함께 표시 |

- 성공·완료를 나타내는 녹색과 주가 상승 적색을 서로 다른 의미 토큰으로 관리한다.
- 선택된 하단 메뉴는 밝은 앰버 계열을 사용한다.
- 대시보드 거래 추가 `+` 버튼은 원형과 흰색 아이콘을 유지하되, 검정보다 한 단계 밝은 진한 회색(`neutral/800`)을 사용하여 자산 정보보다 과도하게 강조되지 않도록 한다.
- 색상만으로 상승·하락을 전달하지 않는다.
- 모바일 보유종목 행은 `종목명 | 등락률 | 평가금액`의 3열 구조로 표시한다.
- 종목명 열은 긴 이름을 고려하여 가장 넓게 확보하고, 등락률은 중앙보다 오른쪽에 배치한 전용 열 안에서 우측 정렬하며, 평가금액은 우측 끝선에 정렬한다.
- 등락률과 평가금액의 글자 크기는 종목명보다 작게 사용한다.
- 대시보드 상단에는 수집 상태를 표시하지 않는다.
- 보유종목 카드 제목 옆에 텍스트 없는 원형 시세 수집 상태 표시를 둔다.
- 보유종목 시세 수집 상태는 정상=녹색, 일부 실패=노란색, 실패=적색으로 표시한다.
- 색상 의미는 접근성 라벨 또는 툴팁으로 함께 제공한다.
