# 종목 데이터 수집 전환 (2026-10-27)

## 범위

기존 DART 모니터링의 상태·최근 결과·이력·대상 목록을 유지하고 종합 수집 카드와 관리자 종목 관리 화면을 연결한다. 직전 완료 4분기는 조회 현황이며 과거 보완 수집을 실행하지 않는다. 수기 저장은 22개 직접 편집, 3개 자동 계산, 1개 조회 전용 필드를 공통 계약으로 검증한다. 원본 DART 및 기존 수기·검토·수집 이력은 삭제하지 않는다.

최초 공시 발견은 올해 1월 1일부터 발표일 기준으로 조회하되, API의 전체 조회 제한에 맞춰 최대 90일 구간으로 나눈다. 올해 발표된 전년도 사업보고서도 포함한다. 확인 완료 후에는 2일을 중첩하여 조회한다. 일반 공시는 최신 연간·최신 중간 보고자료만 처리하고, 이전 일반 공시는 건너뛴다. 과거 정정공시는 그 공시의 기간만 처리한다. 접수번호 고유 키와 페이지 삽입/커서 이동 트랜잭션으로 누락과 중복을 방지한다. 기존 종목에 연결된 정기 보고서만 처리한다. 이전 수기 수집 UI 시험은 재개·갱신 POST가 전혀 발생하지 않고 종목 관리로 이동하는 계약으로 변경한다. 보존된 과거 실행의 서버 조회 검증은 유지한다. 신규·정정 보고서에 명시된 기간만 보완하며 과거 누락 목록을 스캔하지 않는다. 대기열 작업은 실행 내 기간별 고유 대상으로 집계한다. 실제 확인 구간보다 이전의 미수집 자료는 공시 대기로 추정하지 않고 공시 확인 필요로 구분한다. 원천 자료 미제공은 미해결로 남긴다.

DART 검증·저장 후 기간별 KRX/KIS 가격·주식 근거, KIS 연간 지표, 공통 계산기, 검증 가능한 Naver 연간 최종값 순으로 누락만 보완한다. 크롤링은 동일 연도·연결/별도·재무 원문 대조 및 우선주 부재 확인이 필요하다. 검증이 불가능한 값은 미해결이다. 현재 주가를 기간별 재무지표에 대입하지 않는다. 기존 정상 값의 공시 기준이 충돌하면 보존하고 검토 사유를 남긴다.

## 운영 전환

1. 최신 main과 진행 중 PR을 대조한다. 별도 초안 PR에서 CI(실제 MariaDB, 인증, 수집 복구, 두 화면 크기)를 통과한 뒤 병합한다. 병합 커밋 SHA로 기존 Production Deploy를 실행한다.
2. 기존 배포기가 마이그레이션 전 DB 전체를 제한 권한으로 백업하고 gzip 및 SHA256을 검증한다. 같은 백업 디렉터리의 collection-settings에 환경 파일·컨테이너 설정·타이머 정의와 과거 캠페인 상태를 보존한다. 비밀값은 로그나 PR에 출력하지 않는다.
3. 투자동향 컨테이너의 이미지·설정·실행 상태도 보존한다. 기간별 과거 가치지표 루프는 종료하고, 기존 실행 중이던 프로세스만 같은 배포 커밋의 새 이미지로 교체한다. 투자동향 및 현재 참고 지표·주식수 수집은 유지하며, 새 모드에서는 과거 PeriodValuation 조회·저장을 실행하지 않는다. KIS_SUPPLEMENT_ENABLED=false로 구형 루프를 차단하고 KIS_CURRENT_FUNDAMENTALS_ENABLED에 기존 현재 참고 수집 설정을 보존한다. 과거 KIS 캠페인의 STOP을 설정하고 roxstock-kis-history.timer를 disable --now 한다. 실행 중 캠페인 및 구형 DART·일반 collector를 중지한 뒤 새 이미지를 설치한다. 과거 대기열과 완료 지점은 재개하거나 초기화하지 않는다.
4. 보존된 환경 파일의 SECURITY_DATA_COLLECTION_ENABLED=true로 신규 수집기만 활성화한다. 최초 전환 시 신규 수집을 활성화하고 구형 보완을 비활성화한다. 나머지 기존 명시값은 유지하며 누락된 설정만 추가한다. 발견 주기 60분, 재시도 60분, 최대 3회, 배치 20건이다. DART 전역 일일 한도와 공통 잠금을 함께 사용한다. 발견 실패가 최대 횟수에 도달하면 관리자 검토까지 중지한다.
5. 배포 후 공시 커서·대기열·최근 실행·실제 저장 예시를 확인한다. 운영 API의 비로그인 401, 일반 사용자 403, 관리자 200과 실제 화면을 각각 확인한다. 배포 서버가 실제 사용자 역할로 발급한 5분 검증 세션을 사용하며 테스트 종료 즉시 삭제한다. 세션 원문과 개인 계좌 화면은 로그·아티팩트에 남기지 않는다. 운영 UI는 API 목 없이 두 크기로 확인하고 실제 상세값과 렌더링을 대조한다. 신규 없음/공시 대기일 때 저장 성공을 주장하지 않는다.

## 복구

문제가 있으면 먼저 신규 DART collector를 중지한다. DB 전체 복원을 자동 실행하지 않는다. 기존 배포 백업의 이미지 태그와 환경 파일로 API/화면을 복구하고 새 테이블은 남겨 원본·수기 이력 및 접수 대기열을 보존한다. 과거 타이머·STOP·retired 마커는 복구 후에도 그대로 유지한다. 구형 일반 collector에는 과거 보완 타이머가 있으므로 재시작하지 않는다. 투자동향의 구형 이미지로 복구할 때도 KIS_SUPPLEMENT_ENABLED=false를 유지한다. 가격 갱신은 독립 realtime collector로 유지하고, 수정된 신규 일반 collector를 별도 배포한다.

DB 복원이 필요한 경우 이후 정상 거래와 수기 편집 손실을 먼저 대조하고 제한된 복구를 실시한다. 배포 전후 DB 및 설정 백업은 삭제하지 않는다. 새 수집기는 같은 접수번호를 재발견해도 대기열 고유 키로 중복 저장을 막는다.

## 증빙 상태

배포 버전, 병합 SHA, UTC/KST 적용 시각, 실제 실행 ID·건수·저장 근거 및 화면 검증 결과는 PR과 완료 보고에 실제 관측값으로 추가한다. 예시 날짜/수치를 운영 데이터로 삽입하지 않는다.
