# RoxStock 화면번호·메뉴 명세

**버전:** v0.1  
**기준일:** 2026-10-02 (Asia/Seoul)  
**근거:** 사용자가 정리한 현재 Figma 페이지명·순서, A0000~A0003, C9900/T9900의 메뉴 구성  
**상태:** 기획·문서 현행화. 실제 앱 코드·배포·운영 검증 결과를 의미하지 않음

# 1. 기준과 우선순위

현재 페이지 목록을 직접 확인한 결과를 기록한다. 화면번호·페이지명은 이번 사용자 정리와 현재 Figma 페이지 목록을 기준으로 한다. 계산·거래·수집 업무 규칙은 해당 기본설계서·수집기 설계가 담당한다. 오래된 프레임 제목이나 안내문에 남은 번호를 새 번호보다 우선하지 않는다.

# 4. 번호·명명 규칙

- `A`는 공통 기획·명세 페이지, `C`는 커버, `T`는 펼침·태블릿을 뜻한다.
- 같은 기능은 커버·태블릿에서 같은 숫자를 쓴다. 예: `C1000 / T1000`.
- 대메뉴는 1000부터 2100까지 100 단위로 배정한다. 하위 화면은 해당 대메뉴 번호에 1부터 더한다.
- 공유 기능은 대표 기능 아래 번호를 한 번만 배정한다. 진입 메뉴마다 페이지나 번호를 복제하지 않는다.
- 평가자산은 홈 하위 `C1001 / T1001`이다. 예수금은 대메뉴 `C1400 / T1400`이며 홈 카드와 더보기에서 같은 화면으로 진입한다.
- 거래등록·수정은 종목 상세와 매매일지에서 공통 호출한다. 커버 4개 거래 화면과 명세의 Figma 위치는 `C1100`이며 기존 `C1101` 페이지는 삭제됐다. 태블릿 위치는 현재 디자인을 별도 확인한다.
- 더보기는 공통 탐색 화면인 `C9900 / T9900`이다. 더보기 화면 자체는 12개 대메뉴 항목에 포함하지 않는다.
- 페이지명은 `C1000. 홈 · v0.2 · 09.28` 형식이다. 날짜는 해당 수정일의 `MM.DD`이며 연도를 생략한다. 날짜가 없는 `v0.0` 페이지에 임의의 완료일을 추가하지 않는다.
- 업무 데이터의 거래일자·재무 사업연도와 문서 이력의 기준일은 실제 연도를 유지한다. 페이지명 날짜 규칙과 혼동하지 않는다.
- 하단 메뉴의 기존 배치·순서는 유지한다. 더보기 순서와 강제로 맞추지 않는다.
- 페이지 버전과 프레임의 `WORK/FINAL`은 별개다. `v0.2` 페이지라고 모든 프레임이나 실제 개발·배포가 완료된 것으로 판단하지 않는다.

# 7. 공통 디자인 기준

- 커버 370×465, 펼침·태블릿 725×396 CSS px에서 우선 검증한다. CSS 최소 크기를 제한하는 값은 아니다.
- 상단 헤더·하단 메뉴는 각각 44px 고정, 본문은 화면별 정책에 따라 스크롤한다.
- 공통 카드 라운드는 8px이다. 입력필드·칩·팝업은 A0002의 개별 규격을 사용한다.
- 본문을 약 40% 이상 스크롤하면 최상단 이동 버튼을 표시하고 최상단에서는 숨긴다.
- 스크롤 콘텐츠 끝에 80px 안전 여백을 확보해 마지막 항목이 버튼·하단 메뉴와 겹치지 않게 한다.
- 스크롤바가 나타나도 콘텐츠·열 너비가 움직이지 않게 한다.
- 메뉴 아이콘은 더보기의 동일 기능 아이콘을 기준으로 화면별 활성·비활성 상태에서도 도형·선 굵기·비율을 일치시킨다.
- 기간 스와이프 화면은 인접 데이터를 선조회하고 기존 화면·스크롤·필터를 유지한다. 캐시 미적중·조회 실패는 해당 영역의 상태로 처리하며 전체 화면을 로딩 문구로 교체해 깜빡이지 않게 한다. 이 항목은 개발 요구사항이며 이번 문서 작업에서 구현 완료를 검증하지 않았다.

# 9. 원본 내부의 잔존 표기와 해석

2026-10-02 사용자 확정 순서에 맞춰 페이지명과 현재 번호 참조를 현행화한다. 이전 기록은 과거 기준이며 현행 번호를 우선한다.

- C9900/T9900 내부 대표 프레임 이름도 C9900/T9900으로 정리했다. 이전 C0900/T0900은 과거 표기다.
- A0003의 현행 번호표는 12개 대메뉴와 1400 예수금·2100 설정을 명시한다. 과거 번호표의 0900 및 000~003은 현행 기준이 아니다.
- A0000 일부 홈 진입 안내에는 예전 110·120·130·140·150이 남아 있다. 해당 목적지는 순서대로 1001·1400·1100·1200·1300이다.

## 2026-10-03 종목 분류 단순화 확정

이 명세는 기존 추천종목, 4개 탭 및 매수·거래 이력에 따른 관심/보유 등록·분류 제한을 대체한다. 문서 확정이며 Figma·API·DB·개발·QA 완료를 뜻하지 않는다.

| 구분 | 기준과 동작 |
|---|---|
| 관심종목 | 종목 추가에서 선택 가능. 매수·거래 유무를 등록 허용 조건으로 검사하지 않는다 |
| 보유종목 | 종목 추가에서 선택 가능. 매수 내역이 없어도 등록한다. 수동 등록으로 매수 Lot·수량·예수금 변동을 생성하지 않는다 |
| 거래종목 | 거래 이력이 1회 이상이고 현재 종목 전체 잔여 보유수량=0인 자동 상태. 종목 추가의 선택 항목이 아니다 |

- 추천종목 탭·추가 선택지·전용 이동 버튼은 제거한다. 목록은 기존 순서를 축약한 보유종목→관심종목→거래종목 3개 탭이며 클릭/좌우 순환을 같은 순서로 적용한다.
- 관심/보유 선택에 따른 종목 등록은 매수 이력 유무 때문에 거절하지 않는다. 기존 “거래 이력이 있으므로 관심으로 이동 불가” 제한도 폐기한다. 종목 미선택·저장 오류·중복 등록 등 일반 검증과 계좌 격리는 유지한다. “무조건 추가”는 동일 계좌의 같은 종목을 중복 생성한다는 의미가 아니다.
- 거래 발생 이후 보유/거래 전환은 현재 잔여수량을 기준으로 한다. 거래 이력이 있고 잔여수량0이면 거래종목, 다시 매수하여 잔여수량>0이면 보유종목으로 자동 이동한다. 일부 매도하여 수량이 남으면 보유종목을 유지한다.
- “매수가 없다”는 과거 매수 원본 기록이 없다는 뜻이 아니라 현재 남은 매수 Lot 수량이0이라는 뜻이다. 매수 원본·매도·실현손익·매매일지 기록을 보존한다.
- 거래 이력이 없는 수동 보유 등록은 잔여수량0이어도 선택한 보유 분류를 유지한다. 매수가 없다고 등록을 차단하거나 거래종목으로 보내지 않는다.
- 사용자 선택 분류의 저장 허용과 실제 거래 상태의 자동 전환을 구분한다. 거래종목은 자동 목록이며 직접 분류 편집 대상이 아니다. 새 매수·거래 수정/삭제는 허용한다.
- 실제 자산·보유수 집계는 잔여수량>0만 사용한다. 수동 보유 등록만으로 평가금액이나 보유수량을 만들어내지 않는다. 동일 계좌의 여러 탭에 종목을 중복 표시하지 않는다.
- 매도 삭제로 수량이 복원되면 보유종목으로 돌아온다. 기존 연결 매수 보존·수량 재산출·예수금/과거 스냅샷 자동 변경 없음 규칙을 유지한다.
- 기존 추천 분류 데이터의 이관은 별도 개발 검토 항목이다. 종목·거래 기록을 삭제하거나 새 분류로 임의 이관 완료했다고 선언하지 않는다. 서버 저장값/API/수집 대상에서 RECOMMENDED를 제거·대체하는 방법과 기존 데이터 보존을 개발 인계에 기록한다.
- C1100/T1100와 홈 종목 추가, A0000 정보구조·A0001 흐름·A0002 입력폼·A0003 공통 가이드의 관련 분류·상태·문구를 맞춘다. 화면번호·하단 메뉴 순서는 변경하지 않는다. 좌우8px·2열 사이8px·카드8px·헤더/하단44px·최하단80px 기준은 유지한다.
