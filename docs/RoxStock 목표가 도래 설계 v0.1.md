# RoxStock 목표가 도래 설계 명세 v0.1

- 작성일: 2026-10-01 (Asia/Seoul)
- 상태: 사용자 확정 요구사항 및 개발 설계 기준. 구현·QA·배포 완료를 의미하지 않는다.
- 적용 화면: C1000/T1000 홈, 2000 설정, 홈 하위 전체 목록 및 Lot 상세
- 근거: 2026-10-01 사용자 지시와 통합 지시문
- 이 명세는 이전의 “현재가 ≥ 종목별 매도 목표가” 해석을 대체한다.
- 최근 매수 카드는 별도 요구사항이며 이번 명세에서 변경하지 않는다.

## 1. 목적과 범위

선택된 계좌의 잔여 보유 Lot 중 보유기간별 목표수익률을 달성한 항목을 조회한다. 자동 매도·주문·알림 발송 기능은 포함하지 않는다. 목록은 현재 상태를 계산하는 것이며, 과거에 한 번 도달한 항목을 영구 보존하는 이력이 아니다.

## 2. 기본 조건과 설정

| 보유기간 상한(달력일) | 최소 평가수익률 |
| --- | --- |
| 7 | 5% |
| 30 | 10% |
| 90 | 15% |
| 180 | 20% |
| 365 | 30% |

각 조건은 독립적인 OR 조건이다. 각 조건 안에서는 보유일수 상한과 최소 수익률을 모두 만족해야 한다. 기간 구간을 서로 배타적으로 나누지 않는다. 경계값은 포함한다.

설정에서 조건 추가·수정·삭제를 제공한다. 조건은 최대 5개이며 보유기간 오름차순으로 표시한다. 보유기간은 1 이상의 정수, 수익률은 0보다 큰 유한한 수치다. 같은 기간 상한은 중복 저장하지 않는다. 5개이면 추가 버튼을 비활성화하고 이유를 안내한다.

초기 조건은 위 5개다. 사용자가 명시적으로 전부 삭제한 빈 설정은 기능 비활성 상태이며, 기본값을 다시 자동 삽입하지 않는다. 최초 설정 미생성과 명시적 빈 설정을 구분한다. 저장 성공 후 홈 조회를 갱신하고 실패하면 입력을 보존한다. 프론트와 백엔드 모두 개수·중복·입력값을 검증한다.

설정 저장 범위(사용자 공통/계좌별), 수익률 입력 소수 자릿수 및 최대 입력 범위는 기존 설정 구조를 확인해 구현 전에 명세에 확정 기록할 항목이다. 이 문서는 이를 사용자 확정사항으로 임의 지정하지 않는다.

## 3. Lot별 계산

같은 종목의 분할매수도 독립 Lot으로 처리한다. 종목 평균 매수단가를 사용하지 않는다.

- 보유일수: 오늘의 Asia/Seoul 달력 날짜 − 매수일의 Asia/Seoul 달력 날짜
- 매수 당일: 0일
- 날짜형 매수일은 그대로 날짜로 취급하고, 시각형 값은 한국시간 날짜로 변환한다.
- 달력 날짜 차이로 계산하며, 시각 차이를 24시간으로 나눈 값은 사용하지 않는다.
- 잔여수량: 매수수량 − 해당 Lot에 연결된 매도수량 합계
- 평가수익률(%): (현재가 ÷ 해당 Lot 매수단가 − 1) × 100
- 평가이익액(원): (현재가 − 해당 Lot 매수단가) × 잔여수량
- 수수료·세금은 위 평가 계산에 별도로 차감하지 않는다.
- 잔여수량이 0인 전량 매도 Lot은 제외한다.
- 미래 매수일, 잘못된 수량·단가·시세는 임의 보정하지 않고 판정 불가로 구분한다.

조건 일수 D, 최소수익률 R에 대해 다음을 모두 만족하면 해당 조건을 충족한다.

1. 잔여수량 > 0
2. 0 ≤ 보유일수 ≤ D
3. 평가수익률 ≥ R

표시를 위해 반올림하기 전의 값으로 판단한다. 금액·수익률 비교는 기존 Decimal 계산 정책을 사용하며 부동소수점 오차로 경계값이 달라지지 않게 한다. 나눗셈 없이 비교하는 경우 현재가 × 100 ≥ 매수단가 × (100 + R)로 판정할 수 있다.

현재가 미수집 또는 유효하지 않은 매수단가는 0으로 채우지 않는다. 기존 시세 유효성 정책과 수집 기준 시각을 함께 사용한다.

## 4. 중복 충족·정렬·조회

하나의 Lot이 여러 조건을 충족해도 한 번만 표시한다. 대표 조건은 충족 조건 중 기간 상한이 가장 짧은 조건이다. 대표 조건은 Lot 상세에서 확인하고 홈 두 줄 행에는 추가하지 않는다.

정렬:
1. 평가수익률 내림차순
2. 동률이면 매수일이 오래된 순
3. 동일 날짜이면 Lot ID 기준으로 안정적인 순서 유지

홈은 최대 5건만 표시하고 전체 충족 Lot 건수를 제공한다. 전체가 5건 초과이면 “더보기”를 표시한다. 정확히 5건이면 표시하지 않는다. 설정 조건 5개 제한과 홈 표시 5건 제한은 별개이며 전체 조회 결과 수에는 5건 제한을 두지 않는다.

전체 목록은 동일한 계좌·조건·판정·정렬을 사용한다. 많은 결과는 페이지 단위 추가 조회를 사용하며 한 조회의 계산시각·시세·설정 기준을 유지해 중복/누락을 방지한다. 설정 또는 계좌 변경 시 기존 페이지와 캐시를 초기화한다. 구체적인 API 경로·커서 구조는 기존 API와 맞춰 개발 시 확정한다.

목록 행은 해당 Lot의 기존 상세로 이동한다. 전체 목록은 홈 하위 화면으로 번호를 지정하며 대메뉴를 새로 만들지 않는다. 번호는 현행 화면번호표에서 중복 여부를 확인해 배정한다.

## 5. 두 줄 행 표시

| 줄 | 표시 순서 | 정렬·색상 |
| --- | --- | --- |
| 첫째 | 종목명 / 현재가 | 종목명 왼쪽, 현재가 빨간색·오른쪽 |
| 둘째 | 매수일(보유일수) / 잔여수량 × 매수단가 / 평가수익률 / 평가이익액 | 수익률 빨간색, 평가이익액 빨간색·오른쪽 |

- 날짜: YY.MM.DD, 예: 26.02.10 (10일)
- 수량: 해당 Lot 잔여수량. 분할매도 전의 최초 수량과 혼동하지 않는다.
- 금액: 원 단위, 천 단위 쉼표. 이 행은 프로젝트의 일반 만원 축약보다 본 표시 명세를 우선한다.
- 수익률: 소수점 한 자리
- 같은 종목의 다른 Lot은 각각 별도 두 줄 행
- 현재가 빨간색은 이 목록의 지정 규칙으로 전일 등락 색상과 별개다.
- 큰 금액·긴 종목명·커버 370px에서 겹침과 잘림 없이 검수한다.

계산 예시: 현재가 200,000원, 매수단가 180,000원, 잔여 10주이면 수익률 11.1%, 평가이익액 200,000원이다. 매수일 2026-02-10에 보유 10일인 예시는 기준일 2026-02-20이다. 화면의 실제 오늘 날짜에서 보유일수를 고정하지 않는다.

## 6. 카드·상태·갱신

홈 순서: 기존 보유종목 → 목표가 도래 → 최근 매수.

제목은 “목표가 도래”, 설명은 “보유기간별 목표수익률 달성”이다. 제목 오른쪽은 전체 충족 Lot 건수이며 종목 수와 구분한다. 설정 아이콘은 조건 편집 영역으로 연결한다.

| 상태 | 표시 |
| --- | --- |
| 정상 판정 완료, 충족 0건 | 현재 목표가 도래 항목이 없습니다. |
| 설정 조건 0개 | 조건 미설정 안내와 설정 진입 |
| 일부 Lot 판정 불가 | 확인된 결과와 일부 판정 불가 안내 |
| 전체 판정 불가 | 시세 등 판정 불가 이유 표시 |
| 조회 실패 | 오류 안내와 재시도 |

전체 목록에도 동일한 빈 상태 문구를 사용한다. 조회 실패 또는 일부/전체 판정 불가를 정상 0건으로 표시하지 않는다. 판정 불가가 있으면 건수는 확인 가능한 Lot 기준임을 안내한다.

현재가 수집 기준 시각과 목록 계산시각을 구분한다. 갱신 중 기존 목록을 유지하고 전체 카드 로딩 문구로 교체하지 않는다. 오류 시 기존 결과가 마지막 성공 시점의 자료임을 알린다. 갱신 완료 후 현재 조건을 재평가하고 미충족 Lot은 제거한다. 계좌 변경 시 다른 계좌 결과를 유지해 보여주지 않는다.

## 7. 개발 데이터 계약

다음은 필요한 정보의 논리적 목록이며 기존 DB 필드명이나 신규 API 완료 선언이 아니다.

- 설정: 조건 식별자, 기간 상한, 최소수익률, 저장 범위, 설정 변경 버전
- 항목: 계좌 ID, Lot ID, 종목 ID/명, 매수일, 보유일수, 잔여수량, Lot 매수단가, 현재가, 평가수익률, 평가이익액, 대표 충족 조건, 시세 기준시각
- 목록 메타: 계산시각, 전체 충족 Lot 수, 판정 불가 수/상태, 적용 설정 버전, 추가 조회 정보
- 기존 API 정책에 맞춰 Decimal 직렬화 형식을 유지하고 표시용 값을 판정 입력으로 재사용하지 않는다.
- 단일 판정 로직을 요약·전체 목록에서 공유한다. 프론트가 다른 공식으로 재판정하지 않는다.
- 기존 사용자/계좌 권한과 조회 범위를 유지한다. 목표 판정은 거래·예수금·스냅샷 데이터를 변경하지 않는다.

필수 뷰포트는 커버 370×465·태블릿 725×396 CSS px, 추가 검사는 400×640·816×616이다. 홈 및 전체 목록의 최초/최하단, 설정 편집과 상태별 화면을 Figma와 대조한다.

## 9. 구현 전 확정·인계

설정 저장 범위, 입력 정밀도/상한, 전체 목록 번호·API 경로·페이지 유지 방식은 담당자가 기존 구조를 확인해 후속 명세로 남긴다. 사용자 확정 로직은 임의 변경하지 않는다.

디자인은 Figma에 화면·상태·동선을 남기고 개발은 본 문서를 계산·데이터 기준으로 사용한다. 디자인과 문서 충돌은 기록·해결한 뒤 구현한다. 검증 후 PR 병합·자동 배포를 진행하고 배포 결과를 보고한다. 운영 화면 최종 확인은 사용자가 진행한다.
