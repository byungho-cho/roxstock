# 주식 매매일지 DB 스키마

**버전:** v0.4  
**상태:** 복리계획 1:N 유지 및 계좌 관리 변경 설계  
**기준일:** 2026년 9월 28일

# 1. 변경 목적

설계서 v0.4에서 확정한 `복리계획 1 : 복리목표 N` 구조를 Prisma와 MariaDB 마이그레이션에 반영한다. 거래 Lot, 예수금, 배당, 시세, 스냅샷과 재무 데이터 구조는 v0.2를 유지한다.

# 2. 테이블 구성

저장 테이블은 총 14개다. v0.2의 `compound_growth_goals` 단일 구조를 다음 두 테이블로 분리한다.

| 테이블 | 책임 | 주요 관계 |
|---|---|---|
| `compound_growth_plans` | 계좌별 복리 기간과 공통 기준금액 | `accounts 1:N compound_growth_plans` |
| `compound_growth_goals` | 계획별 복수 목표수익률 | `compound_growth_plans 1:N compound_growth_goals` |

# 5. 서비스 검증 규칙

MariaDB의 일반 UNIQUE/FK만으로 표현하기 어려운 아래 규칙은 Fastify 서비스의 DB 트랜잭션 안에서 검증한다.

- `start_date <= end_date`
- 같은 계좌에서 복리계획 기간 중복 금지
- 계획 생성 시 기준형 목표 한 개를 함께 생성
- 계획마다 목표 한 개 이상 유지
- 계획마다 `is_default = true`인 목표를 정확히 한 개 유지
- 연간 목표수익률과 금액의 허용 범위 검사
- 계획 삭제 시 하위 목표 존재 여부를 확인하고 명시적 삭제 처리

기간 중복 판정:

```text
기존 시작일 <= 신규 종료일
AND 기존 종료일 >= 신규 시작일
```

# 6. 데이터 이관

`20260926165000_compound_growth_plans` 마이그레이션은 기존 단일 구조의 각 행을 다음과 같이 보존한다.

- 기존 `period_name` → 새 계획의 `plan_name`
- 기존 기간·기초자산·연간 추가금·메모 → 새 계획
- 기존 목표명·목표수익률·표시 여부 → 새 하위 목표
- 이관된 하위 목표는 해당 계획의 기본 목표로 설정

# 8. 계좌 관리 추가 스키마 (v0.4)

v0.3의 기존 복리계획 및 거래 스키마는 유지하고 `accounts`에 다음 컬럼을 추가한다. 신규 생성의 계좌번호는 필수이며 기존 NULL 값은 이관 기간에만 조회를 허용한다.

| 컬럼 | 타입 | NULL | 설명 |
|---|---|---:|---|
| `broker_key` | VARCHAR(100) | 이관 중 Y → 완료 후 N | 증권사명 정규화 비교값 |
| `account_number_normalized` | VARCHAR(50) | 이관 중 Y → 완료 후 N | 공백·하이픈 제거한 번호 |
| `is_default` | BOOLEAN | N | 활성 기본 계좌 표시; 기본 FALSE |

- 기존 `account_number`는 사용자가 본 원본 표시값으로 유지한다. 추가·변경 시 원본과 정규화 값을 같은 트랜잭션에서 갱신한다.
- `UNIQUE(broker_key, account_number_normalized)`: 비활성 계좌도 포함하며 동시에 같은 계좌 생성 시 하나만 성공한다. NULL이 있는 기존 행은 보완 후 NOT NULL로 변경한다.
- `is_active = TRUE AND is_default = TRUE`인 행은 최대 한 개로 제한한다. MariaDB의 NULL 허용 UNIQUE 특성을 활용한 생성 컬럼(해당 행만 값 1, 나머지 NULL)에 UNIQUE 인덱스를 거는 SQL 마이그레이션을 사용한다. Prisma 모델에는 `isDefault`를 선언하고 생성 컬럼·인덱스는 마이그레이션 SQL에 관리한다.
- 첫 생성·기본 변경·비활성화·재활성화는 직렬화된 트랜잭션으로 처리해 활성 계좌가 있을 때 정확히 한 기본 계좌가 되도록 한다. 유일 제약은 최대 한 개를 보호하고 최소 한 개는 서비스 트랜잭션이 보장한다.
- 정규화: 번호는 Unicode NFC 후 모든 공백과 ASCII 하이픈 제거. 증권사는 Unicode NFC 후 trim·공백 축약·영문 대소문자 접기. 정규화 뒤 빈 번호는 오류.
- 기존 계좌 중 번호 누락, 정규화 후 중복, 기본 계좌가 없는 상태를 마이그레이션 전에 조사한다. 중복을 임의 병합하거나 기록을 삭제하지 않는다. 사용자 확인으로 정리한 뒤 UNIQUE와 NOT NULL을 적용한다.
- 계좌 삭제는 `is_active=false`로만 처리한다. Lot·매도·예수금·배당·스냅샷·복리계획 FK와 기존 삭제 제한을 유지한다.
