## 현행 기능과 기획

- 개인 계좌의 매수 Lot·분할매도·예수금·배당과 자산 스냅샷을 관리한다. 기존 손익·수익률 계산기를 재사용하고 비율을 합산하지 않는다.
- 계좌/사용자 소유권과 관리자 권한 검사를 유지한다. 개인 스크랩·거래·백업 데이터와 공용 종목·시세·뉴스 원문을 구분한다.
- 스크랩은 사용자·소식 복합키로 저장하며 노란 북마크, 스크랩 필터, 재접속 유지·탐색·실패 복원을 제공한다.
- 종목 전용 연도별 손익은 거래·배당이 있는 전체 연도를 최신순 세로 카드로 표시한다. 전체 통계를 서버에서 한 번에 집계하며 실제 성능 문제 전에는 3년 제한을 적용하지 않는다.
- 거래별 상세는 50건 표시·다음 50건 선조회, 월별 그룹·전체 조건의 월 합계, revision/조건별 커서와 중복 방지를 사용한다. 날짜·종목명 공간·매매/배당·금액의 한 줄 목록이며 종목명이 없어도 열 위치를 유지한다.
- 자료 충족 집계의 분모·제외 사유·정책 버전과 공시 확인 상태를 보존한다. 자료 부족과 실행 오류는 독립적이다. 대상 0의 조회 실패를 정상 완료로 바꾸지 않는다.
- 자료 기준은 종목·보고기간에 저장된 연결/별도 기준을 재사용한다. 없는 경우에만 최초 설정하며 수기 편집은 KRW, 외화·기준 충돌은 안내한다.
- 신규 오류 리포팅 시작점과 기존 원본 사건 보존 정책은 #352 보고서를 따른다. 기록 삭제와 화면 조회 구간 변경을 혼동하지 않는다.

## 구조·API·DB

React + Vite + TypeScript 프런트, Node.js + Fastify + TypeScript API, MariaDB + Prisma, Docker Compose와 기존 CI/CD를 유지한다. `frontend/` 화면, `backend/` 인증·조회·저장 API, `collector/` 수집 실행, `shared/` 공통 도메인·계산·DB, `database/prisma/` 스키마와 마이그레이션이 기준이다. 소스·이미지 분리는 DB나 서버 물리 분리가 아니다.

## 검증·보류·인계

이번 작업은 문서 현행화다. 링크·버전·코드 경로·차이 검사를 수행하며 이전 QA 결과는 원 보고서 날짜와 함께 인용한다. 앱 코드·DB·배포 버전·APK·스케줄을 변경하지 않는다. 실제 한투 수신, 1초 화면 반영, 시장 전환, 41구독 한도에서의 대상 정책, 장외/거래정지·재연결 상태는 후속 개발에서 검증한다. 알림 아이콘의 기능·실시간 화면 메뉴 진입 위치·정렬/종목추가의 상세 UX는 아직 확정되지 않았다. DB 테이블 분리 설계를 임의로 확정하지 않는다.

열린 조사/운영 보고 PR은 당시 기록으로 취급하며 코드 main 반영과 구분한다. #340·#329·#328 등의 초안은 후속 main 보고서를 함께 읽고 과거 조사 수치를 최신 현황으로 재사용하지 않는다. 이번 현행화는 기존 PR 일괄 병합이나 운영 재수집을 요청하지 않는다.
