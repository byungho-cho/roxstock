## 디렉터리와 실행 경계

- `frontend/`: 브라우저 앱; 개발 중 `/api`는 localhost:3300으로 프록시.
- `backend/src/server.ts`, `backend/src/routes/`: API 프로세스. 계좌·종목·거래 라우트는 `/api` 접두.
- `backend/src/collector/worker.ts`: 수집기 실행 진입점. API와 동일 저장소·이미지·Prisma 모델을 쓰고 **별도 컨테이너**에서 실행한다.
- `database/prisma/`: 스키마 및 마이그레이션.
- `infra/docker/compose.prod-backend.yml`: `roxstock-backend`는 앱·DB 네트워크, `roxstock-collector`는 DB 네트워크. 운영 DB는 기존 독립 MariaDB 컨테이너.
- `compose.yml`: 프론트 서비스; `infra/caddy/Caddyfile`: HTTPS 리버스 프록시.

## 기능별 현황

### 프론트엔드

`frontend/src/App.tsx` 기준으로 `/`, `/stocks`, `/stocks/add`, `/stocks/:stockId`, 종목 편집·가치·재무, `/journal`, `/detail/assets`, `/detail/cash`, `/more`, `/trade`가 구현 경로다. `/assets` 및 범용 상세 경로는 임시 안내 화면이다. `useMockData`, `mockApi`와 거래·현금 목업을 사용하므로 프론트 조작만으로 DB 저장을 확정할 수 없다. 신규 화면과 미검토 화면은 커버·펼침 Figma FINAL 대조 후 개발·검수한다. 기존 검토 완료 화면의 재작업 여부는 화면별 요청에 따른다.

### API와 인터페이스

`backend/src/app.ts`에서 계좌, 종목, 거래 라우트를 등록한다. 종목 검색/관심·추천 등록·변경·삭제의 요청·응답은 [종목 API 명세](./api/종목API.md)를 따른다. ID와 금액의 문자열 표현, 보유 분류의 거래 연동을 확인한다. 가격·스냅샷·수집 실행 결과의 프론트 조회 및 화면 연동은 별도 구현·검증 대상이다.

### 수집기

- 종목 마스터: 금융위원회 공공데이터포털 KRX상장종목정보 `getItemInfo_V2`, `DATA_GO_KR_SERVICE_KEY` 사용. Asia/Seoul 매일 07시 기본 실행. 최신 기준일, 페이지, 최소 건수 검증 후 UPSERT. 기본은 기존 종목을 자동 비활성화하지 않음.
- 가격: 네이버 금융 브라우저용 polling 응답. 공식 공개 API가 아니어서 응답 변경 가능성이 있다. 기본 20:00~06:00, 60분 간격, 종목 간 1초 지연. 날짜가 맞지 않는 값은 STALE 처리하며 실패·0원은 마지막 정상 가격을 덮어쓰지 않는다.
- 계좌 스냅샷: 기본 20·21·22·23시, 서울 날짜의 계좌·날짜 UPSERT. 가격 누락으로 합산이 불완전하면 잘못된 0원 스냅샷을 만들지 않는다. 과거 스냅샷 자동 재계산 없음. `daily_position_snapshots` 수집은 1차 범위에서 제외.
- 운영 기록: `collector_runs`, `collector_run_items`, `collector_locks` 테이블 및 JSON 로그. 스케줄과 수동 실행은 동일한 DB 락 사용.
- 현재 코드는 위 일정으로 작성돼 있다. 장 마감 후 하루 한 번 수집으로 변경하는 제안은 **저장소에 반영됐는지 재확인한 뒤** 운영 정책·스케줄·문서를 함께 현행화해야 한다. 스케줄 존재만으로 정상 수집을 의미하지 않는다.
- 명령·환경변수·실행 예시는 [백엔드 README](../backend/README.md)를 참조한다. 키나 DB 암호는 Git에 기록하지 않는다.

### 배포와 확인

- 프론트: `.github/workflows/frontend-image.yml`이 main의 프론트 관련 변경을 감지해 Docker Hub `newrox/roxstock-frontend`에 SHA 태그 이미지를 만들고 SSH 배포한다. 배포 시크릿이 없으면 배포 단계만 건너뛸 수 있다.
- 백엔드: `.github/workflows/backend-check.yml`은 MariaDB에서 Prisma 검증·마이그레이션·타입 검사·테스트 수행. `backend-deploy.yml`은 빌드·Docker Hub `newrox/roxstock-backend` 업로드 후 서버 `scripts/deploy-backend.sh` 실행. 이 스크립트가 Prisma 적용, API health/DB 확인 후 collector 서비스를 실행한다.
- 운영 주소: https://newrox.cafe24.com/ ; 외부 API는 `/api/*`. 내부 `/health`, `/health/db`는 외부 공개 경로가 아니다.
- 마지막 확증된 서버 상태의 근거는 [2026-09-27 16:17 인수인계](./handoff/20260927-1617-server-backend-final.md)다. 해당 시점의 백엔드 이미지는 `sha-5e63475`이며, 그 뒤의 코드·마이그레이션·수집기 배포를 증명하지 않는다.
