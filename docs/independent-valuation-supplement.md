# 독립 2차 가치지표 보완 (2026-10-09)

## 실행 구조와 시간

- 1차 `dart-worker`는 DART 재무자료 수집·저장과 기존 진행 상태를 담당한다. 재무자료 저장 중 네이버·가치지표 보완을 실행하지 않는다.
- 2차는 일반 `worker.ts daemon`의 독립 타이머로 60초마다 실행한다. DART 실행 플래그·인증키·기업코드 매핑에 의존하지 않는다.
- Asia/Seoul 토·일요일은 상시, 평일은 기존 `DART_NIGHT_WINDOW_START_HOUR`~`DART_NIGHT_WINDOW_END_HOUR`(기본 18~06시)에 실행한다. 평일 공휴일은 이번 합의에 따라 야간 기준이다.
- `VALUATION_SUPPLEMENT_ENABLED=false`로 2차만 중단할 수 있다. 기존 일반 수집기 컨테이너에서 실행하므로 별도 서비스가 필요하지 않다.
- 수동 갱신 흐름은 유지한다. 1차 수집의 네이버 추정치 자동 생성은 분리하며, 이번 독립 경로는 실제 저장 재무기간의 확정 연간 자료만 보완한다.

## 대상과 데이터 보존

- 저장된 비철회 DART 재무자료가 있는 활성 주식 종목·기간만 대상이다. 2015~현재 연도 범위이며, 재무자료가 없는 기간을 신규 생성하거나 전체 재수집하지 않는다.
- 활성 계좌 보유·관심·매수 이력 종목을 우선하며 최근 연도부터 처리한다. 이후 일반종목을 처리한다.
- 2021년 이상 연간 기간은 수동 검증을 마친 네이버/FnGuide 연간 확정 자료를 재사용한다. 종목별 제공 연도는 다를 수 있다. 원천에 없는 연도는 수집 성공으로 간주하지 않는다.
- EPS·BPS·PER·PBR·ROE의 기존 정상값과 수동값, 실제 0을 보존한다. PER/EPS, PBR/BPS의 기존 분모가 다른 원천·연도·연결/별도 기준이면 새 비율을 채우지 않는다.
- 출처·재무연도·연결/별도·주가/주식수 정책·계산식은 지표별 provenance에 기록한다. 네이버 제공 비율을 현재 주가나 현재 주식수로 재계산하지 않는다.
- 2015~2020 및 분기는 저장된 계산 근거만 사용한다. 부족한 근거는 사유와 빈 값으로 유지한다. DART 중단 중 주식수 추가 확보·누락 기초계정 재조회는 실행하지 않으며, 이 경로가 해당 자료까지 모두 복구했다고 보고하지 않는다.
- 기존 DART 성공 작업·재무자료·거래·예수금·스냅샷은 변경하지 않는다. 가치지표 실패와 DART 성공은 별도 상태다.

## 제한과 관찰

- 수동/자동 DART와 기존 공유 락을 사용하여 동시에 보완하지 않는다. 실행 중 락을 갱신한다.
- 사이클 최대 10기간, 기간 간 2초, 실패·근거 부족 재시도는 24시간 후다.
- 네이버 요청은 종목당 최대 4호출을 선예약하고 서울 날짜별 200호출 한도로 관리한다. 같은 사이클의 종목별 연도는 공급자 캐시를 공유한다. 저장 근거 계산은 외부 호출 예산을 쓰지 않는다.
- `collector_runs.job_type=VALUATION_SUPPLEMENT`와 일반 수집기 로그에서 결과를 확인한다. 기존 DART 전용 화면의 재무 수집 진행 상태와는 별도다. 운영 실행·보완 건수는 실제 실행 기록 확인 전 완료로 보고하지 않는다.

## 검사

- 단위 검사: 주말/평일 야간 경계, 비활성·시간 외 DB 무접근, 기존값/0 보존, 분모·출처 불일치 차단.
- 격리 MariaDB 검사: 저장 재무자료만 대상, 재무자료 원본 보존, 정상 저장·재실행, 수동값 보존, 공급자 실패 시 값 보존·재시도 지연.
- CI의 phase16 API 검사 다음 독립 단계에서 동일 DB 검사를 실행하여 다른 쓰기 검사와 겹치지 않는다.
- 로컬 DEV 실행과 운영 배포는 구분한다. 운영 전체 재수집·직접 데이터 보정은 수행하지 않는다.
