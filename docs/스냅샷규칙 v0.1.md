# 계좌·종목 일별 스냅샷 규칙

**버전:** v0.1  
**기준:** 매매일지 설계 v0.6

# 1. 생성 대상

- `daily_account_snapshots`: 계좌·한국 날짜별 한 행
- `daily_position_snapshots`: 계좌·종목·한국 날짜별 한 행
- 종목별 스냅샷은 1차 필수 기능입니다.
- 영업일과 휴장일 모두 생성합니다.

# 2. 실행 시점

- 같은 날짜의 행을 약 1시간마다 UPSERT합니다.
- 한국 시간 23시 실행을 당일 마지막 예정 실행으로 사용합니다.
- `is_final`은 두지 않으며 마지막 성공 UPSERT가 당일 값입니다.
- 계좌와 종목 스냅샷은 같은 실행 ID와 같은 트랜잭션 경계에서 계산합니다.

# 3. 가격 선택

1. 당일 정상 가격이 있으면 사용합니다.
2. 휴장일이거나 당일 가격이 없으면 마지막 정상 가격을 사용합니다.
3. 적용 가능한 정상 가격이 한 번도 없으면 해당 종목을 0원으로 계산하지 않고 실행을 실패 처리합니다.
4. 종목 스냅샷 `price_basis_at`에 사용 가격의 기준시각을 저장합니다.
5. 계좌 스냅샷 `price_basis_at`에는 사용한 종목 가격 중 가장 오래된 기준시각을 저장합니다.

# 4. 계산

```text
Lot 잔여수량 = 매수수량 - 연결 매도수량 합계
종목 수량 = 종목별 Lot 잔여수량 합계
종목 매입금액 = Σ(Lot 잔여수량 × Lot 매수단가)
종목 평가금액 = 종목 수량 × 사용 가격
종목 미실현손익 = 종목 평가금액 - 종목 매입금액
계좌 주식평가액 = 종목 평가금액 합계
계좌 총자산 = 계좌 주식평가액 + 현재 예수금
```

# 5. 수기 예수금 조정

사용자가 `accounts.cash_balance`를 직접 수정하면 `cash_balance_adjusted_at`을 함께 갱신합니다. 해당 한국 날짜의 계좌 스냅샷에는 `has_manual_cash_adjustment = true`를 기록합니다. 조정 금액·이전 금액·사유는 별도 이력으로 저장하지 않습니다.

# 6. 검증

- 종목 스냅샷 평가금액 합계 = 계좌 스냅샷 `stock_value`
- `stock_value + cash_balance = total_asset_value`
- 종목별 수량·매입금액·평가금액·미실현손익이 계산식과 일치
- 종목별 `price_basis_at`이 null이 아님
- 계좌·날짜 및 계좌·종목·날짜 UNIQUE가 유지됨
- 음수 잔여수량이 없음

금액 비교는 저장 정밀도 기준으로 정확히 일치해야 합니다. 검증 실패 시 이번 실행 전체를 롤백하고 기존 정상 스냅샷을 유지합니다.

# 7. 휴장일 예수금

휴장일에도 입금·출금·배당 최초 등록이나 직접 예수금 수정이 있으면 현재 예수금을 반영해 계좌 스냅샷을 갱신합니다. 주식평가액은 마지막 정상 가격으로 계산합니다.

# 8. 개발 전달사항

스냅샷 계산과 저장은 재실행 가능한 하나의 서비스로 구현합니다. 테스트에는 영업일, 휴장일, 가격 누락, 분할매도, 전량매도, 수기 예수금 조정, 동시 실행 사례를 포함합니다.
