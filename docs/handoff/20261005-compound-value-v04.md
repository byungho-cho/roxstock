# 복리계획 v0.4 · 가치분석 카드 추가 수정

## 적용 범위
C1900/T1900의 계획 목록, 목표 비교, 목표 상세, 입력, 삭제/기본 목표 변경 확인 및 C1700/T1700의 목록 카드. C1800/T1800과 가치분석 상세/차트 동작은 변경 대상에서 제외한다. REVIEW 및 삭제된 v0.2 복리 화면은 구현 기준에서 제외했다.

## 확정 계산 기준
사용자 선택: 기존 연초 추가 유지. 설계 v0.7을 재사용한다.
- 시작 금액: 시작 연도 초의 자산.
- 시작/종료 연도 모두 포함. 기간은 종료−시작+1.
- 첫해부터 매년 (직전 자산+추가금)×(1+연 수익률/100). 중간 연도 값을 반올림하지 않고 Decimal 400자리 정밀도로 계산하며 표시만 반올림한다.
- 올해 목표: Asia/Seoul의 현재 연도에 해당하는 연말 예상 자산. 계획 기간 밖이면 —.
- 최종 목표: 종료 연도의 같은 계산 결과. 진행률: 선택 계좌 현재 자산÷최종 목표×100. 최종 목표가 0 이하이거나 현재 자산 미수집이면 —.
- 종료 계획 목록의 종료 자산·최종 달성률은 선택 계좌의 종료 연도 12월 31일 DailyAccountSnapshot을 사용한다. 정확한 종료 스냅샷이 없으면 —와 미수집 안내를 표시하며 현재 자산을 종료 자산으로 대체하지 않는다. 현재 진행률과 최종 달성률은 구분한다.
- Figma의 연말 추가금 예시는 채택하지 않았다. 예시 금액/곡선은 운영 데이터에 포함하지 않는다.
- 계획·목표·계좌의 읽기는 RepeatableRead 스냅샷을 사용한다. 현재 자산은 기존 포트폴리오 계산/최신 저장 또는 실시간 가격 기준, 기준일은 계좌 갱신일과 최신 주가 시각 중 최신값이다. 기준 시각과 조회 시각은 API에서 구분한다.

## API 및 삭제 범위
기존 CompoundGrowthPlan/Goal 테이블을 재사용하고 계좌별 조회 및 CRUD를 연결한다. 신규 계획은 기준형 목표를 함께 저장한다. 동일 계좌 기간 중첩을 거절한다. 계획 삭제는 연결 목표를 먼저 삭제한 뒤 계획을 같은 트랜잭션에서 삭제한다. 계좌 행 잠금 이후 계좌/목표 범위를 확인하고 READ COMMITTED 트랜잭션으로 변경을 직렬 처리하며 목표가 있으면 기본 목표가 정확히 하나가 되도록 한다. 마지막 목표 삭제는 허용하며 목표 빈 상태로 전환한다. 다른 계좌 자료는 404로 보호한다.

## 가치분석 필드 완료 여부
- 연결 완료: 현재가/전일 종가, 기준연도의 마지막 저장 EPS/ROE/BPS, W, 지속계수별 적정주가, 고정 요구수익률 8%, 최신 연간 저장 자기자본(수동 비어 있지 않은 값 우선, 최신 유효 DART 보완).
- 발행주식수 연결: SecurityFundamentals. 과거 버전이 저장되지 않으므로 갱신 연도가 선택 기준연도와 같을 때만 표시하고 다른 연도는 —. API에 갱신일을 제공한다.
- 추가 확인 필요: 총액 초과이익·주주가치의 저장 필드 및 확정 계산/집계 기준이 없다. API는 null, 화면은 —. RIM 주당 적정주가의 기존 공식은 그대로 유지한다. 새로운 총액 공식이나 Figma 숫자를 임의로 도입하지 않는다.
- 자본의 결산 연도와 필드 미수집 안내는 API provenance로 제공한다.

## 검사 경계
변경 계산/입력/조회/저장/기본 목표/삭제/계좌 전환/빈 상태/오류/목록 카드 자체검사와 TypeScript·빌드를 수행한다. 회귀검사·Figma 시각 대조·다중 뷰포트 캡처 QA는 수행하지 않는다. 기능 확인의 태블릿 크기 설정은 캡처 QA가 아니다. 운영 검사는 자동 배포 성공 및 읽기 전용 HTTP 확인이며 테스트용 저장/삭제는 MariaDB 테스트 DB에서만 수행한다.
