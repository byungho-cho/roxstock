확정일: 2026-10-09 (Asia/Seoul)

같은 항목의 이전 지시보다 이 문서를 우선한다. 변경되지 않은 12차 현재예수금, 13/13.1차 화면, 14차 팝업 요구는 유지한다. [검증 목록](../qa/accounts-cash-ratio15.md) · [개발현황](../개발현황.md).

## 1. 계좌 카드와 추가·수정

- 상단 왼쪽 계좌명, 오른쪽 공통 Small 선택/사용중 버튼. 선택은 회색, 사용중은 파란 배경·흰색 글자.
- 사용 중 계좌: 노란색 #FACC15 테두리 2px와 동일 색상 제목. 테두리 변경으로 카드 크기가 흔들리지 않는다.
- 미선택 계좌는 기본 테두리·제목. 선택 강조와 아래 자산 비율 색상을 혼동하지 않는다.
- 현재 예수금 라벨은 제거하고 금액만 오른쪽 정렬. 하단 수정일 왼쪽·편집 아이콘 오른쪽을 한 행에 배치.
- 카드 높이는 최신 Figma의 내용에 맞는 간결한 배치를 따른다. 이전 150px 고정 지시를 대체한다.
- 편집은 해당 accountId의 계좌 정보 수정으로 연결. 메인의 별도 예수금 수정·초기화 버튼은 제거.
- 계좌 추가는 목록 하단 전체 너비·42px 버튼. 추가 폼에는 초기화·삭제 버튼 없음.
- 계좌명·증권사·계좌번호 필수. 빨간 별표와 실제 검증 일치. 원본 빈값·정규화 후 빈 계좌번호 저장 차단.
- 증권사+정규화 계좌번호 중복 검사, 수정 계좌 자신은 제외. 기존 계좌 ID·연결 데이터 보존.
- 실제 계좌번호 컬럼 및 기존 값 검증 후 필요한 NOT NULL 이행 방안 작성. 문서만으로 마이그레이션 완료 처리하지 않는다.

## 2. 초기화와 계좌 삭제

| 수정 대상 계좌 상태 | 변경 버튼 왼쪽의 빨간 버튼 |
|---|---|
| 연결 데이터 있음 | 데이터 초기화 |
| 처음부터 연결 데이터 없음 | 계좌 삭제 |
| 초기화 완료 후 연결 데이터 없음 재조회 확인 | 계좌 삭제 |
| 상태 조회 중·실패 | 데이터 없음으로 간주하지 않으며 삭제 실행 불가 |

조회 기간·화면 건수와 무관하게 서버가 대상 계좌 전체의 연결 데이터 유무를 확인한다. 구현 시 실제 테이블·외래키·설정 참조를 조사해 데이터 유무 판단 범위와 계좌 메타데이터 정리 범위를 명시한다. 삭제를 허용하려고 거래 등 연결 데이터를 연쇄 삭제하지 않는다.

### 데이터 초기화

수정 대상 accountId로 기존 초기화 절차를 연결한다. 삭제/유지 안내 카드·계좌명 확인 입력·취소/최종 초기화 버튼을 최신 Figma와 맞춘다. 계좌명 일치 검증과 불일치 실행 비활성, 중복 요청 차단, 실패 시 보존을 유지한다. 커버 외곽 좌우8px·버튼 사이8px, 태블릿 상세 패널 끝선 일치. 성공 후 삭제 가능 상태를 재조회한다.

### 계좌 삭제 확인

- 화면 중앙 DIM 팝업. 제목 계좌 삭제, 본문 “삭제하시겠습니까?”, 왼쪽 취소·오른쪽 빨간 삭제.
- 계좌명 재입력 없음. 취소는 데이터 변경 없음.
- 서버에서 대상·연결 데이터 없음 재검증 후 계좌 자체를 완전히 삭제. 사용자 추가 결정(2026-10-09): 개인 단독 사용으로 로그인·소유권 검사는 후속 2차 범위로 제외.
- 검증과 삭제 사이 동시 변경을 트랜잭션·잠금 또는 동등한 방식으로 방어. 연결 데이터 발견 시 삭제 차단·재조회.
- 사용 중/기본 계좌 삭제 시 남은 활성 계좌로 전환하고 기본 계좌 참조 유효성 유지.
- 마지막 계좌 삭제 시 계좌 없음·추가 안내. 삭제 계좌 선택 상태·캐시·관련 화면 데이터 정리.
- 실패 시 계좌·선택 상태 유지 및 오류/재시도 안내. 검증은 격리 DB/테스트 계좌에서 수행하며 운영 계좌를 시험 삭제하지 않는다.

## 3. 예수금 비율 색상 · 15.1차 수정 반영

예수금 비율 = 예수금 ÷ (주식평가액 + 예수금) × 100. 표시 반올림 전 값으로 판정한다.

| 예수금 비율 | 왼쪽 주식평가액 | 오른쪽 예수금 |
|---|---|---|
| 30% 이상 | 파랑 | 빨강 |
| 20% 이상~30% 미만 | 녹색 | 노랑 |
| 20% 미만 | 빨강 | 파랑 |

정확히 30%는 첫 구간, 20%는 둘째 구간. 사용자 최초 문장의 겹치는 “30% 이하”는 확인 답변에 따라 “20% 미만”으로 확정했다.

- 기존 Figma 공통 색상 토큰을 재사용하고 막대·금액·비율을 함께 적용한다.
- 홈 주식평가액/투자금·예수금 카드, 평가자산 카드·자산구성, 자산분석 자산구성, 현재예수금, 계좌 카드 예수금 금액에 공통 판정 로직 적용.
- 투자금이라는 표시명을 쓰더라도 이 구성 비율의 값은 주식평가액이다. 원금·누적입금으로 대체하지 않는다.
- 각 계좌 카드의 해당 계좌 비율을 사용한다. 현재 선택 계좌 비율을 다른 카드에 복제하지 않는다.
- 총자산0·시세 누락·계산 불가이면 중립색·비율 —. 확인된 금액은 보존. 계산 불가를 0%로 간주하지 않는다.
- 계좌 전환·조회·갱신 뒤 같은 계좌·같은 기준시점으로 재계산한다.
- 월 증감·평가손익·수익률의 부호 색상, 종목별 비중 색상은 별도 의미로 유지.
- 계좌 선택 테두리·제목 노랑은 비율과 무관하게 유지.
- 예시 23.8%: 주식 651,000,000원·76.2% 녹색 / 예수금 203,200,000원·23.8% 노랑. 예시 금액으로 색상을 고정하지 않는다.
- Figma 상태 예시는 예수금35%·25%·15%로 정리. 15.1차에서 홈·평가자산의 별도 카드도 23.8% 구간에 맞춰 주식 녹색·예수금 노랑으로 수정했다.

## 4. 유지하는 데이터 기준

12차의 현재예수금 기준은 선택 계좌 최신 등록 내역(createdAt DESC, id DESC)의 세후예수금(balanceAfter)이다. 조회 기간·거래일자와 독립이며 과거 내역 수정으로 현재예수금이나 이후 내역을 연쇄 재계산하지 않는다. [12차 명세](../development/cash-v05.md) 참조.

수집 로직·손익 계산식·자동 수집 스케줄은 이번 범위에서 변경하지 않는다. 실제 API 필드·삭제 경로·오류 코드는 구현 확인 후 API 문서에 기록하며, 아직 없는 계약을 이미 제공되는 API처럼 표시하지 않는다.

## 5. 검증 및 인계

[15차 검증 목록](../qa/accounts-cash-ratio15.md)에 구현 SHA·검사 근거·미검증 항목을 기록한다. 커버370×465·태블릿725×396 및 큰 화면에서 관련 기능을 확인한다.

개발 인계 순서: 최신 main/진행 작업 확인 → 별도 브랜치 → 구현 및 관련 기능/타입/빌드 검사 → PR·필수 검사 → 병합·자동 배포 결과 확인. main 직접 푸시 금지. 완료 보고에 PR·병합 SHA·실제 배포 SHA·화면 캡처·검사 결과·미검증 포함. 이번 문서 현행화 자체는 앱 빌드·배포·DB 변경을 수행하지 않는다.
