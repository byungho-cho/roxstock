# 15.1차 · 자산구성 최종 선택 3안

확정일: 2026-10-09 (Asia/Seoul). 사용자가 대비형 3안을 선택하고 금액·%는 현재 3안의 고정색 유지로 확인했다. 이 문서는 앞선 15.1차 고정 막대 색상 및 1·2안보다 우선한다. 사용자 요청으로 커버·태블릿의 이전 1·2안 예시 화면 4개와 사용 종료된 2안 전용 컴포넌트 세트를 삭제했다. 개발 기준으로 최종 3안만 남기며 변경 이력은 Git 이력에서 확인한다.

## 금액·퍼센트 글씨: 고정색

| 예수금 비율 r | 투자금(주식평가액) 글씨 | 예수금 글씨 |
|---|---|---|
| 20% < r < 30% | 녹색 | 노랑 |
| r ≤ 20% 또는 r ≥ 30% | 적색 | 파랑 |

정확히 20%, 30%는 적색/파랑이다. 22%, 28%는 녹색/노랑이다. 기존 공통 색상 토큰을 사용하고 농도·명도·투명도를 비율에 따라 변경하지 않는다. 이전 15.1차의 30% 이상 투자금 파랑/예수금 빨강 규칙은 폐기한다.

## 막대: 비율에 맞는 길이와 서로 반대인 농도

예수금 비율 r = 예수금 ÷ (주식평가액 + 예수금) × 100. 반올림 전 값으로 판정한다. 왼쪽은 주식평가액, 오른쪽은 예수금이며 원금·누적입금으로 대체하지 않는다.

- 안정 구간(20 < r < 30): 투자금 70→80%일수록 녹색은 진해지고, 예수금 30→20%일수록 노랑은 옅어진다.
- 그 외 구간: 투자금 50→100%일수록 적색은 진해지고, 예수금 50→0%일수록 파랑은 옅어진다.
- 예수금 50% 이상은 양쪽 막대 농도를 50% 때의 색상으로 유지한다. 50%와 60%는 같은 색이지만 길이는 다르다.
- 막대 전체 실제 표시 폭 W에 대해 투자금 폭 = W × (100-r)/100, 예수금 폭 = W × r/100. 여백·테두리를 포함한 카드 폭을 W로 사용하지 않는다.
- 예수금 60% 예시는 왼쪽 40%·오른쪽 60%이며, 모든 예시를 기본 78/22 길이로 재사용하지 않는다.

선택된 Figma 3안의 농도 기준(막대에만 적용):

| 구간 | 보간값 | 투자금 막대 시작 → 끝 | 예수금 막대 시작 → 끝 |
|---|---|---|---|
| 20 < r < 30 | t=(r-20)/10 | #22C55E → #A7F3D0 | #FEF08A → #EAB308 |
| 그 외, 0≤r≤100 | u=min(r,50)/50 | #EF4444 → #FECACA | #BFDBFE → #3B82F6 |

RGB 각 채널을 시작+(끝-시작)×보간값으로 계산한다. 위 값은 선택한 시안의 기준이며 금액·% 글씨에는 사용하지 않는다. 안정 구간의 ‘예수금 30→30%’ 입력은 앞선 ‘20%가 가장 옅고 30%에 가까울수록 진함’에 맞춰 30→20%로 해석한 것을 기록한다.

## 적용 화면과 예제 전용 라벨

- 홈의 주식평가액·예수금 카드, 평가자산·자산분석의 자산구성, 현재예수금, 계좌별 예수금 금액에 동일 계좌의 판정 기준을 사용한다. 막대가 있는 화면은 농도를 적용하며 금액·%는 고정색이다.
- 비교 예제의 ‘투자금(주식평가액)·예수금’ 라벨은 설명용이며 실제 화면에 새 라벨을 추가하지 않는다.
- 자산분석의 자산구성 카드는 최종 3안 배치로 교체한다. 제목 아래에 투자금/예수금 금액을 좌우로, 그 아래에 비율 막대를, 마지막 줄에 투자금/예수금 %를 좌우로 배치한다. 기존 막대 아래의 ‘주식·예수금’ 두 행과 라벨은 제거한다. 총자산·자산추이·기간 성과 구성 등 다른 카드는 유지한다. 커버·태블릿의 실제 상태 화면 및 전체 콘텐츠 참고 화면에 동일하게 적용한다.
- 월 증감·평가손익·수익률의 부호 색상, 종목별 비중 색상, 계좌 선택 테두리·제목의 노란색은 유지한다.
- 분모 0·시세 누락·비율 계산 불가는 중립색·비율 —, 확인된 금액 보존. 계산 가능한 예수금 0%와 계산 불가를 구분한다.
- 계좌 관리·초기화·삭제, 12차 현재예수금 데이터 기준, 수집·손익 계산식은 변경하지 않는다.

## 예시와 검증

예수금 22·28·20·10·30·40·50·60%의 여덟 예시를 보존한다. 22%는 진한 녹색/옅은 노랑, 28%는 옅은 녹색/진한 노랑이다. 10%는 20%보다 투자금 적색이 진하고 예수금 청색이 옅다. 각 구간의 글씨는 동일한 기본색이다.

검증 경계: 0%, 19.99%, 20%, 20.001%, 22%, 28%, 29.999%, 30%, 40%, 50%, 60%, 100%. 반올림 전 판정·막대 폭 합계·글씨 고정색·50% 이후 농도 고정·계좌 전환·계산 불가·손익 색상 회귀를 확인한다.

## 추가 보완 메모 · 발행주식수·자기주식수 저장 (2026-10-09)

상태: 사용자 요청으로 이번 수정 목록에 추가한 개발 대기 항목. 기존 15.1차 색상 구현 완료와 구분하며, 16차의 다른 확정 요구를 변경하지 않는다. 이번 확인에서는 DB 조회와 DART 응답 대조만 수행했고 코드·DB 데이터·수집 설정은 변경하지 않았다.

### 확인 근거

확인한 서버 백엔드 이미지 기준 커밋: `dd0a21c1d0f3a6e49ece4b2ca9dfee8f81e7b867`. 삼성전자 보통주(005930, securityId 262)의 동일 공시 응답과 저장 데이터를 대조했다.

| 결산기준일 | 접수번호 | 발행주식수 `istc_totqy` | 자기주식수 `tesstk_co` | 유통주식수 `distb_stock_co` |
|---|---|---:|---:|---:|
| 2025-12-31 | 20260310002820 | 5,919,637,922 | 91,828,987 | 5,827,808,935 |
| 2026-06-30 | 20260814003699 | 5,846,278,608 | 82,086,705 | 5,764,191,903 |

- DART `stockTotqySttus.json`의 두 실제 응답은 모두 정상(status 000)이며 세 항목이 함께 제공된다. [공식 API 계약](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS002&apiId=2020002).
- 현재 `fetchPeriodShares`는 보통주의 `distb_stock_co`만 `outstanding`으로 추출한다. 발행주식수·자기주식수는 반환하지 않는다.
- `period_valuations.supplemental.shares`에 저장된 유통주식수와 접수번호가 위 응답과 일치했다. 삼성전자의 `security_fundamentals` 레코드는 없었다.
- 가치분석의 `issuedShares`는 별도 fundamentals 필드를 읽으므로, 유통주식수가 저장되어 있어도 발행주식수는 —로 표시된다. 공급자 미제공 문제가 아니라 추출·저장·화면 연결 보완 대상이다.

### 개발 보완 범위

1. 기존 주식수 API 응답에서 발행주식수·자기주식수·유통주식수를 함께 추출·저장한다. 별도 원천 API를 추가하지 않는다. 0은 정상 수치로 보존하고 누락·빈 값·—는 0으로 바꾸지 않는다.
2. 주식 종류(보통주/우선주), 사업연도, 보고서 구분, 접수번호, 결산기준일, 수집시각을 함께 관리한다. 종목에 해당하는 주식 종류를 사용하며 보통주와 우선주 또는 합계 행을 섞지 않는다. 현재 화면의 발행주식수에 유통주식수를 대신 넣지 않는다.
3. 저장 형식과 API 계약을 보완해 가치분석 상세·목록 및 같은 필드를 쓰는 재무제표 화면에 실제 발행주식수를 연결한다. 과거 조회에 최신값을 임의 대입하거나 저장 수정연도를 공시 기준연도로 간주하지 않는다. 표시할 공시·결산기준일을 식별할 수 있게 한다. 유통주식수·자기주식수의 새 화면 항목 추가는 이번 메모만으로 확정하지 않는다.
4. 기존 데이터도 두 필드 누락 여부를 기준으로 보충할 수 있게 한다. 현재 보완 수집의 `status === SUCCESS` 조기 종료나 동일 접수번호 캐시 때문에 필드 추가가 영구히 건너뛰어지지 않도록 확인한다. 수동 재무제표 갱신과 정기 수집 모두 같은 주식수 추출·저장 경로를 사용한다.
5. 삼성전자 두 공시부터 검증한 뒤 기존 수집 대상의 누락분을 보충한다. 기존 호출 한도·간격·재시도·중복 방지를 유지하며 실패 시 정상 저장값은 보존한다. 보충 작업의 대상 수·완료·실패를 구분한다.
6. 기존 수동 입력값, 주식 종류 및 시점별 근거를 보존한다. EPS/BPS/RIM 등 계산의 분모를 이번 표시 보완과 함께 일괄 교체하지 않는다. 현재 유통주식수 계산 근거와 중복 자기주식 차감이 없는지 회귀 확인한다.

### 완료 판정

- 위 두 공시의 세 수치가 DB에 저장되고 같은 주식 종류·접수번호·기준일에서 발행주식수 − 자기주식수 = 유통주식수인지 확인.
- 기존 SUCCESS 자료도 누락 두 필드를 보충하며 재실행 시 중복 없이 동일 결과인지 확인.
- 실제 자기주식 0, 항목 누락, 통신 실패, 공시 정정·접수번호 불일치, 보통주/우선주 구분을 검증.
- 가치분석의 발행주식수 표시와 API/DB가 일치하며 연도 전환 시 해당 공시 기준을 유지하는지 확인.
- 기존 유통주식수와 가치지표가 의도 없이 변경되지 않았는지 확인.
- 구현 PR, 검증 결과, 실제 보충 건수와 배포 상태를 별도로 기록하기 전에는 구현·데이터 보충 완료로 표시하지 않는다.
