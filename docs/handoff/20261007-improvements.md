## 2026-10-07 · 개선 개발 지시문 (사용자 확정)

상태: 개발 요구 확정 / 문서·디자인 현행화 / 구현·배포·기능 QA 대기.
이번 절은 동일 항목의 이전 명세보다 우선한다. 2026-10-06 인수인계의 미완료 요구는 계속 유효하다. 기존 데이터 복구와 이번 소스 개선을 구분한다.

### 1. 종목 상세 보유현황 정렬
보유 Lot 카드는 매수일 내림차순으로 표시하여 최근 매수일이 맨 위에 온다. 같은 날짜는 일관된 보조 키로 정렬한다. 커버·태블릿 모두 적용하고 보유량·손익 계산은 변경하지 않는다.

### 2. 종목 상세 거래내역 상단 카드
거래내역 탭의 현재가·전일 대비 카드를 해당 종목 전체 기간의 **매매손익 금액·수익률** 요약으로 교체한다. 현재 계좌·종목의 투자손익 상세 ‘매매손익’과 동일한 집계·분모를 재사용한다. 총 매수금 대비 기준을 확인하여 두 화면의 금액·비율이 일치하도록 한다. 배당과 미실현 평가손익은 제외한다. 매수 동작은 유지한다. 요약·보유현황 탭의 현재가 카드는 기존 정책을 유지한다. 전량 매도 종목·부분 매도·손익 0·분모 0·조회 실패를 구분한다.

### 3. 과거 내역 화면 자동 갱신 제거
투자손익 및 과거 거래 조회 등 한 번 조회한 자료를 재사용할 수 있는 화면은 재활성화·포커스 복귀·화면 재진입에 따른 무조건 재조회와 주기적/실시간 갱신을 제거한다. 캐시가 있으면 즉시 표시한다. 거래·배당 등록/수정/삭제 성공 시 관련 캐시를 무효화하고, 계좌·연도·종목 등 조회 조건 변경 시 해당 조건 자료를 조회한다. 계좌·기간·종목별 캐시를 격리하고 오래된 응답 혼입을 차단한다. 현재가가 필요한 홈·보유평가 화면 및 서버 수집 기능의 갱신은 유지한다. 실패를 0원으로 대체하지 않는다.

### 4. 종목 이동 이름 한 줄 표시
투자손익 종목 상세의 좌우 이전/다음 종목명은 한 줄 말줄임으로 표시한다. 폭이 부족한 경우 최대 5글자와 …로 축약하고 중앙 종목명을 침범하지 않는다. 전체 이름은 접근성 이름으로 제공한다.

### 5. 투자손익 종목 상세 스와이프
본문 좌우 스와이프로 종목을 전환한다. 왼쪽은 다음, 오른쪽은 이전이며 진입 목록의 현재 정렬 순서와 좌우 버튼 순서를 따른다. 처음·마지막 종목에서는 멈춘다. 인접 종목을 선조회하되 다른 종목 데이터를 새 제목 아래 표시하지 않는다. 세로 스크롤·버튼·입력·차트·뒤로가기 제스처와 충돌하지 않게 한다.

### 6. 연도별 투자손익의 투자금 기준
지난 연도는 해당 연말 스냅샷의 투자금을, 진행 중인 올해는 해당 연도의 가장 마지막 유효 스냅샷 투자금을 사용한다. 올해를 무조건 어제 날짜로 고정하지 않는다. 기준일을 함께 확인할 수 있게 한다. 누적 매수금·실시간 평가금액으로 대체하지 않는다. 연말 스냅샷 누락 시 대체일 정책은 별도 확정 전까지 미수집으로 구분하며 임의 날짜로 조용히 치환하지 않는다.

### 7. 종목별 손익 정렬·총계 위치
연도 상세 ‘종목별 손익’과 투자손익 종목별 탭 ‘종목별 누적 수익’은 **부호를 포함한 손익액 내림차순**을 기본으로 한다. 절댓값·수익률 정렬이 아니다. 제목 오른쪽에 내림/오름 토글을 두며 재정렬 시 종목·수익률·금액을 함께 이동한다. ‘총 N개’는 제목 옆으로 옮긴다. 선택 종목 상세의 이웃 이동도 현재 목록 정렬을 따른다.

### 8. 월별 매매·배당 텍스트 색상
투자손익 종목 상세 ‘월별 손익·배당 내역’의 유형 텍스트는 매매=해당 행 손익색(이익 적색/손실 청색/0 중립), 배당=노란색으로 표시한다. 금액 색상은 기존 정책을 유지한다.

### 9. 홈 로딩 성능 개선
첫 진입과 재진입의 API 응답 시간·중복 요청·직렬 의존·렌더링 대기를 측정하고 병목을 튜닝한다. 캐시가 있으면 즉시 표시하고 필요한 갱신은 뒤에서 수행한다. 캐시가 없는 첫 진입은 준비된 카드부터 표시하고 미완료 카드에만 로딩 상태를 둔다. 전체 API가 끝날 때까지 화면 전체를 막지 않는다. 임시 0원이나 다른 계좌의 자료를 표시하지 않는다. 동일 조건의 수정 전후 첫 유효 카드 표시 시간·전체 로딩 시간·요청 수를 보고한다.

### 10. 매매일지 거래현황 스와이프 개선
날짜·요약·거래 목록·빈 상태를 포함한 거래현황 카드 전체에서 날짜 스와이프가 동작하도록 영역을 넓힌다. 거리·속도·가로/세로 방향 판정을 조정하여 짧은 의도적 가로 움직임도 자연스럽게 인식한다. 세로 스크롤을 우선 보호하고 버튼 클릭을 오인하지 않으며 한 제스처당 한 날짜만 전환한다. 왼쪽 다음 날/오른쪽 이전 날, 날짜 버튼과 동일한 경계 규칙을 사용한다. 인접 날짜 선조회와 요청 중복 방지를 적용한다. 거래 없는 날짜도 동일하게 동작한다.

### 11. 일별손익 스와이프 추가
날짜 선택부·전체손익·실현손익·거래현황 등 본문 전체에서 좌우 스와이프로 날짜를 전환한다. 방향·감도·축 판정은 거래현황과 공통으로 관리한다. 세로 스크롤·행 상세 진입·버튼 동작을 보존한다. 헤더·하단 메뉴는 고정하고 인접 날짜 캐시를 재사용한다.

### 12. 투자금 화면의 누적 매매손익 표시
현재 평가금액 카드 아래 ‘투자금 대비 차액’을 **선택 연도의 누적 매매거래 실현손익**으로 변경한다. 올해는 ‘올해 누적 매매손익’, 과거는 ‘YYYY년 누적 매매손익’으로 표시한다.
- 금액 = 해당 연도 매도 거래의 실현손익 합계. 배당·미실현 평가손익 제외.
- 비율 = 해당 연도 누적 매매손익 ÷ 해당 화면의 누적투자금 × 100. 분모 0은 —.
- 색상은 손익 금액의 양/음/0을 따른다. 상단 평가금액의 값은 변경하지 않는다.
- 분기 선택은 기존대로 차트·투자내역에 적용하며 이 요약은 연간 값이다.
- 사용자 확인용 예시: 평가금액 81,845,732원 / 누적투자금 107,317,732원 / 올해 누적 매매손익 +39,720,500원 / +37.0%. 화면 예시이며 운영 API 검증값으로 간주하거나 코드에 고정하지 않는다.

### 개발 순서·검증·인계
손익·스냅샷 기준(2/6/12)을 먼저 구현하고 정렬·표시(1/4/7/8), 캐시·로딩(3/9), 공통 스와이프(5/10/11)를 진행한다. 소스 변경은 별도 브랜치와 PR로 제출하며 v0.1 복귀 기준을 유지한다. 이번 개선으로 기존 매수·매도·배당·예수금 원본이나 과거 스냅샷을 임의 수정하지 않는다.

**웹서버 담당:** 필요한 API·집계·캐시 계약 변경 및 API 검증만 수행한다. 브라우저 검증은 요구하지 않는다. 정상 응답뿐 아니라 집계 대조·빈 결과·실패·계좌/연도/종목 경계·배당 제외·분모 0을 검증하고 응답 예시와 결과를 남긴다.

**프런트 담당:** 화면 연결·캐시 무효화·정렬·색상·스와이프·홈 성능을 구현하고 브라우저/실기기 검증을 맡는다. 작은 화면·태블릿, 가로/세로/대각선 제스처, 빈 날짜, 빠른 전환, 뒤로가기·스크롤 복원, 포커스 복귀 시 불필요한 요청 제거를 확인한다.
