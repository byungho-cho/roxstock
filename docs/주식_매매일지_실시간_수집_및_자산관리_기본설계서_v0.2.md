# 1 설계 결론

매수와 매도는 하나의 자기참조 거래 테이블로 합치지 않고 buy_trades와 sell_trades로 분리한다. 하나의 매수 거래는 독립된 Lot이며, sell_trades는 반드시 한 buy_trades 행을 참조한다. 실현손익은 저장하지 않고 연결된 매수단가와 매도단가로 계산한다.

예수금은 거래 내역을 다시 합산해 복구하는 원장 값이 아니라 사용자가 증권계좌에서 확인한 현재 실제 현금이다. 신규 매수, 매도, 입금, 출금과 배당은 등록 순간에만 예수금에 반영하며 이후 수정 또는 삭제는 예수금을 자동 변경하지 않는다.

# 4 매수와 매도 설계

## 4 1 buy_trades

| **컬럼**               | **논리 타입** | **필수** | **설명**                     |
|------------------------|---------------|----------|------------------------------|
| id                     | BIGINT        | 필수     | 매수 Lot 식별자              |
| account_id             | BIGINT        | 필수     | 계좌 FK                      |
| security_id            | BIGINT        | 필수     | 종목 FK                      |
| bought_at              | DATETIME      | 필수     | 매수일시                     |
| quantity               | DECIMAL       | 필수     | 최초 매수수량                |
| unit_price             | DECIMAL       | 필수     | 해당 매수 건의 평균 매수단가 |
| memo                   | TEXT          | 선택     | 매수 판단 메모               |
| created_at, updated_at | DATETIME      | 필수     | 생성 및 수정시각             |

## 4 2 sell_trades

| **컬럼**               | **논리 타입** | **필수** | **설명**                |
|------------------------|---------------|----------|-------------------------|
| id                     | BIGINT        | 필수     | 매도 식별자             |
| buy_trade_id           | BIGINT        | 필수     | 매도 대상 buy_trades FK |
| sold_at                | DATETIME      | 필수     | 매도일시                |
| quantity               | DECIMAL       | 필수     | 매도수량                |
| unit_price             | DECIMAL       | 필수     | 매도단가                |
| memo                   | TEXT          | 선택     | 매도 판단 메모          |
| created_at, updated_at | DATETIME      | 필수     | 생성 및 수정시각        |

- buy_trades에는 초기 보유 여부 컬럼을 두지 않는다.

- sell_trades에는 account_id와 security_id를 중복 저장하지 않고 buy_trades를 통해 확인한다.

- 매도가 연결된 매수 건은 매도 행을 먼저 처리하기 전에는 삭제하지 못하게 한다.

- 한 번의 실제 매도가 여러 매수 Lot을 포함하면 Lot별 sell_trades 행으로 나누어 저장한다.

# 6 예수금 설계

## 6 1 기준값

accounts.cash_balance는 현재 증권계좌에서 확인한 실제 예수금이며, 추가 투자 가능 금액을 보여주는 기준이다. 사용자는 실제 잔액과 다르면 이 값을 직접 수정할 수 있으며 직접 수정 이력은 저장하지 않는다.

| **이벤트** | **신규 등록 시 예수금**  | **저장 테이블**   | **성과 분류**  |
|------------|--------------------------|-------------------|----------------|
| 매수       | 매수수량 × 매수단가 차감 | buy_trades        | 투자 거래      |
| 매도       | 매도수량 × 매도단가 증가 | sell_trades       | 투자 거래      |
| 입금       | 입금액 증가              | cash_transactions | 외부 자금 유입 |
| 출금       | 출금액 차감              | cash_transactions | 외부 자금 유출 |
| 배당       | 실제 세후 배당금 증가    | dividends         | 투자수익       |

## 6 2 변경 처리

- 신규 기록 생성과 예수금 1회 반영은 하나의 DB 트랜잭션으로 처리한다.

- 매수, 매도, 입출금 또는 배당을 수정하거나 삭제해도 예수금은 자동 변경하지 않는다.

- 거래 내역만으로 예수금을 재계산하거나 과거 예수금을 복원하지 않는다.

- 예수금 보정 행이나 보정 이력 테이블은 두지 않는다.

# 7 거래비용

개별 매수와 매도에는 세금 또는 수수료 컬럼을 두지 않는다. 거래비용은 monthly_trading_costs에서 계좌별 월간 합계만 수기로 기록한다. 연간 비용은 월간 금액을 합산하며 예수금, 매수단가와 실현손익에는 자동 반영하지 않는다.

# 9 현재가와 스냅샷

## 9 1 현재 평가

market_prices는 종목별 최신 현재가, 가격 기준시각과 수집 상태를 유지한다. 대시보드는 스냅샷이 아니라 최신 가격과 매수 Lot 잔여수량을 이용해 현재 평가액을 계산한다.

## 9 2 일별 스냅샷

| **항목**        | **설계 기준**                              |
|-----------------|--------------------------------------------|
| 갱신 주기       | 매시간 오늘 날짜의 같은 행을 UPSERT        |
| 마지막 갱신     | 한국 시간 23시                             |
| 최종 상태       | is_final 등 별도 상태 컬럼을 사용하지 않음 |
| 계좌 고유조건   | account_id + snapshot_date                 |
| 포지션 고유조건 | account_id + 대상 식별자 + snapshot_date   |
| 시간 정보       | snapshot_date, price_as_of, updated_at     |

23시 갱신값이 해당 날짜의 마지막 스냅샷이 된다. 매시간 새 행을 쌓지 않으므로 초기 버전에는 시간대별 자산 이력이 남지 않는다. 현재 평가액은 최신 시세로 별도 계산하므로 사용자는 스냅샷 주기와 관계없이 현재 상태를 확인할 수 있다.

# 12 데이터 정합성과 제약

- 매도수량은 연결된 매수 Lot의 잔여수량을 초과할 수 없다.

- 매도 등록은 트랜잭션 안에서 잔여수량을 확인해 중복 매도를 방지한다.

- sell_trades.buy_trade_id는 buy_trades.id를 참조하고 삭제는 제한한다.

- 금액, 수량과 비율은 부동소수점이 아닌 DECIMAL을 사용한다.

- 현재가가 없거나 오래된 경우 가격 기준시각과 상태를 화면에 표시한다.

- 현재 예수금은 거래 원장과 일치 여부를 강제하지 않고 사용자 확인값을 우선한다.
