# 주식 매매일지 웹 서비스 기획서

**버전:** v0.3  
**부제:** 개인용 단순 자산관리와 매수 건별 성과 추적

| 항목 | 내용 |
|---|---|
| 서비스 유형 | 개인 투자자를 위한 모바일 중심 주식 매매 기록·자산·가치투자 관리 서비스 |
| 핵심 목표 | 실제 예수금과 현재 자산을 명확히 보여주고, 사용자가 선택한 매수 건을 기준으로 매도 성과를 추적한다 |
| 주요 사용자 | 여러 매수 건과 가치투자 후보를 직접 관리하는 개인 투자자 |
| 기획 기준일 | 2026년 9월 16일 |
| 연계 문서 | 매매일지 설계 v0.3, 매매일지 스키마 v0.2 |
| 문서 상태 | DB 스키마 v0.2 초안 및 핵심 메뉴 명명 규칙 반영 |

# 1. 서비스 개요

RoxStock은 매수 건별 보유수량과 매도 손익, 현재 실제 예수금, 주식 평가액, 배당, 가치투자 지표와 장기 복리목표를 한곳에서 관리하는 개인용 주식 매매일지다.

초기 버전은 증권사의 모든 정산 규칙을 재현하지 않는다. 사용자가 현재 얼마를 보유하고 있고, 얼마를 더 투자할 수 있으며, 각 투자 판단이 어떤 결과를 만들었는지를 단순하고 명확하게 보여주는 데 집중한다.

# 2. 제품 원칙

- 한 번의 매수를 하나의 독립된 매수 Lot으로 관리한다.
- 매도는 사용자가 선택한 단일 매수 Lot에만 연결한다.
- 여러 매수 Lot을 한 번의 매도로 묶는 기능은 제공하지 않는다.
- 한 매수 Lot은 여러 번 나누어 매도할 수 있다.
- 예수금은 현재 증권계좌에서 확인되는 실제 현금 잔액을 기준으로 한다.
- 신규 거래는 등록 순간에만 예수금에 반영하고, 이후 거래 수정·삭제는 예수금을 자동으로 되돌리지 않는다.
- 현재가는 자동 수집하되 수집이 불가능하면 사용자가 직접 수정할 수 있다.
- 개인용 초기 버전에 필요한 기능부터 구현하고, 복잡한 기능은 실제 필요가 확인될 때 추가한다.
- 모든 화면에서 주가와 손익의 상승 금액은 밝은 적색, 하락 금액은 밝은 청색, 보합은 흰색으로 표시한다.
- 색상만으로 상태를 구분하지 않고 부호와 수익률을 함께 표시한다.

# 3. 1차 개발 범위

| 포함 | 제외 또는 후속 검토 |
|---|---|
| 계좌, 현재 예수금, 매수, 매도, 입금, 출금, 배당 | D+1·D+2 결제 예정금액 분리 |
| 매수 Lot별 잔여수량과 실현·미실현손익 | FIFO·LIFO·종목 전체 평균단가 매도 |
| 관심·보유·추천종목 통합 목록 | 여러 매수 Lot 일괄매도 |
| 최신 현재가 자동·수기 갱신 | 전체 틱 데이터 영구 저장 |
| 일별 계좌 스냅샷 | 시간대별 스냅샷 이력 보존 |
| 종목별 일별 스냅샷 | 실제 사용 여부는 구현 전 재검토 |
| 재무제표와 가치평가 지표 | 컨센서스·업종 평균·고급 지표 |
| 세전·세후 배당금 | 기업행사·해외주식·다중 통화 |
| 여러 복리목표와 매년 추가 투자금 | 증권사 주문 자동 실행 |

# 4. 핵심 사용자 흐름

## 4.1 최초 설정

1. 계좌와 증권사명을 등록한다.
2. 현재 증권계좌에서 확인한 실제 예수금을 입력한다.
3. 기존 매수 건을 종목·매수일시·수량·매수단가로 등록한다.
4. 종목을 관심·보유·추천 중 하나의 목록에 등록한다.
5. 최신 시세와 가치투자 정보를 확인한다.

## 4.2 매수와 매도

1. 매수 등록 시 매수금액과 수수료·세금을 예수금에서 차감한다.
2. 매도할 매수 건을 선택한다.
3. 선택한 매수 건의 잔여수량 범위에서 매도수량과 단가를 입력한다.
4. 매도 등록 시 매도금액에서 수수료·세금을 제외한 금액을 예수금에 더한다.
5. 실현손익은 선택한 매수 건의 매수단가를 기준으로 계산한다.
6. 거래 수정·삭제 후 실제 예수금과 차이가 생기면 사용자가 현재 예수금을 직접 수정한다.

## 4.3 배당과 입출금

- 배당은 세전 배당금과 세후 실수령액을 함께 기록한다.
- 배당 최초 등록 시 세후 실수령액만 예수금에 더한다.
- 연도별 실수령 배당금은 세후 배당금 합계로 계산한다.
- 입금과 출금은 투자손익과 구분되는 외부 현금흐름으로 관리한다.

# 5. 자산과 손익

```text
매수 Lot 잔여수량 = 매수수량 - 연결된 매도수량 합계
실현손익 = 매도수량 × (매도단가 - 연결된 매수단가)
Lot 평가금액 = 잔여수량 × 현재가
Lot 평가손익 = 잔여수량 × (현재가 - 매수단가)
주식 평가금액 = 모든 보유 Lot 평가금액의 합
총 평가자산 = 주식 평가금액 + 현재 예수금
현금 비중 = 현재 예수금 ÷ 총 평가자산 × 100
```

거래비용은 기본 실현손익에 자동 반영하지 않고 별도 참고값으로 보여줄 수 있다. 월별·연도별 수수료와 세금은 예수금 변동 내역의 비용 합계로 계산한다.

# 6. 종목 목록과 모바일 UX

`watchlist_items` 하나에서 종목을 다음 세 가지 유형으로 구분한다.

| 목록 유형 | 화면 탭 | 의미 |
|---|---|---|
| `WATCHLIST` | 관심종목 | 관찰하거나 매수를 검토하는 종목 |
| `HOLDING` | 보유종목 | 잔여수량을 보유한 종목 |
| `RECOMMENDED` | 추천종목 | 추천 대상으로 분류한 종목 |

- 한 종목은 한 유형에만 속하며 여러 탭에 중복 표시하지 않는다.
- 관심·추천종목을 매수하면 보유종목으로 이동한다.
- 전량 매도하면 관심종목으로 이동한다.
- 목록 전체를 한 번 조회하고 React에서 유형별로 필터링한다.
- 탭은 `관심 → 보유 → 추천 → 관심` 순으로 무한 순환한다.
- 반대 방향도 동일하게 순환하며 탭 클릭과 좌우 스와이프를 모두 지원한다.
- 모바일의 동일 레벨 탭·카드·기간 화면에서는 스와이프와 무한 순환을 기본 UX로 사용한다.
- 입력폼, 차트 조작, 버튼 영역과 OS 뒤로가기 제스처의 충돌을 방지한다.

# 7. 시세와 스냅샷

- 종목별 최신 가격 한 건만 저장한다.
- 가격 제공처의 기준시각인 `price_as_of`는 사용하지 않는다.
- 자동 또는 수기 가격 갱신 시각은 `price_updated_at`으로 관리한다.
- 자동 수집 실패 시 마지막 정상 가격을 유지한다.
- 사용자가 현재가와 전일 종가를 직접 수정할 수 있다.
- 다음 자동 수집이 성공하면 수기 가격을 최신 수집 가격으로 갱신한다.
- 당일 계좌 스냅샷은 약 1시간마다 같은 행을 UPSERT하고 23시에 마지막 갱신한다.
- `is_final`은 사용하지 않는다.
- 종목별 일별 스냅샷은 설계에 포함하되 선택 구현으로 둔다.

# 8. 가치투자와 복리목표

| 영역 | 핵심 정보 |
|---|---|
| 재무제표 | 매출, 영업이익, 순이익, 자산, 부채, 자본, 영업현금흐름, 설비투자 |
| 가치평가 | EPS, BPS, PER, PBR, ROE, 주당배당금, 배당수익률, 시가총액 |
| 배당 | 세전 배당금, 세후 실수령액, 종목·월·연도별 합계 |
| 복리목표 | 기간명, 시작자산, 목표수익률, 매년 추가 투자금, 목표 성장곡선 |

한 계좌에 여러 복리목표를 등록할 수 있다. 같은 기간에 연 10%·20%·30% 목표를 비교하거나 1기·2기·3기처럼 5년 단위로 목표율을 다르게 설정할 수 있다. 비교 화면에는 보통 3개를 표시하지만 저장 개수에는 제한을 두지 않는다.

```text
1년 차 목표자산
= (시작 자산 + 연간 추가 투자금) × (1 + 목표수익률)

2년 차 이후 목표자산
= (직전 연도 목표자산 + 연간 추가 투자금) × (1 + 목표수익률)
```

# 9. 주요 화면과 핵심 메뉴

## 9.1 핵심 메뉴

핵심 메뉴명은 가능한 한 4글자로 통일한다. `더보기`는 의미가 가장 명확한 일반 명칭이므로 3글자 예외로 사용한다. 모바일·펼침 화면·태블릿·PC에서 메뉴의 표현 방식이 달라져도 명칭과 기능 범위는 동일하게 유지한다.

| 순서 | 메뉴명 | 주요 기능 |
|---:|---|---|
| 1 | 종목목록 | 관심·보유·추천종목, 종목 상세, 매수 Lot |
| 2 | 매매일지 | 거래 타임라인, 실현손익, 필터, 수정·삭제 |
| 3 | 홈 | 총자산, 주식 평가액, 예수금, 손익, 배당, 자산 추이 |
| 4 | 자산분석 | 예수금, 배당 분석, 가치투자, 복리목표 |
| 5 | 더보기 | 계좌, 현재가 관리, 수집 상태, 앱 설정 |

- 모바일에서는 위 5개 메뉴를 하단 내비게이션으로 제공하고 `홈`을 중앙에 배치한다.
- 화면 제목은 `대시보드`로 유지하고 하단 메뉴명만 `홈`을 사용한다.
- `거래등록`은 이동 메뉴가 아닌 실행 액션으로 분리하고, 모바일 대시보드 제목의 최우측에 44 × 44px 터치 영역을 가진 `+` 아이콘으로 제공한다.
- `+` 아이콘을 누르면 매수·단일 Lot 매도·입금·출금·배당 등록 유형을 선택한다.
- Fold 커버 화면의 세로 공간을 확보하기 위해 하단 고정 거래등록 버튼은 사용하지 않는다.
- 스크롤 가능한 모든 화면은 사용자가 화면 높이의 약 40% 이상 내려갔을 때 `맨 위로` 버튼을 표시한다.
- 최상단에서는 `맨 위로` 버튼을 숨기고, 모바일에서는 하단 내비게이션 위 우측에 독립적으로 배치한다.
- 펼침 화면과 태블릿에서는 같은 메뉴명의 축약형 사이드 내비게이션과 별도 거래등록 액션을 사용할 수 있다.
- PC에서는 같은 메뉴명을 사용하는 좌측 사이드 내비게이션과 상단 또는 콘텐츠 영역의 거래등록 버튼을 사용한다.

# 10. 데이터 원칙

- 금액과 수량은 고정 소수점 타입을 사용한다.
- 현재 보유수량과 평가금액은 매수·매도 내역으로 계산하며 `positions` 테이블은 두지 않는다.
- 매수·매도·배당과 예수금 변동 내역은 FK로 직접 연결하지 않는다.
- 신규 등록과 예수금 반영은 하나의 DB 트랜잭션으로 처리한다.
- 과거 거래 수정·삭제로 예수금과 과거 스냅샷을 자동 변경하지 않는다.
- 매도가 연결된 매수 삭제는 확인 후 연결된 매도와 매수를 한 트랜잭션에서 삭제한다.
- 과거 데이터보다 사용자가 확인한 현재 실제 예수금을 우선한다.
