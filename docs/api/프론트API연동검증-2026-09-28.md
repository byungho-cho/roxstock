# RoxStock 프론트 API 연동 검증 (2026-09-28)

현재 `https://newrox.cafe24.com`은 개발 완료 전까지 테스트 서버로 사용합니다. 프론트는 `VITE_DATA_SOURCE=api`에서 같은 출처의 `/api` 경로를 호출합니다. ID와 Decimal 값은 JSON 문자열입니다.

## 배포 API 대응표

| 기능 | 요청 | 주요 응답 |
|---|---|---|
| 계좌 목록 | `GET /api/accounts` | `data[]: id, name, brokerName, accountNumber, cashBalance, isActive` |
| 계좌 생성 | `POST /api/accounts` | `data: id, cashBalance` |
| 종목 검색 | `GET /api/securities?query=&marketType=&listType=&limit=&offset=` | `data[]`와 `meta.total` |
| 관심·추천 등록 | `POST /api/watchlist-items` | 등록된 종목 전체 DTO |
| 보유종목 | `GET /api/accounts/{accountId}/holdings` | 수량, 평균단가, 현재가, 평가액, 평가손익 |
| 대시보드 | `GET /api/accounts/{accountId}/dashboard` | 예수금, 매입금액, 평가액, 총자산, 보유종목 |
| 거래 목록 | `GET /api/accounts/{accountId}/trades?from=&to=&securityId=` | `data`, `summary`, `daily`, `meta` |
| 잔여 Lot | `GET /api/accounts/{accountId}/buy-lots?securityId=&remainingOnly=true` | 매수·매도·잔여수량과 연결 매도 |
| 매수 | `POST /api/buy-trades` | 거래 ID, 예수금 거래 ID, 금액, 잔액 |
| 매도 | `POST /api/sell-trades` | 위 항목과 잔여수량, 실현손익 |
| 입출금 | `POST /api/cash-transactions` | 예수금 거래 ID, 변경 후 잔액 |
| 거래 수정 | `PATCH /api/buy-trades/{id}`, `PATCH /api/sell-trades/{id}` | 거래 ID, 잔여수량, 재계산 여부 플래그 |
| 거래 삭제 | `DELETE /api/buy-trades/{id}`, `DELETE /api/sell-trades/{id}` | 삭제 결과와 재계산 여부 플래그 |

정확한 필드 형식은 `종목API.md`, `계좌보유대시보드API.md`, `거래API.md`를 기준으로 합니다. 프론트의 `frontend/src/data/roxstockApi.ts` 타입 및 호출 형식과 현재 배포 API가 일치함을 확인했습니다.

## 오류 응답

모든 오류는 다음 형식입니다.

```json
{ "error": { "code": "ERROR_CODE", "message": "설명" } }
```

| HTTP | 코드 | 조건 |
|---:|---|---|
| 400 | `INVALID_INPUT` | ID, 날짜, Decimal, 쿼리 형식 오류 |
| 400 | `INVALID_SOLD_AT` | 매도일이 매수일보다 빠름 |
| 400 | `INVALID_BOUGHT_AT` | 수정한 매수일이 연결 매도일보다 늦음 |
| 400 | `INVALID_FEE_TAX_AMOUNT` | 매도 거래비용이 매도금액보다 큼 |
| 404 | `ACCOUNT_NOT_FOUND` | 활성 계좌 없음 |
| 404 | `SECURITY_NOT_FOUND` | 활성 종목 없음 |
| 404 | `BUY_TRADE_NOT_FOUND` | 매수 Lot 없음 |
| 404 | `SELL_TRADE_NOT_FOUND` | 매도 거래 없음 |
| 409 | `INSUFFICIENT_CASH` | 매수·출금 후 예수금이 음수 |
| 409 | `QUANTITY_EXCEEDS_REMAINING` | Lot 잔여수량 초과 매도 |
| 409 | `QUANTITY_BELOW_SOLD` | 매수수량을 이미 매도한 합계보다 작게 수정 |
| 409 | `SECURITY_CHANGE_BLOCKED` | 연결 매도가 있는 매수의 종목 변경 |
| 409 | `CONNECTED_SELLS_EXIST` | 연결 매도가 있는 매수의 기본 삭제 |
| 409 | `HOLDING_MANAGED_BY_TRADES` | 보유 분류를 관심 API로 직접 변경·삭제 |

## 통합 테스트 데이터와 결과

- 계좌: ID `2`, `API 통합 테스트 20260928`
- 초기 입금: 1,000,000원
- 매수 Lot: ID `4`, 삼성전자(`securityId=262`) 10주 × 70,000원
- 1차 매도: ID `1`, 3주 × 80,000원, 실현손익 30,000원
- 2차 매도: ID `2`, 2주 × 75,000원, 실현손익 10,000원
- 최종 잔여수량: 5주
- 실현손익 합계: 40,000원
- 최종 예수금: 690,000원

검산은 `1,000,000 - 700,000 + 240,000 + 150,000 = 690,000`이며, 실현손익은 `3 × (80,000 - 70,000) + 2 × (75,000 - 70,000) = 40,000`입니다.

추가 검증:

- 매도 메모 수정 성공 후 예수금 690,000원 유지
- 매수수량을 4주로 수정: `409 QUANTITY_BELOW_SOLD`
- 잔여 5주 상태에서 6주 추가 매도: `409 QUANTITY_EXCEEDS_REMAINING`
- 연결 매도 2건이 있는 매수 기본 삭제: `409 CONNECTED_SELLS_EXIST`

## 수정·삭제 확정 규칙

- 거래 수정·삭제는 현재 Lot, 잔여수량, 보유종목 분류에 반영합니다.
- 과거 `cash_transactions`, 계좌의 현재 `cashBalance`, 과거 스냅샷은 자동 재계산하지 않습니다.
- API 응답의 `cashBalanceAdjusted`, `historicalCashTransactionsAdjusted`, `historicalSnapshotsAdjusted`가 모두 `false`인지 확인합니다.
- 연결 매도가 있는 매수 삭제는 사용자 확인 후에만 `?cascadeSells=true`를 사용합니다.
- 실제 증권계좌와 예수금이 달라지면 입금·출금 등록으로 직접 맞춥니다.

## 테스트 데이터 초기화

일상적인 통합 테스트는 기존 데이터를 지우지 않고 `TEST-{날짜}-{순번}` 계좌를 새로 만드는 방식을 권장합니다. 공개 초기화 API는 실수 위험 때문에 제공하지 않습니다.

거래만 초기화할 때는 다음 순서를 사용합니다.

1. `DELETE /api/sell-trades/{sellTradeId}`로 연결 매도를 삭제합니다.
2. `DELETE /api/buy-trades/{buyTradeId}`로 매수 Lot을 삭제합니다.
3. 보유 분류가 자동 재계산됐는지 잔여 Lot과 종목 목록을 확인합니다.

계좌와 예수금 이력까지 완전히 제거해야 하면 DB 담당자가 정확한 테스트 계좌 ID를 확인한 뒤 트랜잭션 안에서 자식 데이터를 먼저 삭제합니다. 운영 계좌 ID나 범위 조건 없는 삭제문은 사용하지 않습니다.

## 남은 API와 우선순위

1. **예수금 내역 조회·월간/연간 집계**: 현재 입출금 등록만 있고 예수금 화면용 조회 API가 없습니다.
2. **배당 등록·조회·수정·삭제**: 배당 테이블은 있으나 API가 없습니다.
3. **거래 단건 상세 조회**: 현재 통합 목록과 Lot 조회로 상세 화면을 구성할 수 있지만 단건 재조회 API는 없습니다.
4. **대시보드 과거 자산 추이**: `daily_account_snapshots` 기간 조회 API가 없습니다.
5. **테스트 계좌 관리 CLI**: 공개 API가 아닌 서버 전용 목록·초기화 명령이 필요합니다.

프론트는 우선 현재 API로 대시보드 → 종목목록·보유종목 → 매매일지 → 매수·매도·입출금 등록을 연결하고, 예수금 상세와 자산 추이는 위 1·4번 API가 추가된 뒤 실제 데이터로 전환합니다.
