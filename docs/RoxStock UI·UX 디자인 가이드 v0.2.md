# 1. 디자인 목표

RoxStock은 개인이 주식 자산과 거래를 빠르게 조회하고 기록하는 서비스다. 장식적인 표현보다 정보의 정확성, 숫자의 가독성, 빠른 조작을 우선한다.

- 다크 모드를 기본이자 v1의 유일한 테마로 사용한다.
- 심플한 화면과 명확한 정보 위계를 유지한다.
- Galaxy Z Fold의 커버 화면을 최우선 사용 환경으로 본다.
- 펼친 화면과 태블릿은 하나의 레이아웃 그룹으로 설계한다.
- PC는 동일한 정보 구조를 넓은 화면에 맞게 확장한다.
- 동일한 데이터와 기능을 유지하면서 화면 크기에 따라 표현 방식만 변경한다.
- React와 MUI로 그대로 구현할 수 있는 구조를 사용한다.

# 2. 우선 사용 환경

## 2.1 Galaxy Z Fold 커버 화면

커버 화면은 RoxStock의 기본 화면이다. 세로 방향의 좁은 화면에서 한 손 조작과 빠른 조회·입력을 지원한다.

- 기준 비율: 세로 기준 약 10:16
- 커버형 최소 검증 프레임: 370 × 465 CSS px (RoxStock 실측 369 × 465의 반올림). 더 넓거나 높은 화면은 같은 정보 구조를 반응형으로 확장
- 기본 레이아웃: 단일 열
- 내비게이션: 하단 메뉴
- 목록 표현: 카드 또는 요약 행
- 표와 상세 데이터: 펼치기 또는 상세 화면에서 제공
- 주요 터치 영역: 최소 44 × 44 CSS px

실제 구현은 물리 해상도가 아닌 브라우저의 CSS viewport를 기준으로 한다.

## 2.2 Galaxy Z Fold 펼친 화면과 태블릿

펼친 화면과 태블릿은 별도 디자인으로 나누지 않고 하나의 반응형 그룹으로 관리한다.

- Galaxy Z Fold 메인 디스플레이: 7.6인치, 4:3, 2448 × 1848
- 펼침형 최소 검증 프레임: 725 × 396 CSS px (RoxStock 실측값). 더 넓거나 높은 화면은 2열 구성과 여백·콘텐츠 영역을 반응형으로 확장
- 기본 레이아웃: 2열
- 목록과 상세, 요약과 차트, 입력폼과 예상 결과를 동시에 표시할 수 있다.
- 표를 기본으로 사용하되 화면 폭에 따라 보조 열을 줄인다.
- 모바일 화면을 단순 확대하지 않고 넓어진 공간에 연관 정보를 배치한다.

## 2.3 PC

PC는 분석과 데이터 비교에 적합한 확장 화면이다.

- 기본 레이아웃: 좌측 사이드바와 다열 콘텐츠
- 데이터 테이블의 전체 열을 제공한다.
- 정렬, 필터, 열 고정 등 표 중심 기능을 제공한다.
- 대시보드 카드와 차트를 한 화면에서 비교할 수 있도록 구성한다.

## 2.4 Galaxy Z Fold8 와이드 실측 브라우저 표시 영역 (2026-09-28)

Galaxy Z Fold8 와이드의 Chrome에서 `https://newrox.cafe24.com/journal?viewport=1`로 RoxStock 자체를 측정했습니다. 다음 값은 **브라우저 탭·주소창이 표시된 상태에서 웹페이지에 제공된 CSS viewport**이며 물리 화소수나 기기 전체 화면 크기가 아닙니다. 브라우저 UI·확대 설정·접기/펼치기에 따라 바뀔 수 있습니다.

| 상태 | `innerWidth × innerHeight` | `clientWidth × clientHeight` | `visualViewport.width × height` | `screen.width × height` | DPR | `visualViewport.scale` |
|---|---:|---:|---:|---:|---:|---:|
| 커버, 주소창 표시 | 369 × 465 | 369 × 465 | 369.78 × 464.89 | 444 × 702 | 3.38 | 1 |
| 펼침, 탭·주소창 표시 | 725 × 396 | 725 × 396 | 725.33 × 396.15 | 871 × 658 | 3.38 | 1 |

- `screen.width`가 아니라 `innerWidth` / `visualViewport.width`를 화면 레이아웃 검증 기준으로 사용합니다. `screen.width ÷ innerWidth`가 두 상태 모두 약 1.2지만 이 측정만으로 원인을 확정하거나 모든 사용자에게 동일한 비율을 가정하지 않습니다.
- 헤더와 하단 메뉴를 각각 44 CSS px로 고정할 때, 본문에 남는 세로 공간은 커버 **약 377 CSS px**, 펼침 **약 308 CSS px**입니다. 실제 레이아웃에서는 안전 영역과 브라우저 UI 변화까지 검증합니다.
- 커버의 최소 검증 크기는 370 × 465로 하고 본문 스크롤·글자 잘림·버튼 겹침을 확인합니다. 더 큰 화면에서는 카드·여백·본문 높이를 가용 공간에 맞게 조정합니다.
- 펼침의 최소 검증 크기는 725 × 396으로 합니다. Figma의 이전 크기 시안은 이 크기에 맞게 재구성하고, 중복·폐기 프레임은 삭제합니다. 2열 배치와 달력·거래 상세가 실제 브라우저 높이에 들어오는지 확인하고, 더 큰 화면에서는 열과 콘텐츠에 가용 공간을 배분합니다.
- 위 수치는 폴드8 커버형·펼침형의 최소 **검증 기준**입니다. CSS의 `min-width`, `min-height`나 고정된 화면 크기로 지정하지 않습니다. 해당 크기 이상에서는 콘텐츠·열 너비·높이와 간격을 반응형으로 조정하고, 비례 확대만으로 처리하지 않습니다. 해당 크기보다 작은 다른 기기에서도 가로 넘침 없이 콘텐츠를 조회할 수 있어야 합니다. 주소창 표시·숨김, 회전, 폴드 상태 및 다른 브라우저 너비에서 콘텐츠가 잘리거나 중복 스크롤되지 않아야 합니다.
- 세로 공간이 부족한 커버 화면은 고정 헤더와 하단 메뉴 사이에서 본문 전체를 스크롤합니다. 펼침형 대시보드·매매일지의 2열 화면은 725 × 396에서 핵심 내용을 한 화면에 배치해 검증하되, 거래 건수 증가처럼 콘텐츠가 많으면 내용 접근을 위한 스크롤을 허용합니다. 펼침형에서도 콘텐츠가 가로 전체를 차지하는 화면은 본문 전체 스크롤을 사용합니다. 스크롤 체계를 화면별로 검증하고 불필요한 중첩 스크롤은 피합니다.
- 빈 거래일 화면만으로 완료 처리하지 않습니다. 매수·매도가 같은 날짜에 표시되고 거래 목록이 늘어난 상태에서도 달력 칩과 금액·수량·단가 정렬을 검증합니다.

# 3. 반응형 구간

| 화면 그룹 | 권장 CSS 폭 | 대표 환경 | 기본 표현 |
|---|---:|---|---|
| 모바일 | 0~599px | Fold 커버, 일반 휴대폰 | 단일 열, 카드 목록, 하단 내비게이션 |
| 펼침·태블릿 | 600~1199px | Fold 펼침, 태블릿 | 2열, 핵심 열 표, 필요 시 축약 사이드바 |
| PC | 1200px 이상 | 데스크톱, 노트북 | 다열, 전체 표, 좌측 사이드바 |

브레이크포인트는 구현 과정에서 실제 콘텐츠 최소 너비를 검증한 뒤 조정할 수 있다. 기기 이름만으로 분기하지 않고 화면 폭과 사용 가능한 공간을 기준으로 한다. 커버 370 × 465와 펼침 725 × 396은 Fold8의 최소 검증 사례이며, 브레이크포인트나 CSS의 최소 크기 제한값이 아니다. 각 구간에서 너비와 높이가 증가하면 카드·열·간격을 공간에 맞춰 조정한다.

# 4. 정보 구조와 내비게이션

모바일 하단 내비게이션은 다음 5개를 유지한다.

| 메뉴 | 주요 기능 |
|---|---|
| 종목목록 | 관심·보유·추천종목, 종목 상세, 매수 Lot |
| 매매일지 | 거래 타임라인, 실현손익, 필터, 수정·삭제 |
| 홈 | 대시보드 진입, 총자산, 주식 평가액, 예수금, 손익, 배당, 자산 추이 |
| 자산분석 | 예수금, 배당 분석, 가치투자, 복리목표 |
| 더보기 | 계좌, 현재가 관리, 수집 모니터링, 앱 설정 |

- 핵심 메뉴명은 가능한 한 4글자로 통일한다. `홈`과 `더보기`는 익숙하고 의미가 명확하므로 예외로 둔다.
- 화면 내부 제목은 `대시보드`를 유지하고 내비게이션 명칭만 `홈`을 사용한다.
- 거래등록은 내비게이션 목적지가 아닌 실행 액션으로 제공한다. Fold 커버에서는 세로 공간 확보를 위해 하단 플로팅 버튼을 사용하지 않고 대시보드 제목 최우측에 44 × 44px 터치 영역의 `+` 아이콘을 둔다.
- 관심·보유·추천 탭은 탭 클릭과 좌우 스와이프를 함께 지원한다.
- 입력폼, 차트, 버튼 영역에서는 화면 스와이프와 조작이 충돌하지 않아야 한다.
- 펼침·태블릿에서는 하단 메뉴를 유지하거나 축약형 사이드 내비게이션으로 전환할 수 있다.
- PC에서는 좌측 사이드바를 기본으로 사용한다.

# 5. 테마와 시각 원칙

## 5.1 다크 모드

v1은 다크 모드만 제공한다.

| 용도 | 기준값 |
|---|---|
| 앱 배경 | #080D18 |
| 기본 표면 | #111827 |
| 주요 액션 | #60A5FA |
| 긍정·완료 | #34D399 |
| 기본 모서리 | 16px |
| 앱 글꼴 | Pretendard |

Figma 환경에 Pretendard가 없을 때는 Inter로 동일한 크기와 굵기를 설계하고, 실제 React 앱에서는 Pretendard를 적용한다.

## 5.2 색상 사용

- 색상은 주요 액션, 상승·하락, 성공, 경고, 오류처럼 의미가 있는 곳에만 사용한다.
- 장식 목적의 과도한 색상과 그라데이션을 사용하지 않는다.
- 금액과 수익률은 색상에만 의존하지 않고 부호와 텍스트를 함께 제공한다.
- 상승은 `+`, 하락은 `-`, 보합은 `0` 또는 `0.0%`를 함께 표시한다.
- 주가와 손익의 상승은 밝은 적색(`red/400`), 하락은 밝은 청색(`blue/400`), 보합은 흰색(`neutral/50`)으로 표시한다.
- 성공·완료 녹색과 주가 상승 적색은 의미가 다르므로 별도의 의미 토큰으로 관리한다.
- 현재 선택된 하단 메뉴는 밝은 앰버 계열을 사용한다. 대시보드의 거래 추가 `+` 버튼은 원형과 흰색 아이콘을 유지하고, 배경은 검정보다 한 단계 밝은 진한 회색(`neutral/800`)을 사용한다.
- 비활성 정보는 대비를 낮추되 읽을 수 있는 수준을 유지한다.
- 대시보드 상단에는 수집 상태 문구를 표시하지 않는다.
- 보유종목 카드 제목 옆에 텍스트 없는 작은 원형 시세 수집 상태 표시를 둔다.
- 상태 색상은 정상=녹색, 일부 실패=노란색, 실패=적색으로 사용한다.
- 원형 표시에는 스크린 리더용 접근성 라벨과 필요 시 툴팁을 제공한다.

## 5.3 가독성

- 화면에서 가장 중요한 숫자는 총자산, 평가금액, 손익, 수익률 순으로 강조한다.
- 금액은 우측 정렬하고 단위와 천 단위 구분을 일관되게 적용한다.
- 차트 축·데이터 라벨·툴팁의 금액은 10,000원 미만이면 `원`, 10,000원 이상이면 `만원` 단위로 표시한다.
- 차트 금액이 1억원 이상이어도 `억`으로 전환하지 않고 만원 단위를 유지한다. 예: 854,200,000원 → 85,420만원.
- 모바일 대시보드 최종안은 카드 제목을 좌측 정렬하고 주요 금액·손익·수익률을 우측 정렬한다.
- 같은 카드 안의 주요 금액과 보조 수치는 동일한 우측 끝선을 사용하며 긴 금액도 한 줄로 유지한다.
- 종목명은 종목코드보다 먼저 읽히도록 한다.
- 보유종목 카드의 종목코드는 11px의 낮은 대비 회색으로 표시하여 종목명을 우선한다.
- 보유종목 카드의 평가금액에는 `평가` 접두어를 반복 표시하지 않는다.
- 평가금액 색상은 전일 종가 대비 상승=밝은 적색, 하락=밝은 청색, 동일=흰색으로 표시한다.
- 평가손익 색상은 평균 매입금액 대비 이익=밝은 적색, 손실=밝은 청색, 동일=흰색으로 표시한다.
- 본문은 지나치게 작게 사용하지 않는다.
- 제목, 핵심 수치, 보조 정보의 크기와 명도 차이를 명확히 한다.

# 6. 표와 모바일 카드 전환

같은 데이터와 기능을 사용하되 화면 크기에 따라 표현 방식을 변경한다.

| 화면 | 표현 방식 |
|---|---|
| 모바일 | 카드 또는 요약 행 목록 |
| 펼침·태블릿 | 주요 열 중심 데이터 테이블 |
| PC | 전체 열 데이터 테이블 |

## 6.1 모바일 카드

모바일 카드에는 다음 정보를 우선 표시한다.

1. 종목명과 종목코드
2. 현재가
3. 보유 수량
4. 평가금액
5. 평가손익과 수익률
6. 거래 또는 보유 상태
7. 상세 진입 액션

매입가, 거래일, 수수료, 메모 등 부가 정보는 카드 펼치기나 상세 화면에서 제공한다. 가로 스크롤 표는 핵심 사용 흐름에서 사용하지 않는다.

보유종목 요약 행은 다음 정렬 규칙을 사용한다.

- `종목명 | 등락률 | 평가금액` 순서의 3열 구조
- 종목명 열은 긴 이름을 고려해 가장 넓게 확보하고 말줄임 적용
- 등락률은 중앙보다 오른쪽에 배치한 전용 열 안에서 우측 정렬
- 평가금액은 모든 행의 우측 끝선에 정렬
- 등락률과 평가금액은 종목명보다 작은 글자 크기로 표시

## 6.2 펼침·태블릿 표

- 주요 열은 한 화면에 유지한다.
- 폭이 부족하면 우선순위가 낮은 열부터 숨긴다.
- 선택한 행의 상세 내용을 옆 패널에 표시할 수 있다.
- 터치 환경을 고려하여 행 높이와 조작 영역을 충분히 확보한다.

## 6.3 PC 표

- 전체 열, 정렬, 필터, 열 고정 기능을 제공한다.
- 숫자 열은 우측 정렬한다.
- 주요 식별 열은 스크롤 중에도 확인할 수 있도록 고정할 수 있다.
- 행 선택, 상세보기, 수정 등 주요 동작을 일관된 위치에 둔다.

# 7. 핵심 화면별 구조

## 7.1 홈 / 대시보드

- 모바일: 총자산 카드 → 손익·예수금 요약 → 자산 추이 → 보유종목 요약
- 펼침·태블릿: 자산 요약과 차트 2열 배치
- PC: 요약 카드, 자산 추이, 보유종목, 최근 거래를 다열 배치
- 총자산은 주식 평가액과 예수금의 합으로 표시한다.
- 카드 내부에서 총 평가자산과 주식 평가액을 전환하는 기능은 제공하지 않는다.
- 총 평가자산 카드를 누르면 평가자산 메인 화면으로 이동한다.
- 예수금 카드는 예수금 화면, 오늘 손익 카드는 오늘 날짜가 선택된 일별손익 화면, 자산 추이 카드는 자산분석 화면으로 이동한다.
- 보유종목 제목 영역은 보유종목 메인 화면으로 이동하고, 개별 종목 행은 선택한 종목의 보유 상세 화면으로 이동한다.
- 헤더의 `+` 버튼은 거래등록 화면으로 이동한다.

### 평가자산 종목별 비중 차트

- 종목별 비중 카드는 순위형 막대와 누적 위치 막대를 모두 제공한다.
- 순위형은 각 종목의 비중 크기 비교를 우선하고 기본 상태로 사용한다.
- 누적형은 앞선 비중을 회색 구간으로 표시하고 현재 종목의 구간 위치를 파란색으로 표시한다.
- 카드 전체를 누르면 두 차트가 순환 전환된다.
- 제목 우측의 상태 배지로 현재 차트가 `순위형`인지 `누적형`인지 표시한다.
- 키보드와 스크린 리더에서는 카드가 전환 버튼임을 알리고 다음 상태를 함께 안내한다.

## 7.2 종목목록

- 모바일: 관심·보유·추천 탭과 종목 카드
- 펼침·태블릿: 종목 표와 상세 패널
- PC: 전체 종목 표, 상세 정보, 재무·가치지표 영역
- 매수 Lot은 서로 구별되는 독립 항목으로 표현한다.

## 7.3 거래등록 액션

- 모바일: 단계가 명확한 단일 열 입력폼
- 펼침·태블릿: 입력폼과 예상 손익·예수금 결과 2열
- PC: 입력, Lot 선택, 계산 결과를 동시에 확인
- 매도는 반드시 하나의 매수 Lot을 선택하게 한다.
- 저장 전에 예상 실현손익과 예수금 변화를 보여준다.

## 7.4 매매일지

- 모바일: 시간순 거래 카드 목록과 필터
- 펼침·태블릿: 거래 표와 상세 패널
- PC: 전체 거래 표, 기간·종목 필터, 상세 정보
- 수정·삭제 시 예수금이 자동 복원되지 않는다는 경고를 명확하게 표시한다.

## 7.5 더보기와 분석

예수금, 배당, 복리목표, 계좌, 현재가 수정, 수집 모니터링, 앱 설정을 제공한다. 사용 빈도가 낮은 기능은 홈과 주요 내비게이션을 방해하지 않도록 더보기 아래에 둔다.

## 7.6 예수금

- 상단에는 현재 실제 예수금과 직접 수정 액션, 마지막 갱신 시각을 표시한다.
- 최종안은 월간과 연간 요약을 하나의 통합 기간 카드에 표시하여 세로 공간을 절약한다.
- 화면 최초 진입 상태는 `월간`이며 현재 월을 표시한다.
- 카드 제목 우측의 `월간`·`연간` 전환 버튼을 누르면 같은 카드 안에서 요약 모드를 교체한다.
- 월간 상태에는 `출금 | 입금`, 연간 상태에는 `출금 | 입금 | 배당`을 표시한다.
- 기간 제목과 금액 영역에는 가로 구분선을, 각 항목 사이에는 세로 구분선을 사용한다.
- 카드 상단 중앙에 월간은 `YYYY년 M월`, 연간은 `YYYY년`을 표시하고 좌우 이동 화살표를 함께 제공한다.
- 가로 스와이프는 현재 모드 안에서만 기간을 이동한다. 월간은 1월부터 이번 달, 연간은 데이터가 존재하는 최초 연도부터 올해까지 순환한다.
- 최신 기간 다음에는 가장 오래된 기간, 가장 오래된 기간 이전에는 최신 기간이 이어진다.
- 월간과 연간은 사용자가 마지막으로 본 기간을 각각 독립적으로 기억하며, 모드를 전환해도 세로 스크롤 위치를 유지한다.
- 데이터가 없는 기간은 빈 상태로 유지하여 탐색 순서를 바꾸지 않는다.
- 가로 스와이프는 방향·거리 임계값을 적용해 화면의 세로 스크롤과 충돌하지 않게 한다.
- 증가 금액은 밝은 적색, 감소 금액은 밝은 청색으로 표시한다.
- 최근 변경은 `구분 | 날짜 | 금액`의 3열 구조이며 각각 좌측·중앙·우측 정렬한다.
- 최초 진입 시 최신 10개를 표시한다.
- 하단 `이전 1개월 불러오기` 버튼으로 현재 가장 오래된 내역의 직전 달 1개월분을 추가한다.
- 월 단위 조회가 구현상 불가능할 때만 30개 단위 페이지 조회를 대체 방식으로 사용한다.
- 무한 스크롤 대신 사용자가 조회 범위를 통제할 수 있는 버튼 방식을 기본으로 사용한다.
- 개인용 v1에서는 잔액 조정 안내 카드를 상시 노출하지 않는다.

## 7.7 일별손익

- 오늘손익 전용 화면을 별도로 만들지 않고 일별손익 화면으로 통합한다.
- 대시보드의 `오늘 손익` 카드를 누르면 오늘 날짜가 선택된 일별손익 화면으로 이동한다.
- 최초 진입일은 오늘이며, 오늘 상태에서는 다음 날짜 이동을 비활성화한다.
- 이전·다음 버튼, 좌우 스와이프, 달력 선택으로 조회 날짜를 변경한다.
- 화면에는 `전체 손익`, `손익 구성`, `종목별 손익`, `거래 현황`을 표시한다.
- 상단 날짜 선택 바는 세로 스크롤 시 화면 최상단에 스티키로 고정한다.
- 종목별 손익은 수익=밝은 적색, 손실=밝은 청색, 보합=흰색으로 표시한다.
- 거래 칩은 예수금 방향을 기준으로 매도=적색, 매수=청색으로 표시한다.
- 매수 금액은 흰색으로 표시하고, 매도 금액은 실현수익=적색, 실현손실=청색으로 표시한다.
- 거래 칩은 30 × 18px, 모서리 5px, 글자 10px를 기준으로 하며 종목명과 8px 간격을 둔다.

## 7.8 자산분석

- 현재 총자산 카드 하단은 한 줄 푸터로 구성한다. 마지막 수집 시각은 좌측에 낮은 대비의 회색으로 표시하고, 기간 성과 요약은 우측에 표시하여 두 텍스트의 하단 기준선을 맞춘다. 수집 시각은 `시세 수집` 문구와 연도를 생략한 `MM.DD HH:mm` 형식을 사용한다.
- 자산 추이 차트는 `1개월 | 3개월 | 6개월 | 1년 | 전체` 기간을 제공한다.
- 차트 금액은 공통 차트 단위 규칙에 따라 원 또는 만원으로 표시한다.
- 기간 성과 구성에는 기간 시작자산, 총입금, 총출금, 순입출금, 평가손익, 실현손익, 배당수익, 수수료·세금, 기간 투자손익, 투자수익률, 현재 총자산을 표시한다.
- `기간 시작자산 + 순입출금 + 기간 투자손익 = 현재 총자산` 관계가 성립해야 한다.
- 모바일에서는 세로 스크롤로 전체 성과 항목과 자산 구성 카드를 순서대로 확인한다.
- 스크롤 최상단 버튼과 마지막 항목이 겹치지 않도록 하단 안전 여백을 확보한다.


## 7.9 수집 모니터링 (더보기 → 수집 모니터링)

### 목적과 범위

운영자가 수집기 전체가 계획대로 실행되고 있는지, 데이터가 얼마나 최신인지, 실패한 대상이 무엇인지 확인한다. 재무제표 전용 통계가 아니다. 읽기 전용 모니터링 화면으로 시작하며 수동 새로고침은 **통계 재조회**만 수행한다. 수집 재실행·작업 중단 버튼은 이번 범위에 포함하지 않는다.

| 수집 기능 | 요약에서 확인할 항목 | 상세에서 확인할 항목 |
|---|---|---|
| 종목 마스터 (KOSPI·KOSDAQ) | 최근 실행 결과·종목 수·마지막 성공·다음 예정 | 실행별 신규/변경/제외/실패, 원천 API 결과, 대상 오류 |
| 실시간 주가 (보유·관심·추천) | 워커 상태·장 구간·마지막 성공 수신·대상/성공/실패·지연 | 최근 주기 처리, 원천 시각·수신 시각, 종목별 오류, SSE 발행·DB 반영 상태 |
| 전체 종목 주가 (장 마감 후) | 최근 실행 결과·대상/성공/실패·마지막 성공 | 실행별 진행률, 미처리·재시도·실패 종목, 가격 기준 시각 |
| 일별 계좌 스냅샷 | 최근 실행 결과·대상/성공/실패 계좌·마지막 성공 | 계좌별 결과, 누락된 시세로 인한 실패 이유, 계산 기준일 |
| DART 재무제표 | 1단계/2단계 상태·진행률·마지막 성공·다음 예정 | 과거 보고서 최초 수집의 종목/연도/보고서 단위 처리량, 잔여량, 미공시·실패; 올해 사업연도 우선종목 1일 1회 및 전체종목 순환의 최근 확인일·대기량·실패·일일 호출량/설정 한도 |

DART 수집기가 아직 배포되지 않은 기간에는 해당 카드에 `미구현` 또는 `미설정`을 표시한다. 정상 실행이나 데이터 없음으로 오인하지 않게 한다. 1단계 완료 후에는 `최초 수집 완료`와 완료 시각을 기록하고 2단계 현행 수집 상태를 별도로 표시한다.

### 요약 화면

- 위치: 더보기 → 수집 모니터링. 헤더는 제목, 전체 상태, 최종 갱신 시각, 수동 새로고침으로 구성한다.
- 상단에는 정상·실행 중·일부 실패·실패·지연·미설정/미구현의 건수와 확인이 필요한 작업의 요점을 표시한다. 상태 색상만으로 판단하지 않도록 상태명과 시각을 함께 표기한다.
- 위 표의 **5개 기능 카드** 각각에 상태, 마지막 시도와 마지막 성공을 구분한 시각, 가장 최근 실행의 대상/성공/실패/건너뜀, 다음 예정(적용 가능할 때)을 표시한다. 카드 전체 또는 `상세 보기`로 해당 기능의 상세로 이동한다.
- 장 외 시간의 실시간 주가는 정상적인 `대기/장 종료`로 표시한다. 실패 또는 데이터 지연으로 자동 분류하지 않는다. 예정 시각이 아직 오지 않은 일별·야간 작업도 정상 대기로 표시한다.
- 최근 오류/지연 3~5건과 최근 실행 기록을 보여주고 전체 기록은 상세에서 확인한다. 상태 판단에 쓰인 기준 시각과 시간대를 명시한다.

### 기능별 상세 화면

- 상단에 기능명, 현재 상태, 마지막 시도/성공, 다음 실행, 현재 진행량, 확인 시각을 표시한다. 요약 화면으로 돌아갈 수 있다.
- 기간·결과 필터를 기본으로 제공하고, 해당 기능에서 의미가 있을 때 시장(KOSPI/KOSDAQ), 종목, 계좌, 수집 단계 필터를 제공한다.
- 실행 이력에는 시작·종료 시각, 실행/예정/완료 상태, 대상·처리·성공·실패·건너뜀/미공시 수, 소요 시간, 오류 요약을 표시한다. 실행을 선택하면 대상별 결과와 오류 원인을 볼 수 있다.
- 실시간 상세는 분 단위 이력의 무한 누적을 전제로 하지 않는다. 최근 주기 집계와 마지막 정상 수신/발행/저장 시각, 워커 하트비트 및 세션 상태를 보여준다. 종목별 오류는 보존 기간 또는 최근 오류 건수의 경계를 명시한다.
- DART 상세는 **1단계 과거 최초 수집**과 **2단계 올해 사업연도 현행 수집**을 분리한다. 1단계는 전체 계획량·처리량·남은량·성공·미공시·실패·마지막 재시도, 하루 API 호출량/설정 한도, 추정 완료일(처리 속도가 충분할 때만 `추정` 표기)을 보여준다. 2단계는 우선종목과 전체종목의 중복 집계를 피하고 각각의 갱신 주기 충족 여부, 올해 보고서별 최신 확인 시각과 지연 대상을 보여준다.
- 결과가 없는 이유를 구분한다: 실행 전, 예정 전, 휴장/장 외, 수집기 미구현, 설정 누락, 원천 미공시, 실제 실패. 상세는 오류 메시지의 민감한 키/토큰을 노출하지 않는다.

### 상태 판정과 공통 디자인

- 정상: 작업별 예정 주기와 허용 지연 범위 안에서 최근 성공. 실행 중: 현재 작업이 진행 중. 일부 실패: 일부 대상만 실패. 실패: 전체 실패 또는 예정 실행 미완료. 지연: 예정된 실행/성공이 허용 범위를 초과. 미설정·미구현: 기능을 사용할 수 없음. 판정 기준은 기능별 스케줄과 거래 세션을 백엔드와 동일하게 적용한다.
- `마지막 시도`, `마지막 성공`, `데이터 기준 시각`, `화면 갱신 시각`을 혼동하지 않도록 라벨을 분리한다. 완료되지 않은 실행은 진행 중으로 보여준다.
- 데이터 재조회 중에는 기존 카드와 필터·스크롤 위치를 유지하고 카드 안에 작은 갱신 표시를 둔다. 일시적인 전체 화면 로딩 전환이나 깜빡임을 만들지 않는다.
- 커버 370 × 465에서는 단일 열의 간결한 상태 카드와 세로 본문 스크롤, 펼침 725 × 396에서는 요약 카드 2열 및 선택 가능한 상세 목록을 검증한다. 더 넓은 화면은 표 열을 확장한다. 기존 헤더·하단 메뉴 높이와 아이콘 체계를 유지한다.
- Figma에는 커버/펼침 기준으로 요약·상세 두 화면을 만들고, 정상·실행 중·일부 실패·실패·지연·장 외 대기·미설정·미구현·데이터 없음과 긴 오류 메시지 사례를 상태 시안으로 포함한다. 숫자·시각의 자리수 증가와 마지막 행 가림을 확인한다.

### 구현 연계와 검수 기준

- 수집기는 공통 조회 모델에 작업 종류, 스케줄/세션, 마지막 시도·성공, 하트비트(상시 워커), 최근 실행 집계 및 대상별 오류를 제공한다. 기존 `CollectorRun/CollectorRunItem`을 재사용하고 실시간 워커에는 보존 기간이 있는 최소 집계/상태 기록을 추가한다.
- 화면은 집계 API를 조회하며 브라우저에서 DART나 시세 원천 API를 직접 호출하지 않는다. 백엔드의 실행 빈도를 화면 열람으로 바꾸지 않는다.
- 검수: 다섯 기능이 모두 보이고 각 상세로 이동한다. 정상 대기와 지연/실패가 구별된다. 실시간 워커 중단 및 오래된 가격 수신이 구별된다. 수집 미구현과 1단계 완료도 정확히 표현된다. 커버/펼침에서 정보가 잘리지 않고 데이터 갱신 시 화면이 깜빡이지 않는다.

# 8. 상태와 피드백

각 화면과 컴포넌트는 다음 상태를 포함해야 한다.

- 기본
- 눌림·선택
- 비활성
- 로딩
- 데이터 없음
- 네트워크 또는 수집 실패
- 입력 오류
- 저장 성공
- 예수금 불일치 경고
- 스크롤 최상단 버튼 표시·숨김

로딩은 화면 전체를 막기보다 영향을 받는 영역에서 표시한다. 데이터가 없을 때는 이유와 다음 행동을 함께 안내한다.

## 8.1 스크롤 최상단 버튼

- 스크롤 가능한 모든 화면에서 화면 높이의 약 40% 이상 내려가면 표시한다.
- 페이지 최상단에서는 표시하지 않는다.
- 모바일에서는 44 × 44px 이상의 원형 버튼으로 만들고 하단 내비게이션 위 우측에 배치한다.
- 원형 배경은 82% 불투명도로 사용하여 아래 콘텐츠가 살짝 비치게 하고, 화살표 아이콘은 100% 불투명도로 유지하여 가독성을 확보한다.
- 버튼은 스크롤 콘텐츠의 레이아웃 항목이나 하단 여백이 아니라 화면 위에 독립적으로 떠 있는 플로팅 오버레이로 구현한다.
- 중간 스크롤 상태에서는 버튼 아래에도 이어지는 콘텐츠가 보여야 하며, 버튼을 위한 인위적인 빈 공간을 만들지 않는다.
- 콘텐츠와 하단 내비게이션을 가리지 않아야 한다.
- 실제 목록 최하단에 도달했을 때만 모바일 기준 최소 104px의 스크롤 안전 여백을 확보하여 버튼이 마지막 항목과 겹치지 않게 한다.
- 최하단 상태 시안에서는 보유종목 전체 개수만큼 행을 표시하여 마지막 항목과 플로팅 버튼 사이의 간격을 검증한다.
- 기본 이동은 부드러운 스크롤을 사용하되 모션 감소 환경에서는 즉시 이동한다.

# 9. React·MUI 구현 기준

- 화면별로 데이터를 중복 가공하지 않고 동일한 데이터 모델을 사용한다.
- 화면 폭에 따라 `MobileCardList`와 `DataTable`을 전환한다.
- 공통 컴포넌트는 Button, Card, Chip/Status, Tab, Bottom Navigation, Text Field, Data Row를 우선 정의한다.
- MUI breakpoint와 `useMediaQuery`를 사용하되 컴포넌트 내부에 임의의 기기명 분기를 만들지 않는다.
- 색상, 간격, 모서리, 타이포그래피는 디자인 토큰으로 관리한다.
- Figma 토큰 이름과 코드의 CSS 변수 또는 MUI theme 이름을 연결한다.
- 모바일과 넓은 화면에서 기능의 의미와 상태는 동일하게 유지한다.
