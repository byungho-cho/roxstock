# 주식 매매일지 DB 스키마

**버전:** v0.3  
**상태:** 복리계획 1:N 구조 반영  
**기준일:** 2026년 9월 26일

# 1. 변경 목적

설계서 v0.4에서 확정한 `복리계획 1 : 복리목표 N` 구조를 Prisma와 MariaDB 마이그레이션에 반영한다. 거래 Lot, 예수금, 배당, 시세, 스냅샷과 재무 데이터 구조는 v0.2를 유지한다.

# 2. 테이블 구성

저장 테이블은 총 14개다. v0.2의 `compound_growth_goals` 단일 구조를 다음 두 테이블로 분리한다.

| 테이블 | 책임 | 주요 관계 |
|---|---|---|
| `compound_growth_plans` | 계좌별 복리 기간과 공통 기준금액 | `accounts 1:N compound_growth_plans` |
| `compound_growth_goals` | 계획별 복수 목표수익률 | `compound_growth_plans 1:N compound_growth_goals` |

# 3. compound_growth_plans

| 컬럼 | 타입 | NULL | 기본값 | 설명 |
|---|---|---:|---|---|
| `id` | BIGINT UNSIGNED | N | AUTO_INCREMENT | PK |
| `account_id` | BIGINT UNSIGNED | N | - | 계좌 FK |
| `plan_name` | VARCHAR(100) | N | - | 1차·2차 등 계획명 |
| `start_date` | DATE | N | - | 시작일 |
| `end_date` | DATE | N | - | 종료일 |
| `initial_asset_value` | DECIMAL(19,4) | N | - | 시작 기준자산 |
| `annual_contribution_amount` | DECIMAL(19,4) | N | 0 | 첫해부터 반영할 연간 추가 투자금 |
| `is_active` | BOOLEAN | N | TRUE | 활성 상태 |
| `display_order` | SMALLINT UNSIGNED | N | 0 | 표시 순서 |
| `memo` | VARCHAR(500) | Y | NULL | 계획 메모 |
| `created_at` | DATETIME(3) | N | CURRENT_TIMESTAMP(3) | 생성 시각 |
| `updated_at` | DATETIME(3) | N | - | 수정 시각 |

인덱스:

- `(account_id, start_date, end_date)`
- `(account_id, is_active, display_order)`

# 4. compound_growth_goals

| 컬럼 | 타입 | NULL | 기본값 | 설명 |
|---|---|---:|---|---|
| `id` | BIGINT UNSIGNED | N | AUTO_INCREMENT | PK |
| `plan_id` | BIGINT UNSIGNED | N | - | 복리계획 FK |
| `goal_name` | VARCHAR(100) | N | - | 안정형·기준형·공격형 등 |
| `annual_target_rate` | DECIMAL(9,4) | N | - | 연간 목표수익률(%) |
| `display_color` | VARCHAR(20) | Y | NULL | 화면 표시용 색상 토큰 또는 HEX |
| `is_default` | BOOLEAN | N | FALSE | 계획 대표 목표 여부 |
| `is_visible` | BOOLEAN | N | TRUE | 비교화면 표시 여부 |
| `display_order` | SMALLINT UNSIGNED | N | 0 | 표시 순서 |
| `created_at` | DATETIME(3) | N | CURRENT_TIMESTAMP(3) | 생성 시각 |

제약과 인덱스:

- `UNIQUE(plan_id, goal_name)`
- `(plan_id, is_default)`
- `(plan_id, is_visible, display_order)`

# 5. 서비스 검증 규칙

MariaDB의 일반 UNIQUE/FK만으로 표현하기 어려운 아래 규칙은 Fastify 서비스의 DB 트랜잭션 안에서 검증한다.

- `start_date <= end_date`
- 같은 계좌에서 복리계획 기간 중복 금지
- 계획 생성 시 기준형 목표 한 개를 함께 생성
- 계획마다 목표 한 개 이상 유지
- 계획마다 `is_default = true`인 목표를 정확히 한 개 유지
- 연간 목표수익률과 금액의 허용 범위 검사
- 계획 삭제 시 하위 목표 존재 여부를 확인하고 명시적 삭제 처리

기간 중복 판정:

```text
기존 시작일 <= 신규 종료일
AND 기존 종료일 >= 신규 시작일
```

# 6. 데이터 이관

`20260926165000_compound_growth_plans` 마이그레이션은 기존 단일 구조의 각 행을 다음과 같이 보존한다.

- 기존 `period_name` → 새 계획의 `plan_name`
- 기존 기간·기초자산·연간 추가금·메모 → 새 계획
- 기존 목표명·목표수익률·표시 여부 → 새 하위 목표
- 이관된 하위 목표는 해당 계획의 기본 목표로 설정

# 7. 다음 DB 검토

- RIM 계산값을 저장할지 조회 시 계산할지 여부
