# 주식 매매일지 DB 스키마 정의서

**버전:** v0.3  
**기준:** 매매일지 설계 v0.5 및 Prisma 현행화

| 항목 | 내용 |
|---|---|
| 작성 기준일 | 2026년 9월 23일 |
| DBMS | MariaDB |
| ORM | Prisma |
| 이전 버전 | 매매일지 스키마 v0.2 보존 |

# 1. v0.3 변경 이력

1. `compound_growth_plans`를 추가하고 `compound_growth_goals`를 하위 목표 구조로 변경했습니다.
2. `buy_trades.bought_at`, `sell_trades.sold_at`을 사용자 입력 날짜형 `trade_date`로 통일했습니다.
3. `cash_transactions.transaction_date`를 날짜형으로 명확히 했습니다.
4. 비용 수정 시 차액을 예수금에 반영한다는 v0.2 규칙을 폐기했습니다.
5. `balance_after`를 최초 등록 직후의 불변 잔액 스냅샷으로 정의했습니다.
6. Lot·매도·삭제·스냅샷·보유현황 계산과 애플리케이션 제약을 명확히 했습니다.

# 2. 공통 규칙

- PK는 `BIGINT UNSIGNED AUTO_INCREMENT`를 사용합니다.
- 금액은 `DECIMAL(19,4)`, 수량은 `DECIMAL(18,6)`, 비율은 `DECIMAL(9,4)`를 기본으로 합니다.
- 사용자 입력 거래일은 `DATE`, 시스템 생성·수정시각은 `DATETIME(3)`입니다.
- 모든 업무 테이블에 `created_at`, `updated_at`을 둡니다.
- 업무 FK의 삭제 기본값은 `ON DELETE RESTRICT`, 갱신은 `ON UPDATE CASCADE`입니다.
- 양수, 날짜 순서, 누적수량과 단일 기본 목표처럼 Prisma만으로 표현하기 어려운 규칙은 API와 테스트로 보장합니다.

# 3. 관계 요약

| 부모 | 관계 | 자식 |
|---|---|---|
| `accounts` | 1:N | `buy_trades`, `cash_transactions`, `dividends`, 스냅샷, `compound_growth_plans` |
| `securities` | 1:N | 매수, 배당, 가격, 종목 스냅샷, 재무·가치정보 |
| `securities` | 1:0..1 | `watchlist_items`, `market_prices` |
| `buy_trades` | 1:N | `sell_trades` |
| `compound_growth_plans` | 1:N | `compound_growth_goals` |

거래·배당과 `cash_transactions`는 최초 등록 시 서비스 트랜잭션으로 함께 생성할 수 있지만 FK로 연결하지 않습니다.

# 4. 핵심 테이블

## 4.1 accounts

| 컬럼 | 타입 | Null | 기본값 | 설명 |
|---|---|---:|---|---|
| `id` | BIGINT UNSIGNED | N | AUTO | PK |
| `name` | VARCHAR(100) | N | - | 계좌명 |
| `broker_name` | VARCHAR(100) | N | - | 증권사명 |
| `account_number` | VARCHAR(50) | Y | - | 계좌번호 |
| `cash_balance` | DECIMAL(19,4) | N | 0 | 현재 실제 예수금 |
| `is_active` | BOOLEAN | N | TRUE | 활성 여부 |
| `display_order` | SMALLINT UNSIGNED | N | 0 | 표시순서 |
| `created_at` | DATETIME(3) | N | NOW | 생성시각 |
| `updated_at` | DATETIME(3) | N | 자동 | 수정시각 |

## 4.2 securities

종목코드, 종목명, 시장, 종목유형, 활성 여부와 공통 시각을 저장합니다. `market_type + symbol`은 UNIQUE입니다.

## 4.3 watchlist_items

`security_id`는 UNIQUE입니다. `list_type`은 `WATCHLIST`, `HOLDING`, `RECOMMENDED` 중 하나이며 한 종목은 한 탭에만 표시됩니다.

## 4.4 buy_trades

| 컬럼 | 타입 | Null | 설명 |
|---|---|---:|---|
| `id` | BIGINT UNSIGNED | N | PK, 매수 Lot ID |
| `account_id` | BIGINT UNSIGNED | N | 계좌 FK |
| `security_id` | BIGINT UNSIGNED | N | 종목 FK |
| `trade_date` | DATE | N | 사용자 입력 매수일 |
| `quantity` | DECIMAL(18,6) | N | 매수수량, 0 초과 |
| `unit_price` | DECIMAL(19,4) | N | 매수단가, 0 초과 |
| `memo` | VARCHAR(500) | Y | 메모 |
| `created_at` | DATETIME(3) | N | 실제 등록시각 |
| `updated_at` | DATETIME(3) | N | 실제 수정시각 |

인덱스는 `(account_id, trade_date)`, `(account_id, security_id, trade_date)`입니다.

## 4.5 sell_trades

| 컬럼 | 타입 | Null | 설명 |
|---|---|---:|---|
| `id` | BIGINT UNSIGNED | N | PK |
| `buy_trade_id` | BIGINT UNSIGNED | N | 선택한 매수 Lot FK |
| `trade_date` | DATE | N | 사용자 입력 매도일 |
| `quantity` | DECIMAL(18,6) | N | 매도수량, 0 초과 |
| `unit_price` | DECIMAL(19,4) | N | 매도단가, 0 초과 |
| `memo` | VARCHAR(500) | Y | 메모 |
| `created_at` | DATETIME(3) | N | 실제 등록시각 |
| `updated_at` | DATETIME(3) | N | 실제 수정시각 |

`buy_trade_id`는 `ON DELETE RESTRICT`입니다. 한 매도는 한 Lot만 참조하며 누적 매도수량은 매수수량을 넘을 수 없습니다. 실현손익은 저장하지 않습니다.

## 4.6 cash_transactions

| 컬럼 | 타입 | Null | 기본값 | 설명 |
|---|---|---:|---|---|
| `id` | BIGINT UNSIGNED | N | AUTO | PK |
| `account_id` | BIGINT UNSIGNED | N | - | 계좌 FK |
| `transaction_type` | ENUM | N | - | BUY·SELL·DEPOSIT·WITHDRAWAL·DIVIDEND |
| `transaction_date` | DATE | N | - | 사용자 입력 기준일 |
| `amount` | DECIMAL(19,4) | N | - | 유형의 원금 금액 |
| `fee_tax_amount` | DECIMAL(19,4) | N | 0 | 수수료·세금 통합값 |
| `balance_after` | DECIMAL(19,4) | N | - | 최초 등록 직후 잔액 스냅샷 |
| `memo` | VARCHAR(500) | Y | - | 메모 |
| `created_at` | DATETIME(3) | N | NOW | 생성시각 |
| `updated_at` | DATETIME(3) | N | 자동 | 수정시각 |

`balance_after`는 수정·삭제 때 재계산하지 않습니다. 비용을 수정해도 현재 예수금에 차액을 반영하지 않습니다.

## 4.7 dividends

계좌, 종목, 수령일, 세전 `gross_amount`, 세후 `net_amount`, 메모와 공통 시각을 저장합니다. 최초 등록 시 `net_amount`만 예수금에 반영하고 수정·삭제 때는 반영하지 않습니다.

# 5. 가격과 스냅샷

## 5.1 market_prices

종목별 한 행이며 `security_id`가 PK입니다. 현재가, 전일 종가, 가격 갱신시각과 공통 시각을 저장합니다. 자동 수집 실패 시 기존 가격을 유지하며 사용자가 직접 수정할 수 있습니다.

## 5.2 daily_account_snapshots

계좌, 스냅샷 날짜, 당시 예수금, 주식 평가금액, 총 평가자산을 저장합니다. `(account_id, snapshot_date)`는 UNIQUE입니다.

## 5.3 daily_position_snapshots

계좌, 종목, 스냅샷 날짜, 수량, 잔여매입금액, 현재가, 평가금액, 미실현손익을 저장합니다. `(account_id, security_id, snapshot_date)`는 UNIQUE입니다.

스냅샷은 같은 날짜를 UPSERT하고 `is_final`을 두지 않습니다. 거래·예수금 수정·삭제로 과거 스냅샷을 변경하지 않습니다.

# 6. 재무와 가치정보

## 6.1 financial_statements

종목, 회계연도, 기간유형, 기간종료일, 매출, 영업이익, 순이익, 자산, 부채, 자본, 영업현금흐름, 자본적지출과 공통 시각을 저장합니다. `(security_id, fiscal_year, period_type)`은 UNIQUE입니다.

## 6.2 valuation_metrics

종목, 기준일, EPS, BPS, PER, PBR, ROE, 주당배당금, 배당수익률, 시가총액과 공통 시각을 저장합니다. `(security_id, metric_date)`는 UNIQUE입니다.

# 8. 조회 계산 규칙

```text
Lot 잔여수량 = 매수수량 - 연결 매도수량 합계
Lot 실현손익 = 매도수량 × (매도단가 - Lot 매수단가)
종목 보유수량 = Lot 잔여수량 합계
종목 잔여매입금액 = Σ(Lot 잔여수량 × Lot 매수단가)
종목 평균단가 = 종목 잔여매입금액 ÷ 종목 보유수량
종목 평가금액 = 종목 보유수량 × 현재가
종목 평가손익 = Σ[Lot 잔여수량 × (현재가 - Lot 매수단가)]
총 평가자산 = 주식 평가금액 + accounts.cash_balance
```

`positions`, 실현손익, 총거래금액과 월별 거래비용은 별도 저장하지 않습니다.

# 9. 트랜잭션 규칙

- 매도 등록 시 대상 Lot을 잠그거나 동등한 방식으로 잔여수량을 검증합니다.
- 매수·매도·배당 최초 등록과 예수금 반영은 각각 하나의 트랜잭션입니다.
- 예수금 내역 등록 시 계좌 행을 잠그고 `balance_after`와 `accounts.cash_balance`를 함께 기록합니다.
- 매수 삭제 시 사용자 확인 후 연결 매도를 먼저 삭제하고 매수를 삭제합니다.
- 수정·삭제는 현재 예수금과 과거 스냅샷을 자동 변경하지 않습니다.
- 스냅샷은 UNIQUE 조건과 UPSERT로 멱등성을 보장합니다.

# 10. 마이그레이션 주의사항

- 기존 초기 마이그레이션은 수정하지 않습니다.
- `bought_at`, `sold_at`의 날짜를 새 `trade_date`로 변환하는 별도 마이그레이션이 필요합니다.
- 기존 `compound_growth_goals`의 기간·시작자산·연간추가금 데이터를 계획 행으로 묶는 이관 규칙을 먼저 결정해야 합니다.
- 이관 규칙이 확정되기 전 운영 DB에는 복리 구조 마이그레이션을 적용하지 않습니다.
