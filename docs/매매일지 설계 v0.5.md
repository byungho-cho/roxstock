**버전:** v0.5  
**부제:** 선택 종목 장중 실시간 시세 수집 구조 현행화

| 항목 | 내용 |
|---|---|
| 문서 목적 | 현재까지 확정된 업무 규칙, 데이터 책임과 Figma 화면 동작을 구현 기준으로 고정합니다 |
| 대상 시스템 | React·Vite·TypeScript, Node.js·Fastify·TypeScript, Prisma·MariaDB |
| 작성 기준일 | 2026년 9월 28일 |

| 문서 상태 | v0.4의 업무·화면 정책을 유지하며 운영 수집기, 전체 종목 일일 수집과 선택 종목 장중 실시간 수집 구조를 반영했습니다 |

# 1. 설계 결론

- 매수와 매도는 `buy_trades`, `sell_trades`로 분리합니다.
- 한 매수는 하나의 독립된 Lot이며 여러 매도를 가질 수 있습니다.
- 한 매도는 반드시 하나의 매수 Lot만 참조합니다.
- 여러 매수 Lot을 한 번에 매도하는 기능은 제공하지 않습니다.
- 보유현황은 조회 시 계산하며 `positions` 테이블을 저장하지 않습니다.
- 예수금은 `accounts.cash_balance`에 현재 실제 금액을 유지합니다.
- 거래·배당·예수금 변동은 최초 등록 때만 현재 예수금에 자동 반영합니다.
- 거래·배당·예수금 내역 수정·삭제 시 현재 예수금을 다시 계산하지 않습니다.
- 현재가, 일별 스냅샷, 가치투자 정보와 복리계획별 여러 하위 목표를 관리합니다.
- Figma는 화면 표현 기준이고, 계산·데이터 충돌 시 이 설계서의 업무 규칙을 우선합니다.

# 4. 매수·매도

## 4.1 매수 Lot

`buy_trades` 한 행이 매수 Lot 한 건입니다. 현재 보유수량과 종목 전체 평균단가는 조회 시 계산할 수 있지만, 평균단가는 매도 연결이나 실현손익 원가로 사용하지 않습니다.

## 4.2 매도

`sell_trades.buy_trade_id`는 한 `buy_trades.id`만 참조합니다. 잔여수량보다 많은 매도는 허용하지 않습니다.

```text
잔여수량 = 매수수량 - 연결된 매도수량 합계
실현손익 = 매도수량 × (매도단가 - 연결된 매수단가)
```

실현손익, 잔여수량과 총거래금액은 저장하지 않고 조회 시 계산합니다.

## 4.3 수정과 삭제

- 거래 수정은 매수·매도 기록만 변경하고 현재 예수금을 다시 반영하지 않습니다.
- 연결된 매도가 없는 매수는 바로 삭제할 수 있습니다.
- 연결된 매도가 있는 매수는 연결 매도 건수를 포함한 확인창을 표시합니다.
- 사용자가 확인하면 연결 매도를 먼저 삭제하고 매수를 삭제합니다.
- 연결 매도와 매수 삭제는 하나의 DB 트랜잭션으로 처리합니다.
- DB FK는 `ON DELETE RESTRICT`로 유지합니다.
- 일괄삭제 UI와 소프트 삭제는 제공하지 않습니다.
- 거래 삭제로 예수금과 과거 스냅샷을 자동 변경하지 않습니다.

# 5. 예수금과 거래비용

## 5.1 현재 예수금

`accounts.cash_balance`는 현재 증권계좌에서 확인한 실제 예수금입니다. 사용자는 이 값을 직접 수정할 수 있고 보정 이력은 따로 저장하지 않습니다.

## 5.2 예수금 변동

`cash_transactions.transaction_type`은 다음 값을 사용합니다.

```text
BUY, SELL, DEPOSIT, WITHDRAWAL, DIVIDEND
```

| 유형 | 최초 등록 시 현재 예수금 계산 |
|---|---|
| BUY | 이전 예수금 - 매수금액 - 수수료·세금 |
| SELL | 이전 예수금 + 매도금액 - 수수료·세금 |
| DEPOSIT | 이전 예수금 + 입금액 |
| WITHDRAWAL | 이전 예수금 - 출금액 |
| DIVIDEND | 이전 예수금 + 세후 배당금 |

수수료와 세금은 `fee_tax_amount` 하나로 통합합니다. 거래·배당 테이블과 예수금 내역 사이에는 FK를 두지 않습니다.

거래·배당·예수금 변동 내역은 최초 등록할 때만 현재 예수금에 반영합니다. 이후 수정·삭제 시에는 비용 차액을 포함하여 현재 예수금을 자동 변경하지 않습니다. 실제 잔액과 차이가 있으면 사용자가 `accounts.cash_balance`를 직접 수정합니다.

```text
월별 비용 = 해당 월 fee_tax_amount 합계
연도별 비용 = 해당 연도 fee_tax_amount 합계
```

## 5.3 예수금 화면

- 현재 예수금과 마지막 갱신시각을 표시합니다.
- 월간·연간 정보를 하나의 통합 기간 카드에서 전환합니다.
- 최초 진입은 현재 월의 월간 상태입니다.
- 월간과 연간의 마지막 조회 기간을 각각 보존합니다.
- 월간은 출금·입금·배당을, 연간은 연간 합계를 표시합니다.
- 기간은 좌우 버튼과 스와이프로 순환 탐색합니다.
- 최근 변경은 `구분 | 날짜 | 금액` 3열로 최신 10개를 표시합니다.
- `이전 1개월 불러오기`로 과거 내역을 추가합니다.
- 데이터가 없는 기간도 같은 구조의 빈 상태로 표시합니다.
- Figma 삭제 확인창의 “삭제하면 예수금에서 제외” 문구는 사용하지 않습니다.
- 수정·삭제 화면에는 현재 예수금이 자동 변경되지 않는다는 안내를 표시합니다.

# 6. 배당

`dividends`에는 세전 `gross_amount`와 세후 `net_amount`를 함께 저장합니다.

```text
배당소득세 = gross_amount - net_amount
연도별 실수령 배당금 = 해당 연도 net_amount 합계
```

배당 최초 등록과 세후 금액의 예수금 증가는 한 DB 트랜잭션으로 처리합니다. 이후 배당 수정·삭제는 현재 예수금을 자동 변경하지 않습니다.

# 7. 종목목록과 가치투자

## 7.1 통합 목록

`watchlist_items.list_type`은 `WATCHLIST`, `HOLDING`, `RECOMMENDED` 중 하나입니다. `security_id`에 UNIQUE를 적용하여 한 종목이 여러 탭에 중복되지 않게 합니다.

- 매수 후 잔여수량이 생기면 `HOLDING`으로 변경합니다.
- 전량 매도하면 `WATCHLIST`로 변경합니다.
- 전체 목록을 한 번 조회하고 React에서 `list_type`으로 필터링합니다.
- 관심·보유·추천 탭은 양방향 무한 순환합니다.

## 7.2 보유종목

- 보유수량·매수단가·매입금액·현재가·평가금액·평가손익·수집상태를 표시합니다.
- 종목 상세는 `요약 | 보유 현황 | 거래내역` 탭을 제공합니다.
- 보유 현황은 Lot별 보유일, 잔여수량, 매수금액, 예상 평가와 목표수익률별 단가·총액을 표시합니다.
- 거래내역은 매수와 연결 매도를 한 묶음으로 표시합니다.
- 매수 후 평균단가는 종목 전체 참고값으로만 표시합니다.

## 7.3 관심·추천과 가치분석

- 관심·추천 목록은 현재가, 등락, PER, PBR, ROE, W 값과 메모를 표시합니다.
- 가치분석은 RIM 기준 W별 적정주가와 상승여력을 제공합니다.
- 재무지표는 연간·분기 전환과 수익성·안정성·성장성 항목을 제공합니다.
- 직접 수정 화면에서는 자동 계산 지표와 계산 기초 데이터를 함께 보여줍니다.

# 8. 현재가와 수집

## 8.1 수집 계층

`market_prices`는 종목별 최신 가격 한 행만 유지합니다. 전체 종목의 종가 보정과 사용자가 실제로 보는 선택 종목의 장중 시세를 서로 다른 작업으로 분리합니다.

| 작업 | 대상 | 기본 일정·주기 | 결과 |
|---|---|---|---|
| 종목 마스터 | KOSPI·KOSDAQ 전체 활성 종목 | 매일 07:00 | `securities` UPSERT |
| 장중 실시간 시세 | `HOLDING + WATCHLIST + RECOMMENDED` 합집합, 최대 100종목 | 평일 정규장 09:00~15:30, 10초 | 메모리 캐시 갱신 및 SSE 전송 |
| 실시간 DB 반영 | 위 장중 실시간 대상 | 60초 | `market_prices` UPSERT |
| 장 마감 시세 | 전체 활성 종목 | 매일 20:00, 1회 | `market_prices` 최종 UPSERT |
| 계좌 스냅샷 | 전체 계좌 | 매일 23:00, 1회 | `daily_account_snapshots` UPSERT |

모든 시각은 `Asia/Seoul` 기준입니다. 장중 실시간 수집의 기본 간격은 10초이며 환경변수로 최소 5초까지 조정할 수 있습니다. 공식 호출 한도가 보장되지 않은 외부 원천을 사용하므로 운영 기본값은 10초로 유지합니다.

## 8.2 실행 프로세스

- Fastify API, 일일 배치 수집기, 장중 실시간 수집기는 각각 독립 프로세스와 Docker Compose 서비스로 실행합니다.
- 장중 실시간 수집기의 장애·재시작은 API 서버와 일일 배치 수집기를 중단시키지 않습니다.
- 공통 Prisma 연결, 가격 타입, 공급자 인터페이스와 로깅은 기존 백엔드 코드를 공유합니다.
- 장중 대상은 `watchlist_items`의 세 분류를 합쳐 만들고 `security_id` 기준으로 중복 제거합니다.
- 보유·관심·추천 분류가 변경되면 다음 대상 갱신 회차에 자동 반영합니다.
- 보유종목은 실제 잔여수량이 있는 거래 데이터를 기준으로 유지하며 사용자가 임의로 분류를 변경하지 않습니다.

## 8.3 실시간 전달과 저장

1. 실시간 수집기가 선택 종목 시세를 10초 간격으로 수집합니다.
2. 유효한 가격을 수집기 프로세스 메모리 캐시에 즉시 반영합니다.
3. 수집기는 Bearer 토큰으로 보호된 내부 `POST /internal/realtime-prices`를 호출하여 API 프로세스 캐시로 전달합니다.
4. API는 SSE(Server-Sent Events)로 연결된 React 화면에 변경 가격을 전송합니다.
5. 프론트엔드는 SSE 메시지를 받으면 해당 종목만 갱신합니다.
6. SSE 연결이 끊기면 최신 가격 REST API를 10초 간격으로 조회하는 폴백을 사용합니다.
7. DB 쓰기 부하는 줄이기 위해 수집기 캐시의 최신 정상 가격을 기본 60초마다 `market_prices`에 UPSERT합니다.
8. API 전달 실패와 관계없이 DB 저장은 계속하며, 20시 전체 종목 수집 결과가 당일 최종 마감 가격을 보정합니다.

SSE는 서버에서 브라우저로의 단방향 가격 전달에 적합하며 React에서는 하나의 연결을 공유합니다. 화면·탭별로 별도 외부 시세 요청을 생성하지 않습니다.

## 8.4 외부 원천과 호출 제어

1차 가격 원천은 네이버 금융 브라우저용 polling JSON 응답을 사용합니다. 공식 공개 API가 아니므로 응답 형식과 접근 정책이 바뀔 수 있으며 공급자 코드는 인터페이스 뒤에 격리합니다.

- 종목코드는 `securities.symbol`의 6자리 코드를 사용하고 `A005930` 형식은 `005930`으로 정규화합니다.
- 동시 요청 수는 기본 5개로 제한하고 전체 회차가 끝나기 전에 다음 회차를 겹쳐 실행하지 않습니다.
- 공급자가 다중 종목 응답을 안정적으로 제공하는 것이 확인되면 배치 단위 호출로 교체할 수 있습니다.
- 인증이 필요한 원천을 추가할 때 키는 환경변수로만 관리하고 Git에는 저장하지 않습니다.
- 원천별 응답 변환은 공급자 모듈에서 처리하여 수집·저장 로직과 분리합니다.

## 8.5 정합성·실패 처리

- 가격이 0, 빈 값, 비정상 숫자이면 저장하거나 전송하지 않습니다.
- 수집 실패 시 마지막 정상 가격을 캐시와 DB에 유지합니다.
- 사용자가 수동 수정한 가격은 다음 정상 자동 수집 성공 시 갱신합니다.
- 공급자 응답의 거래시각 `providerTimestamp`가 현재 저장값보다 오래되면 덮어쓰지 않습니다.
- 휴장일, 장 운영상태 종료, 거래시각 미갱신은 성공과 구분하여 `STALE` 또는 `SKIPPED`로 기록합니다.
- 개별 종목 실패는 다른 종목의 수집을 중단시키지 않습니다.
- 동일 실시간 회차의 중복 실행은 프로세스 락으로 차단하고, 여러 인스턴스 운영 시 DB 락을 함께 사용합니다.
- 실행 시작·종료, 대상 수, 성공·실패·STALE 수, 종목별 실패 사유를 구조화 로그에 남깁니다.
- 수집상태는 영구 가격 데이터보다 최신 수집 실행 결과와 응답 상태로 우선 제공합니다.

# 9. 스냅샷

## 9.1 계좌 스냅샷

`daily_account_snapshots`는 `cash_balance`, `stock_value`, `total_asset_value`를 저장합니다. `account_id + snapshot_date`를 UNIQUE로 둡니다.

## 9.2 종목 스냅샷

`daily_position_snapshots`는 종목별 수량, 매입금액, 현재가, 평가금액과 미실현손익을 저장합니다. 종목별 스냅샷은 선택 구현입니다.

## 9.3 실행 규칙

- 현재 운영 기본값은 한국 시간 23시 1회 실행이며 같은 계좌·날짜를 UPSERT합니다.
- 향후 장중 자산 추이가 필요하면 1시간 간격 갱신을 선택적으로 활성화할 수 있습니다.

- `is_final`은 두지 않습니다.
- 시세가 없으면 잘못된 0원 스냅샷을 만들지 않습니다.
- 거래나 예수금 변경으로 과거 날짜 스냅샷을 수정하지 않습니다.

# 10. 복리계획과 복리목표

Figma 최종 통합 구조인 `복리계획 1 : 복리목표 N`을 사용합니다. 1차·2차·3차처럼 기간이 다른 차수는 계획이고, 같은 기간의 안정형·기준형·공격형은 하위 목표입니다.

## 10.1 복리계획

`compound_growth_plans`는 계좌, 계획명, 시작일, 종료일, 시작자산, 연간 추가 투자금, 표시순서와 상태를 저장합니다.

## 10.2 하위 목표

`compound_growth_goals`는 `plan_id`, 목표명, 연 목표수익률, 표시색상, 기본 목표 여부, 표시 여부와 표시순서를 저장합니다.

- 계획을 만들면 기준형 목표 한 개를 자동 생성합니다.
- 계획 목록의 올해 목표·최종 목표·진행률은 기본 목표 기준입니다.
- 기본 목표 변경은 확인창을 거칩니다.
- 시작연도 선택 시 5년 범위를 제안하지만 시작·종료연도를 수정할 수 있습니다.
- 같은 연도를 선택한 1년 계획도 허용합니다.
- 화면에는 일반적으로 목표 3개를 우선 표시하지만 저장 개수에는 제한이 없습니다.

## 10.3 계산 기준

연간 추가 투자금은 첫해부터 연초에 기초자산에 더한 뒤 해당 연도의 목표수익률을 적용합니다.

```text
첫해 목표자산
= (시작자산 + 연간추가금) × (1 + 목표수익률)

다음 해 목표자산
= (직전 목표자산 + 연간추가금) × (1 + 목표수익률)
```

Figma에 표시된 연말 추가 방식의 예시 금액과 안내문은 구현 기준으로 사용하지 않습니다. 화면 예시 데이터는 위 공식에 맞춰 교체합니다.

# 12. 화면별 설계

## 12.1 홈과 평가자산

- 화면 제목은 `대시보드`, 하단 메뉴명은 `홈`입니다.
- 평가자산·오늘손익은 적색, 주식평가액은 연두색, 예수금은 노란색을 사용합니다.
- 평가자산·예수금·오늘손익·자산추이 카드는 각각 관련 상세 화면으로 이동합니다.
- 보유종목 제목은 목록으로, 개별 행은 해당 종목 상세로 이동합니다.
- 평가자산 화면은 `매입금액 | 평가손익 | 주식평가액`과 전일 대비를 제공합니다.
- 자산구성은 주식·예수금 금액과 비율을 표시합니다.
- 종목별 비중 카드는 `순위형 ↔ 누적형`으로 전환합니다.

## 12.2 매매일지와 일별손익

- 매매일지 기본 화면은 월간 달력입니다.
- 날짜별 매수·매도 건수와 선택 날짜의 거래 요약을 표시합니다.
- 월 이동은 버튼과 스와이프를 지원하고 최초 데이터 월과 현재 월 사이를 순환합니다.
- 일별손익은 전체손익, 평가손익, 실현손익, 종목별 기여도와 거래 현황을 표시합니다.
- 오늘 날짜에서는 다음 날짜 이동을 막고 과거 날짜에서는 `오늘` 바로가기를 제공합니다.
- 날짜 선택 영역은 세로 스크롤 시 상단에 고정합니다.

## 12.3 자산분석과 투자손익

- 자산추이는 `1개월 | 3개월 | 6개월 | 1년 | 전체`를 제공합니다.
- 기간 성과는 시작자산, 입금, 출금, 순입출금, 평가손익, 실현손익, 배당, 비용, 투자손익과 수익률을 제공합니다.
- 투자금 화면은 일별 평가금액과 투자금 추이를 함께 표시합니다.
- 투자손익은 연도별·종목별 전환을 제공합니다.
- 연도 상세에서는 종목별·월별 손익을 조회합니다.
- 종목 상세에서는 매수총액, 매도총액, 매매손익, 배당포함 총손익과 연도·월별 내역을 제공합니다.
- 연도 이동은 올해와 최초 데이터 연도가 이어지는 순환형 탐색을 지원합니다.

## 12.4 거래등록

- 매수는 거래일자, 수량, 단가와 메모를 입력하고 매수금액과 예상 거래 후 예수금을 표시합니다.
- 매도는 선택한 매수 Lot을 고정 표시하고 잔여수량 이내에서 수량과 단가를 입력합니다.
- 예상 실현손익은 선택한 Lot의 매수단가로 계산합니다.
- 거래 후 예수금은 최초 등록 시 예상값입니다.
- 수정 화면의 예수금은 참고값이며 저장 시 현재 예수금을 다시 반영하지 않습니다.
- 여러 Lot을 선택하거나 한 번에 매도하는 UI는 제공하지 않습니다.

## 12.5 더보기와 설정

- 더보기에는 평가자산, 예수금, 일별손익, 자산분석, 투자금, 투자손익, 복리계획, 가치분석, 재무지표, 시세수집과 설정 진입점을 제공합니다.
- 계좌 관리에서는 계좌정보와 현재 실제 예수금을 직접 수정합니다.
- 현재가 수기 수정값은 다음 자동수집 성공 시 덮어씁니다.
- 테마는 다크·라이트·시스템을 제공하며 기본값은 다크입니다.

# 14. 자산과 손익 계산

```text
Lot 평가금액 = 잔여수량 × 현재가
Lot 평가손익 = 잔여수량 × (현재가 - 매수단가)
주식 평가금액 = 모든 보유 Lot 평가금액 합계
총 평가자산 = 주식 평가금액 + 현재 예수금
현금 비중 = 현재 예수금 ÷ 총 평가자산 × 100
기간 투자손익 = 평가손익 + 실현손익 + 배당수익 - 수수료·세금
현재 총자산 = 기간 시작자산 + 순입출금 + 기간 투자손익
```

일별손익·기간성과·투자손익은 기존 거래·배당·예수금·스냅샷에서 계산하는 조회모델로 제공하며 별도 집계 테이블은 두지 않습니다.

# 15. DB 스키마 변경 영향

Figma 현행화에 따라 DB 스키마 v0.3에서 다음 항목을 검토해야 합니다.

3. RIM과 재무지표에 필요한 지배순이익, 발행주식수, 자기주식수, 지배주주자본과 전기 지배주주자본의 저장 위치를 검토합니다.
4. UI 수집상태는 DB 컬럼 추가보다 수집 실행 결과와 응답 상태로 우선 처리합니다.

이 변경은 기존 거래·예수금·Lot 관계를 바꾸지 않습니다.
