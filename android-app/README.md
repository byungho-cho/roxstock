# 앱 개발

기준일: 2026-10-09  
버전: 0.1.0 (1차 시험 구현)
상태: Android 웹 래퍼·기기 내 알림 보관·웹 등록 보조 구현, 시험 APK 빌드·lint 통과. 운영 반영 및 실기기 검증 전. [PR #170](https://github.com/byungho-cho/roxstock/pull/170).

## 목적과 구조

기존 RoxStock 웹사이트를 감싼 안드로이드 앱을 개발한다. 앱 전용 소스는 이 `android-app/` 디렉터리에서 관리한다. 기존 프론트엔드를 복사하지 않고 운영 웹 화면을 활용한다.

- android-app/: 웹 표시, 안드로이드 알림 접근 권한, 체결 알림 수신·보관, 웹과의 연결.
- frontend/: 공통 화면, 알림 아이콘·목록, 기존 거래 등록 화면 자동 입력, 설정의 APK 다운로드 항목.
- backend/: 필요 시 대기 내역 연동 및 중복 등록 방지. 기존 거래 저장 규칙 재사용.
- 웹 화면 변경과 APK 배포는 별개로 관리한다.

Java / Android WebView + AndroidX WebKit을 사용한다. 최소 Android 7.0(API 24), 컴파일·대상 SDK 35. 사용자가 알려준 실제 시험 환경은 Android 17 / One UI 9.0이다. 실제 설치 및 알림 권한 동작은 해당 기기에서 검증해야 한다. WebMessageListener를 지원하는 WebView가 필요하며, 미지원 시 업데이트 안내를 표시한다.

## 확정한 사용자 흐름

1. 사용자가 알림 접근을 허용한 뒤 카카오톡 미래에셋증권의 전량체결(매수·매도) 또는 배당금 입금 알림을 수신한다. 주문 접수·부분체결은 제외한다.
2. 수신 정보는 등록 대기로 보관한다. 수신만으로 거래를 자동 저장하지 않는다.
3. 앱 내 알림 아이콘에 미등록 건수를 표시하고, 아이콘을 누르면 대기 목록을 보여준다.
4. 목록에서 알림을 선택하면 기존 입력 컴포넌트와 거래 API를 재사용하는 알림용 매수·매도·배당 등록 화면으로 이동한다.
5. 확인 가능한 계좌·종목·거래일·수량·체결가격을 자동 입력하고 원본 알림을 함께 표시한다. 불명확한 정보는 임의로 채우지 않는다.
6. 사용자가 확인·수정한 후 저장을 눌러야 거래로 등록된다.
7. 작성 중 새 알림이 오면 기존 입력을 유지하고 목록과 배지만 갱신한다. 화면을 강제로 전환하거나 입력을 덮어쓰지 않는다.
8. 저장 성공 시 등록 완료로 전환하고 미등록 건수에서 제외한다. 저장 실패 또는 저장 전 닫기는 대기 상태를 유지한다.
9. 불필요한 알림은 무시 처리할 수 있다. 재실행 후에도 대기 내역을 유지한다.

### 거래일시와 계좌 판정

- 거래일시는 알림 최초 수신 시각이다. 한국시간으로 표시·수정하며 저장 요청에는 실제 시각을 보존한다. 목록을 나중에 열어도 현재 시각으로 바꾸지 않는다.
- 알림 계좌와 저장된 계좌에서 하이픈·공백만 제거한다. 길이가 같고 별표 위치를 제외한 숫자가 같은 위치에서 모두 같아야 일치한다.
- 현재 선택 계좌가 유일하게 일치하면 바로 자동 입력한다. 불일치·번호 미등록·여러 계좌 일치 시 계좌 선택을 먼저 표시한다. 다른 계좌가 유일하게 일치하더라도 임의 전환하지 않는다.
- 사용자가 고른 실제 계좌는 현재 계좌로 반영한다. 샘플 계좌 선택은 실제 현재 계좌를 변경하지 않는다.
- 최초 저장 요청의 계좌·입력값·요청 ID는 보관한다. 응답 유실·서버 오류 후에는 같은 요청을 재전송하여 중복 거래를 막는다. 명시적 입력 오류만 수정 가능 상태로 되돌린다.

## 처리 기준

- 일반 대화는 저장·전송하지 않고 지원하는 증권사 체결 알림만 대상으로 한다.
- 매수·매도는 전량체결만 대상으로 하며 체결수량·체결단가를 사용한다. 주문수량·체결금액과 다르면 경고하고 사용자가 확인한다. 마지막 알림이 누적 체결인지 실제 예시로 검증해야 한다.
- 저장 재시도나 중복 클릭으로 동일 거래가 중복 생성되지 않도록 한다.
- 권한 해제, 내용 숨김·누락, 네트워크 단절 상황을 처리한다.
- 웹 연결은 신뢰하는 서비스 주소로 제한하며, 외부 페이지에 앱의 알림 데이터나 기능을 제공하지 않는다.

## APK 배포

- 서명한 APK를 웹서버에 업로드한다.
- 웹의 더보기 → 설정 화면 하단에 안드로이드 앱 다운로드를 배치한다.
- 앱 버전, 업데이트 날짜, APK 다운로드 버튼과 설치 안내를 제공한다.
- 사용자가 APK를 내려받아 직접 설치·업데이트한다.
- 업데이트 시 동일한 앱 식별자와 서명을 유지한다.
- APK, 서명 키, 비밀번호, 실제 거래 알림 원문은 Git에 커밋하지 않는다.

## 첫 구현의 저장 범위와 제한

- 실제 알림 원문은 기기의 SQLite와 해당 WebView의 로컬 저장소에만 보관한다. 서버에는 사용자가 확인한 거래 필드만 전송한다. 일반 대화는 저장하지 않는다.
- 원문을 저장소·로그·GitHub 테스트 데이터에 넣지 않는다. 샘플은 가상 계좌와 주문번호를 사용한다.
- 기본 서버 주소: https://newrox.cafe24.com. 앱 연결 기능은 정확히 지정한 HTTPS origin의 최상위 화면에만 제공한다.
- 배당 저장에 기존 trade_requests 테이블을 재사용하는 요청 ID 처리를 추가했다. DB 스키마 변경 없음. 백엔드 반영 전 실제 배당 등록 테스트를 하지 않는다.
- 매도는 기존 API처럼 하나의 매수 건에 연결한다. 여러 매수 건에 걸친 매도는 기존 화면에서 나눠 등록하고 알림을 무시 처리한다.
- 수수료·세금이 없는 매매 알림은 0원으로 채우고 확인 안내를 표시한다. 사용자가 수정할 수 있다.
- 카카오 대화창 이미지와 시스템 알림 본문은 다를 수 있다. 본문에 증권사 식별·전량체결 문구 등이 없으면 수집하지 않는다. 묶음 메시지에서는 최신 메시지를 처리하며 누락 여부를 실기기로 검증한다.
- 기기 간 대기 목록 동기화·다른 증권사·iOS·자동 거래 저장은 포함하지 않는다.

## 바로 테스트하기

### PC 샘플 화면

기존 웹에 영향을 주지 않는 별도 개발 서버에서 `/detail/notifications`를 연다. 이 작업의 실행 주소는 `http://127.0.0.1:3012/detail/notifications`이다. 서버가 종료되었다면 아래처럼 시작한다.

```powershell
$env:VITE_DATA_SOURCE='mock'
npm --workspace frontend run dev -- --host 127.0.0.1 --port 3012 --strictPort
```

1. 매수·매도·배당 샘플 또는 계좌 불일치 샘플을 추가한다.
2. 목록에서 선택하여 계좌 판정, 자동 입력, 수신 일시를 확인한다.
3. 확인 체크 후 샘플 저장을 누른다. 실제 API로 거래를 전송하지 않는다.
4. 저장 전 취소하고 다시 열어 대기 유지, 새 샘플 여러 건을 넣어 목록과 배지를 확인한다.

### APK 빌드와 휴대폰 수신 시험

GitHub Actions의 **Android App Build**가 `assembleDebug lintDebug`를 수행하며 `roxstock-android-test-apk` 결과물을 제공한다. Android Studio에서는 이 디렉터리를 열고 JDK 17, Gradle 8.11.1, SDK 35로 빌드한다.

```text
gradle -p android-app assembleDebug lintDebug
```

1. 결과물 ZIP에서 `app-debug.apk`를 꺼내 휴대폰에 전달하고 설치한다. 시험용 앱 ID는 `com.roxstock.app.debug`이다.
2. 앱 상단의 거래 알림 버튼 → 알림 접근 허용·설정 → RoxStock 허용을 선택한다. OS가 설치 출처 관련 추가 제한 안내를 표시하면 해당 기기의 안내에 따라 본인이 설치한 앱임을 확인한다.
3. 신규 미래에셋 전량체결·배당 알림이 도착하면 앱 상단 건수와 ‘휴대폰에 수신한 대기 알림 확인’에서 원문이 보이는지 확인한다. 거래를 새로 할 필요는 없으며 다음 실제 알림이 올 때 확인한다.
4. 앱 종료·재실행 후 대기 내역 유지, 다른 메시지를 수신했을 때 목록 미추가를 확인한다.
5. 웹·백엔드 변경 반영 후 웹 등록 대기 목록에서 자동 입력과 직접 저장을 시험한다. 샘플 저장은 실제 기록을 만들지 않지만 실제 알림의 저장 버튼은 실제 거래를 만든다.

운영 웹이 아직 이 PR의 화면을 제공하지 않더라도 앱 자체의 수신 확인 메뉴와 권한 설정은 사용할 수 있다. 자동 입력부터 실제 저장까지의 전체 시험에는 웹·백엔드 반영이 필요하다.

### 정식 APK 다운로드 연결

정식 서명 키는 별도 안전한 저장소에 유지하며 Git에 넣지 않는다. 시험용 debug APK는 정식 배포물로 취급하지 않는다. CI 시험 키는 실행마다 달라질 수 있으므로 이전 시험 앱에 덮어쓰기되지 않을 수 있다. 삭제하면 기기 대기 내역도 지워진다.

서버에서 다음 파일을 제공하면 더보기 → 설정 하단에 다운로드 버튼이 활성화된다. 없는 상태에서는 ‘APK 배포 준비 중’을 표시한다. SPA HTML을 메타데이터로 오인하지 않는다.

- `/downloads/android/roxstock-0.1.0.apk`: 정식 서명 APK
- `/downloads/android/latest.json`: 아래 형식

```json
{"version":"0.1.0","updatedAt":"2026-10-09","url":"/downloads/android/roxstock-0.1.0.apk"}
```

APK와 메타데이터는 웹 프론트엔드 배포로 삭제되지 않는 서버 파일 영역에서 제공한다. 업로드 후 HTTPS 응답·설치·동일 서명 업데이트를 확인한 뒤 메타데이터를 공개한다. 현재 공개 업로드는 수행하지 않았다.
