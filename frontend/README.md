# RoxStock Frontend

React + Vite + TypeScript 기반의 모바일 우선 웹 애플리케이션입니다.

## 실행

```bash
npm install
npm run dev:frontend
```

브라우저에서 `http://localhost:3000`으로 접속합니다. `/api` 요청은 개발 중 `http://localhost:3300`으로 프록시됩니다.


## 첫 접속 최적화 (2026-10-11)

홈(`/`)과 자산분석(`/assets`)을 포함한 화면 코드는 경로별로 분리해 필요한 화면만 불러옵니다. 메뉴는 유지하고 화면 영역에 로딩 상태를 표시하며, 파일 다운로드 실패 시 사용자가 새로고침으로 재시도할 수 있습니다.

빌드 마지막 단계에서 JS/CSS/SVG 등 1KB 이상 텍스트 파일의 gzip 사본을 생성합니다. 운영 Nginx는 `gzip_static`으로 사전 압축 파일을 제공하므로 요청마다 압축 연산을 수행하지 않습니다. 압축 미지원 클라이언트에는 원본을 제공합니다. HTML은 재검증하고 정적 파일의 기존 캐시를 유지합니다.

`gzip_proxied any`로 Caddy의 Via 헤더가 있는 요청에도 gzip 사본을 제공하며 `gzip_vary on`으로 압축 지원 여부에 따른 캐시 구분을 알립니다.

## 현행 로딩·오류 안내 (2026-10-16 · V1.0.41)

홈·대시보드 및 최근 정비한 상세 화면은 카드/차트 틀을 유지하고 로딩 중 값 영역을 비웁니다. 과거 스켈레톤 명세보다 최신 화면 구현을 우선합니다. 재조회 때 기존 데이터는 보존하며, 정상 빈 결과와 실패를 구분합니다. 조회 오류는 `QueryErrorNotice`와 공통 `ErrorToastHost`로 표시하고 닫기·재시도·중복 방지·복구 시 정리를 지원합니다.

가치분석·재무제표 목록은 `useIncrementalAnalysisList`로 20개를 먼저 표시하고 30개를 자동 추가한 뒤 다음 50개를 미리 조회합니다. 더보기와 전체 정렬/건수/상세 이동 순서를 유지합니다. 이 정책과 정적 파일 압축은 별개이며 실제 첫 접속 개선 효과는 동일 조건에서 측정해야 합니다.

### 첫 접속 검증

검증: API 모드로 `npm run build:frontend` 실행 후 frontend 디렉터리에서 `npx playwright test -c playwright.first-load.config.ts`. 빌드 결과를 대상으로 홈·자산분석 첫 진입, 불필요한 상세 화면 미로딩, 압축본 정합성, 기간 변경·계좌 전환·오류 복구를 확인합니다. 로컬 Chrome 설치가 필요합니다. 측정된 gzip 크기는 코드 전송량이며 실제 기기 화면 완성 시간과는 다릅니다.
